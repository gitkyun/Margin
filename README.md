## Overview

# RMS — Research Management System

**논문 지도 과정의 피드백을 실제 연구 활동으로 연결하는 연구 관리 시스템**

RMS(Research Management System)는 대학원생이 논문 지도 과정에서 발생하는 미팅 기록, 피드백, 수정 작업, 연구 자료와 교수 검토 이력을 연결해 관리할 수 있도록 돕는 웹 기반 서비스입니다.

단순히 연구 자료와 할 일을 한곳에 모으는 것이 아니라, **어떤 피드백을 받았고, 어떻게 수정했으며, 무엇을 확인받았는지** 이어서 파악할 수 있는 경험을 목표로 합니다.

> **Project Status:** Classroom Demo Implementation Planning · 2026
>
> 대표 시나리오의 실제 구현·배포를 준비하고 있습니다. 앱·API 연결·배포 완료와는 구분됩니다.

## Why RMS?

논문 연구는 계획을 세우고 수행하는 과정뿐 아니라, 지도교수의 피드백을 바탕으로 연구 방향과 내용을 반복적으로 수정하는 과정이기도 합니다.

그러나 실제 연구 과정에서 이러한 기록은 여러 도구에 나뉘어 관리됩니다.

- 미팅에서 받은 피드백은 개인 메모나 메신저에 남습니다.
- 수정해야 할 내용은 별도의 할 일 목록으로 옮겨집니다.
- 논문 초안과 수정본은 여러 파일과 저장소에 쌓입니다.
- 교수의 확인과 추가 수정 요청은 이메일이나 댓글로 전달됩니다.

학생은 다음 미팅을 준비할 때마다 이전 기록을 다시 찾고, 어떤 피드백을 반영했는지 확인하며, 다음에 무엇을 준비할지 판단해야 합니다.

RMS는 이 과정에서 발생하는 네 가지 문제에 집중합니다.

| Problem | Approach |
|---|---|
| 미팅 이후 기록을 다시 정리해야 하는 부담 | 원문을 보존하고 피드백·결정·질문을 후속 작업에 연결 |
| 피드백을 받아도 수정 방법을 판단하기 어려움 | 여러 수정 방안과 예상 결과, 필요한 작업을 비교 |
| 이전 지적과 수정 이력을 추적하기 어려움 | 피드백·작업·문서 버전·교수 응답을 함께 관리 |
| 다음 미팅의 준비 범위를 정하기 어려움 | 보여줄 결과와 남은 작업·질문을 중심으로 준비 |

**RMS의 핵심은 피드백을 기록하는 것에서 끝나지 않고, 실제 수정과 다음 연구 활동까지 연결하는 것입니다.**

## How It Works

RMS는 논문 지도의 반복적인 과정을 다음과 같이 연결합니다.

**Meeting → Feedback → Revision → Task → Review → Next Meeting**

### 1. Record — 지도 내용을 기록합니다

학생은 지도 미팅의 메모를 작성하고 피드백, 결정 사항, 미해결 질문을 정리합니다.

기존 원문을 보존하면서 학생이 정리한 내용과 구분하며, 이후 수정 작업의 근거로 활용할 수 있습니다.

### 2. Explore — 수정 방법을 탐색합니다

정리한 피드백을 바탕으로 가능한 수정 방법을 검토합니다.

필요한 경우 AI를 활용하여 여러 수정 방안의 예상 결과, 필요한 자료와 추가 작업을 비교합니다. 학생은 제안을 수정하거나 직접 방법을 작성할 수 있습니다.

### 3. Plan — 다음 작업을 결정합니다

선택한 수정 방법을 구체적인 할 일로 연결하고 진행 상태와 기한을 관리합니다.

하나의 작업을 여러 피드백이나 미팅에 연결할 수 있으며, 다음 미팅에서 준비할 작업은 학생이 직접 선택합니다.

### 4. Document — 수정 결과를 기록합니다

실제 수정한 내용과 관련 문서 버전, 확인할 위치를 기록합니다.

어떤 피드백을 바탕으로 무엇을 수정했는지 연결하여 이후에도 수정 근거를 확인할 수 있도록 합니다.

### 5. Review — 교수와 수정 결과를 확인합니다

학생은 검토받을 수정 결과와 근거 자료를 선택하고, 공유 내용을 확인한 뒤 지도교수에게 검토 링크를 전달합니다.

교수는 공유된 항목을 확인하고 '수정 내용 확인' 또는 '추가 수정 필요' 등의 검토 결과와 댓글을 남길 수 있습니다.

### 6. Continue — 다음 연구로 이어갑니다

교수 응답과 남은 작업, 미해결 질문을 다음 미팅의 준비 항목으로 연결합니다.

추가 수정이 필요한 경우 이전 자료와 응답을 유지하면서 새로운 수정 결과를 다시 검토받을 수 있습니다.

이 과정은 반드시 순서대로 완료해야 하는 절차는 아닙니다. 학생은 교수의 응답을 기다리는 동안에도 다른 연구 작업과 미팅 준비를 계속할 수 있습니다.

## Key Features

### Research Dashboard

연구 현황과 다음 행동을 한눈에 확인할 수 있는 대시보드입니다.

- 현재 연구 단계와 주요 일정 확인
- 다음 미팅 및 준비 항목 조회
- 진행 중인 작업과 미해결 피드백 확인
- 교수의 새 응답과 검토 대기 항목 확인
- 각 요약 항목에서 원본 기록으로 이동

### Meeting & Feedback Management

지도 미팅에서 발생한 기록을 보존하고 후속 작업과 연결합니다.

- 미팅별 메모 및 이전 기록 관리
- 피드백·결정 사항·미해결 질문 구분
- 원문과 학생이 정리한 내용 연결
- 반복 피드백 및 미해결 사항 확인
- 다음 미팅에 필요한 질문 연결

### AI-Assisted Revision Planning

피드백에 따른 수정 방법을 탐색하고 비교하는 선택적 AI 보조 기능입니다.

- 선택한 피드백과 자료를 기반으로 수정 방안 제안
- 방법별 예상 결과 및 필요한 작업 비교
- 원문 근거와 AI의 새로운 가정·제안 구분
- 수정 방안의 선택·편집 및 직접 작성
- 선택한 방안을 할 일로 연결

AI를 사용하지 않아도 학생은 동일한 기본 작업을 직접 수행할 수 있습니다.

### Task & Meeting Preparation

연구 작업을 관리하고 다음 지도 미팅에서 보여줄 결과를 준비합니다.

- 할 일 생성 및 진행 상태 관리
- 작업별 기한 및 준비 순서 설정
- 피드백과 수정 방안에 연결된 작업 관리
- 미완료 작업의 다음 미팅 재선택
- 결과·자료·질문을 활용한 미팅 준비 문서 구성

작업의 완료 여부와 미팅 준비 상태를 구분하며, 미팅 일정이 변경되어도 개별 작업의 기한을 자동으로 변경하지 않습니다.

### Document & Version Management

연구 자료와 수정 이력을 문서 버전 단위로 관리합니다.

- 논문 초안·발표 자료·분석 결과 등 자료 등록
- 문서 버전별 수정 내용 관리
- 피드백과 관련 문서 버전 연결
- 미팅 제출 자료 및 검토 근거 확인
- 과거 검토에 사용된 파일과 설명 보존

새로운 문서 버전을 등록해도 이전에 검토받은 자료와 응답은 당시 상태로 유지하도록 설계합니다.

### Professor Review

학생이 실제 수정 결과를 공유하고 지도교수의 검토를 받을 수 있도록 합니다.

- 수정 결과와 근거 자료를 묶어 검토 요청 구성
- 공유 내용 미리보기 및 검토 링크 생성
- 지정된 교수 계정의 검토 접근
- 항목별 검토 결과 및 댓글 작성
- 추가 수정 후 재확인 요청
- 검토 차수별 이력 보존

교수는 공유된 검토 항목에만 접근하며 학생의 전체 연구 기록이나 개인 메모는 자동으로 공개되지 않습니다.

### Research Roadmap

전체 연구 계획과 현재 작업을 연결합니다.

- 연구 단계 및 마일스톤 관리
- 단계별 목표와 완료 조건 설정
- 학술대회·학술지 투고 일정 등록
- 논문 심사 및 내부 검토 일정 관리
- 단계별 자료·피드백·작업 연결

공식 마감일과 학생이 설정한 개인 목표일을 구분하며, 연구 단계의 완료 여부는 학생이 직접 관리합니다.

## What Makes RMS Different?

### 1. From Feedback to Action

RMS는 피드백을 단순한 메모나 할 일로 취급하지 않습니다.

피드백의 원문부터 선택한 수정 방법, 실제 작업, 수정 결과, 교수의 검토까지 연결하여 연구자가 이전 판단과 수정 과정을 다시 확인할 수 있도록 합니다.

특히 다음 세 가지 상태를 구분합니다.

| State | Meaning |
|---|---|
| **Task Completed** | 학생이 해당 작업을 수행했는가? |
| **Revision Recorded** | 학생이 피드백에 따른 실제 수정 결과를 남겼는가? |
| **Professor Reviewed** | 교수가 공유된 수정 내용을 확인했는가? |

작업을 완료했다고 해서 피드백 반영이나 교수 확인까지 자동으로 완료되는 것은 아닙니다.

### 2. Human-in-Control AI

RMS에서 AI는 연구자의 판단을 대신하지 않습니다.

AI는 학생이 선택한 기록을 정리하고 여러 수정 방안을 탐색하는 데 도움을 주지만, 연구 방향이나 수정 방법을 최종적으로 결정하지 않습니다.

제안의 근거와 가정을 구분하며 학생은 이를 수정·채택하거나 사용하지 않을 수 있습니다.

**AI는 수정 방법을 제안하고, 학생은 실제로 수행할 방법을 선택합니다.**

### 3. Traceable Research History

연구 과정에서 중요한 것은 현재의 수정본뿐 아니라 이전에 어떤 내용을 검토받았는지 확인할 수 있는 것입니다.

RMS는 피드백과 수정본, 교수 응답을 당시 문서 버전 및 검토 차수에 연결합니다.

새로운 수정 결과가 만들어져도 이전 검토 기록을 덮어쓰지 않으며, 과거 지적이 어떻게 처리되었는지 확인할 수 있도록 설계합니다.

## Target Users

| User | Role |
|---|---|
| **Graduate Student** | 연구 기록, 피드백, 수정 작업, 일정 및 교수 검토 요청 관리 |
| **Academic Advisor** | 학생이 공유한 수정 결과와 자료를 확인하고 항목별 검토 의견 제공 |

RMS는 대학원생을 주 사용자로 설계합니다.

지도교수는 학생의 연구 관리 공간 전체를 사용하는 것이 아니라, 학생이 공유한 수정 결과를 검토하는 협업 참여자로 설정합니다.

교수 전용 대시보드나 다수 학생 관리 기능은 현재 설계 범위에 포함하지 않습니다.

- 연구 자료·피드백·기록 통합 검색
- 여러 기록 비교 및 추가 AI 정리

### Classroom Demo

학생 메모 저장 → 실제 Google API 정리·수정 방안 → 다음 미팅 준비 → v2 수정 결과 공유 → 교수 항목별 응답 → v3 재확인과 이전 이력 조회를 먼저 완성합니다. 시연용 학생·교수 계정으로 접속을 제한하고 실제 저장·파일·권한을 확인합니다. 공개 회원가입과 후속 확장 기능은 시연 필수에서 제외합니다.

상세한 동선과 배포 후 통과 조건은 [수업 시연 기준](docs/development/classroom-demo.md)을 따릅니다.

## Design Principles

**Connected Context**

연구 자료와 피드백, 작업, 수정 결과를 분리된 기록으로 관리하지 않고 원래 맥락으로 연결합니다.

**Traceability**

어떤 피드백을 참고했고, 어떤 내용을 수정했으며, 어느 버전을 검토받았는지 추적할 수 있도록 합니다.

**Human-in-Control**

AI는 선택적으로 사용하며 연구 방향과 수정 결과에 대한 최종 판단은 사용자에게 남깁니다.

**Familiar Interaction**

기존 협업 도구에서 익숙한 자료 공유, 댓글, 할 일 및 일정 관리 방식을 기반으로 논문 지도 과정에 필요한 경험을 구체화합니다.

**Privacy by Default**

학생의 개인 연구 기록과 교수에게 공유하는 자료를 구분하고, 공유 대상과 범위를 학생이 직접 선택하도록 합니다.

## Validation

RMS는 수업 시연을 위한 웹앱 구현·배포를 준비하고 있습니다. 배포 환경에서 대표 시나리오의 동작을 먼저 확인하고 핵심 경험의 사용성과 효과는 별도로 검증합니다.

주요 검증 항목은 다음과 같습니다.

- 학생이 피드백의 원문과 관련 수정본을 정확히 찾을 수 있는가?
- 여러 수정 방법을 비교하고 다음 작업을 스스로 결정할 수 있는가?
- 다음 미팅에서 보여줄 결과와 남은 질문을 구성할 수 있는가?
- 교수가 정확한 수정 위치를 확인하고 검토 결과를 남길 수 있는가?
- 이전 수정본과 교수 응답의 관계를 혼동 없이 이해할 수 있는가?
- 기존 방식과 비교하여 기록 정리 및 미팅 준비에 드는 부담이 줄어드는가?

시간 절감이나 피드백 누락 감소는 검증 목표이며, 현재 달성된 성과로 제시하지 않습니다.

문서의 로컬 연결과 필수 파일을 검사합니다. Python 3.10 이상이 필요합니다.

python3 scripts/check_repository.py

현재 검사는 저장소 구성을 확인합니다. 앱 빌드·제품 기능 테스트는 앱 초기화 후 추가합니다.
