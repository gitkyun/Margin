# 마진 IA v2 설계서

작성일 2026-11-16 · 상태: **설계안(구현 전)**. 이 폴더의 문서는 화면을 새로 짜기 위한 기준이고, 아직 코드에 반영된 것은 없습니다.

마진의 로그인 후 화면을 **상단 메뉴 4개(홈 · 미팅 · 할 일 · 글·자료) + 오른쪽 사이드 창(연구 도우미 · 할 일 · 결정·질문 · 자료)** 구조로 다시 짭니다. 지금 있는 기능은 하나도 버리지 않고 새 자리로 옮기며, 서버 저장 구조(DB 마이그레이션)는 1차 범위에서 바꾸지 않습니다.

## 2. 결정 상태 표기

문서 전체에서 아래 네 가지를 구분해 적습니다.

- **[확정]** 사용자가 대화에서 직접 정한 것. 구현 중 임의로 바꾸지 않습니다.
- **[제안]** 설계자가 정한 기본값. 사용자가 반대하지 않으면 그대로 구현합니다. 바꿔도 다른 화면이 무너지지 않게 범위를 적어 두었습니다.
- **[확인 필요]** 사용자만 정할 수 있는 것. §7에 모았습니다. 답이 없어도 구현이 멈추지 않게 "답이 없으면 이렇게 한다"를 함께 적었습니다.
- **[사실]** 코드·문서에서 읽은 현재 상태. 파일 경로를 붙였습니다. 직접 실행해 보지 않은 것은 "미실행"이라고 적습니다.

## 3. 목표

사용자가 말한 목표는 다음과 같습니다.

> 처음 쓰는 사람도 익숙하면서 편하게, 디자인적으로 예쁘게, 계속 쓰고 싶게, 다른 서비스보다 편하게, 인터랙션 재미있게.

이를 화면 규칙으로 옮기면 네 가지입니다.

1. **미팅이 중심입니다.** 논문 지도는 "미팅 → 받은 말 → 할 일 → 고친 글 → 다음 미팅"으로 돕니다. 피드백을 따로 떼어 내지 않고 그 말이 나온 미팅 기록 안에서 봅니다.
2. **기록 화면은 네 가지만 보입니다.** 원문(전사·메모), 형광펜, 요약, 할 일. 나머지는 눌렀을 때 옆 창에 열립니다.
3. **AI에게 자료를 주고 → 할 일을 뽑고 → 상의하고 → 초안을 받는 흐름**이 어느 화면에서든 한 번의 클릭으로 시작됩니다. 연구 도우미가 오른쪽에 늘 있습니다.
4. **익숙한 틀을 씁니다.** 틀은 토스증권(상단 메뉴, 둥근 본문 판, 오른쪽 창 + 좁은 아이콘 줄, 설정 창), 글 화면은 라이너·매니패스트(열린 문서 탭, 목차, 본문 안 수정 제안)를 따릅니다.

## 5. 용어

화면에 쓰는 말은 `docs/design/ux-writing.md` 용어표를 그대로 따릅니다. 설계 과정에서 쓰던 임시 이름은 아래처럼 정리합니다(왼쪽 말은 화면에 쓰지 않습니다).

| 설계 중 쓰던 말 | 화면에 쓰는 말 | 저장 이름 |
|---|---|---|
| 말씀 | **피드백** | `feedback` |
| 정해진 것 | **결정** | `decisions` |
| 물어볼 것 | **질문** | `questions` |
| 체크리스트 항목 | **할 일** | `tasks` |
| 반영 기록 | **수정 결과** | `results` |
| 교수 확인 | **검토 요청**, 교수 응답 | `reviews` 등 |
| 도우미 | **연구 도우미** (탭·창·버튼 모두) | — |
| 새 소식 | **알림** | `events` |
| 사이드 창, 패널 | 화면에는 이름을 드러내지 않음. 설정 항목 이름만 **사이드 창 위치** | `preferences.panelSide` |

새로 생기는 말은 다섯 개입니다. 구현할 때 `ux-writing.md` 용어표와 일본어 사전에 함께 넣습니다.

| 새 말 | 뜻 | 쓰는 곳 |
|---|---|---|
| **기록** | 미팅 목록의 한 줄 가운데 대면 미팅과 서면 피드백을 함께 부르는 말. 같은 목록에 있어도 검토 요청과 시간 조율은 '기록'이라 부르지 않고 이름 그대로 부름 | 미팅 목록, '기록 추가' |
| **서면 피드백** | 카톡·메일·문서 댓글처럼 글로 받은 피드백을 붙여 넣은 기록 | 기록 종류 배지 |
| **형광펜** | 원문에서 다시 볼 곳을 칠해 둔 표시. 종류 없음 | 원문 선택 메뉴 |
| **요약** | 연구 도우미가 원문을 줄여 쓴 글. 'AI 제안'과 같이 사용자가 실행해야 생김 | 기록 화면 오른쪽 |
| **연구 흐름** | 연구 단계·주요 목표·달력을 모은 화면(지금의 '일정'). 홈 카드 이름은 이미 '연구 흐름'임 | 홈 카드, `/flow` |

새 말 다섯 개 말고도, 화면에 처음 나오는 동작 이름이 있습니다. 뜻을 하나로 고정합니다.

| 동작 이름 | 뜻 | 쓰지 않는 말 |
|---|---|---|
| 녹음 시작 | 녹음을 시작함(동의 창부터) | 미팅 녹음 시작, 기록 시작 |
| 기록 남기기 | 녹음 없이 메모로 미팅 기록을 적음 | 메모로 기록 |
| 기록 완료로 바꾸기 | 녹음 없이 적은 기록을 '기록 완료'로 | — |
| 넘어온 할 일 · 가져가기 | 지난 기록의 남은 할 일 · 그것을 이번 미팅 준비에 연결함(복사 아님) | 이월 |
| 붙이기 | 연구 도우미에게 보낼 근거로 넣음 | 첨부(파일 붙이기에만 씀) |
| 지금 표시 | 녹음 중 지금 시각에 형광펜을 예약함 | 북마크 |
| 선택 · 제안 닫기 | AI 제안을 기록으로 만듦 · 기록으로 만들지 않고 치움 | 채택, 넘기기, 버리기 |

| 훑어보기 | 사이드 창 '자료'에서 글·자료를 읽기 전용으로 잠깐 봄 | 미리보기(글·자료 목록의 미리보기 열에만 씀) |
| 미팅 주기 | 다음 미팅 날짜를 미리 채우는 반복 규칙 | 정기 미팅 |

## 6. 바뀌지 않는 규칙

새 화면도 아래 규칙을 그대로 지킵니다. 출처는 저장소 루트 `AGENTS.md`, `docs/design/README.md`, `docs/design/patterns.md`, `docs/design/ui-quality.md`, `docs/design/ux-writing.md`입니다.

**제품**

1. 주 사용자는 학생입니다. 교수는 지정된 검토 요청과 시간 조율에만 들어옵니다. 교수용 학생 목록·대시보드를 만들지 않습니다.
2. 다섯 가지 상태를 합치지 않습니다: 할 일 완료 / 학생의 수정 결과 / 교수 응답(수정 내용 확인·추가 수정 필요) / 댓글 해결 / 읽음. 할 일을 모두 끝내도 피드백 상태나 교수 응답은 저절로 바뀌지 않습니다.
3. 교수에게 보낸 설명·파일·응답은 그대로 남습니다. 다시 확인받는 것은 그 항목의 새 차수입니다.
4. 연구 도우미는 **이 연구의 기록을 항상 전부 읽습니다**(D13, `AGENTS.md` 2026-11-16, #99). 기록을 고르는 화면은 두지 않습니다. 실행과 채택은 사용자가 하고, 개인 대화·미채택 AI 제안·녹음과 전사문은 읽지 않습니다(전사문은 기록 화면의 [정리하기]에서 본인 것만 보냄). 화면이 알아서 실행하지 않고, 선택하지 않은 AI 제안과 대화는 본인만 봅니다.
5. 전사 원문과 녹음 동의 기록은 고치지 않습니다. 음성을 공유해도 전사문은 공유되지 않습니다.
6. 자동으로 완전히 지우는 일은 없습니다. 지우는 동작은 보관(되돌릴 수 있음)이 기본입니다.
7. DB 마이그레이션은 추가만 합니다. AI 결과·진행률·사용량을 지어내지 않습니다.

**화면**

8. 색·간격·모서리·글자 크기는 Montage 토큰만 씁니다. hex 값, `.dark` 블록, 전역 덮어쓰기 CSS를 만들지 않습니다. 화면 CSS는 `@layer margin` 안에 둡니다.
9. 연구 도우미 입력창·답변·계정 메뉴 등 `docs/design/kokonut-map.md`에 있는 부품은 `src/components/kokonut/`의 원본을 그대로 씁니다. 구조·치수·움직임을 다시 짜지 않습니다.
10. 로그인 후 화면에 구름·유리·굴절 효과를 쓰지 않습니다. AI 전용 색·그라데이션도 없습니다.
11. 한 요소에 테두리·색 채움·그림자를 함께 쓰지 않습니다. 그림자는 본문 판, 떠 있는 면(메뉴·팝오버), 대화상자·시트 세 곳에만 씁니다.
12. 주 행동(파란 채움 버튼)은 화면 머리에 하나만 둡니다.
13. 문구는 해요체, `t("한국어 원문")` + 일본어 사전. 9~11px 글자를 쓰지 않습니다.
14. 화면을 바꾸면 360·390·768·1024·1440px, 라이트·다크, 키보드, 동작 줄이기에서 확인합니다.
