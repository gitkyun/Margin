# 01. 전체 구조

[00-README.md](00-README.md)의 결정(D1~D12)을 화면 지도, 주소, 단축키, 기능 재배치로 옮긴 문서입니다. 따로 표시하지 않은 내용은 모두 **[제안]**입니다.

- 메뉴는 네 개뿐입니다(홈 · 미팅 · 할 일 · 글·자료. 할 일은 2026-11-16 Q2 답으로 남김). 나머지 기능은 (가) 메뉴 화면 안, (나) 사이드 창, (다) 위에 뜨는 창 중 한 곳에 들어갑니다.
- 사이드 창은 어느 화면에서든 같은 내용입니다. 화면마다 내용이 바뀌는 지금의 '여백 패널' 방식은 쓰지 않습니다. 화면에 딸린 보조 정보(목차, 요약, 미리보기)는 본문 판 안의 열로 넣습니다.
- 할 일·피드백·결정·질문·수정 결과 한 건을 누르면 사이드 창 위에 **항목 상세**가 덮입니다. 어느 화면에서 눌러도 같은 모양입니다.

### 3.2 어느 화면에나 붙는 값

| 쿼리 | 뜻 | 규칙 |
|---|---|---|
| `detail=<종류>:<id>` | 항목 상세를 연다. 종류는 `task` `feedback` `decision` `question` `result` | 열려 있는 동안 주소에 남습니다. 뒤로 가기로 닫힙니다. 주소를 복사해 열면 같은 상세가 열립니다. |
| `settings=<구획>` | 설정 창을 연다. 구획은 `profile` `display` `notifications` `assistant` `usage` `shortcuts` `research` `people` `schedule` `danger` | 위와 같습니다. 연구 구획(`research` 이하 넷)은 `/r/:id/…` 주소에서만 열립니다. 연구가 없는 주소에서 받으면 `profile`을 엽니다. |
| `panel=assistant\|tasks\|log\|materials` | 사이드 창을 그 탭으로 연다. 탭 안의 보기까지 정하려면 `:`로 붙입니다: `log:question`(결정·질문 창의 질문 보기). 그 밖의 값은 탭만 엽니다. | **들어올 때만 읽고 주소에서 지웁니다.** 열림·탭·폭은 브라우저에 저장합니다([02](02-shell.md) §4.5). |
| `new=<종류>` | 만들기 창을 연다. 종류는 `record`(녹음 시작) `written` `meeting` `poll` `task` `feedback` `doc` `material` `result` `review` | 들어올 때만 읽고 지웁니다. 함께 오는 값(`feedback=`, `task=`, `version=`, `result=a,b`, `date=`)은 창의 처음 값으로 씁니다. |
| `tour=1` | 화면 안내를 다시 본다(홈에서만) | 지금과 같습니다. |

항목 상세 키는 `item`이 아니라 `detail`입니다. 검토 화면(`/reviews/:requestId`)이 이미 `item=`을 검토 항목 뜻으로 쓰고 있어, 그 화면에서 수정 결과 상세를 열 때 두 뜻이 겹치지 않게 했습니다.

`detail`과 `settings`가 함께 있으면 설정 창이 위에 뜹니다. 값이 틀리면(`detail=task:없는id`, `settings=없는값`) 조용히 무시하고 주소에서 지웁니다. 틀린 값으로 위험 구획(`danger`)이 열리는 지금의 문제(`/r/:id/settings?tab=아무값` → 보관·삭제)를 같이 없앱니다.

### 3.3 예전 주소 이동

알림(`events.href`)과 교수에게 보낸 메일, 사용자의 즐겨찾기에 예전 주소가 남아 있으므로 이동 규칙은 지우지 않고 계속 둡니다. 모두 `replace` 이동이고, 표에 없는 쿼리는 그대로 넘깁니다. 단, 예전 화면의 `tab=` 값은 표에서 쓰고 나면 넘기지 않고 지웁니다(홈·연구 흐름의 `tab=`과 뜻이 달라서). 이동 결과 주소가 다시 이 표에 걸리는 경우는 없도록 만들었고, 테스트로 "표의 모든 새 주소는 표의 예전 주소에 맞지 않는다"를 확인합니다([10](10-build-plan.md) §4 `shell.spec.ts`).

| 예전 주소 | 새 주소 |
|---|---|
| `/r/:id/writing` | `/r/:id/docs?kind=writing` |
| `/r/:id/writing/:documentId` | `/r/:id/docs/w/:documentId` |
| `/r/:id/writing?new=1` | `/r/:id/docs?new=doc` |
| `/r/:id/materials` | `/r/:id/docs?kind=material` (`folder=` 유지) |
| `/r/:id/materials/:materialId` | `/r/:id/docs/m/:materialId` |
| `/r/:id/planning` | `/r/:id/flow` (`phase=` 유지) |
| `/r/:id/planning?tab=calendar` | `/r/:id/flow?tab=calendar` |
| `/r/:id/planning?tab=schedule` | `/r/:id/meetings?type=poll` |
| `/r/:id/feedback` | `/r/:id/tasks?view=feedback` |
| `/r/:id/feedback/:feedbackId` | 그 피드백의 기록이 있으면 `/r/:id/meetings/<기록 id>?detail=feedback:<id>`, 없으면 `/r/:id?detail=feedback:<id>` |
| `/r/:id/feedback?new=1` | `/r/:id?new=feedback` |

[사실, 2026-11-19 5단계] `/feedback?new=1`도 위 표대로 옮겼습니다. `new=feedback`은 어느 화면에서든 그 자리에서 피드백 직접 추가 창을 열고(`components/feedback/FeedbackCreateHost.tsx`), 저장하면 그 피드백의 항목 상세를 엽니다. ⌘K '피드백 추가'는 지금 화면 위에서, 할 일 화면 피드백 보기의 버튼은 그 목록 위에서 엽니다. 예전 피드백 화면(`student/FeedbackPage`)은 지웠고, `/feedback`으로 시작하는 주소는 모두 위 표대로 옮겨집니다.

| `/r/:id/tasks` | 그대로(T1 할 일 화면의 주소) |
| `/r/:id/tasks/:taskId` | `/r/:id/tasks?detail=task:<id>` |
| `/r/:id/tasks?new=1&feedback=…` | `/r/:id/tasks?new=task&feedback=…` |

[사실, 2026-11-19 5단계] `/tasks/:id`(`full=1` 포함)와 `/tasks?new=1…`도 위 표대로 옮겼습니다. `new=task`는 할 일 화면의 할 일 보기에서 빠른 추가 줄을 열고, `feedback=`이 이 연구의 피드백이면 줄 아래에 "‘…’ 피드백에 이어요."를 보이고 그 피드백에 이어 만듭니다. 예전 할 일 화면(`student/TasksPage`)은 지웠습니다.

| `/r/:id/results` | `/r/:id/meetings?type=review` |
| `/r/:id/results/:resultId` | `/r/:id/meetings?type=review&detail=result:<id>` |
| `/r/:id/results?new=1&feedback=&task=&version=` | `/r/:id/meetings?type=review&new=result&…` |

[사실, 2026-11-19 5단계] `/results/:id`(`full=1` 포함)와 `/results?new=1…`은 위 표대로 옮깁니다. `new=result`는 미팅 화면만이 아니라 어느 화면에서든 그 자리에서 작성 창을 엽니다([06](06-assistant.md) §6.6). `/results` 목록도 같은 날 미팅 목록의 수정 결과 구획([04](04-meetings.md) §2.4)으로 옮겼습니다.
| `/r/:id/reviews` | `/r/:id/meetings?type=review` |
| `/r/:id/reviews?new=1` / `?result=a,b` | `/r/:id/meetings?type=review&new=review` / `…&result=a,b` |

[사실, 2026-11-19 5단계] `/reviews` 목록·`new=1`·`result=`도 위 표대로 옮겼습니다. `new=review`(`&result=`로 골라 둠)는 어느 화면에서든 그 자리에서 검토 요청 만들기 창을 엽니다(`components/reviews/ReviewCreateHost.tsx`). 예전 검토 요청 목록 화면은 지웠고, 검토 화면(`/reviews/:id`)의 뒤로 가기는 미팅 검토 보기로 갑니다.
| `/r/:id/meetings/:meetingId?tab=prepare` / `?tab=record` | `…/meetings/:meetingId?mode=prepare` / `?mode=record` |
| `/r/:id/meetings/:meetingId?tab=questions` | `…/meetings/:meetingId` (오른쪽 열 '질문' 구획을 펼친 채로) |
| `/r/:id/meetings?new=1` (`&intent=record`, `&date=`) | `/r/:id/meetings?new=meeting` (`intent=record`면 `new=record`, `date=` 유지) |
| `/r/:id/questions/:id` · `/r/:id/decisions/:id` | `/r/:id?detail=question:<id>` · `/r/:id?detail=decision:<id>` (서버 알림 주소. 지금은 라우트가 없음) |
| `/r/:id/plans/:id` | 그 수정 방법이 달린 피드백의 `/r/:id?detail=feedback:<feedbackId>` |
| `/r/:id/recordings/:id` | 그 녹음의 미팅 `/r/:id/meetings/<미팅 id>` |
| `/r/:id/folders/:id` | `/r/:id/docs?folder=<id>` |
| `/r/:id/assistant` (`?tab=…`, `?mode=…`) | `/r/:id?panel=assistant` (모드는 넘기지 않음) |
| `/r/:id/assistant?document=<id>&selection=1` | `/r/:id/docs/w/<id>?panel=assistant` (선택 문단은 넘어오지 않으므로 글 화면에서 다시 고름) |
| `/r/:id/settings` , `?tab=basic` | `/r/:id?settings=research` |
| `/r/:id/settings?tab=members` | `/r/:id?settings=people` |
| `/r/:id/settings?tab=phases` | `/r/:id/flow` |
| `/r/:id/settings?tab=lifecycle` | `/r/:id?settings=danger` |
| `/account` , `?tab=profile` | `/r?settings=profile` |
| `/account?tab=appearance\|notifications\|ai\|usage` | `/r?settings=display\|notifications\|assistant\|usage` |

이동 규칙이 쓰는 값(`tab`, `new`, `mode`, `intent`)은 넘기지 않고 지웁니다. 표에 없는 `tab` 값은 그 묶음의 첫 구획으로 갑니다(`/r/:id/settings?tab=아무값` → `?settings=research`, `/account?tab=아무값` → `?settings=profile`).

[사실, 2026-11-18 4단계 구현] 연구 도우미 화면 주소는 위 두 줄대로 옮깁니다(`lib/legacy-routes.ts`). 예전 제안 탭(`tab=overview`)은 창의 제안 보기(`&panelView=suggestions`)로 엽니다. 사이드 창은 `?panel=assistant|tasks|log`(연구 도우미는 `&panelView=suggestions|runs`)로 열리고, 연 뒤에는 주소에서 이 값을 지웁니다(닫은 뒤 새로 고쳐도 다시 열리지 않게, `lib/side-panel.ts`). 홈의 "확인할 AI 제안", ⌘K의 '연구 도우미', G A도 화면을 옮기지 않고 이 값으로 창을 엽니다.

`/feedback/:id`·`/plans/:id`·`/recordings/:id`처럼 대상을 찾아야 하는 이동은 **첫 불러오기가 끝난 뒤** 판단합니다. 대상 기록이 있고 내가 읽을 수 있으며 보관되지 않았을 때만 그 기록 화면으로, 아니면 `/r/:id?detail=…`로 보내 항목 상세의 '열 수 없음'([06](06-assistant.md) §6.7)이 뜨게 합니다(남의 '나만 보기' 미팅에 달린 공유 피드백이 깨진 기록 화면으로 가지 않게).

`/login?next=`의 허용 목록(`lib/social-login.ts`의 `safeNext`)은 지금 `/r` `/reviews` `/schedule` `/join`만 받습니다. 새 주소는 모두 `/r` 아래라 그대로 통과합니다.
