# 04. 미팅 (M1~M4)

주소 `/r/:id/meetings/:recordId?`. 이 서비스의 중심 화면입니다. 미팅 기록, 서면 피드백, 검토 요청, 시간 조율이 **한 목록**에 모이고, 기록 한 건 안에서 원문 → 형광펜 → 요약 → 할 일이 이어집니다(D3·D4·D5). 따로 표시하지 않은 내용은 **[제안]**입니다.

```
│ [기록 추가 ▾]   │ 제6차 논문 지도   기록 완료   11월 13일 14:00   [나만 보기] [⋯]      │
```

| 판 폭 단계([02](02-shell.md) §1.1) | 배치 |
|---|---|
| 아주 넓음(1024 이상) | 세 열(220 · 남는 폭 · 340). 가운데 열은 최소 400 |
| 넓음(864~1023) | 목록 열이 접혀 머리 왼쪽의 [기록 목록 ▾] 버튼이 됨(누르면 같은 목록이 팝오버로). 두 열 |
| 보통·좁음(864 미만) | 한 열. 목록 화면 → 기록 화면으로 넘어가고, 기록 머리 왼쪽에 [← 미팅] (목록으로 돌아감), 기록 화면 위에 `원문 \| 요약·할 일` 전환 |

참고: 창 1440px에서 사이드 창(312)을 열면 판은 1040px이라 세 열이 유지됩니다(220 + 480 + 340). 1280px에서 열면 880px이라 목록이 접히고, 1024px 태블릿(948)도 목록이 접힙니다.

## 2. 기록 목록(왼쪽 열)

### 2.1 위쪽

| 요소 | 동작 |
|---|---|
| [기록 추가 ▾] | 테두리 버튼(파란 채움은 기록 머리의 주 행동 하나에만 씀). §7의 다섯 가지 메뉴 |
| 찾기 칸 | 제목·메모 본문에서 찾기(`?q=`). 한글 초성 찾기는 지금 `lib/hangul-search.ts` 사용 |
| 보기 고르기 | 220px 열에 칩 네 개가 들어가지 않으므로 선택 상자 하나: `전체 ▾` → 전체 / 남은 할 일 있는 기록(`open`) / 서면 피드백(`written`) / 검토 요청(`review`) / 시간 조율(`poll`). 주소 `?type=`. 전체가 아니면 선택 상자 옆에 [×]로 끔. 안 읽은 검토 응답이 있으면 선택 상자와 '검토 요청' 항목에 점 |

### 2.2 줄

묶음과 순서는 [08](08-data.md) §4.2. 한 줄 높이 56px(제목 한 줄 + 보조 한 줄).

| 종류 | 아이콘 | 보조 줄 | 오른쪽 |
|---|---|---|---|
| 미팅 · 녹음 중 | 빨간 점 | "지금 녹음 중" | — |
| 미팅 · 준비 중 | 달력 | "11월 20일 (금) 14:00 · 준비 중" / "날짜 미정 · 준비 중" | 홈의 다음 미팅이면 작은 '다음' 표시 |
| 미팅 · 날짜 지남, 기록 없음 | 달력 | "11월 13일 · 기록 없음" | — |
| 미팅 · 기록 완료 | 마이크(녹음 있음) 또는 메모 | "11월 13일 · 48분" / "11월 13일 · 메모" | 남은 할 일 수 |
| 서면 피드백 | 종이(말풍선은 아이콘 줄의 '결정·질문'이 씀) | "11월 12일 · 카톡" | 남은 할 일 수 |
| 검토 요청 | 체크 표시 방패 | "11월 10일 · 공유 중 · 응답 2/3" / "공유 중지" | 안 읽은 응답 점 |
| 시간 조율 | 시계 | "조율 중 · 3명 중 2명 응답" | — |
| 미팅 · 취소 | 달력에 줄 | "11월 6일 · 취소" (취소한 미팅 보기를 켰을 때만) | — |

- 줄을 누르면: 미팅·서면 피드백은 오른쪽에 열리고 주소가 바뀝니다. 검토 요청은 M3(`/reviews/:requestId`), 시간 조율은 M4(`/schedule/:pollId`)로 갑니다.
- 고른 줄은 `--selected-fill`. 올리면 `--hover-fill`. 줄 메뉴(올리거나 초점이 가면 보이는 [⋯], 오른쪽 버튼도 같은 메뉴): 열기 / 새 탭에서 열기 / 기록 정보 편집 / 보관.
- 목록은 50줄씩 그리고 끝에 [더 보기]를 둡니다(찾기는 전체에서).
- 상태는 색만으로 구분하지 않고 보조 줄의 글자로 함께 알립니다.

### 2.3 아래쪽

- "취소한 미팅 보기" 스위치(켜면 `?cancelled=1`).
- "보관한 기록 n개"(있을 때만) → 누르면 목록이 보관한 기록으로 바뀌고 각 줄에 [복원].

### 2.4 `type=review`일 때

목록 맨 위에 접을 수 있는 구획 "수정 결과 n개"가 생깁니다. 구획 머리에 `요청 전 | 요청에 포함 | 보관함` 전환(기본 '요청 전', 지금 수정 결과 목록의 필터)과 찾기 칸. 펼치면 수정 결과 줄(제목 · 연결된 피드백 수)과 [검토 요청 만들기]. 줄을 누르면 항목 상세(`?detail=result:<id>`). 그 아래는 검토 요청 줄만 보이고, 보조 필터 `전체 | 공유 중 | 공유 중지`가 붙습니다(지금 검토 요청 목록의 필터).

[사실, 2026-11-19 5단계 구현] 구획은 `components/meetings/ResultsSection.tsx`, 나누기는 `lib/results-section.ts`입니다.
- '요청 전 | 요청에 포함 | 보관함'(주소 `results=`, 기본 요청 전): 검토 요청에 담긴 적이 있으면 요청에 포함입니다.
- 찾기는 구획에 따로 두지 않고 목록 위 '기록에서 찾기'(`q`)가 수정 결과의 제목·내용도 찾습니다.
- 칸 폭이 같아(220px 열에서 약 70px) 보기 이름 옆에 수를 붙이지 않고 구획 머리에 합계(보관 제외)를 둡니다.
- 보관함 줄에는 [복원]이 있습니다.
- 구획 아래 버튼은 [수정 결과 작성] — 그 자리의 창 `new=result` — 과 [검토 요청 만들기] — 아직 예전 검토 요청 화면의 창 — 입니다.
- 검토 요청 줄의 보조 필터는 주소 `share=`이고, '전체'에는 초안도 들어갑니다.
- 예전 `/results` 목록 주소는 이 보기로 옮겼고 예전 수정 결과 화면(`student/ResultsPage`)은 지웠습니다.

## 3. 기록 머리

```
[기록 목록 ▾]  제6차 논문 지도   [기록 완료]   11월 13일 (금) 14:00            [나만 보기 ▾]  [⋯]
```

머리의 주 버튼(파란 채움)은 준비 모드의 [녹음 시작] 하나뿐입니다. 기록됨 모드의 [정리하기]는 머리에 두지 않고 오른쪽 열 요약 구획(§5.4 ①)에만 둡니다(같은 버튼을 두 곳에 두지 않음).

| 요소 | 내용 |
|---|---|
| 제목 | `heading2`. 누르면 그 자리에서 고칠 수 있음(Enter 저장, Esc 취소, 200자 — 서버 한도) |
| 상태 배지 | 준비 중 / 기록 중 / 기록 완료 / 취소(용어표 그대로). 서면 피드백은 '서면 피드백 · 카톡' |
| 날짜·시각 | 누르면 날짜·시각 고르는 팝오버. 시각 표기는 `lib/time-format.ts` |
| 공개 범위 | `나만 보기` / `공동연구자와 공유`(지금 `VisibilityField`). 공동연구자가 없으면 버튼을 숨김 |
| 모드별 버튼 | 준비: [녹음 시작] (주) [기록 남기기] (테두리, 녹음 없이 `mode=record`) · 기록 남기는 중(녹음 없음, §6.0): [녹음 시작] (테두리) [기록 완료로 바꾸기] (주) · 기록됨: 없음 · 녹음: 없음(조작은 녹음 줄) |
| ⋯ | 기록 정보 편집(이름·날짜·시각·상태 직접 바꾸기) / 홈의 다음 미팅으로 지정 / 준비 내용 보기 ↔ 기록 보기 / 녹음 관리 / TXT로 내보내기 / 미팅 취소 ↔ 취소 되돌리기 / 보관 |

'미팅 취소'는 확인 창("미팅을 취소할까요? 기록과 준비한 내용은 그대로 남아요." [닫기] [미팅 취소])을 거칩니다. '보관'은 바로 실행하고 6초 되돌리기 알림을 띄웁니다.

'녹음 관리'는 작은 창(폭 480)입니다: 녹음마다 한 줄(시작 시각 · 길이 · [재생]) · '공동연구자와 음성 공유' 스위치(지금 기능. 아래에 "음성을 공유해도 전사문은 공유되지 않아요." 한 줄) · 지금 있는 녹음 삭제·내려받기 동작은 그대로. 녹음이 없으면 메뉴 항목을 보이지 않습니다.

예전 주소의 미팅 탭 값은 이렇게 옮깁니다([01](01-structure.md) §3.3): `?tab=prepare` → `?mode=prepare`, `?tab=record` → `?mode=record`, `?tab=questions` → 쿼리 없음(오른쪽 열 '질문' 구획을 펼친 채로), `/meetings?new=1` → `/meetings?new=meeting`.

## 4. 준비 모드

미팅 전에 여는 화면입니다. 가운데 열은 **가져갈 것**, 오른쪽 열은 **지난 기록에서 넘어온 것**입니다. 모든 변경은 바로 저장됩니다(글 칸은 0.8초 뒤, 목록 조작은 즉시). 저장 버튼이 없습니다.

### 4.1 가운데 열

| 구획 | 내용 | 조작 |
|---|---|---|
| 보여 줄 결과 | 이번 미팅에서 보여 주려는 것 한두 문장(`goal`). 3줄 글 칸 | 비워 둬도 됨. 지금은 준비 창을 저장할 때 필수였지만, 바로 저장 방식이라 필수를 뺌 |
| 가져갈 할 일 | 이 미팅에 연결한 할 일(`taskIds` 순서). 줄: 체크 · 제목 · 기한 | 끌어서 순서 바꾸기, Alt+↑/↓, 줄 메뉴의 '위로'·'아래로', 줄의 [빼기] (연결만 끊음. 할 일은 남음) · [+ 할 일 추가] (새 할 일을 만들어 바로 연결) · [남은 할 일에서 고르기] (찾기 되는 고르기 창) |
| 보여 줄 글·자료 | 연결한 자료 버전(`versionIds`)과 글(`documentIds`). 줄: 종류 · 제목 · 버전 | [글·자료에서 고르기] · [PDF 바로 올리기] (지금 `QuickPdfUpload`). 줄을 누르면 W2/W3 |
| 물어볼 질문 | 연결한 질문(`questionIds` 순서) | 한 줄 입력으로 추가, 끌어서 순서(Alt+↑/↓, 줄 메뉴 '위로'·'아래로'), [열린 질문에서 고르기] |
| 연구 도우미 | 한 줄 버튼 [연구 도우미와 준비하기] | 사이드 창을 열고 이 기록을 근거로 붙인 뒤 권하는 질문 세 개를 보여 줌([06](06-assistant.md) §2.6). 보내기는 사용자가 누름 |

### 4.2 오른쪽 열 "지난 기록에서"

| 구획 | 내용 |
|---|---|
| 넘어온 할 일 n개 | [08](08-data.md) §4.5의 목록. 줄마다 [가져가기], 위에 [모두 가져가기]. 가져간 줄은 가운데 열로 옮겨 가며 사라짐(200ms). 출처 기록 이름을 보조 줄에 |
| 열린 질문 n개 | 지난 기록의 해결 안 된 질문. [가져가기] |
| 직전 기록 | 바로 앞 기록의 제목·날짜·요약 첫 세 줄 + [기록 열기] |

넘어온 것이 하나도 없으면 "지난 기록에서 넘어온 것이 없어요." 한 줄만 둡니다.

### 4.3 날짜가 지난 준비 중 미팅

머리 아래 띠: "미팅 날짜가 지났어요." [기록 남기기] (= `mode=record`로 전환) [날짜 바꾸기].

## 5. 기록됨 모드

### 5.1 가운데 열: 원문

**재생 줄**(녹음이 있을 때, 열 위에 붙어 있음): 재생/멈춤 · 지금 시각 · 끌 수 있는 줄 · 전체 길이 · 속도(1× 1.25× 1.5× 2×) · 녹음이 둘 이상이면 [녹음 2개 ▾]. 초점이 재생 줄에 있을 때 Space 재생/멈춤, ←/→ 5초 이동.

**보기 전환** `전사 | 메모`: 둘 다 있을 때만 보입니다. 주소 `?src=`. 전사가 있으면 전사가 기본.

| 보기 | 내용 | 고치기 |
|---|---|---|
| 전사 | 문장마다 왼쪽에 시각(누르면 그 자리부터 재생). 재생 중인 문장은 옅게 강조하고 따라 내려감(사용자가 직접 스크롤하면 따라가기를 멈추고 "지금 위치로" 알약을 띄움) | 읽기가 기본. [편집]을 누르면 지금의 전사 편집기(충돌 처리 포함). ⋯에 '인식 원문 보기'(고치기 전 원문, 읽기 전용) · 'TXT로 내보내기' · '메모에 붙이기' |
| 메모 | 미팅 중 적은 글 또는 붙여 넣은 서면 피드백 | 미팅 기록은 늘 편집 가능(0.8초 자동 저장, 충돌 비교, 초안 되살리기 — 지금과 같음). 메모 칸 오른쪽 아래에 저장 상태: 저장 중 / 저장됨 · 14:02 / 저장 실패 [다시 시도] (녹음 화면·§6.0의 메모 칸도 같음). **서면 피드백은 읽기가 기본**이고 [편집]을 눌러야 고칠 수 있음(받은 글을 실수로 바꾸지 않게) |

글줄: `body2` 읽기용 줄 높이([02](02-shell.md) §2), 최대 폭 720px.

**키보드로 읽기**: 전사와 읽기 상태의 메모(서면 피드백)는 커서가 없으므로 문장(전사)·문단(메모) 단위로 초점을 받습니다. ↑/↓ 이동, Shift+↑/↓로 범위를 넓히고, Enter로 그 범위에 §5.2 선택 메뉴를 엽니다. 문장 안의 일부만 고르는 것은 마우스·터치로 합니다.

**형광펜만**(`?marks=1`): 표시가 있는 문장과 앞뒤 한 문장만 남기고 나머지를 접습니다. 접힌 자리는 "… 12:31~18:02 접힘"으로 보이고 누르면 그 부분만 펼쳐집니다. 표시가 하나도 없으면 스위치를 비활성으로 두고 이유를 보여 줍니다("형광펜이나 피드백을 표시한 곳이 없어요.").

전사는 녹음한 본인만 볼 수 있습니다. 공유된 기록을 공동연구자가 열면 전사 자리에 "전사문은 녹음한 사람만 볼 수 있어요."가 보이고, 음성 공유가 켜져 있으면 재생 줄은 동작합니다.

### 5.2 글자를 골랐을 때

글자를 끌어 고르면 고른 곳 위에 메뉴가 뜹니다. 키보드로는 §5.1 '키보드로 읽기'로 범위를 고르고 Enter, 편집 중인 메모에서는 Shift+화살표로 고른 뒤 메뉴가 뜨면 Tab으로 들어갑니다.

| 버튼 | 하는 일 | 저장 |
|---|---|---|
| 형광펜 | 형광펜 색(`--mark-fill`, [02](02-shell.md) §2)을 칠함. 다시 고르고 누르면 지움. 단축키는 읽기 상태의 원문에서 `H`(수식 키 없음. 편집 중인 메모에서는 단축키 없이 메뉴로) | `transcriptMarks` / `memoMarks`. 누르는 즉시 칠해짐 |
| 피드백 추가 | 고른 글로 피드백을 만듦 | `feedback`: 제목 = 고른 글 앞 40자, 내용 = 고른 글 전체, 원문 위치(메모와 전사에서 저장 키가 다름, [08](08-data.md) §3.3), 상태 '시작 전' |
| 결정 추가 | 결정을 만듦 | `decisions`: 내용 = 고른 글 |
| 질문 추가 | 질문을 만듦 | `questions`: 내용 = 고른 글, 열림 |
| 할 일 추가 | 할 일을 만듦 | `tasks`: 제목 = 고른 글 앞 80자, `sourceRecordId` = 이 기록, 원문 위치 |
| 연구 도우미에게 묻기 | 사이드 창을 열고 고른 글을 근거로 붙임 | 저장 없음 |

- 피드백·결정·질문·할 일은 **창을 띄우지 않고 바로 만듭니다.** 오른쪽 열에 새 줄이 생기고 제목이 고칠 수 있는 상태로 초점을 받습니다. 아래에 "피드백을 만들었어요. [보기] [되돌리기]"(6초). 되돌리면 보관 처리합니다. 오른쪽 열이 보이지 않는 한 열 배치(보통·좁음)에서는 초점을 옮기지 않고 알림만 띄우며, [보기]가 `요약·할 일` 전환으로 가서 그 줄을 짚습니다.
- **휴대폰(767px 이하)·터치**: 떠 있는 메뉴 대신 화면 아래(녹음 줄·아래 탭 줄 위)에 고정 줄 `[형광펜] [피드백 추가] [할 일 추가] [더 보기 ▾]`을 띄웁니다(더 보기: 결정 추가 · 질문 추가 · 연구 도우미에게 묻기). 운영체제의 기본 선택 메뉴와 겹치지 않게 고른 곳 위에는 아무것도 띄우지 않습니다. 줄 높이 48, 버튼 높이 44.
- **공개 범위**: 원문에서 만든 피드백·결정·질문·할 일은 서버 기본값(`shared`)을 쓰지 않고 공개 범위를 직접 정해 저장합니다. 메모에서 만든 것은 **그 기록의 공개 범위를 따르고**, 전사에서 만든 것은 **늘 '나만 보기'(`private`)**로 만듭니다(전사문은 녹음한 사람만 보는 규칙 — 고른 글이 피드백 내용·알림 제목·교수에게 보이는 발췌로 퍼지지 않게). 전사에서 만든 항목을 공유로 바꾸려 하면 "전사문 일부가 공동연구자에게 보여요." 확인을 거칩니다. 공개 범위는 작성자만 바꿀 수 있습니다(서버 규칙).
- 고른 글이 2자 미만이거나 2,000자를 넘으면 형광펜만 켜지고 나머지는 비활성입니다(이유: "2자 이상 2,000자 이하로 골라 주세요.").
- 전사 편집 중·메모 저장 충돌 중에는 메뉴를 띄우지 않습니다.

### 5.3 원문 위의 표시

| 표시 | 모양 |
|---|---|
| 형광펜 | 글자 뒤 `--mark-fill` 바탕(정의는 [02](02-shell.md) §2. Montage에 노랑 원자 색이 없어 `lime` 계열 + 투명도). `<mark>`로 그림 |
| 피드백·결정·질문·할 일로 만든 곳 | 글자 아래 2px 밑줄(`--brand`) + 문장 끝에 번호 동그라미(①②…). 종류는 색이 아니라 오른쪽 열의 아이콘과 이름으로 구분 |

- 밑줄이나 번호를 누르면 그 항목의 상세가 열리고 오른쪽 열의 해당 줄을 짚습니다(움직임은 [02](02-shell.md) §10 '짚기'). 오른쪽 열의 줄에 올리거나 초점이 가면 원문의 해당 곳에 `--selected-fill`이 깔립니다(양쪽이 서로를 가리킴).
- 위치를 찾지 못한 항목([08](08-data.md) §4.6)은 원문에 표시가 없고 오른쪽 열에만 보입니다.
- 항목이 딸리지 않은 형광펜을 누르면 그 자리에 작은 메뉴 [형광펜 지우기]가 뜹니다. 같은 범위를 다시 골라야만 지울 수 있으면 찾기 어렵기 때문입니다(2026-11-17 검토). 범위를 다시 골라 [형광펜]을 누르는 방법(§5.2)도 그대로 됩니다.

### 5.4 오른쪽 열

위에서 아래로 다섯 구획입니다. 구획 머리를 누르면 접힙니다(접힘 상태는 이 브라우저에 기억).

**① 요약**

| 상태 | 보이는 것 |
|---|---|
| 요약 없음, 제안도 없음 | "요약이 아직 없어요." + [정리하기] + "원문을 연구 도우미에게 보내 요약과 할 일 제안을 받아요." |
| 메모는 없고 내 전사문만 있음(2a, 전사문을 보내기 전 단계) | [정리하기] 비활성 + "지금은 메모만 정리할 수 있어요. 전사문을 메모에 붙이면 정리할 수 있어요." + [메모에 붙이기] (지금 있는 기능. 공유 기록이면 "전사문이 공동연구자에게 보여요." 확인을 먼저). 2b가 들어가면 이 줄은 없어짐 |
| [정리하기]를 누름 | 고르는 단계 없이 바로 실행합니다("기록을 고르는 화면은 두지 않는다", `AGENTS.md`). 보내는 것: 이 기록의 메모 + **본인이 녹음한 전사문**(있으면). 버튼 아래에 늘 한 줄 "이 기록의 메모와 내 전사문으로 정리해요."(남의 녹음만 있으면 "이 기록의 메모로 정리해요.") · 버튼 옆 [⋯] › '형광펜 친 부분만 정리' · 모델·답변 깊이는 계정 기본값 · 예상 크레딧은 보여 주지 않음(지어내지 않음). 전사문을 보내는 것은 서버 변경이 필요한 2b 단계부터이고, 그 전에는 메모만 보냄 |
| 실행 중 | Kokonut `ai-tool-calls` 한 줄(연구 도우미와 같은 대기 표시. `ai-loading`은 쓰지 않음 — `kokonut-map.md`). 실제 지난 시간 표시, [멈추기]. 화면을 떠나도 계속됨 |
| 결과 도착 | 요약 제안(글) + [요약 저장] [제안 닫기]. 아래 ②에 AI 제안 줄이 생김 |
| 요약 저장됨 | 요약 글 · "연구 도우미가 쓴 요약 · 11월 16일" · [편집] [다시 정리하기] (테두리). 요약이 6줄을 넘으면 6줄에서 접고 [더 보기] (아래 구획이 밀려나지 않게) |
| 요약 뒤 원문이 바뀜 | 요약 아래 "원문이 바뀌었어요. 요약은 바뀌기 전 내용 기준이에요." |
| 공유 기록에서 [요약 저장] | 확인 한 줄: "공동연구자도 이 요약을 볼 수 있어요. 전사문에만 있던 내용이 담길 수 있어요." [취소] [저장] |

요약은 사람이 고칠 수 있습니다([편집] → 글 칸 → 저장하면 `editedAt`). 구획 머리 ⋯ › '요약 지우기'(6초 되돌리기, 원문은 그대로). 요약은 원문이 아니므로 항상 "연구 도우미가 쓴 요약" 표시를 달고, 원문 열과 섞이지 않습니다.

**② 피드백·할 일** (머리에 "남은 3 / 전체 7")

- 피드백마다 한 묶음: 번호 · 제목 · 상태(시작 전 / 진행 중 / 수정 결과 있음 / 보류 / 고치지 않음) · 교수 응답이 있으면 테두리 배지(수정 내용 확인 / 추가 수정 필요). 그 아래 들여 쓴 할 일 줄(체크 · 제목 · 기한).
- 피드백에 딸리지 않은 할 일은 맨 아래 "그 밖의 할 일".
- 피드백 줄에 올리거나 초점이 가면 [+ 할 일] (그 피드백에 딸린 할 일을 한 줄 입력으로 추가). 터치 기기에서는 줄의 [⋯] 안에 있음([02](02-shell.md) §9).
- 줄을 누르면 항목 상세. 체크는 그 자리에서.
- **AI 제안 줄**(정리하기 결과, 아직 고르지 않은 것): 점선 테두리 · 'AI 제안' 표시 · 제목 · 근거 문장 한 줄 · [선택] [제안 닫기]. 위에 [모두 선택]. 선택하면 실선 줄로 바뀌며 저장되고, 닫으면 사라집니다(본인만 보던 제안이라 다른 사람에게는 처음부터 보이지 않음).
- 맨 아래 [+ 피드백 추가] [+ 할 일 추가] (한 줄 입력).

**③ 결정 n** · **④ 질문 n**

- 결정 줄: 내용 · 이유가 있으면 보조 줄 · 이전 결정을 바꾼 것이면 "이전 결정 바꿈". [+ 결정 추가].
- 질문 줄: 동그라미(누르면 해결, 다시 누르면 다시 열림) · 내용. 줄 메뉴 '다음 미팅에 가져가기'. [+ 질문 추가].
- 세 건 이하면 펼친 채로, 넘으면 접힌 채로 시작합니다.

**⑤ 준비한 것** (접힌 채로 시작)

보여 줄 결과 한 줄, 가져간 할 일 n개, 보여 준 글·자료 n개, 물어본 질문 n개. [준비 내용 보기] (= `mode=prepare`).

### 5.5 서면 피드백 기록

같은 화면에서 재생 줄과 '전사' 보기, '준비한 것' 구획이 없습니다. 머리에 "서면 피드백 · 카톡 · 11월 12일 받음". 나머지(형광펜, 정리하기, 피드백·할 일, 결정, 질문)는 같습니다.

## 6. 녹음 모드

### 6.0 녹음 없이 기록 남기기 (`mode=record`, 녹음 안 함)

준비 모드의 [기록 남기기], 홈의 '지난 미팅 기록 남기기', 날짜가 지난 미팅 띠(§4.3)가 여는 화면입니다.

- 가운데 열 전체가 메모 칸입니다(0.8초 자동 저장). 맨 위에 테두리 버튼 [녹음 시작] (누르면 §6.1로, 메모는 그대로 아래 칸으로 감).
- 오른쪽 열은 '준비한 것'(§6.2와 같음). 가져간 할 일·질문을 체크할 수 있습니다.
- 미팅 상태는 '준비 중' 그대로입니다('기록 중'은 녹음 중이라는 뜻이라 메모로는 바꾸지 않음, [08](08-data.md) §7). 목록 줄 보조 줄은 "메모 적는 중"입니다.
- 머리의 주 버튼 [기록 완료로 바꾸기]를 누르면 상태가 '기록 완료'가 되고 기록됨 모드로 바뀌며, 요약 구획이 [정리하기]를 권합니다. 메모가 비어 있으면 비활성("메모를 적으면 기록 완료로 바꿀 수 있어요."). 미팅 날짜 전이면 확인을 한 번 거칩니다.
- 이 화면을 그냥 떠나도 메모는 저장되어 있고, 다음에 열면 메모가 있는 준비 중 미팅이므로 이 화면으로 열립니다([08](08-data.md) §4.3).
- 기록 완료·취소한 미팅에는 이 화면이 열리지 않습니다(`mode=record`를 무시하고 기록됨으로).

화면의 행동 이름은 두 가지로만 씁니다: 녹음하는 것은 **녹음 시작**, 녹음 없이 메모로 남기는 것은 **기록 남기기**.

### 6.1 시작

1. [녹음 시작] → 지금의 녹음 동의 창(참석자 동의 확인). 동의하지 않으면 시작하지 않습니다.
2. 브라우저 마이크 권한. 거부하면 "마이크를 쓸 수 없어요. 브라우저 주소창의 자물쇠에서 마이크를 허용해 주세요." + [기록 남기기] (§6.0).
3. 시작되면 화면 아래에 녹음 줄이 생깁니다. 효과음은 설정이 켜져 있을 때만.

```
│ ● 12:31  ▁▂▃▂▁   [지금 표시]  [일시정지]  [끝내기]              제7차 논문 지도 │
```

- 가운데 열 위: 실시간 전사. 확정된 문장은 `--text`, 아직 인식 중인 말도 `--text`로 쓰고 끝에 '인식 중' 배지를 붙입니다(색만으로 구분하지 않고, 읽어야 하는 글을 흐린 색으로 쓰지 않음). 새 문장이 오면 아래로 따라 내려가고, 사용자가 위로 올리면 멈춘 뒤 [지금 위치로].
- 가운데 열 아래: 메모 칸(기본 30%). 경계를 끌거나 [넓히기]·[줄이기] 버튼으로 높이를 바꿉니다. 녹음과 상관없이 자동 저장.
- 오른쪽 열: 준비한 것. 가져온 할 일과 질문을 미팅 중에 체크할 수 있습니다.
- 녹음 줄의 **[지금 표시]**: 누른 시각을 기억해 두었다가 저장한 뒤 그 시각의 문장에 형광펜을 칠합니다. 누르면 줄에 "표시 3개"가 굴러서 올라갑니다. 단축키 ⌘/Ctrl+Shift+Enter는 **메모 칸 안에서도 동작하는 유일한 예외**입니다(녹음 중에는 대개 메모 칸에 초점이 있으므로). 브라우저 단축키와 겹치지 않는지 0단계에서 확인합니다([10](10-build-plan.md) §7 V13).
- 실시간 전사를 지원하지 않는 브라우저: 전사 자리에 "이 브라우저는 실시간 전사를 지원하지 않아요. 녹음은 그대로 저장돼요." 메모 칸이 열 전체를 씁니다.
- 다른 화면으로 가도 녹음은 이어지고 녹음 줄이 따라옵니다.

### 6.3 끝내기

[끝내기] → 지금의 확인 단계(전사 확인·고치기, [저장] [버리기] [TXT로 내보내기]). 저장하면 음성과 전사가 올라가고(실패하면 [다시 시도], 화면을 떠나지 말라는 안내), 미팅 상태가 '기록 완료'가 되고 기록됨 모드로 바뀝니다. 오른쪽 열 요약 구획이 [정리하기]를 권합니다. **한 열 배치(보통·좁음)에서는 저장 직후 `요약·할 일` 쪽으로 엽니다**([정리하기]가 `원문` 뒤에 숨지 않게, 2026-11-17 검토). §6.0의 [기록 완료로 바꾸기]와 §7.2의 서면 피드백 저장 직후도 같습니다. 2시간이 되면 저절로 멈추고 같은 확인 단계로 갑니다. [버리기]는 확인 창("녹음과 전사를 버릴까요? 되돌릴 수 없어요." [취소] [녹음 버리기])을 거칩니다.

## 7. 기록 추가 (M2)

[기록 추가 ▾], 상단 '+', ⌘K에서 같은 창이 열립니다.

### 7.1 녹음 시작

- 오늘 날짜의 준비 중 미팅이 하나면 바로 그 기록으로 가서 동의 창을 띄웁니다.
- 둘 이상이거나 없으면 작은 창: "어느 미팅을 녹음할까요?" — 오늘·가장 가까운 예정 미팅 목록 + "새 미팅으로 녹음"(이름 칸, 기본값 "11월 16일 미팅"). 고르면 그 기록으로 가서 동의 창.
- 이미 녹음 중이면 메뉴 항목이 "녹음 중인 기록으로 가기"로 바뀝니다.

### 7.2 서면 피드백 붙여넣기 (창 폭 640)

| 칸 | 규칙 |
|---|---|
| 제목 | 필수, 200자(서버 한도). 기본값 "11월 12일 서면 피드백"(받은 날을 바꾸면 따라 바뀜. 사용자가 고친 뒤에는 따라 바뀌지 않음) |
| 받은 날 | 기본 오늘 |
| 어디서 받았나요 | 카톡 / 메일 / 문서 댓글 / 메모 / 기타. 기본 카톡 |
| 내용 | 필수. 붙여넣기. 아래에 "1,204 / 50,000자". 넘으면 저장을 막고 "50,000자까지 넣을 수 있어요. 나눠서 넣어 주세요." |
| 공개 범위 | 나만 보기(기본) / 공동연구자와 공유. 공동연구자가 없으면 숨김 |

- 그림을 붙여 넣으면 "사진은 아직 넣을 수 없어요. 글자만 붙여 넣어 주세요."(그림은 버리고 글자는 넣음)
- [취소] [저장]. 저장하면 그 기록이 기록됨 모드로 열립니다. 쓰던 내용이 있는데 닫으려 하면 "작성을 닫을까요?" [계속 작성] [버리고 닫기].
- 저장 실패: 창을 닫지 않고 "저장하지 못했어요. 입력한 내용은 그대로 있어요." + 다시 시도.

### 7.3 파일에서 가져오기

TXT·MD 파일을 고르거나 미팅 화면에 끌어 놓으면 7.2 창이 열리고 내용 칸에 파일 글자가, '어디서 받았나요'에 '파일'이 채워집니다.

| 경우 | 문구 |
|---|---|
| 글자를 읽지 못함 | "파일을 읽지 못했어요. UTF-8로 저장한 TXT·MD 파일인지 확인해 주세요." |
| 50,000자 초과 | 앞 50,000자만 넣지 않고 막음: "파일이 50,000자를 넘어요. 나눠서 넣어 주세요." |
| PDF | "PDF는 글·자료에 올린 뒤 연구 도우미에게 읽게 할 수 있어요." + [자료로 올리기] |
| 그 밖의 형식 | "TXT, MD 파일만 가져올 수 있어요." |

### 7.4 다음 미팅 잡기 (창 폭 480)

- 이름: 기본값은 지금 규칙("지도 미팅"). 200자(서버 한도).
- 방식 `날짜 정하기 | 시간 조율`.
  - 날짜 정하기: 날짜(미팅 주기가 있으면 다음 차례가 채워짐. 달력에서 날짜를 눌러 들어왔으면 그 날짜) · 시각 · "날짜는 나중에 정할게요" 체크(날짜 미정 미팅). [만들기] → 그 기록의 준비 모드.
  - 시간 조율: 지금의 시간 조율 만들기 양식(제목, 참석자 이메일 20명까지, 후보 시간 12개까지). [조율 시작] → M4.
- 지난 날짜를 고르면 막지 않고 "지난 날짜예요. 지난 미팅을 기록하려면 그대로 만들어 주세요."

### 7.5 교수님께 검토 요청

지금의 두 단계 창을 그대로 씁니다(제목 · 검토할 교수 · 수정 결과 고르기 → 교수님께 보일 내용 미리보기 → 검토 링크 만들기). 검증·문구·미가입 교수 안내·직접 입력한 이메일의 지도교수 자동 등록도 그대로입니다. 고를 수정 결과가 하나도 없으면 1단계에 "검토받을 수정 결과가 아직 없어요." + [수정 결과 추가] (수정 결과 대화상자).

링크를 만든 뒤에는 M3로 가고, "검토 링크를 만들었어요. 링크를 복사해서 교수님께 직접 전달해 주세요."(만든 것과 보낸 것은 다름).

## 8. 검토 요청 한 건 (M3)

`/reviews/:requestId`. 지금의 검토 상세 화면(항목 | 수정 내용·파일 | 교수 응답·댓글 세 열)을 **그대로** 본문 판에 넣습니다. 바뀌는 것은 네 가지뿐입니다.

| 바뀌는 것 | 내용 |
|---|---|
| 뒤로 | "← 미팅"(`/r/:id/meetings?type=review`) |
| 메뉴 켜짐 | 상단 '미팅' |
| '수정 결과에서 고치기' | 수정 결과 화면 대신 항목 상세(`?detail=result:<id>`)를 엶 |
| 교수 응답에서 할 일 추가 | 학생 쪽에서 볼 때 교수 응답·댓글 옆에 [할 일 추가]. 제목 = 댓글 앞 80자, 그 수정 결과에 연결된 피드백에 딸림([06](06-assistant.md) §6.2와 같은 동작). 교수 쪽 화면에는 없음 |

기록 목록 열은 보이지 않습니다(이 화면이 세 열을 다 씀). 사이드 창은 그대로 쓸 수 있습니다. 교수가 같은 주소를 열면 틀 없이 지금의 단독 화면이 뜹니다([07](07-other-screens.md) §5).

## 9. 시간 조율 한 건 (M4)

`/schedule/:pollId`. 지금 화면 그대로. "← 미팅"은 `/r/:id/meetings?type=poll`(목록의 보기 고르기가 '시간 조율'로 켜짐, [×]로 끔). 확정하면 미팅이 만들어지고(지금 동작) [확정한 미팅 열기]가 그 기록의 준비 모드로 갑니다. 가능한 시간을 고르다가 저장하지 않고 떠나려 하면 이동 확인을 띄웁니다(지금은 없는 보호를 추가).

## 10. 연구 도우미와의 연결

| 자리 | 동작 |
|---|---|
| 기록을 열어 둔 채 사이드 창의 연구 도우미를 엶 | 입력창 위에 **실선 칩 "지금 보는 기록 · 제6차 논문 지도 ×"**가 저절로 놓여 이 기록을 먼저·빠짐없이 읽음(고르는 단계 없음, [06](06-assistant.md) §2.2). 전사문은 이 칩으로 보내지 않음. ×로 빼면 그 대화에서는 다시 놓이지 않음 |
