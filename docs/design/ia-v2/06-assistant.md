# 06. 사이드 창 (P1~P5)과 할 일 화면(T1)

어느 화면에서든 같은 내용으로 열리는 오른쪽(또는 왼쪽) 창입니다. 탭 넷(연구 도우미 · 할 일 · 결정·질문 · 자료)과 그 위에 덮이는 항목 상세로 이루어집니다. 할 일은 메뉴의 **할 일 화면(T1)**이 전체 기능을 갖고, 사이드 창의 할 일 탭(P2)은 다른 화면을 보면서 체크하는 간단한 보기입니다(§3, 2026-11-16 Q2 답). 틀·폭·열고 닫기는 [02](02-shell.md) §4에 있습니다. 따로 표시하지 않은 내용은 **[제안]**입니다.

## 1. 원칙

1. **연구 도우미는 이 연구의 기록을 항상 전부 읽고 답하지만, 스스로 실행하지 않습니다**([00](00-README.md) D13, `AGENTS.md`, #99). 서버가 요청한 사람의 권한으로 이 연구의 기록(미팅·피드백·할 일·질문·결정·글·단계·주요 목표·자료·첨부 파일)을 한 번에 48,000자까지 읽습니다(기록 한 건은 미팅 4,000·피드백 2,000·글 8,000·첨부 6,000·그 밖 800자까지, 넘으면 오래된 것부터 빠짐). **기록을 고르는 화면은 두지 않습니다.** 사용자가 붙이는 것은 파일뿐이고, 붙인 파일과 화면에서 넘긴 대상(§2.2)은 먼저·전부 읽습니다. 개인 대화·미채택 AI 제안·녹음과 전사문은 읽지 않습니다(전사문은 기록 화면의 [정리하기]에서 본인 것만 보냄, [04](04-meetings.md) §5.4). 보내기는 사용자가 누릅니다. 읽는 범위의 정본은 서버 코드(`ai-assist/workspace.ts`)와 `docs/product/ai-guidelines.md`입니다.
2. **부품은 Kokonut 원본이고, 배치는 지금 연구 도우미 화면(2026-11-16 사용자 확정)과 같습니다.** `docs/design/kokonut-map.md`에서 '적용'인 부품만 씁니다: 입력창(`ai-prompt`), 근거·요청 종류가 있을 때의 검색 입력창(`ai-input-search`), 대기 질문(`ai-message-queue`), 첨부(`ai-attachment`), 음성(`ai-voice`, 입력창 **왼쪽**), 모델·깊이(이전의 두 칩 구성 — 사용자가 정한 예외), 생각 단계·첫 답 대기(`ai-tool-calls` 한 줄), 인용(`ai-citations`). 입력창 위에는 추천 모델 '시도하기', 아래에는 실제 잔액·이번 요청 사용량·사용 내역 줄을 둡니다. **쓰지 않는 것**: `ai-loading`(대기는 `ai-tool-calls`로 통일), `ai-handoff`('교수님 검토로 넘기기' 제거), 입력창 안의 `ai-context-meter` 고리(아래 사용량 줄로 대신), 폴더 버튼. 구조·치수·움직임을 다시 짜지 않습니다.
3. **좁은 폭에서 원본이 깨지면 창을 넓힙니다.** 312px(안쪽 280px)에서 입력창 도구 줄이 넘치는지는 2026-11-17에 쟀습니다([10](10-build-plan.md) §7 V7): 가로 넘침은 없고 도구 줄이 3줄로 접혀 입력창 높이가 180px에서 252px이 됩니다(360px 창은 2줄 216px, 440px 창도 2줄). 넘치지 않으므로 기본 폭 312를 유지합니다. 기존 화면에서 입력창 묶음 폭만 줄여 잰 값이라 4단계에서 사이드 창 안에 넣은 뒤 다시 확인합니다. 넘치면 부품을 고치지 않고 사이드 창 기본 폭 전체를 360px로 올립니다(탭별 폭은 두지 않음, [02](02-shell.md) §4.5). 지금 화면의 "추천 질문 묶음에 맞춘 가변 폭(최대 760px)"은 본문 전체를 쓰던 때의 규칙이라 사이드 창에서는 창 폭을 따릅니다.
4. AI 없이도 모든 일이 됩니다. 할 일·결정·질문·자료 창과 항목 상세는 AI와 무관하게 동작합니다.

## 2. P1 연구 도우미

### 2.1 배치

```
┌ 연구 도우미 ──────────── [새 대화] [대화 목록 ▾] [×] ┐
│ 대화 | 제안 3 | 실행 내역                            │
├────────────────────────────────────────────────────┤
│                              어제 미팅에서 뭘 해야 해? │ ← 내 질문
│ ▸ 3단계 · 12초                                      │ ← 생각 단계(접힘)
│ 지난 미팅에서 나온 할 일은 세 가지예요. …¹ …²          │ ← 답(인용 표시)
│ [복사] [다시 답하기] [할 일 추가] [글로 저장]          │
│ ┌ 이어서 ──────────────────────────────┐            │
│ │ 수정 방법 제안받기   초안 쓰기          │            │ ← 이어서 할 일(정해진 목록)
│ └──────────────────────────────────────┘            │
├────────────────────────────────────────────────────┤
│ [지금 보는 기록 · 제6차 논문 지도 ×] [카톡.pdf ×]     │ ← 화면에서 넘긴 대상 / 붙인 파일
│ 추천 모델 ○○  [시도하기]                               │ ← 지금 화면과 같음
│ ┌ 입력창(Kokonut ai-prompt) ─────────────────────┐  │
│ │ 무엇을 도와드릴까요?  / 로 요청 종류            │  │
│ │ 🎙 [모델][깊이]                        📎  ↑    │  │
│ └────────────────────────────────────────────────┘  │
│ 잔액 18,240 · 이번 요청 120 · [사용 내역]               │ ← 실제 값만
└────────────────────────────────────────────────────┘
```

입력창 안의 순서와 간격은 지금 화면의 Kokonut 원본 그대로이고, 위 그림은 자리만 보여 줍니다.

휴대폰에서는 `대화 | 제안 | 실행 내역` 전환을 줄로 두지 않고 층 머리의 [⋯] 메뉴에 넣습니다([02](02-shell.md) §6).

머리의 이름은 '연구 도우미'입니다. 계정 설정에서 이름을 지었으면(나만의 연구 도우미) 대화 안의 말머리에만 그 이름을 씁니다(지금과 같음).

### 2.2 무엇을 읽는지

| 방법 | 동작 |
|---|---|
| (아무것도 안 함) | 이 연구의 기록을 전부 읽음(§1). 입력창 아래에 늘 "이 연구의 기록을 읽고 답해요." |
| 지금 보는 대상 | 기록·글·PDF 자료를 연 채, 또는 피드백·할 일 상세를 연 채 연구 도우미를 열면 그 대상이 **실선 칩 "지금 보는 기록 · 제목"으로 자동으로 먼저 놓임**(고르는 단계 없음). ×로 빼면 그 대화에서는 다시 놓이지 않음. 대상이 하나인 요청(미팅 정리·수정 방법 제안·원고 검토·논문·자료 요약)은 이 칩의 대상을 쓰고, 칩이 없으면 서버가 가장 최근 기록을 고름(#99 규칙) |
| 파일 붙이기(📎) | PDF·TXT·MD, 여러 개. 붙인 파일은 전체 본문(최대 48,000자)을 먼저 읽음(지금 기능) |
| 화면의 버튼 | 원문에서 고른 글 '연구 도우미에게 묻기', 할 일 줄의 '연구 도우미와 상의', 자료의 '연구 도우미에게 읽게 하기' — 누르면 창이 열리고 그 대상이 칩으로 놓임 |

- 화면을 옮기면 칩은 새 화면의 대상으로 바뀝니다(새 화면에 대상이 없으면 칩이 사라짐). ×로 뺀 대상은 그 대화 동안 다시 놓이지 않습니다.
- 칩으로 놓을 수 있는 종류는 서버가 받는 근거 종류뿐입니다(`meetings, feedback, documents, versions, attachments, tasks, phases, milestones`). 결정·질문·수정 결과 상세, 링크 자료에서는 "지금 보는 기록" 칩이 생기지 않습니다(그래도 연구 기록으로서 읽힘).
- 웹 검색·일정 확인 모드에서는 연구 기록과 칩을 보내지 않으므로(지금 규칙) 입력창 아래 줄을 그 모드의 설명으로 바꿉니다.
- 답의 인용(`ai-citations`)에는 읽은 기록이 제목으로 보이고, 누르면 그 기록으로 갑니다. 실행 기록에는 본문 없이 종류·제목만 남습니다(서버 규칙).
- 한도를 넘어 빠진 기록이 있을 수 있다는 점은 답이 스스로 밝힙니다(`ai-guidelines.md` 근거 범위 규칙). 화면은 따로 경고하지 않습니다.
- 칩의 대상이 바뀐 뒤 보내면 서버가 알려 주고(`SOURCE_CHANGED`), 화면은 "보고 있던 기록이 바뀌었어요. 최신 내용으로 다시 보낼까요?" [다시 보내기]를 보여 줍니다.

### 2.3 요청 종류(`/`)

지금의 명령 메뉴에 둘을 더합니다. 고르면 입력창 위에 설명 띠가 생기고(지금 `AIComposerBanner`), `바꾸기 /`로 다른 종류로 바꿉니다.

| 명령 | 하는 일 | 서버 모드 | 대상 |
|---|---|---|---|
| (없음) | 묻고 답하기 | `ask_research` | 연구 기록 전체 |
| 미팅 정리 | 요약, 피드백·결정·질문·할 일 제안 | `organize_meeting` | 칩의 미팅, 없으면 메모가 있는 가장 최근 미팅 |
| 수정 방법 제안 | 피드백을 어떻게 고칠지 | `suggest_revisions` | 칩의 피드백, 없으면 처리 전인 가장 최근 피드백 |
| 원고 검토 | 글의 문장·흐름 점검 | `review_writing` | 칩의 글, 없으면 가장 최근 글 |
| 할 일 정리 | 남은 할 일을 다음 미팅 기준으로 정리 | `plan_research` | 연구 기록 전체 |
| 논문·자료 요약 | 첨부한 자료나 PDF의 고른 쪽을 읽고 요약 | `read_material` | 붙인 파일, 없으면 가장 최근 첨부 파일 |
| 웹 검색 (지금 있음) | 웹을 찾아 답함 | `ask_research` + 웹 검색 켬 | 질문만 보냄(지금 규칙) |
| 일정 확인 (지금 있음) | 이 연구의 미팅·할 일·주요 목표 일정을 확인 | `ask_research` + 일정 읽기 | 요청자 권한으로 최근 등록 500개 중 최대 80개만 쓰고, 연구 기록·대화 이력은 보내지 않음. 일정을 만들거나 바꾼 것처럼 표시하지 않음(지금 규칙) |
| **초안 쓰기** (새로) | 연구 기록으로 글 초안을 씀(칩이 있으면 그 대상 중심) | `ask_research` + 정해 둔 지시문 | 연구 기록 전체 |
| **수정 제안** (새로, 3단계 뒤쪽) | 열어 둔 글에 본문 안 제안을 만듦 | `suggest_edits` | 열어 둔 글(글 화면에서만 보임) |

명령 이름은 지금 메뉴의 이름(`lib/experience.ts`의 `modeLabels`, `ComposerCommands.tsx`)과 같게 씁니다. '수정 제안'은 '수정 방법 제안'과 헷갈리지 않게 설명 띠에 "열어 둔 글에 바로 고칠 곳을 표시해요."를 붙입니다.

알맞은 기록이 하나도 없으면 서버가 AI를 부르지 않고 무엇이 필요한지 알려 줍니다(#99, [09](09-states.md) A18). 화면은 그 안내를 그대로 보여 줍니다.

### 2.4 답과 그 아래의 버튼

| 버튼 | 언제 | 하는 일 |
|---|---|---|
| 복사 · 다시 답하기 | 늘 | 지금과 같음 |
| 할 일 추가 | 답에 할 일 제안이 있을 때 | 제안을 줄로 펼쳐 보여 줌. 줄마다 [선택]. 선택한 것만 `tasks`가 됨(칩의 기록이 있으면 `sourceRecordId` 포함) |
| 글로 저장 | 답이 200자 이상일 때 | 제목을 묻는 작은 창 → 글·자료에 '메모' 글로 저장하고 "글로 저장했어요. [열기]"([05](05-docs.md) §3.9). 근거 목록이 `draftedFrom`에 남음 |
| 이 글에 넣기 | 글을 열어 둔 때 | 커서 자리에 넣음 |
| 요약 저장 | '미팅 정리' 결과일 때 | 그 기록의 요약으로 저장([04](04-meetings.md) §5.4 ①과 같은 동작) |

'교수님 검토로 넘기기'는 두지 않습니다(2026-11-16 사용자 결정, `kokonut-map.md`). 검토 요청은 수정 결과 상세(§6.6)의 [검토 요청 만들기]에서 만듭니다. 답 아래 버튼은 아이콘 버튼(복사·다시 답하기) 다음에 글자 버튼을 둡니다.

- 답 안의 인용 표시(¹ ²)는 지금의 `ai-citations` 그대로입니다. 누르면 그 근거의 해당 자리(기록의 원문 위치, 글의 문단)로 갑니다.
- 생각 단계와 걸린 시간은 서버가 준 실제 값만 보여 줍니다(지금과 같음).
- **이어서**(답 아래의 칩 두세 개)는 AI가 지어낸 것이 아니라 요청 종류별로 정해 둔 목록입니다.

| 방금 한 요청 | 이어서 |
|---|---|
| 미팅 정리 | 수정 방법 제안받기 · 초안 쓰기 |
| 수정 방법 제안 | 할 일 추가 · 초안 쓰기 |
| 초안 쓰기 | 글로 저장 · 더 짧게 · 더 자세히 |
| 원고 검토 | 수정 제안 받기 |
| 그 밖 | 없음 |

칩을 누르면 입력창이 채워질 뿐이고, 보내기는 사용자가 누릅니다.

### 2.5 대화 목록

- [대화 목록 ▾]: 위쪽에 "이 기록에서 한 대화"(지금 화면과 `scope`가 같은 대화), 아래에 최근 대화. 제목은 첫 질문 앞부분.
- [새 대화]: 입력창과 칩·붙인 파일을 비웁니다. 진행 중인 요청이 있으면 "답을 받는 중이에요. 새 대화를 시작해도 답은 이전 대화에 남아요."
- 대화가 길어져 대화 기록 한도(최근 10개·30,000자)에 가까우면 지금처럼 새 대화를 권합니다.
- 대화는 본인만 봅니다. 연구를 바꾸면 그 연구의 대화만 보입니다(다른 연구의 입력·파일을 가져오지 않음).

### 2.6 빈 대화의 첫 화면

AI를 부르지 않고, 지금 화면과 저장된 기록만 보고 **해 볼 만한 것**을 최대 세 개 권합니다. 누르면 요청 종류와 입력창이 채워집니다(보내기는 사용자가).

| 지금 화면 | 조건 | 권하는 것 |
|---|---|---|
| 기록(기록됨) | 요약 없음 | 이 기록 정리하기 |
| 기록(기록됨) | 남은 피드백 있음 | 남은 피드백의 수정 방법 제안받기 |
| 기록(준비) | 넘어온 할 일 있음 | 이번 미팅에 보여 줄 것 정리하기 |
| 기록(준비) | — | 물어볼 질문 제안받기 |
| 글 | 연결된 피드백 중 안 다룬 것 있음 | 남은 피드백으로 수정 제안받기 |
| 글 | — | 이 글의 흐름 점검하기 |
| 홈 | 남은 할 일 있음 | 이번 주 할 일 정리하기 |
| 어디서나 | 연구에 기록이 거의 없음 | 파일을 올려 읽게 하기 |

### 2.7 제안 보기

지금 연구 도우미 화면의 '제안'(고르지 않은 AI 제안)입니다. 실행별로 묶어 보여 줍니다: 어느 기록·글에서 나왔는지, 제안 줄(제목·근거 문장), 줄마다 [선택] [제안 닫기]. 선택하면 해당 기록(피드백·결정·질문·수정 방법·할 일·요약)이 저장되고 "피드백으로 저장했어요. [열기]". 본인만 봅니다.

### 2.8 실행 내역

AI 실행 목록(`aiRuns`): 요청 종류 · 모델 · 상태(실행 중 / 성공 / 실패 / 중단) · 시각 · 쓴 크레딧. [사실] `aiRuns`에는 크레딧과 대화·기록 연결이 없으므로, 쓴 크레딧은 `rms_ai_usage()`의 크레딧 이력에 같은 실행이 있을 때만 보이고 없으면 칸을 비웁니다. 줄을 누르면 대화 메시지나 제안의 `runId`가 같은 곳으로 가고, 없으면 누를 수 없습니다(누를 수 있는 줄만 화살표 표시). 맨 아래 "사용량·플랜 보기" → 설정 창.

### 2.9 입력창 위의 안내 줄

한 번에 하나만, 위에 있을수록 먼저입니다. 문구와 조건은 [09](09-states.md) §2.

미리보기 모드 → AI 미연결 → 크레딧 소진 → 요청이 잦음(잠시 뒤 다시) → 이번 달 크레딧 80% 이상 사용 → 추천 모델 안내(지금 있는 띠)

(24시간 100회 한도는 없어졌습니다. 서버 응답에 남아 있는 `limit:100` 값으로 계산하지 않습니다.)

## 3. 할 일: T1 할 일 화면과 P2 할 일 창

2026-11-16 사용자 답(Q2): "할 일 남겨둬, 꽤 중요한 기능이야." 할 일은 상단 메뉴에 남고, 사이드 창에도 간단한 보기가 있습니다. 두 곳은 같은 줄 부품(`TaskRow`)과 같은 저장을 씁니다.

### 3.1 T1 할 일 화면 (`/r/:id/tasks`)

```
┌ 본문 판 (내용 최대 880, 가운데) ────────────────────────────┐
│ 할 일                                   [+ 할 일 추가]      │ ← 주 버튼
│ 할 일 4 | 피드백 6                                         │ ← Tab, ?view=feedback
│ ‹ 11월 16일 주 ›   월 화 수 목 금 토 일                      │ ← 주간 띠
│                    ·  ●     ◆                              │
│ [찾기      ]  남은 ▾  필터 ▾                 내 할 일|모두    │
│ ── 기한 지남 ──                                            │
│ ☐ 표 2 출처 표기                         2일 지남 · 6차      │
│ ── 오늘 ──                                                 │
│ ☐ 선행연구 비교표 보완                    오늘 · 6차         │
│ ── 이번 주 ── … ── 나중 ── ── 기한 없음 ──                  │
│ ▸ 오늘 끝낸 할 일 2개                                       │
└────────────────────────────────────────────────────────────┘
```

**할 일 탭**
- **주간 띠**: 지금의 `WeekStrip`(7일, 주 넘기기, 오늘로, 키보드). 날짜 아래 점은 기한인 할 일, 마름모는 미팅. 날짜를 누르면 그날 기한인 할 일과 그날 미팅만 보이고, 다시 누르면 풀립니다.
- **찾기 · 상태(남은 / 완료 / 전체 / 보관함) · 필터(우선순위, 어느 기록에서 나왔는지)** — 지금 할 일 화면의 필터 전부. 주소 `?status=` `?q=`.
- **묶음**: 기한 지남 / 오늘 / 이번 주 / 나중 / 기한 없음. 끝낸 것은 '오늘 끝낸 할 일 n개'에 접혀 있고, 상태를 '완료'로 바꾸면 전부 보입니다.
- **줄**(`TaskRow`): 체크 · 제목 · 기한 · 출처. 체크 동작·되돌리기·효과음·휴대폰 밀어서 끝내기는 모든 화면에서 같습니다. 줄을 누르면 항목 상세(`?detail=task:<id>`, 사이드 창 위에 덮임).
- **[+ 할 일 추가]**: 목록 맨 위에 한 줄 입력. Enter로 저장하고 다음 줄을 이어서 쓸 수 있습니다. Esc로 닫습니다.
- 공동연구일 때 `내 할 일 | 모두`.

**피드백 탭** (`?view=feedback`, 지금 피드백 화면을 대신함)
- 모든 기록의 피드백을 한곳에서 봅니다. 필터: 상태(여럿 고르기: 시작 전 / 진행 중 / 수정 결과 있음 / 보류 / 고치지 않음 / 보관함), 기록. 찾기.
- 묶음: 기록별(최근 기록 먼저), 맨 아래 "기록 없이 추가한 피드백".
- 줄: 제목 · 상태 · "할 일 1/3" · 교수 응답이 있으면 테두리 배지. 누르면 항목 상세.
- 기본 필터는 '시작 전'과 '진행 중'(남은 피드백)입니다. 탭에 남은 피드백 수.
- 이 탭에서는 머리의 주 버튼이 [+ 피드백 추가]로 바뀝니다(피드백 입력 창, [02](02-shell.md) §3.5). 탭과 맞지 않는 [+ 할 일 추가]를 남겨 두지 않습니다(2026-11-17 검토).

판 폭이 좁음이면 주간 띠가 한 줄로 줄고 필터가 [필터 ▾] 하나로 모입니다.

### 3.2 P2 할 일 창 (사이드 창 탭)

다른 화면(미팅·글)을 보면서 할 일을 체크하는 간단한 보기입니다. 필터·피드백 탭은 두지 않습니다.

- 머리: "할 일" · [+] · [할 일 화면에서 보기 ›] (T1).
- 남은 할 일만, 묶음은 기한 지남 / 오늘 / 이번 주 / 그 뒤(접힘). 같은 `TaskRow`.
- [+]는 맨 위 한 줄 입력(T1과 같은 동작).
- 지금 화면이 T1이면 이 탭의 아이콘은 그대로 두되, 열면 "할 일 화면을 보고 있어요." 대신 **같은 목록을 보여 줌**(빈 탭을 만들지 않음).

## 4. P3 결정·질문

- `결정 | 질문 n` 전환.
- **결정**: 지금의 결정 기록(`DecisionLog`) — 날짜별로, 결정 내용 · 이유 · "이전 결정 바꿈"으로 이어진 줄. 바뀐 옛 결정은 흐리게 보이고 무엇으로 바뀌었는지 이어집니다. [+ 결정 추가] (어느 기록의 결정인지 고름).
- **질문**: 열린 질문이 위, 해결한 질문은 접혀 아래. 줄: 동그라미(해결·다시 열기) · 내용 · 나온 기록. 줄 메뉴 '다음 미팅에 가져가기'(다음 미팅이 없으면 비활성, 이유 "다음 미팅을 먼저 잡아 주세요."). [+ 질문 추가].
- 줄을 누르면 항목 상세.
- 결정·질문 각각 맨 아래에 '보관한 결정 n개'·'보관한 질문 n개'(있을 때만). 누르면 보관한 줄이 펼쳐지고 줄마다 [복원].

## 5. P4 자료

다른 화면을 보면서 글·자료를 곁에서 확인하는 창입니다.

- 목록: 찾기 + 최근 고친 순의 글·자료(한 줄 44px, 종류 · 제목 · 고친 때).
- 줄을 누르면 창 안에서 **훑어보기**가 열립니다: 글은 읽기 전용 본문, PDF는 작은 보기(쪽 넘기기), 링크는 주소. 위에 [← 목록].
- 훑어보기 위의 버튼: [열기] (W2/W3로 이동) · [연구 도우미에게 묻기] (칩으로 놓고 창을 엶) · (준비 중인 기록을 보고 있을 때) [이 미팅에 가져가기].
- 편집은 여기서 하지 않습니다.

## 6. P5 항목 상세

주소 `?detail=<종류>:<id>`. 사이드 창 위에 덮입니다([02](02-shell.md) §4.3). 다섯 종류가 같은 틀을 씁니다.

**항목 상세의 폭은 사이드 창의 폭 그대로입니다(기본 312, 안쪽 280).** 본문 위로 더 넓게 띄우지 않습니다. 미팅 화면에서 원문의 밑줄과 오른쪽 열의 줄이 서로를 가리키려면([04](04-meetings.md) §5.3) 상세가 오른쪽 열을 가리면 안 되기 때문입니다(2026-11-17 검토: 와이어프레임의 440px 떠 있는 상세가 오른쪽 열과 녹음 줄을 가렸음). 아래 그림은 구획의 순서만 보여 주고, 진행 다섯 칸은 §6.2의 줄인 모양으로 그립니다.

```
┌ [←] 피드백 ───────────────────── [⋯] [×] ┐
│ 선행연구 표에 비교 기준 추가      [진행 중 ▾] │ ← 제목(바로 고침) · 상태(바로 바뀜)
│ ●피드백 ─ ●수정 방법 ─ ●할 일 2/3 ─ ○수정 결과 ─ ○교수 응답 │
│ ── 원문 ──                                 │
│ “선행연구 표는 비교 기준을 하나 더 넣는 게…”   │
│ ▶ 12:04~12:31   [기록에서 보기]             │
│ ── 수정 방법 ──  ── 할 일 ──  ── 수정 결과 ── │
│ ── 교수 응답 ──  ── 개인 메모 ──  ── 연결된 기록 ── │
└────────────────────────────────────────────┘
```

### 6.1 고치는 방식(다섯 종류 공통)

| 무엇 | 방식 |
|---|---|
| 제목, 상태, 체크, 기한, 우선순위 | 그 자리에서 바꾸면 바로 저장. 실패하면 되돌리고 알림 |
| 긴 글(내용, 설명, 이유, 개인 메모) | [편집]을 누르면 글 칸과 [취소] [저장]. 저장 안 하고 닫으려 하면 이동 확인 |
| 연결(피드백 ↔ 할 일 ↔ 글 ↔ 미팅) | 고르기 창에서 넣고 빼면 바로 저장 |
| 보관 | ⋯ › 보관. 바로 실행 + 6초 되돌리기. 보관된 항목을 열면 위에 "보관한 항목이에요." [복원] |

⋯ 메뉴 공통: 링크 복사(이 상세를 여는 주소) / 보관.

### 6.2 피드백

| 구획 | 내용과 동작 |
|---|---|
| 진행 다섯 칸 | 피드백 → 수정 방법 → 할 일 → 수정 결과 → 교수 응답. 각 칸은 있음/없음과 수(지금 `lib/feedback-progress.ts`). 칸을 누르면 아래 해당 구획으로. 다섯 이름을 한 줄에 다 쓰면 280px에 들어가지 않으므로(글자 폭 계산으로 약 350px) **점 다섯 개를 한 줄에 놓고 그 아래에 지금 칸의 이름과 수만 글자로** 씁니다(예: "할 일 2/3"). 각 점의 접근성 이름에는 칸 이름과 상태를 모두 넣습니다. 창을 400px 이상으로 넓히면 다섯 이름을 모두 보입니다(컨테이너 쿼리) |
| 상태 | 시작 전 / 진행 중 / 수정 결과 있음 / 보류 / 고치지 않음. **사용자가 바꾸는 값**이고 저절로 바뀌지 않음 |
| 원문 | 당시 인용 · 녹음 구간 듣기(Kokonut `clip-trimmer`: 양끝 손잡이, 반복) · [기록에서 보기] (그 기록의 원문 그 자리로). 위치를 못 찾으면 "원문이 바뀌어 위치를 찾지 못했어요." |
| 내용 | 피드백 본문(20,000자) |
| 수정 방법 | 저장한 수정 방법(제목·방법·기대 결과·가정·필요한 자료) · [직접 쓰기] · [연구 도우미에게 제안받기] → AI 제안 카드(지금 `RevisionSuggestions`·`SmartSuggestionCard`): [이 방법 선택] / 고쳐서 쓰기. 선택 취소·다시 선택 가능. 선택은 완료가 아님 |
| 할 일 | 이 피드백에 딸린 할 일(체크 가능) · [+ 할 일 추가] · 수정 방법에서 [할 일 추가] (제안된 할 일을 미리 채움) |
| 수정 결과 | 이 피드백의 수정 결과 줄(제목 · 검토 요청 전 / 검토 요청 n건) · [수정 결과 추가] (지금의 수정 결과 대화상자). 할 일을 모두 끝냈는데 수정 결과가 없으면 "할 일을 모두 끝냈어요. 어떻게 고쳤는지 수정 결과로 남길 수 있어요." |
| 교수 응답 | 이 피드백의 수정 결과가 검토 요청에 담겼으면: 최신 차수의 응답 배지(응답 전 / 수정 내용 확인 / 추가 수정 필요) · 응답 댓글 앞부분 · [검토 열기] · **[할 일 추가]** (응답 댓글 앞 80자를 제목으로, 이 피드백에 딸린 할 일을 만듦. 바로 만들고 6초 되돌리기. 교수 응답을 본 뒤 할 일로 가는 길 — 2026-11-17 검토). 담기지 않았으면 [검토 요청 만들기] (이 수정 결과를 고른 채 검토 요청 창을 엶. 이미 보낸 요청에 항목을 더하지 않음)(수정 결과가 없으면 비활성, 이유 "수정 결과를 먼저 남겨 주세요.") |
| 개인 메모 | 나만 보는 메모. 교수·공동연구자에게 보이지 않는다는 한 줄 |
| 연결된 기록 | 나온 기록, 연결된 글 |
| (글을 열어 둔 때) | [이 글에 수정 제안받기] ([05](05-docs.md) §3.6, 3단계 뒤쪽) |

### 6.3 할 일

제목 · 체크 · 상태(시작 전 / 진행 중 / 완료) · 기한 · 우선순위 · 담당(공동연구) · 단계 · 설명 · 원문 인용([기록에서 보기]) · 연결된 피드백(넣고 빼기) · 수정 방법(연결 유지) · 고칠 글(글 고르기 → 그 글의 제목 목록에서 위치 고르기(`sectionAnchor`), 고르지 않으면 글 맨 위 여백. 고르면 그 글의 여백에 보임) · [글 열기] (W2의 그 제목 위치로) · 가져간 미팅 목록과 [다음 미팅에 가져가기] · 수정 결과와 [수정 결과 추가].

### 6.4 결정

내용 · 이유 · 이전 결정 바꿈(고르기) · 원문 인용 · 나온 기록 · [할 일 추가] (결정 내용을 제목으로).

### 6.5 질문

내용 · 열림/해결 · 원문 인용 · 나온 기록 · 가져간 미팅 · [다음 미팅에 가져가기].

### 6.6 수정 결과

제목 · 수정한 내용 · 종류(문서 / 기타) · 파일 버전과 볼 위치 · 연결된 피드백·할 일 · 담긴 검토 요청과 차수별 교수 응답·댓글(읽기 전용, 지금 수정 결과 상세의 응답 패널. 응답마다 [할 일 추가] — §6.2와 같은 동작이고 연결된 피드백이 있으면 그 피드백에 딸림) · [편집] (수정 결과 대화상자) · [검토 요청 만들기] · [검토 열기].

문서 종류의 수정 결과는 파일 버전과 볼 위치가 있어야 검토 요청에 담을 수 있습니다(서버 규칙). 없으면 [검토 요청 만들기]가 비활성이고 "문서 수정에는 파일과 볼 위치가 필요해요. 편집에서 추가해 주세요."

### 6.7 열 수 없을 때

| 경우 | 보이는 것 |
|---|---|
| 찾지 못함(없는 id, 다른 연구의 것, 볼 권한이 없음 — 화면은 이 셋을 구분할 수 없음: 남의 '나만 보기' 기록은 부트스트랩에 오지 않음) | 첫 불러오기가 끝난 뒤 판단합니다. "이 항목을 열 수 없어요. 보관했거나 볼 수 없는 항목이에요." [닫기]. 닫으면 주소에서 `detail`을 지움 |
| 보관한 항목 | 상세를 열고 위에 "보관한 항목이에요." [복원] (§6.1) |
| 불러오는 중 | 뼈대 |
| 저장 충돌 | "다른 창에서 내용이 바뀌었어요." [새 내용 보기] — 내가 쓰던 글은 글 칸에 그대로 둠 |
