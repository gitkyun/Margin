# 화면 규칙: 색 역할 · 화면 머리 · 움직임

[디자인 기준](README.md)이 "무엇으로 만드는가"(Montage 토큰·부품)라면, 이 문서는 "어디에 무엇을 쓰는가"입니다. 2026-11-09 검수(`docs/qa/2026-11-09-design-review.md`, 별도 PR)의 결정(Q1·Q2·Q3·Q9)을 규칙으로 옮겼습니다. 새 화면과 수정은 이 규칙을 따르고, 어긋나는 기존 화면은 검수 로드맵 순서로 고칩니다.

## 1. 색 역할

**원칙: 색 하나에 뜻 하나. 같은 뜻은 공개 화면·앱·라이트·다크 어디서나 같은 토큰.**

| 역할 | 토큰·부품 | 쓰지 않는 곳 |
|---|---|---|
| 주 행동 | Montage `Button` solid primary(브랜드 파랑). 한 화면 머리에 하나. 공개 화면도 같음 | 반전(검정/흰) 버튼을 주 행동으로 쓰지 않음 |
| 파란 면 위의 행동 | 흰 바탕(`--semantic-static-white`) + 브랜드 글자(`--semantic-foreground-brand-primary`) 버튼 하나 | 소개 화면 마지막 파란 띠 같은 브랜드 면에서만 |
| 보조 행동 | `Button` outlined assistive, `TextButton` | — |
| 선택·현재 위치 | `--selected-fill` 면 + `--semantic-foreground-brand-primary` 글자(+ 필요하면 `--selected-line`). 같은 내용 보기 전환은 `SegmentedControl`(`Segments`) | 호버와 같은 색으로 만들지 않음 |
| 호버 | 행은 `--hover-fill`, 누를 수 있는 카드는 `--hover-line` | 파랑 |
| 링크 글자 | `TextButton color="primary"` | — |
| 학생 작업 상태 | Montage `ContentBadge`: 초록 `positive`=완료·확정, 주황 `cautionary`=보류·공유 중단·미확정, 빨강 `negative`=오류·삭제, 회색 `neutral`=시작 전·취소 | '정보'에 별도 색을 만들지 않음(중립 배지 + 아이콘) |
| **교수 결과** | `ContentBadge` **outlined** + 고정 아이콘 + 문구('수정 내용 확인', '추가 수정 필요'). 학생 완료(초록 채움)와 모양이 달라야 함 | 학생 상태색과 같은 채움 배지 |
| 정보 유형(달력·주간 띠의 점·막대에만) | 미팅=브랜드, 마감=주황, 단계 목표=보라, 주요 목표=상태에 쓰지 않는 accent 하나 | 배지·버튼 |
| 면 층위 | 바탕 `--canvas` < 작업 면 `--surface` < 떠 있는 면 `--surface-raised`(메뉴·입력창·알림) | 선택 표시를 면 단계로 만들지 않음 |
| 반전(inverse) 면 | 짧게 뜨는 툴팁(Montage Tooltip)에만 | 주 행동·선택·알림·켜짐 표시. 반전 면은 다크에서 밝아지므로 고정 흰 글자를 올리면 안 읽힘 |

글자 위계는 여섯 단계만 씁니다: 화면 제목 · 구역 제목 · 카드 제목 · 본문(`neutral-primary`) · 보조(`neutral-secondary`) · 메타(`neutral-tertiary`). 읽어야 하는 내용은 보조색으로 쓰지 않습니다.

PR마다 확인: `git grep -n 'data-theme="dark"'` 결과가 늘지 않았는지, `color: var(--surface)`·`background: var(--brand)`처럼 면·전경 토큰을 뒤바꿔 쓰지 않았는지.

## 2. 화면 머리

순서는 하나로 고정합니다.

```
[뒤로]                          (상세, 767px 이하에서만 보임)
제목 · 상태 배지          [보조] [주 행동] [더보기]
설명 한 줄
[탭]                            (다른 내용 묶음이 있을 때)
[도구 줄: 보기 전환 · 찾기 · 거르기 · 개수]
```

- `PageHeader`(`components/common.tsx`)의 `back`·`tabs`·`toolbar` 자리를 씁니다. 화면에서 머리 요소를 따로 쌓지 않습니다.
- 행동: solid primary 많아야 1개, outlined 1개, 나머지는 `IconButton`(더보기) + Montage Menu.
- **탭 vs 보기 전환**: 탭(Montage Tab)은 다른 내용 묶음(피드백·할 일·수정 결과, 로드맵·캘린더·시간 조율). 보기 전환(`SegmentedControl`)은 같은 내용을 다르게 볼 때(시간순·관계도, 목록 거르기).
- 가로로 넘치는 탭·보기 전환은 끝에 더 있다는 표시(가장자리 흐림)를 둡니다.

| 꼴 | 머리 | ≥1200 | 768–1199 | ≤767 |
|---|---|---|---|---|
| 목록 | 제목(명사) · 설명 · 주 행동 "OO 만들기" · 탭(있으면) · 도구 줄 | 제목 줄 한 줄, 도구 줄 한 줄 | 거르기 칸은 둘째 줄로 감김 | 주 행동은 설명 아래 전체 너비, 찾기 칸 전체 너비, 거르기 5개 이상이면 선택 상자 |
| 상세 | 뒤로 · 제목+상태 배지 · 메타 한 줄 · 주 행동=흐름의 다음 단계 · 편집은 보조 | 경로 표시 3단계, 뒤로 숨김 | 행동이 넘치면 설명 아래로 | 뒤로 보임, 편집은 아이콘 버튼 |
| 홈 | 연구명 · "현재 단계 · 다음 미팅" · 상황별 주 행동 1개 | 본문 순서: 확인할 내용(있을 때) → 다음 미팅·주간 띠 → 남은 할 일 → 바로 시작 | 같음 | 같음 |
| 설정 | 제목 · 설명. 옆 메뉴는 탭 또는 목록 | 2열 | 2열 | 메뉴가 위, 내용이 아래 |

## 3. 움직임

Montage에는 움직임 토큰이 없습니다. 아래 세 단계를 `src/design/tokens.css`의 `--motion-*`로 두고 그것만 씁니다.

| 단계 | 쓰는 곳 | 시간 | 곡선 | 동작 줄이기 |
|---|---|---|---|---|
| 미세(micro) | 호버·초점·누름의 색·테두리·그림자, 체크 | 120ms | `cubic-bezier(0.2, 0, 0, 1)` | 색 변화만 남김 |
| 부품(component) | 목록 들고 남, 접힘·펼침, 메뉴·알림 등장, 숫자 바뀜 | 등장 200ms / 퇴장 160ms | 등장 위와 같음, 퇴장 `cubic-bezier(0.3, 0, 1, 1)` | 높이·위치 움직임 없음, 투명도는 즉시 |
| 화면(page) | 화면 전환, 시트·대화상자, 소개 화면 장면 | 300ms(소개 히어로만 최대 600ms) | `cubic-bezier(0.2, 0, 0, 1)` | 즉시 |

- 무한 반복은 실제로 진행 중일 때만(불러오는 중, AI 실행 중). 로그인 후 장식 반복은 쓰지 않습니다.
- 지어낸 대기(일부러 늦추는 순차 등장)는 쓰지 않습니다.
- motion 라이브러리의 `reducedMotion="user"`는 이동·배치만 끕니다. 높이·투명도 애니메이션은 `useReducedMotion()`으로 직접 끕니다.
