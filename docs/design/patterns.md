# 화면 규칙: 색 역할 · 화면 머리 · 움직임

> 2026-11-16 정보 구조 개편(IA v2) 설계가 확정됐습니다(구현 전). 화면 배치·메뉴·주소의 새 기준은 [docs/design/ia-v2](ia-v2/00-README.md)이고, 이 문서의 셸·여백 패널·사이드바 규칙(§1-1 마지막 줄, §2-1)은 구현 단계에 맞춰 [02 틀](ia-v2/02-shell.md)로 바뀝니다. 색 역할·모서리·그림자·움직임 규칙은 그대로입니다.

[디자인 기준](README.md)이 "무엇으로 만드는가"(Montage 토큰·부품)라면, 이 문서는 "어디에 무엇을 쓰는가"입니다. 2026-11-09 검수(`docs/qa/2026-11-09-design-review.md`, 별도 PR)의 결정(Q1·Q2·Q3·Q9)을 규칙으로 옮겼습니다. 새 화면과 수정은 이 규칙을 따르고, 어긋나는 기존 화면은 검수 로드맵 순서로 고칩니다.

## 1. 색 역할

**원칙: 색 하나에 뜻 하나. 같은 뜻은 공개 화면·앱·라이트·다크 어디서나 같은 토큰.**

| 역할 | 토큰·부품 | 쓰지 않는 곳 |
|---|---|---|
| 주 행동 | Montage `Button` solid primary(브랜드 파랑). 한 화면 머리에 하나. 공개 화면도 같음 | 반전(검정/흰) 버튼을 주 행동으로 쓰지 않음 |
| 파란 면 위의 행동 | 흰 바탕(`--semantic-static-white`) + 브랜드 글자(`--semantic-foreground-brand-primary`) 버튼 하나 | 소개 화면 마지막 파란 띠 같은 브랜드 면에서만 |
| 보조 행동 | `Button` outlined assistive, `TextButton` | — |
| 현재 위치 (2026-11-18) | 상단 메뉴는 진한 글자·굵기·밑줄, 아이콘 줄·설정 항목·분류·폴더·문서 탭·목록의 지금 항목은 `--navigation-selected-fill`(중립) 면 + `--text` 글자 + 굵기 600~700. 찾기 창의 키보드 하이라이트는 `--hover-fill` | 파란 면·파란 글자. 위치 표시는 색 없이 명도와 굵기로 읽혀야 함 |
| 고른 값 | 선택지·켜진 도구·고른 카드처럼 사용자가 값을 고른 상태: `--selected-fill` 면 + `--semantic-foreground-brand-primary` 글자(+ 필요하면 `--selected-line`). 같은 내용 보기 전환은 `SegmentedControl`(`Segments`) | 현재 위치 표시, 호버와 같은 색 |
| 호버 | 행은 `--hover-fill`, 누를 수 있는 카드는 `--hover-line` | 파랑 |
| 링크 글자 | `TextButton color="primary"` | — |
| 학생 작업 상태 | Montage `ContentBadge`: 초록 `positive`=완료·확정, 주황 `cautionary`=보류·공유 중단·미확정, 빨강 `negative`=오류·삭제, 회색 `neutral`=시작 전·취소 | '정보'에 별도 색을 만들지 않음(중립 배지 + 아이콘) |
| **교수 결과** | `ContentBadge` **outlined** + 고정 아이콘 + 문구('수정 내용 확인', '추가 수정 필요'). 학생 완료(초록 채움)와 모양이 달라야 함 | 학생 상태색과 같은 채움 배지 |
| 정보 유형(달력·주간 띠의 점·막대에만) | 미팅=브랜드, 마감=주황, 단계 목표=보라, 주요 목표=초록. 점·막대 모양이라 같은 색의 상태 배지와 구분됨 | 배지·버튼 |
| 면 층위 | 바탕 `--canvas` < 작업 면 `--surface` < 떠 있는 면 `--surface-raised`(메뉴·입력창·알림) | 선택 표시를 면 단계로 만들지 않음 |
| 반전(inverse) 면 | 짧게 뜨는 툴팁(Montage Tooltip)에만 | 주 행동·선택·알림·켜짐 표시. 반전 면은 다크에서 밝아지므로 고정 흰 글자를 올리면 안 읽힘 |

글자 위계는 여섯 단계만 씁니다: 화면 제목 · 구역 제목 · 카드 제목 · 본문(`neutral-primary`) · 보조(`neutral-secondary`) · 메타(`neutral-tertiary`). 읽어야 하는 내용은 보조색으로 쓰지 않습니다.

PR마다 확인: `git grep -n 'data-theme="dark"'` 결과가 늘지 않았는지, `color: var(--surface)`·`background: var(--brand)`처럼 면·전경 토큰을 뒤바꿔 쓰지 않았는지.

## 1-1. 면과 모서리

- 모서리는 네 단계만 쓴다. 셸(사이드바·본문·여백 패널·대화상자) 16, 묶음(카드·목록 상자·입력창) 12, 조작 요소는 Montage 부품 값 그대로, 작은 표시(배지·칩)는 6 또는 알약. 안쪽 모서리가 바깥보다 작아야 한다.
  - (IA v2 0단계부터, 구현 전) 상단 줄의 메뉴 항목과 찾기 칸은 모서리 10(`--radius-10`, 토스증권 실측)을 쓴다. 이 값을 더해 셸 16 · 묶음 12 · 메뉴 항목·찾기 칸 10 · 조작 요소 Montage 값 · 작은 표시 6 또는 알약이 된다. IA v2의 셸은 상단 줄·본문 판·사이드 창·대화상자다([02 틀](ia-v2/02-shell.md) §2).
- 한 요소에 보더, 색 채움, 그림자를 함께 쓰지 않는다. 묶음은 1px 선만, 묶음 안의 약한 구분은 채움(`--surface-muted`)만, 떠 있는 면(메뉴·입력창·알림)만 그림자를 쓴다.
- 강조 카드는 브랜드 선(`--selected-line`) 1px 하나로 표시하고 한 화면에 하나만 둔다(예: 홈의 다음 미팅).
- 빈 상태는 `EmptyState` 부품 하나로 만든다: 아이콘, 한 줄 제목, 이 화면에서 하는 일 요점 2~3개(`points`), 주 행동 하나. 머리에 같은 행동 버튼을 또 두지 않는다.
- 그림자는 로그인 후 화면에서 겹쳐 뜨는 것에만 쓴다: 떠 있는 면(`--raise-shadow`), 대화상자·시트·겹쳐 뜨는 사이드 창(768~1199, `--shadow-pop`). 나란히 놓인 본문 판·사이드 창은 그림자 대신 1px 안쪽 선(`--ia-pane-edge`)과 바탕 명도 차이로 나눈다(2026-11-18). 선이 있는 카드와 입력창에는 그림자를 더하지 않는다.
- 로그인 후 화면의 본문은 `main.workspace-content` 안쪽 폭을 모두 쓴다(본문 최대 1040px 규칙은 2026-11-16에 폐기). 긴 글(연구 도우미 대화, 글쓰기 종이)의 읽기 열만 720~760px로 둔다. 자세한 값은 §2-2 배치 규칙. IA v2 설계서가 화면별 폭을 따로 정한 곳(예: 미팅 화면 폭별 배치 [04](ia-v2/04-meetings.md) §1)은 설계서를 따른다.
- (현재 구현 — IA v2 0단계에서 바뀜: 새 기준 → [02 틀](ia-v2/02-shell.md) §4) 여백 패널 안쪽은 `PanelFrame`으로 만든다: 이름, 닫기, 탭(연결·응답·도우미 가운데 최대 세 개). `]` 키로 여닫는다. IA v2에서는 화면마다 내용이 바뀌는 여백 패널 대신 어느 화면에서나 같은 사이드 창(연구 도우미 · 할 일 · 결정·질문 · 자료 네 탭 + 항목 상세)을 쓰고, `]`는 마지막 탭으로 여닫는다.

## 1-2. 작은 부품 규칙 (2026-11-10 사용자 검수에서 정함)

같은 지적이 되풀이되지 않게 새 화면을 만들 때 먼저 확인합니다.

- **상태 표시는 한 겹만.** 고른 날짜·오늘처럼 한 요소의 상태를 면과 원을 겹쳐 두 번 표시하지 않습니다. 날짜는 숫자 원 하나로 표시합니다(주간 줄 36px, 캘린더 28px).
- **빈 상태는 가운데.** `EmptyState`는 놓인 칸의 가운데에 오고 설명과 버튼 사이는 16px입니다. 화면마다 따로 정렬하지 않습니다.
- **날짜·아이콘 칸은 정사각형.** 목록 앞의 날짜 칸, 아이콘 칸은 가로와 세로가 같습니다(미팅 목록 56px). 테두리와 면을 함께 쓰지 않고 옅은 면만 씁니다. 문서 미리보기처럼 실제 종이 비율을 보여 주는 칸만 예외입니다.
- **도구 줄은 한 줄, 묶음 순서 고정.** 편집 도구는 문서 위에 붙이고 되돌리기 → 문단 형식 → 글자 서식 → 목록 → 삽입 순서로 묶습니다. 본문을 가리는 떠 있는 도크, 누를 때 튀어 오르는 움직임을 쓰지 않습니다.
- **입력창 아래 줄은 줄바꿈 없이.** AI 입력창은 왼쪽 ＋(첨부), 선택 칸, 오른쪽 보내기 순서이고 안내 문장을 입력창 밖에 따로 늘어놓지 않습니다. Enter로 보냅니다.
- **달 넘기기는 달 이름 양옆.** 캘린더의 이전·다음 버튼은 달 이름 바로 옆에 둡니다.
- **설정은 한 곳에만.** 화면 테마처럼 계정 설정에 있는 항목을 찾기 창이나 다른 메뉴에 다시 넣지 않습니다.
- **등록과 선택을 나눕니다.** 사람(교수 등)은 연구를 시작하거나 설정할 때 등록하고, 작업 화면에서는 고르기만 합니다. 지도교수는 연구를 만들 때와 연구 설정에서 등록하고(`Research.advisorEmails`, 연구 JSON에 저장돼 마이그레이션 없음), 검토 요청에서는 고르기만 합니다.

## 2. 화면 머리

순서는 하나로 고정합니다.

```
[뒤로]                          (상세, 767px 이하에서만 보임)
제목 · 상태 배지          [보조] [주 행동] [더보기]
설명 한 줄
[탭]                            (다른 내용 묶음이 있을 때)
[도구 줄: 보기 전환 · 찾기 · 거르기 · 개수]
```

- `PageHeader`(`components/common.tsx`)의 `back`·`status`·`meta`·`tabs`·`toolbar` 자리를 씁니다. 화면에서 머리 요소를 따로 쌓지 않습니다. 간격·정렬 값은 §2-2 배치 규칙입니다.
- 행동: solid primary 많아야 1개, outlined 1개, 나머지는 `IconButton`(더보기) + Montage Menu.
- **탭 vs 보기 전환**: 탭(Montage Tab)은 다른 내용 묶음(피드백·할 일·수정 결과, 로드맵·캘린더·시간 조율). 보기 전환(`SegmentedControl`)은 같은 내용을 다르게 볼 때(시간순·관계도, 목록 거르기).
- 가로로 넘치는 탭·보기 전환은 끝에 더 있다는 표시(가장자리 흐림)를 둡니다.

| 꼴 | 머리 | ≥1200 | 768–1199 | ≤767 |
|---|---|---|---|---|
| 목록 | 제목(명사) · 설명 · 주 행동 "OO 만들기" · 탭(있으면) · 도구 줄 | 제목 줄 한 줄, 도구 줄 한 줄 | 거르기 칸은 둘째 줄로 감김 | 주 행동은 설명 아래 전체 너비, 찾기 칸 전체 너비, 거르기 5개 이상이면 선택 상자 |
| 상세 | 뒤로 · 제목+상태 배지 · 메타 한 줄 · 주 행동=흐름의 다음 단계 · 편집은 보조 | 경로 표시 3단계, 뒤로 숨김 | 행동이 넘치면 설명 아래로 | 뒤로 보임, 편집은 아이콘 버튼 |
| 홈 | 연구명 · "현재 단계 · 다음 미팅" · 상황별 주 행동 1개 | 본문 순서: 확인할 내용(있을 때) → 다음 미팅·주간 띠 → 남은 할 일 → 바로 시작 | 같음 | 같음 |
| 설정 | 제목 · 설명. 옆 메뉴는 탭 또는 목록 | 2열 | 2열 | 메뉴가 위, 내용이 아래 |

설정 줄은 현재 구현입니다. IA v2(구현 전)에서는 설정 화면 대신 `?settings=`로 여는 설정 창을 씁니다([07 설정 창](ia-v2/07-other-screens.md) §1).

## 2-1. 셸과 너비별 배치

> (현재 구현 — IA v2 0단계에서 바뀜: 새 기준 → [02 틀](ia-v2/02-shell.md) §1.2 폭 구간, §4 사이드 창과 아이콘 줄, §6 휴대폰) IA v2의 셸은 상단 줄(메뉴 4개: 홈 · 미팅 · 할 일 · 글·자료), 본문 판, 오른쪽 사이드 창(기본 312px, 글 편집·자료 보기 440px, 312~640px 끌어서 조절), 아이콘 줄 56px입니다. 사이드 창은 1200px 이상에서 본문을 밀고 768~1199px에서 겹쳐 뜨며, 767px 이하는 아래 탭 줄(홈 · 미팅 · 할 일 · 글·자료 · 연구 도우미)과 전체 화면 시트입니다. 그때 아래 표, 여백 패널 문단, 사이드바 묶음 순서·아래 자리 하나·집중 모드 문단은 지웁니다([10 구현 순서](ia-v2/10-build-plan.md) §6). 그때까지 지금 화면은 아래 규칙을 따릅니다.

셸은 사이드바, 본문, 여백 패널 세 영역입니다. 너비 기준은 Montage(sm 768, md 992, lg 1200, xl 1600)만 씁니다.

| 너비 | 사이드바 | 여백 패널 | 연구 홈 |
|---|---|---|---|
| 1600 이상 | 232 | 400, 본문 옆 | 2열(옆 열 360) |
| 1200~1599 | 232. 집중 모드에서는 60 레일 | 360, 열면 본문이 줄어듦 | 2열(옆 열 320) |
| 992~1199 | 60 레일. 펼치면 본문 위에 뜸 | 340, 열면 본문이 줄어듦 | 2열(옆 열 300) |
| 768~991 | 60 레일. 펼치면 본문 위에 뜸 | 본문을 덮는 오른쪽 시트(최대 420) | 1열 |
| 767 이하 | 없음(상단 줄의 메뉴 버튼) | 전체 화면 시트 | 1열 |

- 집중 모드는 연구 도우미, 글쓰기 문서 편집, 여백 패널이 열린 동안입니다. 들어가면 레일로 접고 나오면 원래대로 돌아옵니다. 집중 모드에서 직접 펼친 선택은 따로 기억합니다(`rms-sidebar-focus-expanded`).
- 여백 패널은 화면이 `MarginPanel`(`src/components/margin-panel/`)로 내용을 넣습니다. 화면 안에 따로 오른쪽 열을 만들지 않습니다.
- 여백 패널의 면은 본문과 같은 `--surface`에 왼쪽 선 하나입니다. 그림자는 본문을 덮는 시트일 때만 씁니다. 크기 조절 손잡이는 두지 않습니다. (사실: 지금 코드에는 이미 폭 조절 손잡이 `components/margin-panel/PanelResizer.tsx`가 있습니다. IA v2는 이것을 사이드 창 폭 조절에 그대로 씁니다 → [02 틀](ia-v2/02-shell.md) §4.4.)
- 초점: 열면 패널의 첫 조작 요소로, 닫으면 열기 전 자리로 돌아옵니다. Esc는 본문을 덮는 시트일 때만 닫습니다.
- 사이드바 묶음은 연구 홈 → 지도 흐름(미팅, 피드백·수정, 할 일, 검토 요청) → 연구 작업(글쓰기, 자료, 계획·일정) → 연구 도우미 순서입니다. (지금 코드는 묶음 이름 없이 홈 · 미팅 · 피드백 · 할 일 · 문서 · 일정 여섯과 연구 도우미입니다 — `components/WorkspaceShell.tsx`의 `NAV_PATHS`.)
- 사이드바 아래 자리는 하나만 씁니다. 시작 체크리스트(다 못 했을 때) → AI 사용량(한도의 80% 이상일 때) → 비움.

## 2-2. 배치 규칙 (전 화면 공통, 2026-11-16)

로그인 후 모든 화면이 같은 틀을 씁니다. 틀의 CSS는 `src/reference.css`의 "화면 틀" 구역과 `src/styles.css`의 "대화상자 틀" 구역에 있고, 화면 CSS에서 같은 값을 다시 덮지 않습니다. 값이 어색하면 화면에서 고치지 말고 이 절과 틀을 함께 고칩니다. 숫자 확인은 `scripts/qa/layout-probe.mjs --check`([UI 품질 기준](ui-quality.md) §5).

### 화면 틀

- 본문은 `main.workspace-content` 안쪽 폭을 전부 씁니다. 화면 루트에 `max-width`·`margin: auto`·좌우 여백을 두지 않습니다.
- 좌우·위 여백은 `main.workspace-content`의 padding 하나입니다: 992px 이상 위 28 / 좌우 32, 768~991 위 20 / 좌우 16, 767 이하 16 / 16.
- 예외(틀은 꽉 차고 안쪽 읽기 열만 좁게): 글쓰기 종이와 연구 도우미 대화 열은 720~760px 가운데, 설정·계정의 입력 폼 열은 최대 720px 왼쪽 정렬. 자료 상세의 PDF 나란히 보기는 지금 배치를 유지합니다.

### 화면 머리 (`PageHeader`)

순서: [뒤로] → 제목+상태 배지 | 오른쪽 행동 → 설명 한 줄 → 메타 줄 → 탭 → 도구 줄

- 제목 h1: 768 이상 28px/38px, 767 이하 22px/28.6px. 모든 화면 같고 왼쪽 정렬. 제목의 위쪽 가장자리는 main 안쪽 시작점과 같습니다.
- 행동 버튼: 높이 40(`Button` 기본 크기), 제목 줄의 위쪽에 맞춤, 버튼 사이 8. solid primary는 한 머리에 1개까지.
- 767 이하: 행동 버튼은 설명 아래로 내려가고 주 행동이 남은 너비를 채웁니다.
- 설명: 14px/22px, 제목 아래 8. 메타 줄(`meta`)은 그 아래 8, 항목 사이 8.
- 머리 아래 여백: 탭이 있으면 16, 없으면 24.
- 긴 제목은 줄바꿈됩니다. 제목 칸(`.page-heading`)은 `min-width: 0`, 행동 칸(`.page-actions`)은 `flex: none`.

### 탭과 도구 줄

- 다른 내용 묶음 전환 = 밑줄 탭. 탭 아래 여백 24.
- 같은 목록을 한 기준으로 거르기 = `SegmentedControl`(`Segments`). '필터' 버튼으로 바꾸지 않습니다. 기준이 둘 이상이면 SegmentedControl 하나 + 그 옆 '필터' 버튼.
- 도구 줄(`.page-toolbar`): 왼쪽에 거르기, 오른쪽에 찾기. 사이 12, 세로 가운데 정렬, `flex-wrap: wrap`, 줄바꿈되면 줄 사이 8. 위 여백 0, 아래 여백 16.
- 찾기 칸(`.page-search`): 높이 40, 768 이상 너비 240 고정, 767 이하 전체 너비로 둘째 줄.
- 목록 위 찾기·고르기 칸은 모두 높이 40·모서리 12(`--field-height-toolbar`·`--field-radius-toolbar`, Montage medium과 같음). 화면 CSS가 직접 만든 `input`·`select`도 이 두 토큰을 쓴다. 폼 안 입력은 48(large).
- 할 일 줄의 우선순위 점은 제목 뒤에 둔다. 앞에 두면 줄마다 제목 시작선이 달라진다.
- 오른쪽 열(사이드 창 + 아이콘 줄, 2026-11-19): 토스증권 골조. 화면 위아래로 붙은 평평한 열, 바탕(`--canvas`)과 같은 면, 본문과는 1px 선. 아이콘 줄 60: 맨 위 밀기(≫) 버튼, 32 칸 아이콘 + 짧은 이름, 켜짐은 칸 중립 채움 + 진한 글자, 아래쪽 이름 없는 32 정사각 버튼(화면 배치·설정). 768 이상에서 창 닫기는 밀기 버튼만(×는 휴대폰 시트).
- 탭·SegmentedControl 항목은 줄바꿈하지 않습니다. 넘치면 그 줄만 가로 스크롤(항목 `flex: none`, 컨테이너 `overflow-x: auto`).
- 767 이하에서 거르기 항목이 5개 이상이면 선택 상자로 바꿉니다.

### 간격

허용 값은 `var(--spacing-2|4|6|8|12|16|20|24|32|40)`입니다. px 숫자를 직접 쓰지 않고, 홀수·중간값은 가장 가까운 허용 값(같으면 큰 쪽)으로 옮깁니다.

| 사이 | 값 |
|---|---|
| 아이콘 ↔ 글자 | 8 |
| 버튼 ↔ 버튼, 칩 ↔ 칩 | 8 |
| 라벨 ↔ 입력 | 8 |
| 입력 ↔ 도움말·오류 글 | 6 |
| 입력 묶음 ↔ 입력 묶음 | 20 |
| 마지막 입력·본문 ↔ 버튼 줄 | 24 (16 미만 금지) |
| 카드 안쪽 여백 | 768 이상 24, 767 이하 16 |
| 카드 ↔ 카드, 구역 ↔ 구역 | 24 |
| 목록 행 위아래 여백 | 16 |
| 구역 제목 ↔ 구역 내용 | 12 |

버튼·입력·배지가 다른 요소와 맞닿으면(간격 0) 결함입니다.

### 정렬

- 기본은 왼쪽 정렬. 가운데 정렬은 `EmptyState`, 로딩, 아이콘만 있는 버튼 안쪽에만 씁니다.
- 같은 화면의 구역들은 왼쪽 가장자리 x좌표가 같습니다(카드 안쪽 내용끼리도 같음).
- 한 줄(행) 안: 앞 아이콘·날짜 칸은 위 정렬, 뒤 배지·화살표는 세로 가운데.
- 표: 머리 칸과 값 칸의 가로 정렬·좌우 여백이 같습니다.
- 버튼 줄: 화면 머리와 대화상자는 오른쪽 정렬, 본문 안 폼은 왼쪽 정렬.

### 긴 글

- 기본은 줄바꿈 허용. `white-space: nowrap`은 버튼 글자, 배지, 탭, 날짜·숫자, 단축키 표시에만 쓰고, 그 요소를 담은 줄이 감기거나 스크롤돼야 합니다.
- 글자가 들어가는 flex·grid 자식에는 `min-width: 0`, grid 열은 `minmax(0, 1fr)`.
- 줄 수: 화면 제목·상세 본문 = 제한 없음 / 목록의 제목·보조 설명 = 2줄까지 / 메타(날짜·개수) = 1줄 말줄임. 줄 수 제한은 `-webkit-line-clamp`로 하고, 잘리는 요소에는 전체 글을 `title`로 줍니다.
- 글자를 담는 요소에 고정 `height`를 쓰지 않고 `min-height`를 씁니다. 2줄이 되면 행이 커져야 하고 옆 요소를 밀어내거나 겹치면 안 됩니다.
- 공백 없는 긴 파일명·URL·이메일: `overflow-wrap: anywhere`.
- 한 줄 입력은 넘치면 안에서 스크롤, 여러 줄이 예상되면 textarea(자동 높이). 입력 칸 위 라벨은 줄바꿈을 허용합니다.
- 사이드바 메뉴 이름은 2줄까지 줄바꿈하고 아이콘은 첫 줄에 맞춥니다. 연구 전환 버튼의 연구 이름과 계정 칸의 이메일은 1줄 말줄임입니다.

### 너비 기준

Montage 기준만 씁니다: 767 이하 / 768~991 / 992~1199 / 1200~1599 / 1600 이상. 미디어 쿼리는 `max-width` 767·991·1199·1599, `min-width` 768·992·1200·1600만 씁니다. 예외는 대화상자 버튼 줄의 479 하나입니다.

### 대화상자 (`components/ui/dialog.tsx`)

`DialogContent` 안에 `DialogHeader` → `DialogBody` → `DialogFooter` 순서로 둡니다. 폼이면 `<form>`으로 Body와 Footer를 함께 감쌉니다.

- 안쪽 여백 768 이상 24, 767 이하 20. 닫기 버튼은 제목과 같은 줄 오른쪽 위에 놓이고 줄을 따로 차지하지 않습니다.
- 제목 ↔ 설명 8, 머리 ↔ 본문 20, 본문 안 묶음 사이 20, 본문 ↔ 버튼 줄 24.
- 버튼 줄: 오른쪽 정렬, 순서 [취소][주 행동], 사이 8, 높이 40. 479 이하에서는 버튼들이 같은 너비로 한 줄을 나눠 씁니다.
- 팝업 최대 폭 520(`.wide-dialog`는 560). 767 이하는 Montage 아래 시트(화면 폭, 최대 480)입니다. 내용이 길면 `DialogBody`만 스크롤됩니다.

## 3. 움직임

Montage에는 움직임 토큰이 없습니다. 아래 세 단계를 `src/design/tokens.css`의 `--motion-*`로 두고 그것만 씁니다.

| 단계 | 쓰는 곳 | 시간 | 곡선 | 동작 줄이기 |
|---|---|---|---|---|
| 미세(micro) | 호버·초점·누름의 색·테두리·그림자, 체크 | 120ms | `cubic-bezier(0.2, 0, 0, 1)` | 색 변화만 남김 |
| 부품(component) | 목록 들고 남, 접힘·펼침, 메뉴·알림 등장, 숫자 바뀜 | 등장 200ms / 퇴장 160ms | 등장 위와 같음, 퇴장 `cubic-bezier(0.3, 0, 1, 1)` | 높이·위치 움직임 없음, 투명도는 즉시 |
| 화면(page) | 화면 전환, 시트·대화상자, 소개 화면 장면 | 300ms(소개 히어로만 최대 600ms) | `cubic-bezier(0.2, 0, 0, 1)` | 즉시 |
| 강조(1회) | 소개 화면의 시작 버튼 둘레 빛(`StartGlow`). 화면에 처음 들어올 때 한 번만, 호버·재진입에는 돌지 않음 | 한 바퀴 900ms + 사라짐 200ms | `linear` | 돌지 않음 |

- 강조(1회)는 한 화면에서 주 행동 버튼 하나에만 씁니다. 브랜드 한 색, 바깥 1.5px 고리, 번짐 6px 이내이고 버튼 자체의 색·모양은 바꾸지 않습니다. 로그인 후 화면에는 온보딩 완료 버튼 말고는 쓰지 않습니다.
- 무한 반복은 실제로 진행 중일 때만(불러오는 중, AI 실행 중). 로그인 후 장식 반복은 쓰지 않습니다.
- 지어낸 대기(일부러 늦추는 순차 등장)는 쓰지 않습니다.
- 연구 홈의 화면 안내(`HomeTour`)는 흐림 없이 어두운 면과 브랜드 색 고리로만 짚습니다. 고리와 설명 카드는 화면 단계(300ms)로 다음 자리에 옮겨 가고, 동작 줄이기에서는 바로 옮깁니다.
- 온보딩 소개는 자동으로 넘어갑니다(장 5초, 흐름 단계 6초). 한 번 끝까지 가면 멈추고 되풀이하지 않으며, 마지막 장과 질문 단계는 사람이 직접 넘깁니다. ‘자동 넘김 멈추기’ 버튼을 항상 두고, 단계를 직접 고르면 멈추고, 동작 줄이기에서는 켜지 않습니다. 남은 시간은 진행 막대나 단계 아래 줄로 보여 줍니다.
- 온보딩의 화면 그림은 전체 레이아웃을 먼저 보여 준 뒤 1초 머문 다음 그 단계의 핵심 컴포넌트로 천천히 확대해 들어갑니다(1.6초, 최대 2.6배, `lib/use-zoom-into.ts`). 확대된 동안 나머지는 `filter: blur(3px) brightness(0.78)`와 한 단계 어두운 바탕 면으로 약간 어둡고 흐리게 물러납니다(2026-11-11 사용자 요청). 이 흐림은 그림 안의 초점 표현에만 쓰고, 면 뒤를 비치는 유리 효과(`backdrop-filter`)는 계속 쓰지 않습니다.
- 온보딩(`/r/new`)은 단계마다 움직임으로 반응합니다(2026-11-11 사용자 요청). 단계 전환은 화면 단계(300ms, 가는 방향에서 32px), 소개 장면은 장마다 한 번 최대 600ms, 미리보기에 반영된 자리는 옅은 브랜드 면으로 한 번 짚습니다(900ms). 되풀이하지 않고, 동작 줄이기에서는 모두 끕니다.
- motion 라이브러리의 `reducedMotion="user"`는 이동·배치만 끕니다. 높이·투명도 애니메이션은 `useReducedMotion()`으로 직접 끕니다.
