## 0. 한눈에

화면을 본문과 여백으로 나눈다. 본문에는 학생이 쓰는 기록(미팅 메모, 피드백, 원고)을 두고 오른쪽 여백에는 그 기록에 붙는 것(연결된 기록, 교수 응답, 연구 도우미)을 둔다. 지도교수가 원고 여백에 의견을 적는 장면이 서비스 이름의 뜻이고 지금 피드백 상세의 오른쪽 AI 패널이 이미 이 구조의 시작이다. 새 장식을 얹으려는 계획이 아니다. 있는 구조를 규칙으로 올리고 나머지 화면을 그 규칙에 맞춘다.

## 3. 설계 방향

### 3.1 원칙

1. 본문과 여백. 내가 쓰는 기록은 본문에, 그 기록에 붙는 것은 오른쪽 여백에 둔다. 사이드바는 이동에만 쓴다.
2. 한 화면에 지금 할 일 하나. 주 행동은 화면 머리에 하나만 두고 상황에 따라 바뀐다.
3. 화면을 바꾸지 않는 질문은 묻지 않는다. 온보딩의 질문은 모두 홈의 어느 부분을 채운다.
4. AI가 없어도 완성된다. 지금은 AI 키가 비어 있다. 여백 패널은 AI 없이도 쓸모가 있어야 하고 AI 자리는 쓸 수 없다는 사실을 그대로 보여 준다.
5. 덜어서 위계를 만든다. 강조를 더하기 전에 같은 무게로 놓인 것을 줄인다.

### 3.2 참고 화면에서 가져올 것

사용자가 준 화면에서 구조와 원리를 가져오고 모양은 Montage로 다시 만든다.

| 서비스 | 가져올 구조 | 가져오지 않을 것 |
|---|---|---|
| Attio 온보딩 | 왼쪽에 질문 하나씩, 오른쪽에 작업 공간 미리보기. 처음에는 점선 뼈대이고 답할 때마다 이름, 메뉴, 표가 채워진다. 끝난 단계는 'n steps completed'로 접힌다. 마지막에 미리보기가 실제 화면이 된다. 사이드바의 'Getting started 0/6' | AI가 회사 정보를 조사해 자동으로 채우는 단계(마진은 AI 미연결이고 가짜 결과를 만들지 않는다), 체험 기간 안내 |
| Liner Scholar | 대화 화면에서 사이드바가 아이콘 레일로 줄어든다. 대화 오른쪽에 결과물·출처 카드. 라이브러리는 목록 + 오른쪽 상세 패널. 사이드바의 업데이트 팝오버 | 왼쪽 채팅 배치(7.1에서 비교), 에이전트 메뉴 8개 나열, 크레딧 충전 버튼 상시 노출, 저자·학술지 같은 서지 필드 |
| GitHub | 기능 안의 묶음은 상단 탭. 본문 + 오른쪽 메타 열. 설정은 왼쪽 하위 메뉴 2열. 목록 행은 제목 + 메타 한 줄 + 상태 | 탭 9개 수준의 밀도 |
| Modulify | 기능 첫 화면 위의 설명 띠(아이콘, 제목, 설명, 요점 3개). 설정 행은 설명 왼쪽, 조작 오른쪽. 위험 구역 분리. 사이드바 아래 카드 | 입력창 하나가 홈 전체인 구성, 업그레이드 카드 2장, 상시 채팅 위젯 |

## 4. 구조 설계

### 4.1 셸의 세 영역과 두 모드

> (IA v2 0단계에서 바뀜, 2026-11-19 구현 — 지금 기준 → [02 틀](ia-v2/02-shell.md) §1·§4) IA v2에서는 사이드바·레일·집중 모드 대신 상단 줄(메뉴 4개) + 본문 판 + 오른쪽 사이드 창(312px, 글 편집·자료 보기 440px) + 아이콘 줄 56px을 씁니다. 4.1~4.5는 지금 화면의 기준으로 남겨 둡니다.

```
┌ 사이드바 ┬───────── 본문 ─────────┬──── 여백 패널 ────┐
│ 232 / 60 │ 상단 줄(경로·도움·알림) │ 360 (320~400)     │
│          │ 화면 머리               │ 연결 · 응답 · 도우미 │
│          │ 내용                    │                   │
└──────────┴─────────────────────────┴───────────────────┘
```

- 둘러보기 모드: 사이드바 232px + 본문. 홈, 목록, 설정.
- 집중 모드: 레일 60px + 본문 + 여백 패널. 연구 도우미 작업대, 글쓰기 문서 편집, 미팅 기록 중, 검토 요청 상세.
- [확인] 60px 레일과 접기 버튼은 이미 있다(`WorkspaceShell.tsx:181`, 저장 키 `rms-sidebar-collapsed`). 새로 만드는 것은 모드에 따른 자동 접힘과 여백 패널이다.
- 자동 접힘 규칙: 집중 모드 화면에 들어가면 접고 나오면 원래대로 돌린다. 사용자가 집중 모드에서 직접 펼쳤다면 그 선택을 집중 모드용으로 따로 기억한다. 둘러보기 모드의 설정은 건드리지 않는다.

### 4.4 화면 원형

화면은 다섯 꼴 가운데 하나를 따른다. 화면 머리 순서는 화면 규칙 2절 그대로다.

| 꼴 | 구성 | 해당 화면 |
|---|---|---|
| 홈 | 머리(연구명, 현재 단계, 주 행동 1개) + 본문 열 + 옆 열 | 연구 홈 |
| 목록 | 머리 + 탭(있으면) + 도구 줄 + 목록. 행을 고르면 상세로 이동하거나(기본) 여백 패널에 미리보기(자료) | 미팅, 피드백·수정, 할 일, 자료, 검토 요청, 내 연구 |
| 상세 | 뒤로 + 제목·상태 + 메타 한 줄 + 탭 + 본문. 연결된 기록과 응답은 여백 패널 | 미팅 상세, 피드백 상세, 수정 결과 상세, 자료 상세 |
| 작업대 | 레일 + 넓은 본문 + 여백 패널. 머리는 한 줄로 줄인다 | 연구 도우미 대화, 글쓰기 편집, 미팅 기록 중 |
| 설정 | 왼쪽 하위 메뉴 + 폼. 행은 설명 왼쪽, 조작 오른쪽. 위험한 동작은 맨 아래 구역 | 연구 설정, 계정 |

빈 상태는 하나의 부품으로 통일한다 [제안]. 아이콘, 한 줄 제목, 이 화면에서 하는 일 요점 2~3개, 주 행동 하나가 들어간다. Modulify의 설명 띠는 늘 보이는 머리로 쓰지 않고 빈 상태와 첫 방문에만 쓴다. 늘 보이면 방문할 때마다 세로 공간을 쓴다. 지금 글쓰기 빈 화면은 머리에 버튼 둘, 본문에 같은 버튼 하나가 더 있다 [확인].

### 4.5 여백 패널

- 폭 360px(1600 이상 400). 크기 조절 손잡이는 두지 않는다.
- 여는 곳: 상단 줄 오른쪽의 패널 버튼, 단축키 하나(구현 때 기존 G 단축키와 겹치지 않게 정한다), 본문 안의 관련 버튼(예: 수정 방법의 'AI 제안').
- 탭은 화면에 따라 최대 세 개다.

| 탭 | 내용 | 나오는 화면 |
|---|---|---|
| 연결 | 이 기록과 이어진 미팅, 피드백, 할 일, 자료, 수정 결과 | 상세 화면 전부 |
| 응답 | 교수 결과와 댓글 | 수정 결과, 검토 요청 |
| 도우미 | 지금 기록을 근거로 넣은 연구 도우미 | AI를 쓸 수 있는 화면 전부 |

- 닫으면 본문이 원래 폭으로 돌아온다. 열림 상태는 화면 꼴별로 기억한다.
- 초점: 열면 패널의 첫 조작 요소로, 닫으면 연 버튼으로 돌아온다(대화상자 래퍼와 같은 규칙). 덮는 시트일 때만 Esc로 닫는다.
- 면: 본문과 같은 작업 면(`--surface`)에 왼쪽 선 하나. 그림자는 덮는 시트일 때만.

## 5. 온보딩

### 5.1 언제 뜨나

- 로그인했는데 연구가 하나도 없을 때. 지금의 빈 '내 연구' 목록과 대화상자를 대신한다.
- 연구를 더 만들 때도 같은 화면을 쓴다. 이름만 적고 나머지는 건너뛸 수 있다.
- 교수 계정에는 뜨지 않는다. 교수는 검토 링크로만 들어온다.
- 가입 미리보기 화면은 그대로 둔다. 온보딩이 계정 발급처럼 보이면 안 된다 [결정].
- 화면마다 '건너뛰고 빈 연구로 시작'이 있다. 누르면 이름만 받고 홈으로 간다.

### 5.2 질문 세 개

> 2026-11-10 변경: 네 번째 질문 "이 연구로 무엇을 밝히려 하나요?"(연구 목적·연구 질문, 건너뛰기 가능)를 더했다. 16절 참고.

| # | 질문 | 입력 | 미리보기에서 채워지는 곳 | 저장되는 곳(기존 데이터) | 건너뛰면 |
|---|---|---|---|---|---|
| 1 | 어떤 연구를 하고 있나요? | 연구 이름(필수), 한 줄 설명(선택) | 사이드바의 연구 이름, 홈 제목과 설명 | `saveResearch`의 name, description (`AuthPages.tsx:225`) | 건너뛸 수 없음 |
| 2 | 지금 어느 단계인가요? | 여섯 단계 가운데 하나(주제 정의, 선행연구, 연구 설계, 자료 수집·분석, 집필, 최종 수정·제출) 또는 '나중에 정할게요' | 홈 머리의 현재 단계, 계획·일정의 단계 줄 | 기본 단계(`phaseTitles`, `domain.ts:289`)를 만들고 고른 단계를 현재 단계로 지정 | 단계를 만들지 않는다. 계획·일정은 지금의 빈 상태 그대로 |
| 3 | 다음 지도 미팅은 언제인가요? | 날짜·시간 / 아직 안 잡혔어요 / 방금 미팅을 마쳤어요 | 주간 띠의 점, 다음 미팅 카드, 홈의 주 행동 | 미팅 한 건. 날짜가 없으면 날짜 미정 미팅(지원됨, `MeetingsPage.tsx:59`). '방금 마쳤어요'는 오늘 날짜의 미팅 | 미팅을 만들지 않는다. 홈의 주 행동은 '미팅 만들기' |

3번이 가장 중요하다. 답에 따라 홈에서 처음 할 일이 갈린다.

- 날짜가 있다 → 주 행동 '미팅 준비하기'
- 방금 마쳤다 → 주 행동 '미팅 기록 남기기'(메모를 붙여넣는 화면으로)
- 아직 없다 → 주 행동 '미팅 만들기'. 체크리스트는 피드백 적어 두기부터 안내한다

### 5.3 묻지 않는 것

| 묻지 않는 것 | 이유 |
|---|---|
| 전공, 학위 과정, 학교 | 화면을 바꾸지 않는다 |
| 지도교수 이메일 | 처음부터 물으면 무언가 전송될 것 같아 망설인다 [가설]. 검토 요청을 만들 때 묻는다 |
| 공동연구자 초대 | 혼자 시작하는 것이 기본이다. 홈 머리의 초대 버튼이 이미 있다 |
| 학생·교수 역할 | 교수는 이 화면에 오지 않는다 |
| AI 사용 여부, 테마 | 설정에 있고 기본값으로 충분하다 |
| 자료 올리기 | 온보딩을 길게 만든다. 체크리스트의 한 항목으로 둔다 |

PRD의 첫 번째 위험이 정리 부담을 줄이려다 입력과 확인 절차가 늘어나는 것이다. 질문은 세 개에서 늘리지 않는다.

```
│ 어떤 연구를 하고 있나요?   │   │ ░ 미팅             ░░░░░░░░░░    │ │
│ [ 연구 이름            ]  │   │ ░ 피드백·수정      ┌─────────┐   │ │
│ [ 한 줄 설명(선택)     ]  │   │ ░ 할 일            │ ░░░░░░  │   │ │
│                          │   │                    └─────────┘   │ │
│ [ 계속 ]                  │   └─────────────────────────────────┘ │
│ 건너뛰고 빈 연구로 시작    │   오른쪽은 미리보기예요.               │
└──────────────────────────┴──────────────────────────────────────┘
   왼쪽 40%(최대 480px)          오른쪽 60%, 옅은 바탕 위의 창
```

- 왼쪽: 진행 표시(1/3), 질문 하나, 입력, '계속' 버튼, 건너뛰기. 끝난 질문은 한 줄 요약으로 접히고 누르면 고칠 수 있다.
- 오른쪽: 실제 홈을 줄인 창. 누를 수 없고 보조 기술에서는 숨긴다(`inert`, `aria-hidden`). 화면 낭독기에는 왼쪽에서 답이 반영됐다는 문장을 읽어 준다.
- 991px 이하는 위아래로 쌓는다. 미리보기는 질문 위 160px 높이의 띠로 줄이고 마지막 화면에서만 크게 보여 준다.
- 사이드바와 상단 줄은 없다. 왼쪽 위에 로고만 둔다.

### 5.5 미리보기가 채워지는 순서와 홈으로 커지기

1. 처음: 점선 뼈대. 사이드바 줄, 제목 자리, 카드 자리만 보인다.
2. 1번 답: 연구 이름이 사이드바와 제목 자리에 글자로 들어간다. 입력하는 동안 바로 반영한다.
3. 2번 답: 머리에 현재 단계가 생기고 단계 줄이 한 칸 채워진다.
4. 3번 답: 주간 띠에 점이 찍히고 다음 미팅 카드에 날짜와 남은 일수가 들어간다. 주 행동 버튼의 글자가 정해진다.
5. 마지막: '내 연구 홈으로' 버튼이 켜진다. 누르면 미리보기 창이 화면 전체로 커지면서 실제 홈이 된다.

- 채워지는 움직임은 부품 단계(등장 200ms)다. 일부러 늦추는 순차 등장은 쓰지 않는다 [결정].
- 홈으로 커지는 전환은 화면 단계다. 브라우저의 화면 전환 기능(View Transitions API)으로 미리보기 창과 실제 셸을 같은 요소로 이어 준다. 지원 범위는 구현할 때 MDN에서 확인하고 지원하지 않는 브라우저와 동작 줄이기 설정에서는 200ms 페이드로 대신한다.
- 미리보기는 앱 토큰으로 새로 만든다. 소개 화면의 `lp-` 클래스를 빌려 쓰지 않는다(디자인 기준 2절 4번).
- 저장은 마지막 버튼을 누를 때 한 번에 한다. 그전에는 아무것도 만들지 않는다. 저장에 실패하면 입력을 그대로 두고 같은 자리에서 다시 시도하게 한다.

### 5.6 시작 체크리스트

온보딩이 끝난 홈 맨 위와 사이드바 아래 자리에 '시작하기 0/4'를 둔다.

| 항목 | 끝난 것으로 보는 조건(기존 데이터에서 계산) |
|---|---|
| 미팅 기록 남기기 | 메모나 녹음이 있는 미팅 1건 이상 |
| 피드백 한 건 정리하기 | 피드백 1건 이상 |
| 할 일 만들기 | 할 일 1건 이상 |
| 원고나 자료 올리기 | 문서 또는 자료 1건 이상 |

- 새 저장 항목을 만들지 않는다. 완료 여부는 있는 기록에서 계산하고 접은 상태만 브라우저에 연구별로 기억한다. DB 마이그레이션이 필요 없다.
- 4/4가 되면 사라진다. 그전에도 닫을 수 있다.
- 검토 요청은 넣지 않는다. 빈 연구에 검토부터 요구하지 않는다는 기능 명세의 요구를 따른다.

### 5.7 문구 초안

해요체, 용어표를 따른다. 확정 전 초안이다.

| 자리 | 문구 |

| 질문 1 도움말 | 지도받는 연구마다 하나씩 만들어요. 이름은 나중에 바꿀 수 있어요. |
| 질문 2 | 지금 어느 단계인가요? |

## 6. 연구 홈

홈은 이번 미팅 주기의 화면이다. 상황에 따라 주 행동 하나가 머리에 올라온다.

| 상황 | 주 행동 | 맨 위 카드 |
|---|---|---|
| 새 연구(체크리스트 미완료) | 체크리스트의 다음 항목 | 시작하기 |
| 확인할 교수 응답이 있다 | 응답 확인하기 | 확인할 내용 |
| 오늘 미팅이 있다 | 기록 시작 | 다음 미팅 |
| 미팅이 며칠 남았다 | 미팅 준비하기 | 다음 미팅(준비 진행 포함) |
| 미팅 기록은 끝났고 정리한 피드백이 없다 | 피드백 정리하기 | 지난 미팅 |
| 예정된 미팅이 없다 | 미팅 만들기 | 남은 할 일 |

배치(1200px 이상).

```
연구 이름 · 현재 단계 ▸                         [ 주 행동 ]
설명 한 줄 · 공동연구자 초대
┌ 본문 열 ───────────────────┐ ┌ 옆 열 320 ──────┐
│ 다음 미팅(강조 카드, 하나)   │ │ 확인할 내용      │
│  준비할 일 1/3 · 자료 · 질문 │ │ 이번 주(주간 띠) │
│ 남은 할 일                  │ │ 최근 문서        │
└────────────────────────────┘ └────────────────┘
```

| 카드 | 처리 | 이유 |
|---|---|---|
| 다음 미팅 | 유지, 본문 열 맨 위 | 핵심 과업 |
| 남은 할 일 | 유지 | |
| 확인할 내용 | 유지. 있을 때는 옆 열 맨 위, 주 행동으로도 올라온다 | [결정] Q6 순서의 첫 번째 |
| 주간 띠 | 유지하되 옆 열로 옮기고 높이를 줄인다 | 다음 미팅 카드와 정보가 겹친다 |
| 최근 문서 | 유지, 옆 열 | |
| 연구 도우미 홍보 카드 | 제거 | 여백 패널 버튼이 대신한다. AI가 연결되지 않은 지금은 누를 이유가 없는 카드다 |
| 최근 활동 | 공동연구자가 있을 때만 | 혼자 쓰는 연구에서는 늘 빈 안내다 |
| 바로 시작 | 할 일도 미팅도 없을 때만 | 주 행동과 체크리스트가 대신한다 [14절 D4] |
| 연구 단계 | 머리의 현재 단계 표시로 흡수 | 카드 하나를 쓸 정보량이 아니다 |

카드가 9개에서 5개로 준다. 목표 높이는 1440px에서 화면 1.5배 이내다(측정해서 확인).

## 7. 연구 도우미

### 7.1 어디에 둘 것인가

> (IA v2 4단계에서 바뀜, 2026-11-19 구현 — 지금 기준 → [06 연구 도우미](ia-v2/06-assistant.md) §2) IA v2에서 연구 도우미는 전체 화면 작업대를 두지 않고 어느 화면에서나 오른쪽 사이드 창의 첫 탭으로 엽니다(지금 `/r/:id/assistant`는 `?panel=assistant`로 이동). 기록을 고르는 화면은 없고 이 연구의 기록을 항상 전부 읽습니다(D13, #99). 7.3 작업대는 지금 화면의 기준으로만 남깁니다.

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A. 지금처럼 | 전체 화면 대화 + 피드백 상세 패널 | 바꿀 것이 없다 | 표면이 둘이고 근거가 안 보인다 |
| B. 오른쪽 여백 패널 + 작업대 (권고) | 어느 화면에서든 오른쪽 패널로 연다. 긴 대화는 작업대 화면 | 지금 패널과 같은 쪽이다. 본문(내 기록)이 왼쪽에 남는다. IA 기준안(필요한 자리에서 연다)과 맞는다 | 셸을 고쳐야 한다 |
| C. 왼쪽 채팅(Liner 문서 편집 방식) | 왼쪽 대화, 오른쪽 문서 | 문서를 AI가 만들어 주는 서비스에 맞는다 | 마진에서는 학생의 기록이 본문이고 AI는 덧붙는 쪽이다. 사이드바와 대화가 왼쪽에 겹친다. 기존 패널과 방향이 반대다 |

B를 권한다. 판단을 바꿀 조건: 글쓰기에서 AI가 초안을 직접 만들어 주는 기능이 중심이 된다면 C를 글쓰기 화면에 한해 다시 검토한다.

### 7.2 패널의 도우미 탭

```
┌ 연구 도우미 ──────────────── × ┐
│ 근거 2개                  바꾸기 │
│  ▪ 이 피드백                    │
│  ▪ 제5차 논문 지도 메모          │
│ ─────────────────────────────── │
│ (대화 또는 제안 카드)            │
│ ─────────────────────────────── │
│ [ 질문을 적어 주세요         ↑ ] │
│  수정 방법 제안 ▾                │
└─────────────────────────────────┘
```

- 근거가 늘 위에 보인다. 지금 화면의 기록은 자동으로 근거에 들어가고 '바꾸기'를 누르면 같은 패널 안에서 목록을 고른다. 모달을 쓰지 않는다.
- 원문, AI 제안, 가정을 나눠 보여 주는 기존 규칙은 그대로다 [결정].
- 선택한 제안만 기록에 남는다는 안내는 제안 카드의 버튼 옆에 둔다.

### 7.3 작업대

```
┌레일┬──────────── 대화 ─────────────┬── 여백 패널 ──┐
│ 60 │ 연구 도우미 · 나만 보는 공간   │ 근거 │ 제안 │ 기록 │
│    │ [대화 기록 ▾]  [새 대화]       │                │
│    │                               │ ▪ 고른 기록 목록 │
│    │   (대화, 최대 폭 720)          │ ▪ 확인할 제안    │
│    │                               │ ▪ 실행 기록      │
│    │ [ 입력창                    ] │                │
└────┴───────────────────────────────┴────────────────┘
```

- 대화 목록 열을 없애고 머리의 '대화 기록' 메뉴로 옮긴다. 대화가 720px 폭을 온전히 쓴다.
- 지금의 'AI 제안' 탭 내용(확인할 제안, 실행 기록)은 패널의 제안·기록 탭이 된다.
- '사용량' 탭은 없애고 계정 설정의 사용량으로 가는 링크만 남긴다.

### 7.4 입력창

- 지금: 첨부, 요청 종류, 모델, 보내기 네 개가 한 줄 [확인].
- 바꾼 뒤: 입력, 요청 종류, 보내기. 근거 고르기는 패널 위로 올라갔다. 모델 고르기는 고를 모델이 둘 이상일 때만 요청 종류 옆에 보인다. 연결 전에는 모델 이름을 지어내 보여 주지 않는다 [결정].
- 한글 조합 중 Enter로 보내지 않는 기존 처리는 유지한다.

### 7.5 AI를 쓸 수 없을 때

지금이 이 상태다. 도우미 탭은 다음처럼 보인다.

- 한 줄 안내: 지금은 연구 도우미를 쓸 수 없어요. 직접 작성은 그대로 할 수 있어요.
- 입력창은 꺼진 모양으로 두고 이유를 옆에 적는다.
- 본문의 AI 버튼(예: 'AI 제안')은 보조 버튼 크기를 유지하고 '직접 작성'이 주 행동이 된다.
- 진행률, 예상 시간, 예시 답변을 만들어 보여 주지 않는다.

### 7.6 정리되는 것

| 지금 | 바꾼 뒤 |
|---|---|
| 연구 도우미 탭 3개(대화, AI 제안, 사용량) | 작업대 한 화면 + 패널 탭 |
| 피드백 상세의 `ai-workbench` | 여백 패널의 도우미 탭 |
| 자료 선택 모달 | 패널의 근거 목록 |
| 홈의 연구 도우미 카드 | 상단 줄의 패널 버튼 |

| 계획·일정 | 탭(로드맵, 캘린더, 시간 조율), 보기 전환 | 빈 상태 통일. 탭마다 주 행동 이름을 맞춘다(1차 QA P2-18) | |
| 연구 설정·계정 | 왼쪽 하위 메뉴 2열 | 행을 설명 왼쪽·조작 오른쪽으로. 보관·삭제는 맨 아래 위험 구역 | |

## 9. 시각 규칙

색 역할과 글자 위계 여섯 단계는 화면 규칙 1절을 그대로 쓴다. 아래는 거기에 없는 것만 정한다 [제안]. 승인되면 `patterns.md`에 옮긴다.

### 9.1 면, 보더, 필, 그림자

| 쓰임 | 처리 | 예 |
|---|---|---|
| 바탕 | `--canvas`, 선과 그림자 없음 | 셸 뒤 |
| 작업 면 | `--surface` + 1px 선(`--line`), 그림자 없음 | 사이드바, 본문, 여백 패널 |
| 묶음(카드) | 1px 선, 채움 없음, 그림자 없음 | 홈 카드, 목록 상자 |
| 묶음 안의 약한 구분 | 채움(`--surface-muted`), 선 없음 | 인용한 원문, 근거 목록, 표 머리 |
| 묶음 안의 항목 구분 | 가로 선 | 목록 행, 설정 행 |
| 떠 있는 면 | `--surface-raised` + 그림자, 라이트에서는 선 없음 | 메뉴, 팝오버, 입력창, 알림 |
| 강조 카드 | 브랜드 선(`--selected-line`) 1px, 채움과 그림자 없음. 한 화면에 하나 | 홈의 다음 미팅 |
| 선택·현재 위치 | `--selected-fill` + 브랜드 글자 | 사이드바 현재 메뉴 |

- 한 요소에 보더, 색 채움, 그림자를 함께 쓰지 않는다. 지금 홈의 다음 미팅 카드는 파란 선 + 그림자, 도우미 카드는 파란 선 + 파란 채움이다 [확인].
- 상자 안의 상자는 두 겹까지. 카드 안에서는 상자를 더 만들지 않고 선이나 채움으로 나눈다.
- 그림자는 두 단계만 쓴다. 떠 있는 면은 small, 대화상자와 시트는 large. 지금은 다섯 단계가 쓰인다 [확인].

### 9.2 모서리

| 단계 | 값 | 쓰는 곳 |
|---|---|---|
| 셸 | 16 | 사이드바, 본문, 여백 패널, 대화상자 |
| 묶음 | 12 | 카드, 목록 상자, 입력창 |
| 조작 | Montage 부품 값 그대로 | 버튼, 입력, 메뉴 항목 |
| 작은 표시 | 6 또는 알약 | 배지, 칩 |

안쪽 모서리가 바깥보다 작아야 겹쳤을 때 고르게 보인다. 지금은 셸과 카드가 같은 16px이고 본문 셸만 14px이다 [확인]. 쓰는 토큰이 9종에서 4종으로 준다.

### 9.3 글자

| 역할 | 목표 크기 | 비고 |
|---|---|---|
| 화면 제목 | 24 | |
| 구역 제목 | 18 | 지금 홈 17px [확인] |
| 카드 제목 | 16 | 강조 카드의 제목만 20 |
| 본문 | 15 | |
| 보조 | 14 | |
| 메타 | 13 | 최소 12. 11px 이하는 쓰지 않는다 |

px는 목표값이고 구현할 때 Montage 타이포 토큰 가운데 가장 가까운 것을 고른다. 홈에서 12px 이하 글자의 비율(지금 79개 중 29개)을 절반 아래로 줄이는 것을 목표로 둔다. 글자를 키우는 것만으로는 안 되고 메타 정보의 개수부터 줄여야 한다.

### 9.4 크기와 밀도

| 자리 | 조작 높이 |
|---|---|
| 공개 화면 주 행동 | 48 |
| 화면 머리의 행동 | 40 |
| 도구 줄, 거르기 | 32 |
| 행 안의 행동 | 28~32 |
| 767px 이하 | 최소 40, 주 행동 44 이상 |

목록 행 높이는 두 줄 정보일 때 64~72px, 한 줄일 때 48px. 카드 안쪽 여백은 24px(767px 이하 16px).

### 9.5 색

- 역할표를 그대로 쓴다. 새 색을 만들지 않는다 [결정].
- 브랜드 색 채움은 주 버튼과 선택 표시에만 쓴다. 카드 배경에 브랜드 색을 깔지 않는다.
- AI 표시는 아이콘과 '연구 도우미' 이름으로 한다. AI 전용 색이나 그라데이션은 두지 않는다.

### 9.6 효과

- 구름 셰이더는 공개 화면 히어로에만 [결정].
- 로그인 후에는 그라데이션, 흐림, 유리 효과를 쓰지 않는다. 상단 줄의 반투명은 스크롤 때 내용이 비치는 용도로만 남긴다.

### 9.7 움직임

세 단계는 그대로 쓰고 이름 붙은 장면 두 개를 더한다.

| 장면 | 내용 | 단계 |
|---|---|---|
| 온보딩에서 홈으로 | 미리보기 창이 화면 전체로 커진다 | 화면(300ms). 동작 줄이기에서는 즉시 |
| 시작하기 테두리 빛 | 주 버튼 바깥 1.5px 고리에 브랜드 파랑 빛이 한 바퀴 돌고 사라진다 | 새 규칙 필요 [D6] |

시작하기 테두리 빛의 상세 [제안].

- 어디에: 소개 히어로의 '시작하기', 소개 맨 아래 '마진 시작하기', 온보딩의 '내 연구 홈으로'.
- 언제: 히어로는 제목이 자리 잡은 뒤 한 번. 맨 아래 버튼은 화면에 들어올 때 한 번. 온보딩 버튼은 켜지는 순간 한 번. 호버에는 돌지 않는다.
- 모양: 버튼을 감싼 요소에 고리를 그린다. 버튼 자체의 모양은 덮지 않는다(디자인 기준: `data-slot="button"`으로 모양을 덮지 않음). 호 길이는 고리의 4분의 1, 색은 브랜드 토큰 한 가지, 번짐은 6px 이내.
- 시간: 한 바퀴 900ms + 사라짐 200ms. 되풀이하지 않는다.
- 동작 줄이기: 돌지 않는다.
- 판단: 도는 테두리 빛은 AI 제품에서 흔해 가볍게 보일 위험이 있다. 그래서 단색, 1회, 얇게로 제한한다. 온보딩 버튼은 상태가 바뀌는 순간과 맞물려 뜻이 있고 히어로는 장식에 가깝다. 하나만 고른다면 온보딩 쪽을 권한다.
- 화면 규칙 3절은 소개 히어로만 최대 600ms라고 적고 있어 900ms는 규칙을 넘는다. 승인되면 '강조(1회)' 줄을 더한다.

### 9.8 아이콘

- 한 묶음으로 맞춘다. 우선순위는 낮다(P2).

## 11. 검증

### 11.1 자동 검사

```bash
python3 scripts/check_repository.py
cd apps/home-preview
npm run typecheck
npm run test
npm run test:backend
npm run test:sites
npm run build
```

화면 회귀는 `apps/home-preview/scripts/qa/screens.mjs`의 `capture`와 `compare`를 쓴다. 온보딩 화면과 패널이 열린 상태를 `routes.mjs`에 더하고 768px에서 조작 요소 폭 24px 미만을 잡는 검사가 2절 3번을 잡는지 먼저 확인한다.

### 11.2 화면 확인

- 너비 360, 390, 768, 1024, 1440. 라이트와 다크.
- 상태: 빈 화면, 로딩, 저장 실패, 긴 제목, AI를 쓸 수 없을 때, 동작 줄이기.
- 키보드: 온보딩 전체, 패널 열고 닫기, 초점이 돌아오는 자리.
- 사람 눈으로 보는 최종 확인은 사용자가 한다 [결정].

### 11.3 사람 대상 확인

아직 하지 않았다. 대학원생 5명 안팎, 한 사람 30분을 제안한다.

| 과제 | 보는 것 |
|---|---|
| 처음 들어와 연구를 만들고 오늘 미팅 메모를 남긴다 | 온보딩에 걸린 시간, 건너뛴 질문, 홈에서 처음 누른 곳 |
| 피드백 한 건의 수정 방법을 정하고 할 일로 만든다 | 누른 횟수, 막힌 곳, 헷갈린 말 |
| 교수 응답을 확인하고 고칠 곳을 찾는다 | 홈에서 응답까지 가는 길 |
| 연구 도우미가 무엇을 읽고 답했는지 말해 본다 | 근거를 찾는 데 걸린 시간 |

진행 방법 [제안]. 사람이 직접 해야 하고 AI가 대신할 수 없다.

1. 미리보기 모드(로그인 없이 가상 기록)로 진행한다. 실제 연구 자료와 마이크는 쓰지 않는다.
2. 과제마다 시작 화면을 정해 둔다: 첫 과제는 `/r/new`, 둘째는 데모 연구의 피드백 상세, 셋째는 연구 홈, 넷째는 연구 도우미.
3. 과제 동안 말을 걸지 않고 화면 녹화와 누른 곳만 기록한다. 끝난 뒤 헷갈린 말과 기대와 달랐던 곳을 묻는다.
4. 이번에 새로 넣은 것 가운데 꼭 볼 것: 피드백 진행 줄을 완료율로 읽는지, 여백 패널이 열릴 때 왼쪽 메뉴가 접히는 것을 알아채는지, ‘근거 n개’ 버튼으로 근거를 바꾸는 길을 찾는지, 자료 목록에서 미리보기와 전체 화면을 구분하는지.
5. 다섯 명 가운데 세 명 이상이 막힌 곳만 고친다. 한두 명의 의견은 기록만 한다.

소개 화면은 5초 보여 준 뒤 무엇을 하는 서비스인지 적게 한다. 목표 수치는 지금 화면으로 먼저 재고 나서 정한다(PRD의 방침과 같다).

### 11.4 단계별 완료 기준

- P1: 768px 홈에서 날짜 버튼 폭 24px 이상, 제목이 글자 단위로 끊기지 않는다. 소개 카드에 올려도 그림이 바뀌지 않고 카드 어디를 눌러도 기능 둘러보기로 간다.
- P2: 홈 카드 5개 이하, 여섯 상황 모두에서 머리의 주 행동이 하나다. 1440px 높이가 화면 1.5배 이내다.
- P3: 연구가 없는 계정이 온보딩으로 들어간다. 이름만 적고 끝낼 수 있다. 세 답이 홈에 그대로 보인다. 저장 실패 때 입력이 남는다.
- P4: 다섯 너비에서 4.2의 표대로 배치된다. 패널을 닫으면 연 버튼으로 초점이 돌아온다.
- P5: 도우미를 여는 길이 패널 하나다. 근거 목록이 답과 같은 화면에 보인다. AI를 쓸 수 없을 때 가짜 내용이 없다.
