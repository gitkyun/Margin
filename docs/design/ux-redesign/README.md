## 작업 환경과 토큰 사용 (11/13 점검)

확인한 사실
- Graphify 0.9.108 설치됨(`~/.local/bin/graphify`, 스킬 있음). 이 저장소에는 그래프(`graphify-out/`)가 아직 없다.
- Headroom 0.44.0 설치됨. 프록시는 꺼져 있고(127.0.0.1:8787 응답 없음) `ANTHROPIC_BASE_URL`이 api.anthropic.com을 가리킨다. `headroom doctor`는 "Claude 데스크톱 앱의 세션은 프록시를 거치지 않는다(앱이 주소를 덮어씀)"고 보고한다. MCP 서버로는 `~/.claude.json`에 등록돼 있으나 이 세션의 도구 목록에는 올라오지 않았다. 즉 지금은 압축이 전혀 일어나지 않는다.
- Ponytail은 실행 파일이 아니라 스킬(`~/.claude/skills/ponytail`)이다. 설치돼 있다.
- 켜진 플러그인 15개. 플러그인별 스킬 파일 수: ecc 810, mattpocock 38, claude-mem 30, bmad 29, pm-skills 66, 그 외 소수. 세션마다 스킬 목록이 시스템 지침에 실린다.
- 이 세션 측정값(진단 끝 무렵): 컨텍스트 345,723 토큰 가운데 대화 273,358, 시스템 도구 17,462, MCP 도구 15,997, 시스템 지침 13,156, 스킬 9,759, 메모리 파일 8,633. 주간 한도는 전체 63%, Fable 97% 사용.

토큰이 새는 곳 (위 수치와 이번 작업 기록에서)
1. 대화 이력이 전체의 79%다. 한 세션에서 가입·카카오·AI 설정과 UX 진단을 이어서 했기 때문이다. 주제가 바뀌면 새 세션으로 시작하는 것이 가장 크게 준다.
2. 고정 비용(도구·지침·스킬·메모리)이 턴마다 약 65,000 토큰이다. 이 가운데 쓰지 않는 플러그인(pm-skills 8개, bmad 2개, vercel, figma 등)의 목록이 포함된다.
3. 가장 비싼 모델(Fable)로 반복 클릭·기록 작업을 했다. 전수 클릭은 정해진 절차라 가벼운 모델로도 된다.
4. GateGuard 훅이 새 파일의 첫 쓰기를 한 번 거부해서 긴 문서를 두 번 보내게 된다(이번에 보고서 1건이 그랬다).
5. 화면 캡처보다 요소 목록을 글자로 읽는 방식이 훨씬 쌌다(캡처 1장 ≈ 요소 40개 목록과 비슷한 비용인데 정보는 목록이 많다). 이번 진단은 중간부터 이 방식으로 바꿨다.

권장 구성 (적용하지 않았다. 설정을 바꾸는 일이라 승인이 필요하다)
- 이 재설계 작업은 새 세션에서 이어 간다. 시작할 때 이 `README.md`만 읽게 한다.
- 탐색·전수 클릭·문서 정리는 Sonnet, 설계 판단과 최종 검토만 상위 모델로 나눈다(`~/.claude/settings.json`의 기본 모델은 이미 sonnet이다).
- 이 프로젝트에서 쓰지 않는 플러그인을 프로젝트 설정으로 끈다: pm-skills 8개, bmad 2개. 복구는 같은 설정에서 다시 켜면 된다.
- Graphify: 구현 단계(4단계) 들어가기 전에 `graphify update apps/home-preview/src`로 코드 그래프를 한 번 만든다(LLM 호출 없음). `graphify-out/`은 `.gitignore`에 추가해야 한다. 진단 단계에서는 화면을 직접 눌렀으므로 쓰지 않았다.
- Headroom: 데스크톱 앱 세션에서는 프록시가 적용되지 않으므로 지금 구성에서는 효과가 없다. 터미널의 `claude`를 `headroom wrap claude`로 쓸 때만 의미가 있다. 데스크톱 앱을 계속 쓴다면 MCP 등록만 남기거나 꺼 둔다.
- GateGuard: `docs/**/*.md`를 `GATEGUARD_EXEMPT_GLOBS`에 넣으면 문서 이중 전송이 없어진다.
- 세 도구가 서로 충돌하는 곳은 찾지 못했다. Headroom과 claude-mem은 둘 다 "기억" 기능이 있어 겹치지만 Headroom 쪽은 지금 동작하지 않는다.
