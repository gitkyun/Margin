# 마진 전체 점검 (2026-11-14)

기획부터 화면 세부까지 한 번에 다시 본 결과다. 고칠 항목은 9절에 번호를 붙였다. 사용자가 번호별로 허락한 것만 고친다.

## 근거와 표기

- 스크린샷: 이 세션에서 찍은 마진 화면 174장(로컬 미리보기 165장, 운영 9장)을 한 장씩 다시 읽었다. 사진 번호는 `scratchpad/margin_shots.txt`의 번호다. 11/10~11/11에 찍은 1~130번은 그 뒤 PR #44~#79가 들어가서, 지금 화면에서 다시 확인한 것만 문제로 남겼다.
- 지금 화면: 로컬 미리보기(`main` `5e033bd`)에서 360~1440px, 라이트·다크로 다시 눌러 봤다.
- 코드 점검 2건: 디자인 시스템(색·글자·간격·중단점·부품), 한국어 문구(AI 티·용어·중복).
- 레퍼런스: [ref-log.md](ref-log.md)(Liner·매니패스트·GitHub·토스·Linear), [feature-matrix.md](feature-matrix.md).
- 앞선 진단: [findings.md](findings.md)(구조 문제 S1~S7, 오류 B1~B13). 겹치는 것은 그 번호를 함께 적었다.
- 표기: [화면] 지금 화면에서 확인 / [코드] 소스에서 확인 / [사진] 사진에만 있고 지금은 다시 못 봄 / [추정] 해석 / [제안] 고칠 방향.

## 0. 결론

1. 기능은 다 있는데, 서로 이어 주는 장치가 약하다. 미팅 시간이 지나도 화면이 바뀌지 않고, 결과를 받은 뒤 다음 행동이 없다. 같은 곳으로 가는 문은 둘 이상이다.
2. 화면마다 설명이 너무 많다. 제목 아래 설명이 제목을 되풀이하고, 같은 안내가 한 화면에 세 번 나온다. 사람들이 "AI가 만든 것 같다"고 느끼는 가장 큰 원인이 이것이다.
3. 디자인 시스템은 색만 토큰이고 나머지는 화면별 숫자다. 간격 직접값 1,480줄, 중단점 10종, 빈 상태 15종 이상, 확인 창 구현 8가지.
4. 익숙함에서 가장 크게 어긋나는 것은 넷이다. 상단 줄의 언어 버튼, 브라우저 기본 오류 말풍선, 댓글을 고치거나 지울 수 없는 점, AI 답 아래에 버튼이 없는 점. 레퍼런스 다섯 곳 어디에도 이런 곳은 없었다.

## 2. UX: 자유도·피드백·막힌 길

- 입력 오류: 입력 양식 39개 중 35개가 브라우저 기본 말풍선("이 입력란을 작성하세요.")으로 막는다. `required` 74곳, `noValidate` 4곳. 앱이 준비한 오류 문구("미팅 이름을 입력해 주세요." 등)는 말풍선에 가려 나오지 않는다. 가입은 '8자 이상'이라고 써 놓고 3자를 받는다. [코드][화면] 사진 097
- 비활성 이유: 로딩이 아닌 비활성 버튼 30곳 중 이유가 붙은 곳은 1곳뿐이다. 'AI로 메모 정리'는 메모가 비면 꺼지는데, 이유를 알려 줄 문구는 버튼이 눌려야 뜨게 돼 있어서 영영 안 뜬다. [코드]
- 저장: 글쓰기는 '저장됨'이라고 쓰여 있는데 '저장' 주 버튼이 켜져 있다. 미팅은 탭만 바꿔도 '이 브라우저에 저장됨' 알림이 뜬다(B4). 교수 응답의 '변경 내용 저장'은 아무것도 바꾸지 않아도 켜져 있다. [화면]
- 확인 창: 공통 확인 창이 없다. 손으로 만든 창 5곳 이상과 `window.confirm` 3곳이 섞여 있고, 휴지통 확인 창은 입력 칸과 버튼이 붙어 있다. [코드][사진 114·117]
- 댓글: 답글·해결만 있고 수정·삭제·링크 복사가 없다. 해결한 댓글도 접히지 않는다. GitHub·Linear·매니패스트는 셋 다 있다. [화면] 관찰 기록 U
- 좋은 점: 대화상자·메뉴·사이드바·⌘K는 모두 Esc로 닫히고 초점이 원래 버튼으로 돌아온다. 매니패스트는 설정 창이 Esc로 닫히지 않았다. [화면]

## 4. 레이아웃과 반응형

- 상단 줄이 92% 불투명이고 흐림 처리가 없어 스크롤하면 본문 글자가 비친다. 같은 요소를 세 파일이 덮어써서 마지막 파일(`reference.css:162`)의 값이 남는다. [화면][코드] 사진 005·094·100·162·168
- 768~1199px에서 펼친 사이드바가 본문을 덮는데 뒤가 어두워지지 않는다(`.sidebar-backdrop` 투명). Esc와 바깥 클릭으로는 닫힌다. 오른쪽 시트의 어둡게 처리는 정의되지 않은 토큰이라 항상 하드코딩 값이 쓰인다. [화면 1024][코드] 사진 054·058·068·075·080
- 모바일 상단 줄: 언어 버튼 두 개(각 68×30)가 폭을 차지해 현재 위치가 '연..'으로 잘리고, 연구 도우미에서는 화면 이름 위에 패널 아이콘이 겹친다(B7). [화면 390] 사진 147·149
- 모바일 캘린더 일정 목록: 날짜 칸이 '11월 / 10일 / 화요일'로 세 줄이 된다. 목록이 오늘이 아니라 달의 첫 일정부터 시작한다. [화면 390] 사진 106·107
- 빈 상태가 카드 한가운데 크게 떠서 첫 화면 아래 내용이 밀린다(다음 미팅, 글쓰기, 계획). [화면] 사진 071·146·175
- 중단점이 10종(479·480·599·767·768·899·991·1199·1200·1600)이다. Montage 기준은 4종이다. [코드]
- 고쳐진 것: 480px 이하에서 사이드바가 펼쳐진 채 캘린더 숫자가 겹치던 문제(사진 029·032)는 지금 서랍으로 바뀌어 없다. 768·1024·1280·1440px 모두 가로 넘침이 없다. [화면]

## 7. AI 티

### 문구

- 연구 도우미가 가장 심하다. 빈 화면 제목이 "무엇을 도와드릴까요?"로 챗봇 상투구이고, 예시 셋이 모두 "~해 줘" 꼴이다. '쓸 수 없다'는 안내가 상단 띠, 입력창 위, 입력창 안내문 세 곳에 있다. [화면][코드]
- 목록 화면 7곳에서 제목 아래 설명이 제목을 되풀이한다("미팅 / 다음 미팅을 준비하고 지난 기록을 확인하세요."). ux-writing.md 3장이 지우라고 한 문장이다. [코드]
- 피드백 상세 '수정 방법' 칸 하나에 설명이 다섯 줄이다: 부제, 면책 문장, 빈 상태 제목, 빈 상태 설명, 버튼. '할 일 완료는 ~와 별개' 같은 면책은 앱 전체에 7곳 있다. [화면][코드]
- 공개 소개에는 대구("피드백은 할 일로, / 수정 결과는 검토 요청으로"), 근거 없는 효과("시간이 줄어요"), "X는 Y" 같은 꼴의 타일 4개가 있다. FAQ 5개가 두 페이지에 복사돼 있는데 답은 서로 다르다. "교수님께는 … 연구 방향만 보여요"는 8곳에 있다. [코드]
- '~할 수 있어요'가 158줄이다. 가운데점 110줄은 문장 안 구분, 3개 이상 나열, 쉼표 혼용이 섞여 있다. [코드]
- 메모에 '[음성 인식 전사 · 제목]', AI 답에 '[새 제안]'이 글자 그대로 들어간다. 뒤의 것은 서버 함수의 지시문 때문이고 운영에서 보였다(사진 168). [코드][사진]
