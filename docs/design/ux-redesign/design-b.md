## 1. 설계 원칙 다섯 가지

1. **한 종류의 일은 한 가지 방식으로만.** 만들기·저장·삭제·뒤로·AI 실행의 규칙을 5절에 하나씩 정하고 모든 화면이 따른다.
2. **메뉴는 일의 흐름대로.** 데이터 종류(수정 결과, 자료)가 아니라 학생이 하는 일(미팅 → 피드백 → 할 일 → 문서)로 나눈다.
3. **목록 → 상세 + 오른쪽 패널.** 상세 화면은 모두 같은 틀이다. 연결된 기록·교수 응답·연구 도우미는 오른쪽 패널에 둔다(이미 있는 `margin-panel`을 넓힌다).
4. **주소는 되도록 그대로.** 메뉴 묶음만 바꾸고 기존 주소는 살린다. 옮기는 주소는 옛 주소에서 새 주소로 넘겨 준다. 교수에게 보낸 검토 링크(`/reviews/:requestId`)는 바꾸지 않는다.
5. **숫자는 토큰으로만.** 간격·글자·반경·터치 크기를 Montage 변수 안에서 단계로 묶고, 화면 CSS에 숫자를 직접 적지 않는다.

## 2. 사이트맵

### 2.1 사이드바: 9개 → 6개 + 도우미

> **IA v2로 대체**(구현 전): 상단 메뉴 4개 홈 · 미팅 · 할 일 · 글·자료 + 오른쪽 사이드 창(연구 도우미 · 할 일 · 결정·질문 · 자료). 피드백 메뉴는 두지 않음 → [01 전체 구조](../ia-v2/01-structure.md) §1·§2, [02 틀](../ia-v2/02-shell.md) §3.

```
지금                                  B안
─────────────────────                 ─────────────────────
연구 전환 · 찾기 ⌘K                   연구 전환 · 찾기 ⌘K
연구 홈                               홈
지도 흐름                             미팅              ← 시간 조율이 여기로
  미팅                                피드백            ← 수정 결과·검토 요청을 보기로 포함
  피드백·수정                         할 일
  할 일                               문서              ← 글쓰기 + 자료
  검토 요청                           일정              ← 로드맵 + 캘린더
연구 작업                             ───────
  글쓰기                              연구 도우미
  자료                                ───────
  계획·일정                           연구 설정 · 모든 연구
연구 도우미                           (계정 메뉴: 프로필 / 언어 › / 테마 › / 사용 안내 / 로그아웃)
연구 설정 · 모든 연구
(계정 메뉴)
```

- 묶음 이름('지도 흐름', '연구 작업')을 없앤다. 메뉴가 6개면 묶음 없이도 훑어진다. 모바일에서 묶음 이름과 항목의 정렬이 어긋나던 문제(B12)도 같이 없어진다.
- 메뉴 이름은 짧게: '연구 홈'→'홈', '피드백·수정'→'피드백', '계획·일정'→'일정'. 화면 머리의 제목도 같은 이름으로 맞춘다.

### 2.2 화면과 주소

> **IA v2로 대체**(구현 전): 새 주소와 예전 주소 이동 표 → [01 전체 구조](../ia-v2/01-structure.md) §3.

| 메뉴 | 화면 안 보기(탭) | 주소 | 바뀌는 점 |
|---|---|---|---|
| 홈 | — | `/r/:id` | 6절 |
| 미팅 | 목록 · 시간 조율 | `/r/:id/meetings`, `/r/:id/meetings?view=schedule` | 시간 조율이 일정에서 옮겨 옴. 상세는 그대로 `/meetings/:id?tab=` |
| 피드백 | 피드백 · 수정 결과 · 검토 요청 | `/feedback`, `/results`, `/reviews` (그대로) | 세 주소를 한 메뉴의 세 보기로. 머리의 주 버튼은 세 보기 모두 '피드백 추가' 하나 |
| 할 일 | 남은 할 일 · 완료 · 전체 · 보관함 | `/tasks` (그대로) | 추가 창 간소화(5.1) |
| 문서 | 글 · 파일 | `/writing`, `/materials` (그대로) | 두 메뉴를 한 메뉴의 두 보기로. 주 버튼 '새로 만들기 ▾'(계획서 / 원고 / PDF 올리기 / 링크) |
| 일정 | 로드맵 · 캘린더 | `/planning`, `/planning?tab=calendar` | 시간 조율 탭 제거 |
| 연구 도우미 | — | `/assistant` | 7절 |
| 연구 설정 | 기본 정보 · 지도교수 · 공동연구자 · 보관·삭제 | `/settings?tab=` | '연구 단계' 탭 제거(일정에서 함), '지도교수' 탭 신설(기본 정보에서 분리) |
| 계정 설정 | 프로필 · 화면 · 알림 · AI · 사용량·플랜 | `/account?tab=` | 그대로. 언어·테마는 계정 메뉴에서도 바로 |
| 검토 상세 | — | `/reviews/:requestId` | 주소 그대로(교수와 공유). 학생에게는 '피드백 › 검토 요청'으로 돌아가는 길 표시 |

옮기는 주소는 하나다: `/planning?tab=schedule` → `/meetings?view=schedule`. 옛 주소는 새 주소로 넘긴다.

- [확인] 데이터 관계: 수정 결과는 피드백 여러 개에 이어질 수 있고(`RevisionResult.feedbackIds[]`), 검토 요청은 수정 결과 여러 개를 담는다(`ReviewItem.resultId`). 그래서 수정 결과·검토 요청을 피드백 상세 **안에만** 두면 안 된다. 피드백 상세에는 이어진 것을 보여 주고, 전체 목록은 피드백 메뉴의 보기로 남긴다.

### 2.3 '피드백' 메뉴의 세 보기가 탭인 이유

지금은 '피드백 / 수정 결과' 탭을 누르면 주 버튼이 바뀌고 화면이 통째로 달라진다(findings S5). B안에서는 세 보기를 **같은 일의 단계**로 다룬다.

```
피드백  ──→  수정 결과  ──→  검토 요청
(받은 것)    (고친 것)       (교수에게 보낸 것)
```

- 머리의 주 버튼은 세 보기 모두 '피드백 추가'다. 수정 결과와 검토 요청은 피드백 상세에서 만든다(4.2). 목록에서 바로 만들고 싶을 때는 각 보기의 빈 상태나 도구 줄의 보조 버튼을 쓴다.
- 탭에 개수를 붙인다: '피드백 3 · 수정 결과 2 · 검토 요청 1'. 교수 응답이 새로 온 검토 요청이 있으면 그 탭에 점을 단다. (**IA v2로 대체**, 구현 전: 피드백은 미팅 기록 안과 할 일 화면의 '피드백' 탭, 수정 결과·검토 요청은 미팅 목록 `type=review`. 새 응답 표시는 상단 종 · '미팅' 메뉴 점 · 미팅 목록의 검토 요청 칩·줄 · 홈 주 행동 네 곳 → [02 틀](../ia-v2/02-shell.md) §3.4)

### 3.3 상단 줄

> **IA v2로 대체**(구현 전): 상단 줄에 로고 · 연구 이름 · 메뉴 4개 · 찾기 · + · 종 · 계정 → [02 틀](../ia-v2/02-shell.md) §3.

```
지금:  [≡] 연구명 › 화면명        [패널] [🇰🇷한국어][🇯🇵日本語] [?] [🔔]
B안:  [≡] 연구명 › 화면명                          [패널] [?] [🔔]
```
- 언어 버튼 두 개를 뺀다(G1). 모바일 375px에서 경로가 '연.'으로 잘리던 공간(139px)이 돌아온다.
- 상단 줄 바탕을 불투명하게 한다(B6, 지금 `--topbar`가 88% 불투명).
- '?'는 `/guide`(공개 화면)로 나가지 않고 앱 안의 도움말 창(이미 있는 `ShortcutHelp`·`GuideReplay` 활용)을 연다.

## 5. 공통 규칙

### 5.1 만들기

| 경우 | 방식 | 크기 |
|---|---|---|
| 제목 하나면 되는 것(할 일, 질문, 결정, 폴더) | 목록·구역 안의 한 줄 입력. Enter로 저장, '자세히'로 창 열기 | — |
| 입력 2~5개(피드백, 미팅, 수정 방법, 수정 결과) | 작은 창 | 폭 480, 높이는 내용만큼 |
| 미리보기·확인이 필요한 것(검토 요청, 자료 올리기) | 큰 창, 단계 표시 | 폭 640 |
| 여러 질문(연구 만들기) | 전용 페이지 | — |

- 어디서 누르든 **지금 화면 위에** 창이 뜬다. 홈의 '할 일 만들기'가 할 일 화면으로 옮겨 가지 않는다(지금은 옮겨 감, findings S2).
- 한 창을 여는 버튼은 화면에 하나만 둔다(지금 미팅 준비 탭은 3개가 같은 창을 연다).
- ⌘K 명령 팔레트: 연구 안에는 이미 미팅 만들기·할 일 추가·수정 결과·검토 요청·글 쓰기가 있다(11/14 확인, 관찰 W절). 빠진 '피드백 추가'만 더하고, 연구 목록(/r)의 ⌘K에도 최근 기록을 보여 준다.

### 5.2 저장

- 글을 쓰는 곳(미팅 메모, 문서, 피드백 원문)은 자동 저장. 머리에 '저장됨 · 방금'만 보이고 알림은 띄우지 않는다.
- 아무것도 바꾸지 않았으면 '저장됨' 알림을 띄우지 않는다(B4).
- 창 안의 폼은 '저장' 버튼. 설정의 선택·스위치는 고르면 바로 적용(토스증권 설정과 같은 방식).
- 버전은 저장과 다른 행동이다: '버전 남기기'.

### 5.3 지우기·되돌리기

| 행동의 성격 | 방식 | 해당 |
|---|---|---|
| 되돌릴 수 있고 나만 영향 | 바로 실행 + 알림에 '되돌리기'(6초) | 할 일 완료, 질문 해결, 자료 보관, 할 일 보관, 연구 보관 |
| 다른 사람에게 영향 | 확인 창(무엇이 어떻게 되는지 한 문장) | 연구 휴지통(공동연구자 접근 차단·검토 공유 중지), 검토 공유 중지 |
| 되돌릴 수 없음 | 확인 창 + 이름 입력 | 영구 삭제만 |

- 연구 휴지통은 이름 입력을 빼고 확인 창으로 내린다. 공유 중지는 '공유 설정' 창 안이 아니라 검토 상세의 더보기 메뉴로.
- 연구 카드의 더보기 메뉴: 연구 설정 / 보관 / 휴지통으로 옮기기(지금은 1항목).

### 5.4 뒤로 가기와 위치

- 상세 화면의 맨 위에 '← 목록 이름'을 둔다(학생 화면엔 있음, 교수 검토 상세엔 없음 — 관찰 V절). 크기를 32px 이상으로(지금 검토 상세 21×21).
- 만들기 창을 열거나 닫는 것은 주소를 바꾸지 않는다. 그래서 브라우저 뒤로 가기가 늘 직전 화면으로 간다.
- 보기 탭과 필터는 모두 주소에 남긴다. 새로 고쳐도, 공유해도 같은 화면.

### 5.5 오류·빈 상태·불러오기

- 입력 오류: 입력란 아래 한 곳에만. 첫 오류 칸으로 초점을 옮긴다.
- 서버 오류: 알림 한 줄 + '다시 시도'.
- 빈 상태: 아이콘 · 한 줄 제목 · 할 수 있는 일 요점 2개 이하 · 주 버튼 1개. 머리에 같은 버튼이 있으면 빈 상태에는 버튼을 두지 않는다.
- 홈의 빈 상태는 동시에 둘 이상 보이지 않게 한다(6절).

## 7. 연구 도우미와 AI

> **IA v2로 대체**(구현 전): 연구 도우미는 오른쪽 사이드 창의 한 탭이고, 이 연구의 기록을 항상 전부 읽으며 기록을 고르는 화면은 없음(D13, `AGENTS.md`, #99) → [06 연구 도우미](../ia-v2/06-assistant.md) §2.

| 자리 | 하는 일 | 근거(읽는 기록) | 결과의 다음 행동 |
|---|---|---|---|
| 미팅 상세 › 패널 › 도우미 | 메모 정리 | 이 미팅 메모(자동) | 제안마다 피드백으로 저장 / 할 일로 / 버리기 |
| 피드백 상세 › ② 수정 방법 › AI | 수정 방법 제안 | 이 피드백 + 이어진 미팅 메모(자동) | 수정 방법으로 채택 / 버리기 |
| 문서 편집 › 문장 고르기 › AI | 원고 검토 | 고른 문장 | 원문 옆에 나란히, 받아들이기 / 버리기 |
| 연구 도우미 화면 | 연구 전체에 대한 질문 | 사용자가 패널에서 고름 | 복사 / 다시 시도 / 피드백·할 일로 저장 |

- 연구 도우미 입력줄의 '요청 종류' 드롭다운(6종)을 없앤다. 대상이 정해진 일은 그 대상 화면에서 하고, 도우미 화면은 대화 하나만 한다. 빈 화면에는 지금처럼 예시 질문 3개.
- 답 표시: 글자가 차례로 나오게 한다. '[새 제안]' 같은 표시는 글자로 두지 않고 배지로(B11). 실행 중 문구는 근거가 없으면 '연구 정보만으로 답을 준비하고 있어요'.
- '대화 기록'과 패널의 '실행 기록'을 '지난 대화' 하나로 합친다. 미팅의 '기록' 탭은 그대로 두고, AI 쪽에서 '기록'이라는 말을 쓰지 않는다.
- 지키는 원칙: AI는 사용자가 누를 때만 실행, 결과는 사용자가 채택해야 기록이 된다, 채택한 것에는 'AI 제안에서 가져옴' 표시, 채택하지 않은 제안과 대화는 나만 본다(`AGENTS.md`).

## 8. 디자인 시스템 개선

### 8.1 유지

### 8.2 바꾸는 것: 숫자를 단계로

[확인] 지금 앱 CSS에서 간격(`gap`·`padding`·`margin`)에 Montage 변수를 쓴 곳은 약 370곳, 숫자를 직접 쓴 곳은 1,500곳이 넘는다(12px 168, 10px 148, 8px 141, 20px 128, 18px 98, 14px 91, 22px 59, 9px 52, 7px 47, 5px 47, 13px 38 …). 글자 크기는 대부분 Montage 변수를 쓰지만 8단계 이상이 섞이고 `10px` 직접 지정이 19곳이다. 반경은 변수 9종을 쓴다.

새 단계(모두 Montage 변수 이름 그대로, 새 값을 만들지 않음)

| 종류 | 쓰는 단계 | 용도 |
|---|---|---|
| 간격 | `--spacing-4` · `8` · `12` · `16` · `24` · `32` · `48` | 4 아이콘과 글자, 8 같은 줄의 부품, 12 행 안, 16 카드 안, 24 구역 사이, 32 화면 머리 아래, 48 큰 구역 |
| 글자 | caption1(12) · label2(13) · label1(14) · body1(16) · headline1(18) · heading1(22) · title2(28) | 메타 · 보조 버튼 · 기본 UI · 긴 글 · 카드 제목 · 상세 제목 · 화면 제목 |
| 반경 | `--radius-8` · `--radius-12` · `--radius-full` | 입력·버튼·작은 칩 · 카드·창·패널 · 배지·아바타 |
| 터치 | 데스크톱 최소 32px, 모바일(767 이하) 최소 44px | 모든 버튼·링크·체크 |

- caption2(11px)와 직접 쓴 10px는 없앤다(`ui-quality.md`의 9~11px 금지와 같음).
- 연구 홈 제목 25.63px(관찰 기록 A절)처럼 계산으로 나온 크기를 없애고 title2로.
- 새 이름의 별칭 변수를 만들지 않는다. 화면 CSS의 숫자를 위 Montage 변수로 바꾸는 작업이다.
