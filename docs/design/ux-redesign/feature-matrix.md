# 기능별 대응표 — 마진의 모든 기능을 레퍼런스의 같은 역할 화면과 맞대기 (2026-11-14, 2판)

- 근거: 마진은 `observation-log.md`(A–U), 레퍼런스는 `ref-log.md`(1 Liner · 2 매니패스트 · 3 GitHub · 4 토스증권 · 5 Linear·flex 첫 화면 · 6 보충 · 7 Linear 안쪽 · 8 flex).
- 표시: **[사실]** 직접 눌러 본 것 / **[못 봄]** 확인하지 못한 것 / **[제안]** 이 문서의 제안(확정 아님).
- 제안은 `AGENTS.md` 제품 규칙을 지키게 썼다. 특히 다음 다섯 가지를 따랐다.
  - 교수 결과는 '수정 내용 확인'과 '추가 수정 필요' 두 가지이고, 추가 수정 필요에는 이유 댓글이 필요하다.
  - 완료·반영·교수 결과·댓글 해결·읽음을 하나로 합치지 않는다.
  - AI는 사용자가 고른 원문에만 쓴다.
  - 자동 영구 삭제는 하지 않는다.
  - 로그인 후 테마는 계정 설정 한 곳에만 둔다.
- 1판(공통 기능 12개)은 3부로 옮기고 Linear 내용을 더했다. 1판 원본은 세션 임시 폴더에 보관했다.

## 2부. 연구 업무 기능별 상세

### 2.1 내 연구 — 목록·보관·휴지통
- **마진** [사실]
  - 보기: 진행 중 / 보관함 / 휴지통(`?view=`).
  - 카드 ⋯ 메뉴에는 '휴지통으로 옮기기' 하나만 있다.
  - 휴지통으로 옮길 때 연구 이름을 입력해야 한다. 복원할 수 있는 동작인데도 그렇다.
  - 옮긴 뒤 뜨는 알림에 되돌리기가 없다.
  - 휴지통 카드는 눌러도 반응이 없다.
- **Linear** [사실]: 팀 설정 맨 아래 Danger zone이 3단계다.
  - Leave.
  - **Retire**: 새로 만드는 것은 막고 기록은 보존한다.
  - **Delete**: 30일 안에 복원할 수 있다.
- **GitHub** [사실]: Danger Zone에 Archive(읽기 전용으로 보관)와 삭제가 따로 있다.
- **매니패스트** [사실]
  - 사이드바에 '휴지통' 메뉴가 있다.
  - 목록 머리: 새 폴더 · '+ 새 프로젝트'. 그 아래 찾기 · 선택 · 정렬.
  - 행마다 ⋯ 메뉴가 있고, 맨 아래에 사용량 줄이 있다.
- **[제안]**
  - 보관 설명을 Retire처럼 한 문장으로 붙인다: "새 기록은 막고 지금까지 기록은 그대로 둬요."
  - 휴지통 옮기기는 이름 입력 없이 바로 하고, 알림에 '되돌리기'를 단다.
  - 이름 입력은 완전 삭제에만 받는다.
  - 카드 ⋯ 메뉴는 연구 설정 · 보관 · 휴지통으로 옮기기, 세 개로 한다.

### 2.2 연구 만들기
- **마진** [사실]
  - 4단계: 이름·설명·교수 이메일 → 단계 → 미팅 날짜 → 목적·질문.
  - 날짜를 비운 채 넘어가면 아무 안내 없이 '아직 안 잡혔어요'로 바뀐다.
- **Linear** [사실]
  - 워크스페이스는 3칸으로 만든다: 이름, URL(이름에서 자동 생성), 지역.
  - 프로젝트 만들기 창: 이름 · 한 줄 요약 · 속성 칩(상태·리드·멤버·시작일·목표일…) · 본문 · Milestones.
  - **칩은 비워도 만들어진다.**
- **flex** [사실]
  - 회사명 → 직원 수 → 하는 일 순서로, **답하면 다음 칸이 하나씩 나타난다**.
  - **오른쪽 미리보기에 답에 맞춘 '해야할 일'이 바로 채워진다**("4대보험 취득 신고", "입사자 한 달 리뷰").
- **[제안]**
  - 필수 칸은 연구 이름 하나로 줄이고, 지도교수 이메일은 선택으로 둔다.
  - 단계·다음 미팅·목적은 Linear처럼 비워도 되는 칩으로 한 화면에 모은다.
  - 칩을 고를 때마다 flex처럼 오른쪽 홈 미리보기(HomePreview, 이미 있음)의 '먼저 할 일'이 바뀌게 한다.

### 2.3 연구 홈
- **마진** [사실]
  - 카드가 11종이고, 빈 안내 5개가 한꺼번에 보인다.
  - 숫자가 빠진 문장이 있다("남은 할 일 개 남음").
  - 한 카드 안의 링크 4개가 모두 같은 곳으로 간다.
- **토스** [사실]
  - 내 계좌 화면은 한 줄 흐름이다: 바로 할 일 버튼(채우기·보내기·환전) → 금액 → 추이 → 이번 달.
  - 숫자마다 사람 말 한 문장이 붙는다("한 달 전과 투자 자산이 똑같아요").
  - 오른쪽 '주문내역'은 어느 화면에서나 고정으로 보인다.
- **Linear** [사실]
  - 팀 Overview: 팀 자료(문서·링크를 섹션으로 정리) + 멤버.
  - My issues: 배정 / 만든 것 / 구독 / 활동.
  - 끝내지 않은 설정은 사이드바 'Try' 묶음에 남는다.
- **[제안]**
  - 맨 위에 '지금 할 일 한 줄'과 이유 한 문장을 둔다. 예: "다음 미팅까지 3일 · 확인할 교수 응답 1개".
  - 그 아래 카드는 다음 미팅 · 남은 할 일 · 교수 응답, 셋만 둔다.
  - 빈 안내 5개는 하나로 합친다.
  - 시작하기는 사이드바 아래 'Try' 자리로 옮긴다.
  - 같은 곳으로 가는 링크 4개는 카드 전체 링크 하나로 바꾼다.

### 2.4 미팅 — 준비·기록·녹음·결정·질문
- **마진** [사실]
  - 상세 탭은 준비 / 기록 / 결정·질문 세 개다.
  - 준비 버튼 3개가 모두 같은 창을 연다.
  - 녹음은 동의 체크 2개를 해야 시작된다.
  - 'AI로 메모 정리'를 누르면 오른쪽 패널의 '도우미' 탭이 열린다.
  - 질문 해결은 되돌릴 수 없다.
  - 미팅을 열기만 해도 '저장됨' 알림이 뜬다.
- **매니패스트** [사실]
  - "회의록을 올리면 AI가 확정·미정·기각 결정을 뽑음 · 결정을 기획서에 반영(승인해야 바뀜)".
  - 반영은 "원하는 것만 골라" 한다.
- **Linear** [사실]: Cycles는 짧은 기간 단위로 일을 묶고, **끝나지 않은 일을 다음 기간으로 넘긴다**.
- **[제안]**
  - 준비 탭 맨 위에 '지난 미팅 뒤 끝나지 않은 할 일 n개 — 이번 준비에 넣기'를 둔다(Cycles식 이월).
  - 준비 버튼 3개는 섹션마다 '+' 하나로 나눈다.
  - 'AI로 메모 정리' 결과는 결정·질문·할 일 후보로 나눠 보여 주고, 사용자가 골라서 반영한다(원문·제안 구분 규칙).
  - 질문 해결에 되돌리기를 단다.
  - 열기만 했을 때 뜨는 저장 알림은 없앤다.

### 2.5 피드백
- **마진** [사실]
  - '피드백 / 수정 결과'가 탭처럼 보이지만 누르면 다른 화면으로 바뀐다.
  - 상태 필터가 주소에 남지 않는다.
  - 추가 창은 2칸이다.
  - 홈의 '피드백 한 건 정리하기'는 목록까지만 간다.
- **Linear** [사실]
  - Triage: "다른 곳에서 들어온 이슈를 먼저 받는 받은 편지함 — 받아들이거나 거절하고 우선순위를 정한 뒤 작업에 넣는다." 우선순위를 꼭 고르게 하는 옵션이 있다.
  - 이슈 상세: '1 / 4' 위·아래 이동, 오른쪽 속성 칸, 하위 이슈, 활동 기록.
- **GitHub** [사실]: 모든 필터가 주소 `?q=`에 남고, 라벨 칩을 누르면 바로 걸러진다.
- **[제안]**
  - 미팅에서 막 받은 피드백은 '정리 전' 묶음에 먼저 둔다(Triage). 하나씩 할 일로 / 수정 방법 쓰기 / 보류를 고르게 한다.
  - 상태 필터를 주소에 남긴다.
  - 상세에서 위·아래로 다음 피드백으로 넘어갈 수 있게 한다.
  - '피드백 / 수정 결과'를 같은 화면의 실제 탭으로 바꾼다.

### 2.6 수정 방법과 수정 결과
- **마진** [사실]
  - 수정 방법은 '직접 작성'과 'AI 제안'을 오간다.
  - 수정 결과의 '작성' 버튼이 44×24px로 작다.
  - 결과 작성 창에 체크 6개가 있는데 이름이 없다.
  - '검토 요청 만들기'를 누르면 다른 화면으로 옮겨 가고, 뒤로 가기로 돌아오지 않는다.
- **GitHub** [사실]
  - PR = 설명 + 바뀐 파일 + 검사.
  - 바뀐 파일 탭은 파일 나무 · **"0 / 7 viewed"** · 파일마다 Viewed 체크로 되어 있다.
- **Liner** [사실]: 고칠 곳을 본문에 바로 표시하고, 하나씩 '적용 / 적용 안 함', 맨 아래 '모두 적용'.
- **매니패스트** [사실]: 항목 상세에 '보강'(AI) 버튼과 '수용 기준 0/4' 체크리스트가 있다.
- **[제안]**
  - 피드백 상세 한 화면에 ① 피드백 → ② 수정 방법 → ③ 수정 결과 → ④ 검토 상태를 차례로 둔다.
  - 수정 방법에 '완료 기준' 체크를 둘 수 있게 한다(매니패스트). 교수 응답 전에 스스로 확인하는 데 쓴다.
  - 검토 요청은 그 자리에서 창으로 연다.

### 2.7 검토 요청 — 보내기·공유·차수
- **마진** [사실]
  - 만드는 흐름: 제목·교수·결과 → '공유할 내용 확인' → 링크 만들기.
  - 링크를 만들면 "링크를 복사해서 교수님께 직접 전달해 주세요" 알림이 뜬다.
  - 상세에 항목 · 차수 · 다시 확인 요청 · PDF · 댓글이 있다.
  - '공유 중지'는 공유 설정 창 안에 숨어 있다.
  - 뒤로 버튼이 21×21px로 작다.
- **GitHub** [사실]
  - 머리: 상태 배지 + 누가 어디로 + 탭(숫자 포함).
  - **스크롤하면 얇은 고정 줄로 바뀐다.**
  - 대화는 시간순 기록이고, 끝에 결론 상자가 붙는다. 되돌리기 버튼은 그 일 옆에 있다.
- **[제안]**
  - 머리를 '상태 배지(응답 전 / 일부 응답 / 모두 확인) + 교수 + 보낸 날 + 차수'로 만들고, 스크롤하면 고정 줄로 바꾼다.
  - 공유 중지는 창 밖으로 꺼내 위험 표시와 함께 둔다.
  - 차수는 시간순 기록에 이어 붙인다(이전 차수 보존).
  - 링크를 복사한 뒤 버튼을 '복사됨'으로 바꾼다. 링크 만들기 ≠ 보내기 구분은 문구로 지킨다.

### 2.8 교수 응답
- **마진** [사실] (11/14 운영 교수 계정, observation-log V절)

  - **고른 값에 따라 칸 이름이 바뀐다**: 추가 수정 필요 → "추가로 수정할 내용 · 필수", 수정 내용 확인 → "응답 댓글 · 필요할 때만 남겨 주세요". 이유 필수 규칙은 이미 지키고 있다.
  - 저장하면 "이 요청의 모든 항목에 결과를 남겼어요. 학생에게 알림으로 보여요."가 뜬다. 응답 변경 이력은 그 자리에서 펼쳐진다.
  - 문제
    - '변경 내용 저장'이 바꾼 것이 없어도 켜져 있다.
    - 목록으로 돌아가는 버튼이 없다(로고 = 홈).

- **GitHub** [사실]

- **[제안]**
  - 두 선택지에 한 줄 설명을 붙인다.
    - '수정 내용 확인 — 이 항목은 더 고치지 않아도 돼요'
    - '추가 수정 필요 — 무엇을 더 고칠지 남겨 주세요'
  - '변경 내용 저장'은 바뀐 것이 있을 때만 켠다(매니패스트·Liner 저장 버튼과 같은 규칙).

## 3부. 공통 기능 (1판 + Linear 보충)

### 3.1 프로필
- 계정 메뉴 위치
  - 마진·Liner·매니패스트: 왼쪽 아래.
  - GitHub: 오른쪽 위 서랍.
  - Linear: 왼쪽 위 워크스페이스 메뉴.
  - 어디나 첫 줄은 지금 로그인한 계정, 마지막 줄은 로그아웃이다.
- 프로필 화면
  - GitHub: 칸마다 "어디에 보이는지" 한 줄을 붙인다.
  - Linear: 온보딩 첫 단계에서 사진·이름·직함을 받고, 건너뛸 수 있다.
  - 토스: 커뮤니티 활동 화면이다.
- **[제안]**
  - 계정 메뉴를 이 순서로 바꾼다: 이름+이메일 / 계정 설정 / 언어 › / 사용량 / 사용 안내 / 로그아웃.
  - 운영 화면에는 이미 이메일과 '로그아웃'이 있다. 미리보기 모드에만 이메일이 없고 마지막 줄이 '로그인 화면으로'다. 미리보기에도 '미리보기 끝내기'처럼 무슨 동작인지 드러나는 이름을 쓴다. [사실: 11/14 운영 교수 계정]
  - 이름 칸 아래에 "교수님 화면에 이 이름으로 보여요"를 적는다.
  - 테마는 계정 설정에만 둔다(AGENTS).

### 3.2 설정
- 저장 방식
  - GitHub: "Selections are applied immediately and saved automatically."
  - 토스: 스위치를 누르면 바로 적용된다.
  - Linear: 줄마다 '이름 + 한 줄 설명 + 지금 값'을 보여 준다.
  - 마진: 탭마다 다르다. 알림 스위치 옆에 저장 버튼이 따로 있다.
- 위험한 동작
  - GitHub: 붉은 Danger Zone에 모은다.
  - Linear: Leave / Retire / Delete(30일 안에 복원) 3단계.
  - 마진: 연구 설정에 위험 구역이 없다.
- 설정 여는 곳
  - 토스: 화면 안 버튼이 설정 창의 해당 탭을 바로 연다.
  - Linear: 설정은 전체 화면이고 'Back to app'으로 돌아간다.
- **[제안]**
  - 스위치는 누르면 바로 저장한다. 글 칸 묶음만 '변경 취소/저장'을 둔다.
  - 설정 행은 '이름 + 한 줄 설명 + 지금 값'으로 쓴다.
  - 연구 설정 맨 아래에 '위험한 작업'을 두고 보관 / 휴지통 / 지도교수 연결 끊기를 넣는다.

### 3.3 언어
- 언어를 두는 곳
  - Liner·매니패스트: 프로필 메뉴 › 언어 ›. Liner는 "영어 - English"처럼 두 언어로 적고, 매니패스트는 '영어 / 한국어'로 한국어 이름만 적는다.
  - 매니패스트는 설정 창 › 일반에도 테마·언어 선택 상자가 있어 **두 곳에서 같은 설정을 바꾼다**. 메뉴(빠른 입구)와 설정(전체 목록)에 함께 두는 것은 흔한 방식이고, 마진이 다른 점은 앱 상단 줄에 둔 것이다.
  - GitHub·토스·Linear: 언어 설정이 없다.
  - 매니패스트: 공개 화면에서만 상단에 둔다.
  - 마진: 로그인한 뒤에도 상단 줄에 버튼 2개가 있다. 누르면 새로 고침되어 쓰던 글이 사라지고, 모바일에서 상단 줄 폭의 37~40%를 차지한다.
- **[제안]**
  - 계정 메뉴 › 언어 ›로 옮긴다.
  - "일본어 - 日本語"처럼 쓰고 지금 언어에 ✓를 붙인다. 국기는 쓰지 않는다.
  - 쓰던 글이 있으면 바꾸기 전에 묻는다.

### 3.4 테마
- 테마를 두는 곳
  - Liner·매니패스트: 프로필 메뉴 › 테마.
  - GitHub·Linear: 설정 › 화면 모양(시스템 / 라이트 / 다크). Linear는 'Aa' 미리보기를 보여 준다.
  - 토스: 설정 › 일반.
- **[제안]**
  - 계정 설정 › 화면 설정에 'Aa' 미리보기 카드 3개를 둔다.
  - 공개 푸터의 테마 전환은 유지한다(AGENTS).
- **마진 다크 모드** [사실, 관찰 W절]: 화면은 깨지지 않지만, 주 버튼 흰 글자 on #3385FF가 3.54:1로 본문 크기 기준(4.5:1)에 못 미친다. 다크 모드의 주 색을 한 단계 어둡게 하거나 글자를 굵게(18.66px 굵게면 3:1 기준) 해야 한다 — 색 토큰 수준에서 고친다.

### 3.5 온보딩
- 첫 생성 양식
  - Linear: 3칸.
  - flex: 칸이 하나씩 나타나고, 미리보기가 따라 바뀐다.
  - 마진: 4단계.
- 첫 안내
  - Linear: 5단계, 모두 Skip할 수 있다. 끝나면 **연습용 할 일 4개를 실제 이슈로 넣어 준다.**
  - 토스·GitHub: 기능 옆 말풍선 하나.
  - 마진: 화면 안내 4단계 + 시작하기 체크리스트.
- 빈 상태
  - Linear: 개념 1~2문장 + 만들기 + 단축키 + 문서 링크.
  - 매니패스트: 일의 종류를 카드로 설명한다.
- **[제안]**
  - 시작하기 항목을 연구 안의 실제 할 일로 넣는다(예: "지도교수 이메일 등록", "첫 미팅 날짜 정하기").
  - 빈 화면은 '개념 한 문장 + 만들기 + 단축키'로 통일한다.

### 3.6 AI 채팅 (연구 도우미)
- 레퍼런스
  - Linear: 오른쪽 아래 400×560 떠 있는 창. 지금 보는 이슈를 문맥 칩으로 붙인다. "@ to mention any issue, project, or document".
  - GitHub Copilot: 모드 · 범위 · 모델 · 효율/균형/지능을 고른다. 작업 칩을 누르면 입력란에 틀만 채운다.
  - 매니패스트: 문서 옆 칸. 실행 전에 비용 문장을 보여 주고, 한 일은 접힌 기록으로 남긴다.
  - 토스: 채팅 없이 표의 한 칸으로 넣는다.
- 마진
  - 별도 화면과 근거 패널로 되어 있다.
  - 답 아래에 버튼이 없다.
  - '[새 제안]'이 글자 그대로 보인다.
  - 비용 고지가 없다.
- **[제안]**
  - 지금 보는 피드백·미팅은 **문맥 후보 칩**으로만 보여 준다. 사용자가 눌러야 근거로 붙는다(AGENTS: 선택한 원문에 한해).
  - '@'로 미팅·피드백·문서를 부를 수 있게 한다.
  - 답 아래에 복사 / 다시 생성 / 할 일로 만들기 / 피드백에 붙이기 버튼을 둔다(붙이기 = 채택).
  - 요청 종류를 고르면 입력란에 틀을 채운다.
  - 무거운 요청에는 비용 문장을 붙인다.
  - 깊이 이름을 '빠르게 / 보통 / 자세히'로 바꾼다.
  - 화면마다 따로 있는 도우미를 Linear처럼 떠 있는 창 하나로 합치는 안은 따로 검토한다.

### 3.9 검색·명령 팔레트
- 레퍼런스

  - Linear: 속성마다 한 글자 단축키.

## 4부. 먼저 고칠 것 (제안, 묶음 단위)

1. **흐름 잇기**: AI 답 → 할 일·피드백(3.6), 댓글 → 할 일(3.7), 수정 결과에서 그 자리 검토 요청(2.6). 지금은 기능마다 거기서 끝난다.
2. **만들기 창 통일**: 할 일·피드백·미팅 창을 '제목 + 속성 칩 + 연달아 만들기'로 맞추고, 쓰다가 닫으면 묻는다(2.9, 3.10).
3. **검토 상세와 교수 응답 창**: 상태 배지, 고정 머리, 선택지마다 설명 한 줄(2.7, 2.8).
4. **언어·계정 메뉴·설정 저장 규칙**(3.1~3.3).
5. **첫 생성 한 화면 + 시작하기를 실제 할 일로**(2.2, 3.5).
6. **미팅 이월 + AI 메모 정리 후보 고르기**(2.4).
7. **알림 이유 꼬리표, ⌘K 빈 상태, 자료 '마지막으로 쓴 곳'**(3.8, 3.9, 2.11).
