## 1. 한 줄 답

**마진이 낯선 까닭은 생김새가 아니라 "같은 종류의 일이 화면마다 다른 방식으로 일어나기" 때문이다.** 만들기, 저장, 설정, 삭제, 뒤로 가기, AI 실행이 각각 두세 가지 방식으로 구현돼 있어서, 한 화면에서 배운 것이 다음 화면에서 통하지 않는다. 익숙한 소프트웨어는 이 여섯 가지가 서비스 전체에서 한 가지 방식으로만 일어난다.

먼저 고칠 순서는 (1) 설정의 자리, (2) 만들기·저장·삭제의 규칙, (3) 탐색과 돌아오기, (4) AI 결과의 다음 행동, (5) 간격·글자·터치 영역의 토큰화다.

## 2. 구조 문제 7가지

### S1. 설정이 세 곳에 흩어져 있고, 언어가 가장 좋은 자리를 차지한다

- [확인] 언어 전환 버튼 두 개(🇰🇷한국어 / 🇯🇵日本語)가 로그인 후 모든 화면의 상단 줄에 늘 있다. 같은 설정이 계정 설정 › 화면 설정에도 있다. 테마는 계정 설정과 공개 화면 푸터에 있다. (B, O, R)
- [확인] 언어 버튼을 누르면 페이지 전체가 새로 고쳐진다. 글쓰기처럼 수동 저장인 화면에서 잘못 누르면 쓰던 내용이 사라질 수 있다. (B, J)
- [확인] 모바일 375px에서 언어 버튼 두 개가 상단 줄 폭의 37%(139px)를 쓰고, 그 탓에 현재 위치 표시가 16px로 잘려 '연.'만 보인다. (Q)
- [확인] Liner·매니패스트·GitHub·토스증권 모두 언어·테마를 프로필 메뉴나 설정 창 안에 둔다. 상단 줄에 언어를 상시 노출한 곳은 없다. (references.md 2절)
- [추정] 원인은 "일본어 지원을 눈에 띄게"라는 요구를 상단 줄 고정으로 풀었기 때문이다. `AGENTS.md`의 "로그인 후 테마는 계정 설정 한 곳" 원칙이 언어에는 적용되지 않았다.
- [제안] 로그인 후 상단 줄에서 언어를 빼고 계정 메뉴(왼쪽 아래 아바타)에 '언어 ›', '테마 ›' 하위 메뉴를 둔다. 첫 방문자를 위한 언어 선택은 공개 화면 머리와 로그인 화면에만 남긴다. 전환은 새로 고침 없이 하거나, 저장하지 않은 내용이 있으면 먼저 묻는다.

### S2. '만들기'가 네 가지 방식이다

- [확인] 같은 홈에서 '할 일 만들기'와 '새 연구 계획서 만들기'는 다른 화면으로 옮긴 뒤 대화상자를 열고, '피드백 한 건 정리하기'와 '원고나 자료 올리기'는 목록까지만 데려간다. (E)
- [확인] '문서 만들기'는 메뉴(계획서/원고), '연구 만들기'는 전체 화면 4단계, '검토 요청 만들기'는 대화상자 안 2단계, 나머지는 대화상자 1장이다. (D, H, J)
- [확인] 대화상자 크기가 560×269부터 560×661까지 9종이고, 입력 8개짜리 '할 일 추가'도 입력 2개짜리 '피드백 추가'도 같은 틀이다. 모바일에서는 전부 거의 전체 화면이 된다. (F~L, Q)
- [확인] 한 대화상자를 여는 버튼이 여러 개다. 미팅 준비 탭의 '준비 편집'·'할 일 고르기'·'자료 고르기'가 같은 대화상자를, 피드백 상세의 '직접 작성'·'수정 방법 작성'이 같은 대화상자를 연다. (F, P)
- [추정] 화면마다 따로 만들면서 "어떤 일은 대화상자, 어떤 일은 페이지"라는 기준이 없었다. `patterns.md`에는 화면 머리 규칙만 있고 만들기 규칙이 없다.
- [제안] 기준 하나를 정한다. 입력 3개 이하이고 지금 화면을 떠날 필요가 없으면 그 자리에서(인라인 입력 또는 작은 대화상자), 입력이 많거나 미리보기가 필요하면 오른쪽 패널, 여러 단계면 전용 페이지. 홈의 바로가기는 "어디서 누르든 지금 화면 위에 만들기 창이 뜬다"로 통일한다(GitHub의 전역 만들기 버튼과 같은 방식).

### S3. 저장 방식이 화면마다 다르고, 저장 알림이 믿기 어렵다

- [확인] 미팅 메모는 자동 저장인데 글쓰기 문서는 수동 저장이다(머리에 '저장' 버튼과 '저장 1회' 표시, 바꾸면 '저장하지 않은 변경'). 설정은 '변경 취소/저장' 버튼, 화면 설정은 고르면 바로 적용이다. (F, J, N, O)
- [확인] 지난 미팅을 열거나 탭을 바꾸기만 해도 '이 브라우저에 저장됨'이 뜬다. 아무것도 바꾸지 않았는데 저장했다고 알린다. (F)
- [확인] 사용 안내는 "메모는 자동으로 저장돼요"라고 설명한다. (R)
- [제안] 글을 쓰는 화면은 모두 자동 저장으로 맞추고 상태는 머리의 작은 글자 하나('저장됨 · 방금')로만 보인다. '버전 남기기'는 저장과 별개의 행동으로 유지한다. 폼은 "바로 적용"(스위치·선택)과 "저장 버튼"(글자 입력) 두 가지만 쓴다.

### S4. 지우기·되돌리기의 무게가 뒤바뀌어 있다

- [확인] 복원할 수 있는 '휴지통으로 옮기기'는 연구 이름을 직접 입력해야 하는데, '자료 보관'과 '질문 해결로 표시'는 확인도 되돌리기도 없이 바로 실행된다. 할 일 완료에는 '되돌리기'가 있는 알림이 뜬다. (C, F, I, K)
- [확인] 연구 카드의 더보기(⋯) 메뉴에는 항목이 '휴지통으로 옮기기' 하나뿐이다. (C)
- [제안] 규칙 세 단계. 되돌릴 수 있으면 바로 실행 + 알림에 '되돌리기'. 다른 사람에게 영향이 가면(공유 중지, 공동연구자 접근 차단) 확인 대화상자. 영구 삭제만 이름 입력.

### S5. 탐색: 돌아오는 길이 끊기고, 같은 곳으로 가는 문이 여러 개다

- [확인] 수정 결과 상세에서 '검토 요청 만들기'를 누르면 검토 요청 화면으로 옮겨 가고, 브라우저 뒤로 가기를 눌러도 원래 화면으로 돌아오지 않는다. (G)
- [확인] 검토 요청 상세는 주소가 `/reviews/:id`로 연구 밖에 있다. 앱 안의 '사용 안내'는 공개 화면 머리(로그인/시작하기)를 쓰는 `/guide`로 나간다. (H, R)
- [확인] 홈의 '지도 미팅', '자료 0개', '질문 0개', '미팅 준비하기' 네 개가 같은 곳으로 간다. '미팅 준비하기'는 머리와 카드에 두 번 있다. (E)
- [확인] '피드백 / 수정 결과'는 탭처럼 보이지만 누르면 주소와 머리 버튼이 바뀌는 다른 화면이다. 계획·일정의 탭 세 개도 탭마다 머리의 주 버튼이 바뀐다. (G, L)
- [확인] 목록 필터가 미팅·할 일·자료는 주소에 남고 피드백은 남지 않는다. (F, G, I, K)
- [확인] 연구 설정의 '연구 단계' 탭은 읽기 전용 목록과 계획·일정으로 가는 링크뿐이다. 지도교수 등록은 '기본 정보' 탭 안에 있다. (N)
- [제안] 4절의 방향 B 참고. 탭은 "같은 대상의 다른 면"에만 쓰고, 성격이 다른 것은 메뉴로 올리거나 합친다. 만들기 흐름은 지금 화면 위에서 끝내 뒤로 가기 문제를 없앤다.

### S6. AI: 결과를 받은 뒤 할 수 있는 일이 없다

- [확인] 운영에서 실제로 물었을 때 답 아래에 버튼이 하나도 없었다(복사, 다시 시도, 저장, 할 일로 만들기). 답은 10~15초 뒤 한 번에 나타났고 문장마다 '[새 제안]'이 글자 그대로 붙어 있었다. (S)
- [확인] 기록을 고르지 않았는데 실행 중 문구가 '선택한 기록을 바탕으로 답변을 준비하고 있어요'였다. (S)
- [확인] AI로 들어가는 문이 셋이다: 사이드바의 연구 도우미(전체 화면 대화 + 근거 패널), 미팅 기록의 'AI로 메모 정리'(오른쪽 패널의 도우미 탭), 피드백 상세의 'AI 제안' 탭. 요청 종류 6가지는 대화 입력줄의 드롭다운에 들어 있다. (F, M, P, S)
- [확인] '기록'이라는 말이 미팅의 기록 탭, 대화 기록, 실행 기록 세 가지 뜻으로 쓰인다. (M)
- [확인] Liner는 에이전트마다 전용 입력 화면(예시 문장 버튼, 한 가지 일만 하는 실행 버튼, 아래에 최근 기록)을 두고, 매니패스트는 왼쪽 대화 + 오른쪽 문서 구조에서 AI가 한 일을 단계로 접어 보여 준다. (references.md)
- [제안] 5절.

### S7. 치수가 토큰이 아니라 화면별 숫자다

- [확인] 연구 홈 한 화면에 글자 크기 9종(11·12·13·14·15·17·20·24·25.63px), 간격 9종(3·4·5·6·7·9·10·13·31px), 모서리 8종이 쓰인다. 홈 제목만 25.63px이고 다른 화면은 28px이다. 설정 화면은 본문이 13px 중심, 목록 화면은 14px 중심이다. (A)
- [확인] 모바일 홈에서 누를 수 있는 요소 44개 중 37개가 44px보다 작다. 데스크톱에서도 뒤로 가기 21×21, 패널 안 링크 높이 16px, 날짜 입력 74×20 같은 요소가 있다. (F, H, L, Q)
- [확인] 체크 버튼·스위치 다수에 접근성 이름이 없고, 날짜 선택 버튼 이름이 영어(Toggle date picker)다. (D, F, G, H, I, O)
- [확인] 저장소의 화면별 CSS가 `public-site.css` 2,458줄, `student.css` 1,781줄, `styles.css` 1,512줄 등으로 나뉘어 있고, 너비 기준이 767·991·1199 외에 480·479·599·899px도 쓰인다.
- [추정] Montage 토큰은 색에는 잘 적용됐지만 간격·글자 크기는 화면 CSS에서 숫자로 직접 적었다. 5·7·9·13px 같은 값은 4px 배수 체계 밖이다.
- [제안] 간격 6단계(4·8·12·16·24·32), 글자 6단계(12·13·14·16·20·28), 모서리 3단계(8·12·16), 최소 터치 높이(데스크톱 32, 모바일 44)를 토큰으로 정하고 화면 CSS의 숫자를 토큰으로 바꾼다. 화면 하나씩이 아니라 공통 부품(버튼, 행, 카드, 대화상자, 탭) 순서로 진행한다.

| 달라지는 것 | 언어·테마를 계정 메뉴로. 만들기·저장·삭제 규칙 통일. 3절 오류 수정. 간격·글자 토큰화 | A 전부 + 수정 결과를 피드백 상세 안으로, 검토 요청을 "피드백을 교수에게 보내기" 행동으로, 글쓰기와 자료를 '문서'로, 계획·일정에서 시간 조율을 미팅으로 옮김. 상세 화면은 본문 + 오른쪽 패널로 통일. 전역 만들기 버튼 | 화면을 "미팅 한 회차"를 단위로 재구성. 준비 → 진행(기록) → 정리(피드백·할 일) → 보내기(검토)가 한 화면의 단계. 목록 메뉴는 보조 |
| 학생이 느끼는 변화 | 같은 화면인데 덜 헷갈린다 | 메뉴가 줄고, 피드백 하나를 열면 수정 방법·할 일·결과·교수 응답이 한 곳에 있다 | 메뉴를 고르지 않고 "지금 단계"만 따라간다 |
| 장점 | 위험이 작고 빨리 끝난다. 기존 주소·데이터 그대로 | 흩어진 것이 합쳐져 클릭이 준다. 익숙한 "목록 → 상세 + 옆 패널" 꼴 | 지도 과정에 가장 잘 맞는다. 처음 쓰는 사람에게 쉽다 |
| 단점·위험 | 9개 메뉴의 겹침(피드백/수정 결과/검토 요청, 글쓰기/자료)은 남는다 | 주소 이전과 화면 6~7개 재배치. 교수 화면과 맞물린 검토 요청 이동은 신중해야 함 | 미팅 없이 쓰는 사람(혼자 정리, 수시 피드백)이 갈 곳이 애매. 거의 새로 만드는 수준 |
| 난이도 | 낮음(화면 단위 PR 8~10개) | 중간(공통 틀 먼저, 그다음 화면 묶음 4개) | 높음(데이터 모델은 유지 가능하지만 화면 대부분 재작성) |
| 디자인 시스템 | 색·부품 유지, 간격·글자 토큰 추가 | 같음 + 상세 화면 틀·패널·만들기 창을 공통 부품으로 | 같음 + 단계 진행 부품 신설 |

**추천은 B다.** 이유: (1) S2·S5가 가리키는 문제의 절반은 메뉴가 일의 흐름이 아니라 데이터 종류대로 나뉜 데서 온다. A로는 이것이 남는다. (2) 11/10 계획으로 여백 패널과 온보딩이 이미 들어와 있어 B의 "본문 + 오른쪽 패널" 틀은 새로 만드는 것이 아니라 넓히는 것이다. (3) C는 사용자 테스트 없이 가기에는 가정이 많다. B를 끝낸 뒤 홈을 C의 "지금 단계" 방식으로 바꾸는 것은 따로 할 수 있다.

순서는 A의 항목을 먼저 한다(B에서도 그대로 필요하다). A까지만 하고 멈춰도 손해가 없다.

## 5. AI 경험 방향

| 일 | 지금 | 제안 | 까닭 |
|---|---|---|---|
| 미팅 메모 정리, 피드백의 수정 방법 제안, 원고 검토 | 연구 도우미 입력줄의 '요청 종류' 드롭다운 + 각 화면의 패널 | 그 기록이 있는 화면의 오른쪽 패널에서만 실행. 근거는 지금 보고 있는 기록으로 미리 채움 | 대상이 정해진 일은 대상 옆에서 하는 것이 익숙하다(매니패스트의 대화 + 문서, Liner의 에이전트별 화면) |
| 원고 문장 고치기 | 편집 도구의 'AI 검토' 버튼 | 문장을 고른 뒤 뜨는 작은 메뉴에서 실행, 결과는 원문 옆에 나란히 두고 받아들이기/버리기 | 문서 편집기에서 널리 쓰이는 방식(이번에 레퍼런스에서 직접 확인하지는 않음) |
| 연구 전체에 대한 질문 | 연구 도우미 전체 화면 | 유지. 다만 요청 종류 드롭다운은 없애고 빈 화면의 예시 버튼으로 대신함 | 여러 기록을 넘나드는 질문은 대화가 맞다 |
| 단계에 맞춘 제안(예: 미팅 뒤 "메모를 정리할까요?") | 없음 | 홈과 상세의 '다음 할 일' 자리에 한 줄 제안만. 자동 실행은 하지 않음 | `AGENTS.md`의 "AI는 사용자가 실행·채택" 원칙 |

공통 규칙 [제안]
- 실행 전: 무엇을 읽는지(근거 목록)를 실행 버튼 옆에 보인다. 근거가 없으면 문구도 그에 맞춘다.
- 실행 중: 글자가 차례로 나오게 하고, '실행 중단'은 유지한다.
- 실행 후: 답마다 복사 / 다시 시도 / 기록으로 저장(피드백의 수정 방법, 할 일, 미팅 정리 등 요청 종류에 맞는 하나) 세 가지를 둔다. 저장한 것은 원문과 구분해 '제안에서 가져옴'으로 표시한다.
- 기록: '대화 기록'과 '실행 기록'을 하나로 합치고 이름을 '지난 대화'로 한다.

## 7. 다음에 정할 것

1. 방향 A / B / C 가운데 어느 것으로 갈지. (추천 B, A 항목부터 착수)
2. 언어 전환을 상단 줄에서 빼도 되는지. 일본어 사용자를 위한 노출이 필요하면 로그인 화면과 첫 방문 안내에만 둔다.
