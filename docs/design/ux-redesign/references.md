# 레퍼런스 분석과 공통 패턴 (2026-11-13)

브라우저에 열려 있던 서비스를 직접 눌러 본 것만 적는다. 화면을 본 범위가 좁으므로 "관찰한 화면"을 서비스마다 밝힌다. 남의 서비스에서 결제·거래·전송·삭제·설정 변경은 누르지 않았다.

## 1. 서비스별 관찰

| 서비스 | 관찰한 화면 | 관찰 불가 |
|---|---|---|
| Liner Scholar | 홈(입력창), 프로필 메뉴, 내 라이브러리, 프로젝트, 에이전트(가설 평가) | 대화 실행 결과, 글쓰기·논문 읽기 모드, 모바일 |
| 매니패스트(manyfast.io) — 지시서의 'Manifest' | 홈, 프로필 메뉴, 모든 프로젝트, 프로젝트 편집 화면 | 자료실, 커넥터, 새 프로젝트 흐름, 모바일 |
| GitHub | 저장소 홈, Pull requests 목록, 프로필 메뉴 | 이슈·PR 상세, 저장소 설정(이번에 열지 않음) |
| 토스증권 | 내 계좌(자산), 설정 창 | 주문·거래 화면(누르지 않음) |
| Linear | '작업 공간 만들기' 입력 화면뿐 | 서비스 내부 전체(작업 공간을 만들어야 들어갈 수 있음) |
| flex | 무료 체험 회사 정보 입력 화면뿐 | 서비스 내부 전체 |

### Liner Scholar
- 첫 화면: 가운데 큰 입력창 하나와 모드 탭 3개(물어보기 / 글쓰기 / 논문 읽기). 입력창 안에 첨부(+), 스킬 선택, 음성.
- 사이드바: 새 채팅 → 프로젝트 → 내 라이브러리 → 업데이트(배지) → 에이전트 8개 → 고정됨 → 최근 기록. 맨 아래 프로필 줄과 알림.
- 프로필 메뉴(왼쪽 아래): 계정 이메일, 플랜, 계정 설정, **테마 ›, 언어 ›**, 크레딧, 도움말, API, 고객센터, 로그아웃.
- 라이브러리: 머리(제목 + 설명 한 줄) → 오른쪽에 '새 폴더', '+ 파일 추가'(주 버튼) → 표(체크, 제목, 저널, 저자, 날짜).
- 프로젝트: 머리 → 검색 + 정렬 + '+ 새 프로젝트' → 카드.
- 에이전트 화면: 제목과 설명 한 줄 → 입력창(예시 문장 입력 버튼, 실행 버튼 '가설 평가하기') → 아래에 '최근 기록'. 에이전트마다 한 가지 일만 한다.

### 매니패스트
- 첫 화면: 인사말 + 큰 입력창(모드: 아이디어 / 자료 분석, 글자 수 0/1000) → '기능 체험하기' 카드 3개(닫기 가능) → 최근 프로젝트/최근 기록 탭.
- 사이드바: 작업 공간 전환 → 홈, 모든 프로젝트, 자료실, 커넥터, 휴지통 → 즐겨찾기 → (아래) 플랜 카드, 업데이트 노트, 프로필 줄. 상단 줄: 사이드바 접기, 검색(⌘K), 피드백, 알림, 플랜·인원.
- 프로필 메뉴(왼쪽 아래): 이름·이메일·설정 톱니, **테마 ›, 언어 ›**, 가이드, 홈페이지, 공식 포럼, 로그아웃.
- 모든 프로젝트: 머리(제목) → 오른쪽 '새 폴더', '+ 새 프로젝트'(주 버튼) → 검색, 선택, 정렬 → 표(체크, 이름, 마지막 수정, ⋯) → 사용량 줄(1/3).
- 편집 화면: 왼쪽 아이콘 레일(채팅, 검토, 문서함, 코멘트, 코드, 커넥터, 커스텀, 버전) + 대화 열 + 오른쪽 문서. 대화에는 AI가 한 일이 '생각함 ›', '문서 읽음', '기능 작성 완료'처럼 접힌 단계로 쌓이고 마지막에 요약이 나온다. 입력줄에 모델 선택, '@로 아이템 언급'. 문서 위에 완성도 막대와 '양식 편집'.

### GitHub
- 저장소 안 이동은 상단 탭(Code, Issues, Pull requests, …). 목록 화면: 왼쪽 보기 목록(내가 만든 것, 나에게 배정 등) → 가운데 필터 입력 + 목록 → 오른쪽 위 주 버튼 'New pull request' 하나.
- 전역 상단 줄 오른쪽: 검색, **만들기(+) 메뉴**, 알림, 프로필. 어느 화면에서든 같은 자리.
- 프로필 메뉴(오른쪽 위): Profile, Repositories, …, **Settings, Appearance, Accessibility**, Sign out.

### 토스증권
- 상단 탭(홈, 피드, 주식 골라보기, 내 계좌) + 왼쪽 하위 메뉴(자산, 거래내역, …) + 오른쪽 고정 패널(내 투자, 관심, 최근 본).
- 설정은 오른쪽 아래 톱니 → **화면 가운데 창**: 왼쪽 하위 메뉴(일반, 거래, 알림, 커뮤니티, 단축키, 보안, Open API) + 오른쪽 내용. 색상 모드·사이드 창 위치는 그림을 고르면 바로 적용, 스위치도 바로 적용. 저장 버튼 없음.
- 새 기능은 말풍선과 오른쪽 아래 카드로 한 번 알린다('확인'으로 닫음).

### flex / Linear (가입 단계만)
- flex: 왼쪽 질문("딱 필요한 정보만 받을게요": 회사명, 직원 수) + 오른쪽에 제품 화면의 뼈대 미리보기. 마진의 연구 만들기와 같은 구조다.
- Linear: 가운데 정렬 폼(이름, URL, 지역) + 버튼 하나. 아래에 로그인한 이메일과 '다른 이메일 쓰기'.

## 2. 여러 곳에서 되풀이되는 패턴

| # | 패턴 | 관찰한 곳 | 사용자가 기대하는 것 | 마진에 적용 | 주의 |
|---|---|---|---|---|---|
| P1 | 언어·테마는 프로필 메뉴 안의 하위 메뉴 | Liner, 매니패스트(왼쪽 아래), GitHub(오른쪽 위 Appearance), 토스(설정 창) | "내 설정은 내 이름을 누르면 나온다" | 상단 줄의 언어 버튼을 계정 메뉴로 옮김 | 로그인 전에는 프로필이 없으므로 공개 화면 머리·푸터에 둔다 |
| P2 | 목록 화면의 주 버튼은 오른쪽 위에 하나, 보조 버튼은 그 왼쪽에 테두리 버튼 | Liner 라이브러리·프로젝트, 매니패스트 프로젝트, GitHub PR | "새로 만들기는 오른쪽 위" | 이미 대체로 맞음. 빈 상태에서 본문에 같은 버튼을 한 번 더 두는 것만 정리 | — |
| P3 | 목록은 머리 → 검색·정렬 줄 → 표/카드 | Liner, 매니패스트, GitHub | 훑어보고 좁히기 | 필터를 전부 주소에 남기고 같은 줄 구성으로 통일 | 항목이 10개 미만일 때 검색·정렬 줄이 과하다. 개수에 따라 숨긴다 |
| P4 | AI 첫 화면은 큰 입력창 하나 + 모드/예시 | Liner, 매니패스트 | "여기에 적으면 된다" | 연구 도우미 빈 화면(이미 비슷). 요청 종류 드롭다운을 예시 버튼으로 | 마진은 "고른 기록만 읽는다"가 원칙이라 근거 표시가 입력창 옆에 있어야 한다 |
| P5 | 한 가지 일을 하는 AI는 전용 입력 화면(예시 버튼, 일 이름이 적힌 실행 버튼, 아래에 최근 기록) | Liner 에이전트 | 무엇을 넣고 무엇이 나오는지 한눈에 | 미팅 정리·수정 방법 제안을 대상 화면의 패널에서 같은 꼴로 | Liner처럼 메뉴에 8개를 나열하면 마진에서는 과하다 |
| P6 | 대화(왼쪽) + 결과물(오른쪽), AI가 한 일을 접힌 단계로 | 매니패스트 편집 화면 | AI가 무엇을 읽고 무엇을 바꿨는지 추적 | 글쓰기·피드백 상세의 "본문 + 오른쪽 패널"(마진은 좌우가 반대) | 마진은 AI가 문서를 직접 바꾸지 않으므로 '받아들이기' 단계가 따로 필요하다 |
| P7 | 설정은 왼쪽 하위 메뉴 + 오른쪽 내용, 고르면 바로 적용 | 토스 | 저장 버튼을 찾지 않는다 | 계정 설정의 선택·스위치 항목 | 글자 입력(이름, 이메일)은 저장 버튼 유지 |
| P8 | 프로필·알림·업데이트는 사이드바 맨 아래 | Liner, 매니패스트 | 화면 아래 왼쪽에 "나" | 이미 같음 | — |
| P9 | 전역 만들기 버튼 | GitHub(+) | 어디서든 새로 만들기 | 할 일·피드백·미팅을 어디서든 만드는 버튼(⌘K의 만들기와 연결) | Liner·매니패스트에는 없다. 만들 종류가 여럿인 서비스의 방식이다 |
| P10 | 가입·만들기는 질문 + 미리보기 | flex, (11/10 계획의 Attio) | 답이 화면에 어떻게 반영되는지 본다 | 연구 만들기(이미 적용) | — |

## 3. 관습과 고유 방식의 구분

- 관습으로 볼 것(둘 이상에서 같은 꼴): P1, P2, P3, P4, P8.
- 그 서비스의 일에 맞춘 고유 방식: Liner의 에이전트 8개 메뉴(연구 단계별 도구를 파는 서비스), 매니패스트의 아이콘 레일 8개(문서 하나를 깊게 다루는 편집기), 토스의 오른쪽 고정 패널(시세를 늘 봐야 하는 서비스), GitHub의 상단 탭(저장소 하나에 성격 다른 기능이 많음).
- 마진은 "기록을 쌓고 다음 미팅을 준비하는" 서비스라 Liner·매니패스트의 사이드바 구조(홈, 목록 몇 개, 아래에 나)가 가장 가깝고, AI는 매니패스트처럼 결과물 옆에 붙는 꼴이 맞다.
