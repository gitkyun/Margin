# 수업 시연 구현·배포 기준

수정일: 2026-11-04

이 문서는 [PRD](../product/prd.md)의 수업 시연 범위를 실제 구현·제한 공개 배포로 옮기는 기준이다. 대표 시나리오가 로그인부터 자료 저장·Google AI 호출·교수 응답·재확인까지 이어져야 한다. 현재 React 웹앱과 Supabase 서버는 구현되어 Cloudflare Pages에 배포했다. Gemini 키는 사용자 요청으로 비워 두었다. 아래 시나리오는 완료 체크리스트이며 모든 단계가 검증됐다는 뜻은 아니다. 최신 결과는 [검증 기록](verification-20261104.md)을 따른다.

## 정해진 방향과 남은 선택

| 구분 | 내용 |
|---|---|
| 사용자 확정 | 수업에서 대표 사용자 시나리오를 실제 시연할 수 있도록 구현·배포한다. AI 기능은 Google API에 연결한다. |
| 기존 제품 조건 | 학생 중심, 선택적 AI, 교수 계정 로그인·지정 계정 접근, 항목별 응답, 당시 보존 파일·설명·응답 유지, 학생의 명시적 재확인 요청을 유지한다. |
| 이번 작성 기준 | 시연용 학생·교수 계정을 미리 준비하고 허용 계정만 접속한다. Gemini API를 우선 연결 후보로 두고 앱 서버에서 호출한다. 새 기능 전체보다 아래 시나리오를 먼저 완성한다. |
| 구현 구성 | React·Vite, Cloudflare Pages, Supabase DB·Auth·Storage·Edge Functions, Gemini API. 발급 계정 로그인과 지정 계정 접근. AI 키와 실제 모델 사용 가능 여부는 추후 연결 시 검증한다. |

Google API 사용이 로그인·파일 저장·호스팅까지 Google 서비스로 정했다는 뜻은 아니다. 호스팅 서비스는 서버에서 AI 인증 정보를 보호하고 계정·자료 접근과 영구 저장을 구현할 수 있는 구성을 선택한다. 접속 URL이 존재하더라도 계정·파일·API 접근을 제한하며 공개 회원가입과 불특정 다수 운영은 이번 시연 범위에서 제외한다.

## 대표 시연 시나리오

아래의 문장·연구·파일은 설명용 가상 사례다. 실제 연구 결과나 실제 교수 발언으로 제시하지 않는다. 다음 단계는 앞 단계에서 저장한 같은 기록을 사용한다.

| ID | 사용자 행동 | 실제로 동작할 결과 | 확인할 조건 |
|---|---|---|---|
| D01 | 학생 계정으로 로그인해 연구·미팅을 열고 메모를 입력하거나 붙여 넣는다. | 메모와 연구·미팅 관계를 저장하고 새로고침 후 다시 연다. | 비어 있는 새 연구에서도 시작하며 교수 가입·응답이나 전체 로드맵을 요구하지 않는다. |
| D02 | 메모에서 AI 정리를 실행하고 피드백을 저장한다. 해당 피드백에서 수정 방안을 제안받는다. | Google API의 실제 응답으로 정리 후보와 복수 방안을 표시하고 학생이 고쳐 저장한다. | 원문 발췌·위치와 새 방법·가정을 구분한다. 예시 답변을 실시간 응답으로 표시하지 않는다. |
| D03 | 선택한 방안으로 할 일을 만들고 날짜 미정 또는 지정한 다음 미팅 준비에 포함한다. | 같은 작업에 기한·진행을 저장하고 보여줄 결과·자료·질문을 준비 목록에 연결한다. | 준비 문서 작성과 AI 구성은 선택이다. 완료·학생 반영·교수 결과는 자동 연동하지 않는다. |
| D04 | 실제 수정 결과를 기록하고 가상 원고 v2 파일·확인 위치를 연결한다. 두 수정 결과를 한 요청에 담아 링크를 만든다. | 업로드 파일과 당시 설명을 보존하고 지정 교수 계정에만 검토를 공개한다. | 원 피드백·파일 전체를 미리 본다. 문서 검토에 보존 파일·위치가 없으면 링크 생성을 막는다. |
| D05 | 교수 계정으로 링크를 열어 한 항목은 수정 내용 확인, 다른 항목은 추가 수정 필요와 이유를 저장한다. | 별도 로그인 세션에서 실제 결과·이유·작성자·시각을 해당 항목·차수에 저장한다. | 이유가 비면 추가 수정 필요를 저장하지 않는다. 학생 계정은 교수 결과를 대신 저장하지 못한다. |
| D06 | 학생이 새 응답을 읽고 추가 수정한 v3 파일로 해당 항목만 재확인 요청한다. | 새 차수는 응답 전으로 시작하고 v2·이전 응답과 다른 항목의 결과를 유지한다. | 새 파일 업로드만으로 기존 검토를 바꾸지 않는다. 학생·교수 모두 이전 차수를 다시 열 수 있다. |

시연은 로그인한 학생·교수의 별도 세션으로 수행한다. 화면의 역할 선택 스위치만으로 교수 권한을 부여하는 방식은 사용하지 않는다. 미팅·피드백·작업·수정 결과·검토의 식별자를 이어 사용해 각 화면이 서로 다른 예제 데이터만 보여주는 상태를 피한다.

## 이번 시연과 제품 전체 범위의 구분

| 구분 | 구현 기준 |
|---|---|
| 시연 필수 | D01~D06, 저장한 원문·과거 미팅·파일 버전 조회, 목록으로 복귀, 기본 오류·재시도, 계정·파일·검토 권한 확인 |
| 시연 필수 AI | 메모 정리와 복수 수정 방안 제안은 실제 Google API로 실행한다. 결과를 학생이 편집·저장하고 할 일에 연결한다. |
| 선택 구현 | 준비 문서 AI 구성, 로드맵·일정의 상세 편집, 연구 보관·복원·반복 묶음 등은 제품 초기 설계에 남기되 대표 시연을 먼저 완성한 뒤 확장한다. |
| 시연 제외 | 실제 공개 회원가입·일반 초대·자동 메일·비밀번호 복구의 전체 흐름, 통합 검색·전체 활동·추가 기록 비교·일정 역산·녹음·전사 등 후속 기능 |

시연 필수에서 제외했다고 제품의 기존 초기 기능을 후속으로 재분류하지 않는다. 미구현 메뉴는 숨기거나 준비 중으로 표시하고 동작하는 버튼처럼 제시하지 않는다. 파일 미리보기는 시연용 PDF를 우선 지원하고 추가 형식은 실제 지원 범위를 안내한다.

## Google AI 연결

권장 구조는 `브라우저 → 로그인·권한을 확인하는 앱 서버 → Google AI API → 응답 검증 → 학생 편집 영역`이다. Google 콘솔은 프로젝트·인증·사용량을 관리하는 곳이며 브라우저가 콘솔을 호출하는 구조가 아니다.

| 항목 | 구현 기준 |
|---|---|
| 접속 방식 | 발급된 인증 정보가 Gemini API용인지 다른 Google AI 접속 방식인지 먼저 확인한다. 실제 엔드포인트·SDK·모델·설정 이름을 선택 후 기록하며 서로 다른 방식의 인증 정보를 혼용하지 않는다. |
| 인증 정보 | 서버의 비밀 설정으로 보관한다. Git·브라우저 코드·클라이언트용 환경 변수·응답·시연 화면에 키를 넣지 않는다. |
| 입력 | 선택한 메모 구간·피드백·자료 버전만 전송한다. 시연 최소 구현은 선택 메모·피드백 텍스트로 실행한다. PDF 전체 분석·OCR·외부 URL 수집은 암묵적으로 추가하지 않는다. |
| 정리 응답 | 유형·내용·실제 입력의 출처 식별자·발췌·위치를 받아 원문과 대조한다. 근거가 없는 항목은 원문 사실로 저장하지 않고 확인 필요로 표시한다. |
| 방안 응답 | 수정 방법·예상 결과·필요 자료·추가 작업·근거·가정을 구분한 복수 방안을 받는다. 모든 방안이 같은 작업을 표현만 바꾼 것인지 학생이 비교할 수 있게 한다. |
| 검증·저장 | 구조화된 응답을 받아 필드·유형·출처 관계를 서버에서 검증한다. 형식이 맞아도 사실·의미가 검증된 것은 아니므로 학생이 고쳐 저장한다. 원문 변경·작업 완료·교수 공유는 AI가 실행하지 않는다. |
| 진행·중단 | 생성 중과 완료·실패를 구분하고 중복 실행을 막는다. 영역 닫기와 생성 중단은 구분하며 가능한 중단 범위만 안내한다. |
| 실패 | 시간 초과·사용량 제한·권한 오류·차단·잘못된 응답을 구분한다. 입력을 유지하고 재시도·직접 작성으로 돌아간다. 무한 재시도하지 않는다. |
| 모델·한도 | 사용 가능한 모델과 프로젝트의 실제 한도를 확인해 설정으로 관리한다. 문서에 임의의 무료 호출 수·고정 비용·확정 응답 시간을 약속하지 않는다. |
| 기록 | 제공자·실제 모델·실행 시각·성공 여부를 점검할 수 있게 한다. 비밀 키와 연구 원문 전체를 일반 오류 로그에 남기지 않는다. |

Gemini API의 키를 코드 저장소와 클라이언트에 노출하지 않는 근거는 [Google 공식 키 안내](https://ai.google.dev/gemini-api/docs/api-key)를 따른다. 구조화 출력도 앱에서 값의 타당성을 확인해야 한다는 점은 [공식 구조화 출력 안내](https://ai.google.dev/gemini-api/docs/structured-output?lang=rest)에 명시돼 있다. 프로젝트·모델별 호출 한도와 일시 오류 처리는 [공식 한도 안내](https://ai.google.dev/gemini-api/docs/rate-limits), [오류 처리 안내](https://ai.google.dev/gemini-api/docs/troubleshooting)를 참고한다. 2026-11-03에 공식 문서를 확인했으며 사용자 프로젝트의 설정·키·사용량을 확인한 상태는 아니다.

## 제한 공개 배포 조건

- 사전 발급한 시연 계정의 로그인과 허용 목록을 서버에서 확인한다. 공개 가입은 닫고 가입 화면과 완료 단계만 명시적인 시연으로 제공한다. 계정 이메일 확인 상태는 준비 단계에서 확인한다.
- 교수 검토는 지정 계정·공유 상태를 서버에서 확인한다. 페이지뿐 아니라 파일 다운로드·댓글·응답·AI 실행도 현재 권한을 검사한다.
- 시연 데이터는 DB·파일 저장소에 남기며 새로고침·다른 계정 로그인·앱 재배포 뒤에도 유지한다. 브라우저 임시 저장이나 서버의 임시 파일만으로 보존을 대신하지 않는다.
- 배포 환경의 비밀 설정·허용 도메인·HTTPS·저장소 권한을 구성한다. 실제 주소·서비스·필수 설정 이름과 실행 명령은 선택·구현 후 개발 안내에 기록한다.
- 가상 연구·메모·PDF v1/v2/v3·피드백·두 검토 항목을 준비한다. 실제 계정의 비밀번호·API 키·개인 자료를 Git에 넣지 않는다.
- 반복 연습은 시연 데이터 묶음을 복제하거나 명시적으로 초기화해 시작한다. 초기화는 운영자 작업으로 제한하며 시연 중 기존 검토 이력을 지우지 않는다.

## 배포 후 통과할 확인 항목

| 확인 | 통과 조건 |
|---|---|
| 대표 시나리오 | 배포 주소에서 D01~D06을 이어 수행하고 같은 기록의 관계를 다시 찾는다. |
| 실제 AI | Google API 호출 성공과 응답을 확인하고 학생이 저장한 제안의 실행 출처를 추적한다. |
| 계정·권한 | 로그아웃 상태·지정하지 않은 계정은 자료와 파일을 열지 못하고 학생은 교수 결과를 대신 저장하지 못한다. |
| 필수 이유 | 추가 수정 필요의 공백 이유는 저장되지 않고 결과와 이유가 함께 저장된다. |
| 이력 | v3 재확인 뒤 v2·당시 설명·이전 교수 응답과 다른 항목의 결과가 유지된다. |
| 실패 복귀 | AI 실패·업로드 실패·저장 실패에서 입력을 유지하고 재시도 또는 직접 작성으로 이어진다. |
| 데이터 유지 | 새로고침·다른 세션·재배포 뒤 저장한 메모·작업·파일·검토를 다시 연다. |

인터넷·Google API 장애에 대비한 이전 저장 결과는 별도로 준비할 수 있다. 사용할 때는 저장된 예시임을 표시하며 실시간 호출 성공으로 설명하지 않는다. 이 대체 시연이 실제 API 연결 검증을 대신하지는 않는다.

배포 완료를 기록할 때는 배포 주소·대상 커밋·검증 일시·실제 통과한 항목·남은 제한을 함께 남긴다. 저장소 문서 검사 통과를 앱 실행·배포·사용성 검증 통과로 보고하지 않는다.
