## 실제 Supabase 검사

사전 발급 학생·교수 계정으로 서로 다른 세션을 사용하고, 새 가상 연구에서 검사했다. 기존 실제 연구는 변경하지 않았다.

1. 별도 계정 로그인.
2. 초대 수락 전 연구 차단, 수락 후 공동 기록 접근, 개인 미팅 메모 비공개.
3. 공동 계획서 저장·작성자 보존·오래된 저장 거부·불변 버전 생성.
4. 실제 6쪽 한글 PDF 업로드·공동연구자 다운로드·폴더 연결.
5. 후보 시간 응답·확정·재시도 후 미팅 한 개만 생성.
6. 공동 편집자의 검토 공개와 검토 차수의 실행자 기록.
7. 두 검토 항목에 서로 다른 교수 응답 저장.
8. 한 항목만 재확인, 요청 재시도 중복 방지, 이전 파일·다른 항목 응답 유지.
9. 서버 허용 모델 목록 조회. Gemini 생성 호출은 하지 않음.
10. 멤버 해제 후 문서 접근 차단.
11. 휴지통 이동 후 교수 접근 차단, 복원 후 기록 유지·교수 공유 중지.
12. 검증용 연구 보관.

오래된 문서 저장 요청은 클라이언트의 20초 대기 중 오류 응답을 받지 못했다. 이후 서버 최신본을 다시 읽어 편집자의 내용이 덮어써지지 않은 것은 확인했다. SQLSTATE `40001`의 즉시 응답은 격리 PostgreSQL 검사에서 확인했으며, 실제 네트워크에서 같은 응답을 받았다고 보고하지 않는다. 앱에는 RPC 대기 제한, 저장 실패 후 최신본 대조, 작성본 유지·충돌 비교를 추가했다.

이번 검사에서 만든 가상 연구는 보관했고 파일과 이력은 남겼다. 검증 계정의 기존 세션은 전체 로그아웃하지 않았다.

## 실제 Edge 검사

배포된 `ai-assist` v5에 대해 익명 401, 잘못된 토큰 401, 공유받지 않은 원문 403, 허용하지 않은 출처 403, 허용 출처의 키 미설정 503, OPTIONS 204를 확인했다. 생성 API의 실제 성공은 0회다.

경험 확장 DB 마이그레이션 네 개 및 실시간 전사 마이그레이션 두 개와 함수 v5를 클라우드에 적용했다. `verify_jwt=false`여도 함수 내부에서 Auth 사용자 확인·허용 계정·연구/자료 접근을 검사한다. 모델 목록이 보인다는 사실은 해당 Google 프로젝트의 생성 모델 이용 가능 확인을 뜻하지 않는다.

## 배포 확인

Cloudflare의 배포 성공 상태를 확인하고 HTTP로 소개·로그인·연구·글쓰기 직접 경로와 JS·CSS·글꼴의 응답·빌드 일치를 검사했다. 상세 결과는 [배포 응답 기록](deployment-http-20261105.json)에 남긴다. HTTP 응답 검사를 로그인 후 사용자 흐름 검사로 표현하지 않는다.

배포의 기존 `microphone=()` 정책이 녹음을 막고 있어 `microphone=(self)`로 수정했다. 실제 배포 응답에도 이 정책이 있는 것을 확인했다. 사용자가 권한을 허용해야 하며 카메라·위치 접근은 계속 차단한다. 이것은 실기기 녹음 성공 검사가 아니다.

Compass의 검색·선택·탭 패턴을 RMS에 구현했다. 검색 지우기/입력 복귀, 현재 선택값에서 키보드 이동, 결과 없음에서 잘못된 선택 방지, 필터 포커스 검사 다섯 개가 통과했다. 공식 소스 전체를 설치하거나 복사하지 않았다.

## 실행하지 못한 검사

- 이번 로컬 브라우저 접근은 앱에 저장된 사이트 권한에 의해 차단됐다. 다른 도구·주소로 우회하지 않았다. 따라서 최종 변경분의 1440·1280·768·390px, 두 테마, 키보드·포커스·동작 감소·대비 검증은 미완료다.
- 실제 마이크 장치에서 동의·녹음·일시정지·재생·저장 및 권한 거절을 확인하지 않았다. 관련 코드는 구현되어 있다. 사용자가 마이크 실기기 검사를 직접 하기로 했으며 결과는 아직 받지 않았다.
- Gemini 키는 사용자 요청으로 비워 두었다. 실제 다섯 작업의 생성 결과, 제공자 한도·시간 초과, 생성 중 중단은 키 연결 후 확인해야 한다.
- 전체 D01~D06을 새 배포의 브라우저에서 처음부터 끝까지 수행하지 않았다. 서버 흐름 검사와 전체 시연 완료를 구분한다.
- 저사양 기기·스크린리더·일반 사용자의 사용성 검증은 하지 않았다.

기본 앱 약1.07MB, PDF 생성 청크 약1.25MB의 빌드 경고가 남는다. 편집기·캘린더·다이어그램·PDF는 지연 로드하지만 첫 화면 로드 성능의 실측 점수는 없다.

## 실시간 한국어 전사 추가 검사

브라우저의 실제 음성 인식 이벤트를 받아 화면에 표시하고 녹음 종료 후 수정·저장하는 경로를 구현했다. Web Speech API를 사용하며 Gemini 키나 가짜 응답을 넣지 않았다. 인식 엔진 지원 및 네트워크 상태에 따라 실패할 수 있고 브라우저 제공자 서버로 음성이 전송될 수 있음을 녹음 전에 안내한다.

모의 인식 이벤트로 중간 문장 교체·확정·마지막 결과 대기·일시정지/재개·중단 후 늦은 이벤트 무시·네트워크 오류·재연결 제한·미지원, 화면 글자 표시와 수정본 저장·업로드 중복 방지를 확인했다. 실제 발화를 인식한 시험은 아니다.

실제 Supabase에 가상 연구와 1초 무음 파일을 별도 등록해 다음 6항목을 확인했다. 한국어 문자열은 저장 검사용 입력이며 실제 녹음에서 나온 전사로 보고하지 않는다.

1. 음성 파일과 한국어 텍스트 저장.
2. 수정본·원 인식문 분리, 충돌 거부, 응답 유실 재시도.
3. 공동연구자가 음성은 내려받아도 전사문은 조회·수정할 수 없음.
4. 비로그인 조회·수정 거부.
5. 새 로그인 세션에서 저장문 조회.
6. 휴지통 접근 차단과 복원 후 내용 보존.

첫 실제 충돌 검사에서는 40001 오류 응답이 시간 내 도착하지 않았다. 전사 RPC를 사용자 편집 충돌용 PT409로 바꾼 뒤 HTTP 409를 실제로 확인했다. 다른 문서의 기존 40001 경로까지 검증된 것으로 확대하지 않는다.

검사 연구는 보관했다. 실제 마이크·한국어 인식 정확도·음성 서비스와 동시 녹음·지원 브라우저 차이는 사용자 실기기 검사 결과를 기다린다. 실제 브라우저 화면 점검은 기존 접근 차단 때문에 수행하지 않았고 우회하지 않았다.

Supabase 보안 점검의 신규 전사 테이블에는 RLS와 소유자 조회 정책을 설정했다. 인증 사용자용 SECURITY DEFINER RPC 경고는 의도한 검증 진입점이며 내부 세션·녹음 소유권·원문·수정 번호를 검사한다. 기존 서비스 전용 테이블의 정책 없음 안내는 브라우저 거부 설계다. 기존 비밀번호 유출 검사 비활성 경고는 유지되며 [공식 설정 안내](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)를 참고한다.
