## 수업 시연 적용 기준

이번 구현 목표는 허용 계정만 사용하는 제한 공개 웹앱에서 대표 시나리오를 실제로 수행하는 것이다. AI는 Google API에 연결한다. 제품 전체의 초기·후속 기능 정의는 유지하고 시연의 필수 동작은 [PRD의 D01~D06](prd.md)과 [수업 시연 구현·배포 기준](../development/classroom-demo.md)에 맞춘다.

- 필수 구현은 학생 로그인·메모 저장, 실제 AI 정리·복수 수정 방안, 할 일·다음 미팅 준비, 보존 파일·수정 결과, 검토 링크·교수 응답·재확인과 이전 이력 조회다.
- 시연용 계정을 사전 발급하고 공개 회원가입·전체 계정 복구 흐름은 시연 동선에서 제외하는 것을 작성 기준으로 둔다. 실제 로그인·지정 계정·공유 상태 확인을 역할 선택 화면으로 대신하지 않는다.
- 저장한 기록·파일·응답은 다른 세션과 새로고침 뒤에도 조회한다. 검토 차수와 보존 파일은 재배포 뒤에도 유지할 저장 구성을 사용한다.
- 아래 중요도·P0·P1·기획 상태는 제품 범위이며 구현 완료 표시는 아니다. 시연 필수 밖의 초기 기능도 그대로 유지하고 미구현 화면은 준비 중으로 표시하거나 숨긴다.

## 1. 연구 자료 및 문서 버전 관리
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중

학생은 연구별로 자료와 당시 내용을 보존한 파일 버전을 등록·조회하고, 외부 URL은 보존 파일과 구분한다. 같은 자료·버전을 여러 미팅·수정 결과의 근거로 연결하되 이전 검토 차수의 파일과 위치는 바꾸지 않는다. 미리보기와 기본 목록은 초기 범위로, 자료·기록의 통합 검색은 후속 범위로 두며 기존 편집기·저장소 전면 대체는 제외한다.

**수용 기준:**
```
1. ○ 학생은 연구를 생성·전환·보관·복원해 다른 연구의 자료와 AI 입력을 섞지 않고 이전 기록을 찾을 수 있다.
2. ○ 보존 파일을 새 버전으로 추가해도 기존 검토가 참조하는 과거 버전과 위치를 열 수 있다.
3. ○ 외부 URL 저장은 과거 본문 보존으로 표시하지 않고 파일 미리보기 실패에도 저장된 파일을 유지한다.
4. ○ 하나의 보존 파일을 여러 미팅·검토 항목의 근거로 연결하며 공유 전 공개될 파일 전체를 확인할 수 있다.
```


### 1.1 연구 자료 통합 관리
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 학생 | **기기**: 웹 브라우저

**기능의 근거**: 논문 지도 자료가 문서 편집기, 저장소, 메신저와 개인 메모에 흩어져 있어 학생이 필요한 자료를 매번 다시 찾고 정리해야 한다.

학생이 논문 초안, 발표 자료, 분석 결과, 참고문헌 등 연구 자료를 연구별로 등록하고 분류하는 P0 기능이다. 자료는 미팅·피드백·버전 기록과 연결되는 기준 단위가 된다. 기존 문서 편집기나 클라우드 저장소를 대체하는 파일 저장소 기능은 범위 밖이다.

**개발 준비 슬롯**
- **선행조건**: - 학생이 로그인되어 있고 자료를 등록할 연구 공간이 있어야 한다.
- **트리거**:
  - 학생이 자료 목록에서 자료 등록을 선택하면 시작한다.
  - 학생이 미팅 자료 사전 등록이나 버전 등록 중 새 자료 추가를 선택하면 시작한다.
- **동작**:
  - 학생이 자료 이름, 유형, 파일 또는 외부 링크를 입력한다.
  - 시스템은 자료를 연구에 연결해 저장한다.
  - 학생은 유형과 분류를 바꾸거나 자료를 보관 처리할 수 있다.
  - 자료 추가에서 파일 업로드·외부 링크를 구분한다. 파일명으로 표시 이름을 채우고 유형은 기타를 기본값으로 둔다.
  - 업로드 진행·취소·실패를 표시하고 성공한 파일만 등록·연결한다.
  - 파일 선택 시 미리보기, 외부 링크 선택 시 주소와 원본 열기를 제공한다.
- **결과**:
  - 자료가 연구 자료 목록에 추가되고 버전·미팅·피드백 연결 대상이 된다.
  - 자료 등록 내역은 P1 최근 활동 목록에 표시된다.
- **예외**:
  - 자료 이름이 비었거나 파일·링크가 모두 없으면 저장하지 않는다.
  - 관계가 연결된 자료의 보관은 연결을 유지하며 삭제의 영향과 가능 범위는 연구 기록 관계와 변경 이력 정책에서 결정한다.
  - 지원하지 않는 형식·용량 초과를 안내한다. 미리보기 실패 시 저장 파일은 유지하고 재시도·다운로드를 제공한다.
  - 자료 저장 성공 후 미팅·결과 연결만 실패하면 연결만 재시도한다.
- **표시**:
  - 자료 목록은 유형별 필터와 최근 수정 순 정렬을 제공한다.
  - 자료가 없으면 첫 자료 등록을 안내하는 빈 화면을 보여준다.
  - 초기 미리보기는 PDF·PNG·JPEG를 기준으로 하며 PDF 페이지 이동과 현재 버전을 표시한다. 추가 형식·용량은 운영 전에 정한다.
- **권한 & 접근**:
  - 학생만 자료를 등록·수정·보관할 수 있다.
  - 교수의 자료 열람은 개인 기록과 교수 공유 권한 정책을 따른다.
- **비즈니스 규칙**:
  - 자료 유형은 논문 초안·발표 자료·분석 결과·참고문헌·기타로 구분한다.
  - 등록 당시의 파일로 내용을 보존하는 제출 자료와 내용이 외부에서 변경될 수 있는 참조 링크를 구분한다.
  - 외부 저장소 링크는 내용과 변경 이력을 가져오지 않으며 과거 내용 복원을 보장하지 않는다.
  - 보관은 과거 미팅·피드백 관계와 허용된 조회를 유지하면서 현재 작업 대상에서 제외한다.
- **데이터**: - 자료는 자료ID, 연구ID, 이름(필수), 유형(필수), 입력 형태(등록 파일·외부 참조 링크), 파일 또는 URL, 설명, 상태(활성·보관), 등록자와 등록·수정 시각을 가진다.


### 1.2 문서 버전별 이력 관리
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 학생 | **기기**: 웹 브라우저

**기능의 근거**: 수정본이 여러 개 생기면서 어떤 버전에 어떤 피드백을 받았고 무엇을 고쳤는지 학생이 기억에 의존해 관리하고 있다.

학생이 등록 당시 내용을 보존한 문서의 수정본을 버전별로 구분하고, 각 버전의 진행 내용과 피드백을 연결하는 P0 기능이다. 특정 버전을 미팅에 제출한 여부는 수정 이력과 별도로 기록하며, 제출본과 수정본을 배타적인 자료 유형으로 취급하지 않는다. 외부 링크만 등록한 자료의 과거 내용 보존, 자동 내용 비교와 외부 편집기 동기화는 범위 밖이다.

**성공 기준**: 사용성 검증에서 학생이 피드백의 대상 자료와 반영 근거를 특정 시점의 보존된 버전까지 추적하고 외부 참조 링크의 한계를 구분할 수 있는지 확인한다.

**개발 준비 슬롯**
- **선행조건**: - 버전을 추가할 연구 자료가 등록되어 있어야 한다.
- **트리거**:
  - 학생이 자료 상세에서 새 버전 등록을 선택하면 시작한다.
  - 학생이 미팅 자료 사전 등록에서 제출 버전을 지정하면 시작한다.
- **동작**:
  - 학생은 보존할 파일을 등록해 새 버전을 만들고 이번 버전의 진행 내용을 입력한다.
  - 학생은 해당 버전의 미팅 제출 여부를 별도로 연결한다.
  - 학생은 이 버전과 관계있는 피드백을 선택해 연결한다.
- **결과**:
  - 새 버전이 자료의 최신 버전이 되고 이전 버전은 이력으로 남는다.
  - 연결된 피드백에는 반영을 시도한 버전이 기록된다.
- **예외**:
  - 등록된 보존 버전은 덮어쓰지 않고 새 버전으로 수정 이력을 남긴다.
  - 외부 참조 링크의 내용이 바뀌면 이전 내용을 보여준다고 안내하지 않는다.
- **표시**:
  - 보존된 문서의 버전 목록에는 버전 번호와 등록 시점, 미팅 제출 여부, 연결된 피드백을 구분해 표시한다.
  - 외부 참조 링크에는 등록 시점의 내용이 보존된 문서 버전처럼 과거 내용·댓글 위치가 재현되는 것으로 표시하지 않는다.
- **권한 & 접근**:
  - 학생만 버전을 등록하고 진행 내용을 수정할 수 있다.
  - 교수는 공유받은 버전만 열람할 수 있다.
- **비즈니스 규칙**:
  - 보존 파일을 새 버전으로 추가하면 이전 파일과 검토 차수의 버전 연결을 변경하지 않는다.
  - 같은 이름의 파일은 자동 병합하지 않고 기존 자료의 새 버전인지 별도 자료인지 학생이 고른다.
  - 외부 URL을 등록 당시 내용을 보존한 문서 버전이라고 표시하지 않는다.
- **데이터**:
  - 보존된 버전은 버전ID, 자료ID, 버전 번호(자료 내 유일), 파일, 진행 내용, 등록 시각을 가진다.
  - 미팅 제출 연결은 미팅ID와 버전ID를 가지며 같은 버전은 수정 이력과 제출 이력을 동시에 가질 수 있다.
  - 외부 참조 링크는 과거 내용이 보존된 버전과 동일한 의미로 표시하지 않는다.


### 1.3 교수 검토 구성·미리보기·링크 생성
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 학생 | **기기**: 웹 브라우저

**기능의 근거**: 학생이 수정본을 보내도 교수가 어디를 확인해야 하는지 알기 어렵고, 비대면 상황에서는 확인 요청이 메신저 등으로 흩어진다.

학생이 실제 수정 결과 여러 건과 당시 보존 파일·위치·설명을 한 검토 요청에 담고 지정 교수 이메일 계정에만 열리는 링크를 생성하는 초기 기능이다. 공개 내용을 미리 본 뒤 학생이 링크를 직접 전달하며, 링크 생성만으로 실제 전달·열람을 뜻하지 않는다. 문서 수정은 보존 파일 근거가 필수이고 수정 전 방향 질문의 별도 검토는 제외한다.

**개발 준비 슬롯**
- **선행조건**: 학생이 소유한 연구에 검토할 수정 결과가 있어야 한다. 문서 수정 항목에는 보존 파일 버전과 확인 위치가 필요하며, 비문서 작업에는 보존한 처리 설명·자료·미팅 결정 등을 근거로 사용한다.
- **트리거**: 학생이 수정 결과 상세에서 교수 검토 준비를 선택한다..
- **동작**:
  - 학생은 요청 제목·교수 이메일·검토 항목을 입력하고 기존 처리 설명과 근거를 불러온다.
  - 각 항목의 실제 처리 설명과 확인 위치를 검토한다. 수정 전 방향을 묻는 별도 질문 입력은 두지 않는다.
  - 공개될 본문·원 피드백·첨부 파일 전체를 미리 본 뒤 링크를 만들고 복사해 전달한다.
- **결과**: - 요청과 항목별 검토 차수가 저장된다. 링크 생성은 실제 전달·열람·교수 응답과 구분한다.
- **예외**:
  - 필수 설명·교수 이메일·근거가 없거나 업로드가 진행 중이면 링크 생성을 완료하지 않고 해당 항목을 안내한다.
  - 같은 파일은 여러 검토 항목에서 재사용할 수 있다. 동일 버전이라는 이유만으로 기존 요청 수정을 요구하지 않는다.
- **표시**: - 항목별 설명·근거 버전·위치와 교수에게 공개될 파일 전체를 표시한다.
- **권한 & 접근**: - 학생만 자기 요청을 구성하며 지정 교수 계정만 공유된 내용을 읽고 응답한다.
- **비즈니스 규칙**:
  - 준비 중인 요청은 편집할 수 있다. 공유한 항목의 설명·자료 변경은 2.5 재확인 요청으로 새 차수를 만든다.
  - 개인 메모·전체 작업 목록·미채택 후보는 자동 공개하지 않는다.
  - 교수의 접근 방식은 지정 계정 로그인으로 정하며 실제 로그인·검토의 편의는 후속 검증한다.


### 1.4 연구 자료·기록 통합 검색 및 전체 활동 조회
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 학생 | **기기**: 웹 브라우저

**기능의 근거**: 연구 기간이 길어질수록 과거 피드백과 수정 내용이 쌓여 원하는 기록을 찾는 데 시간이 든다.

학생이 문서, 미팅 기록, 피드백, 과거 수정사항을 한 번에 검색해 필요한 내용을 찾는 P1 후속 개선 기능이다. 검색 결과에서 원래 기록으로 이동할 수 있다. 초기 MVP에는 포함하지 않으며 문서 파일 본문은 검색 대상에서 제외한다.

학생은 후속 전체 활동 목록에서 자료 등록·댓글·일정 변경 등의 시점과 원래 위치를 확인할 수 있다. 초기의 새 응답 표시와 구분하며 교수에게 연구 전체 활동을 공개하지 않는다.

**개발 준비 슬롯**
- **선행조건**: 학생이 열람할 연구가 있어야 한다. 저장 기록이 없으면 검색·활동 없음 상태를 표시한다.
- **트리거**:
  - 학생이 상단 검색창에 검색어를 입력하면 시작한다.
  - 학생이 전체 활동 보기를 선택하면 활동 목록을 조회한다.
- **동작**:
  - 시스템은 열람 권한이 있는 자료, 미팅 기록, 피드백, 수정 기록에서 검색어를 찾는다.
  - 학생은 기록 유형과 주차로 결과를 좁힐 수 있다.
  - 활동 종류·날짜로 목록을 좁히고 원래 기록으로 이동한다. 검색 결과와 활동의 제목·발췌·건수는 현재 권한으로 제한한다.
- **결과**: - 유형별로 묶인 검색 결과가 표시되고 결과를 선택하면 해당 기록으로 이동한다.
- **예외**:
  - 결과가 없으면 검색어나 필터 변경을 안내한다.
  - 검색어가 비어 있으면 검색하지 않는다.
- **표시**:
  - 결과마다 기록 유형, 주차, 일치 부분을 강조해 보여준다.
  - 검색은 결과 없음, 활동은 활동 없음, 불러오기 실패는 재시도 안내로 구분한다. 전체 활동은 후속 기능으로 표시한다.
- **권한 & 접근**: - 검색 결과는 열람 권한이 있는 기록만 포함한다.
- **비즈니스 규칙**:
  - 문서는 제목, 진행 내용, 메타정보만 검색한다.
  - 검색 결과는 관련도순으로 정렬한다.


### 1.5 연구 생성·전환·보관
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 학생 | **기기**: 웹 브라우저

**기능의 근거**: 학생은 지도 기록을 연구별로 이어 보고 다른 연구 자료와 섞이지 않게 관리해야 한다.

학생이 논문별 연구 공간을 만들고 작업 중인 연구를 전환하거나 보관·복원하는 초기 기능이다. 연구 전환은 자료·미팅·피드백·작업·계획의 범위를 함께 바꾸며 보관은 기록 삭제나 검토 공유 중지가 아니다. 연구를 생성한 직후 빈 준비 상태에서도 메모 작성으로 시작할 수 있다.

**성공 기준**: 사용성 검증에서 학생이 새 연구를 만들고 전환·보관·복원해도 기존 기록을 다시 찾아 구분할 수 있는지 확인한다.

**개발 준비 슬롯**
- **선행조건**: - 연구 생성은 학생이 로그인한 경우에 허용한다.
- **트리거**: - 학생이 새 연구 시작, 연구 전환, 보관 또는 복원을 선택하면 시작한다.
- **동작**:
  - 학생은 기본값이 채워진 연구 이름을 확인·수정하여 연구를 생성한다.
  - 학생은 기존 연구를 선택해 작업 범위를 전환하거나 보관 목록에서 복원한다.
- **결과**:
  - 생성한 연구는 빈 준비 상태에서 미팅 기록을 남길 수 있다.
  - 보관된 연구는 활성 목록에서 제외되지만 원래 기록과 공유 상태는 유지된다.
- **예외**:
  - 공백 이름은 저장하지 않으며 실패 시 입력과 기존 연구 목록을 유지한다.
  - 미저장 입력을 두고 연구를 전환하면 계속 편집하거나 버리고 이동할 수 있게 한다.
- **표시**: - 현재 연구 이름과 활성·보관 여부를 보여주고 빈 연구에는 기록 시작을 안내한다.
- **권한 & 접근**:
  - 학생은 자기 연구만 생성·전환·보관·복원한다.
  - 연구 보관만으로 교수의 기존 검토 권한을 변경하지 않는다.
- **비즈니스 규칙**:
  - 연구 전환 시 이전 연구의 AI 처리 선택 자료를 새 연구에 섞지 않는다.
  - 보관은 공유 중지나 영구 삭제와 구분한다.
- **데이터**: - 연구는 연구ID, 소유 학생ID, 이름, 설명, 개인 목표일, 상태(활성·보관)와 변경 시각을 가진다.

## 2. 피드백 이해 및 수정 반영 관리
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중

학생은 미팅 메모와 댓글에서 피드백의 출처를 구분하고 선택한 작업의 실제 수정 결과를 한 번 기록해 여러 피드백과 검토 요청에 재사용한다. 지정 교수 계정은 공유받은 보존 파일과 당시 설명을 보고 항목·차수별로 결과와 댓글을 남긴다. 학생 처리 상태, 작업 완료, 교수 확인은 별도로 유지하고 수정 전 방향을 묻는 별도 검토 기능은 제외한다.

**수용 기준:**
```
1. ○ 학생이 피드백의 출처·처리 상태와 교수의 항목별 결과를 서로 다른 정보로 확인할 수 있다.
2. ○ 문서 수정 결과는 보존 파일과 확인 위치를 근거로 연결하고 같은 파일을 여러 검토 항목에서 재사용할 수 있다.
3. ○ 교수는 항목별 수정 내용 확인 또는 이유 댓글을 포함한 추가 수정 필요를 저장하고 일반 댓글은 결과 선택 없이 작성할 수 있다.
4. ○ 한 항목만 재확인해도 이전 차수의 설명·파일·응답과 다른 항목의 교수 결과가 유지된다.
```


### 2.1 피드백 등록·출처·학생 처리 기록
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 학생 | **기기**: 웹 브라우저

**기능의 근거**: 학생은 자신의 수정 결과와 교수의 반영 확인을 구분해 관리하기 어렵고 어떤 피드백이 남아 있는지 놓치기 쉽다.

학생이 원문이나 댓글에서 피드백을 가져오거나 자신의 정리를 직접 기록하고 출처와 처리 상태를 구분하는 초기 기능이다. 학생은 처리 전·진행 중·반영 기록 있음·보류·미수정 결정을 따로 관리하며 보류·미수정 이유는 개인 기록으로 남긴다. 교수의 항목별 응답은 별도로 저장하고 AI 추출은 원래 발언·댓글 작성자를 바꾸지 않는다.

**성공 기준**: 사용성 검증에서 학생이 문서 수정 외의 연구 결정·미팅 준비 피드백도 근거와 함께 처리하고 교수의 재검토 결과와 자신의 반영 기록을 구분할 수 있는지 확인한다.

**개발 준비 슬롯**
- **선행조건**: 학생이 소유한 연구와 기록할 피드백 내용이 있어야 한다. 기존 확정 피드백이나 교수 원문을 필수로 요구하지 않는다.
- **트리거**: 학생이 피드백 추가, 원문·댓글의 피드백으로 가져오기, 기존 피드백의 상태 변경을 선택한다.
- **동작**:
  - 학생은 내용을 직접 입력하거나 원문·댓글에서 불러와 수정하고 출처를 저장한다.
  - 학생은 처리 전·진행 중·반영 기록 있음·보류·미수정 결정 중 상태를 선택한다.
  - 실제 반영 내용을 남길 때 2.4의 수정 결과를 작성하거나 기존 결과와 연결한다. 보류·미수정 사유는 개인 메모로 남길 수 있다.
- **결과**: 피드백 내용·출처·학생 처리 상태가 저장되고 작업·수정 결과·교수 응답을 연결해 조회한다.
- **예외**: 빈 내용은 저장하지 않는다. 같은 원문에 연결된 피드백이 있으면 기존 항목을 먼저 보여준다. 실패 시 입력과 마지막 저장 상태를 유지한다.
- **표시**: 학생 처리 상태와 교수 결과를 따로 표시한다. 학생이 옮긴 발언·학생 직접 정리·교수 직접 댓글을 구분한다.
- **권한 & 접근**: 학생만 처리 상태·개인 메모를 수정하며 교수의 직접 응답은 대신 수정하지 못한다.
- **비즈니스 규칙**:
  - 작업 완료와 학생 반영 기록, 교수 결과는 서로 자동 변경하지 않는다.
  - 교수의 추가 수정 필요는 기존 학생 반영 이력을 지우지 않는다.
  - 문서 수정의 교수 검토에는 보존 파일·위치가 필요하지만 개인 결과 저장은 2.4의 조건을 따른다.
- **데이터**: - 피드백ID, 연구ID, 내용, 출처 유형·대상·당시 발췌, 처리 상태(처리 전·진행 중·반영 기록 있음·보류·미수정 결정, 기본 처리 전), 개인 메모, 연결 작업·수정 결과, 변경자·시각을 저장한다. 교수 결과는 검토 항목·차수에서 별도로 조회한다.


### 2.2 교수 자료 검토·댓글·항목별 응답
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 교수, 학생 | **기기**: 웹 브라우저

**기능의 근거**: 학생이 기록한 교수 발언과 교수의 직접 확인을 혼동하면 잘못 이해한 채 수정을 계속할 수 있다.

학생이 지정한 이메일 계정으로 로그인한 교수가 공유받은 여러 수정 결과의 당시 설명·파일 위치를 보고 항목별로 ‘수정 내용 확인’ 또는 ‘추가 수정 필요’를 남기는 초기 기능이다. 추가 수정 필요에는 이유 댓글이 필수이고 일반 댓글·답글만 남길 때는 결과 선택이 필요 없다. 학생은 교수 결과를 읽고 답글할 수 있지만 대신 수정하지 않으며 교수 전용 대시보드는 제외한다.

**개발 준비 슬롯**
- **선행조건**:
  - 검토 요청이 공유 중이고 교수 계정의 확인된 이메일이 요청의 허용 주소와 일치해야 한다.
  - 항목에 당시 보존한 설명과 근거 자료가 있어야 한다.
- **트리거**: - 허용된 교수가 검토 항목을 열거나 댓글·응답 저장을 선택하면 시작한다.
- **동작**:
  - 교수는 이전 피드백, 수정 요약과 보존 파일의 확인 위치를 읽는다.
  - 교수는 항목·차수에 수정 내용 확인 또는 추가 수정 필요를 저장하며 추가 수정 필요에는 이유 댓글을 함께 입력한다.
  - 교수와 학생은 허용된 댓글 대화에 답글을 달고 해결·다시 열기로 정리한다.
- **결과**:
  - 응답은 해당 항목·차수의 결과·이유·작성 계정·시각·파일 버전과 연결된다.
  - 최신 차수의 결과만 현재 집계에 반영하고 이전 차수의 응답과 학생의 반영 기록은 유지한다.
- **예외**:
  - 추가 수정 필요의 이유가 공백이면 결과를 저장하지 않는다.
  - 일반 댓글만 남길 때 결과 선택을 강제하지 않는다.
  - 응답 저장 중 공유가 중지되면 현재 접근 권한을 다시 확인하고 저장을 거부한다.
- **표시**:
  - 항목마다 응답 전·수정 내용 확인·추가 수정 필요를 표시하고 교수 결과와 학생 처리 상태를 나란히 구분한다.
  - 최신·이전 차수와 해당 파일·위치·댓글을 구분한다.
- **권한 & 접근**:
  - 지정 계정의 교수만 해당 검토 항목에 본인 결과를 작성·수정하고 허용 자료를 열람·다운로드한다.
  - 학생은 교수 결과를 대신 입력하거나 수정하지 못한다.
- **비즈니스 규칙**:
  - 교수 결과는 응답 전·수정 내용 확인·추가 수정 필요로 구분한다.
  - 교수 결과 수정은 변경 이력을 남기며 필수 이유 댓글 제거에는 대체 이유가 필요하다.
  - 댓글 대화 해결은 교수 결과나 할 일 상태를 바꾸지 않는다.
- **데이터**:
  - 교수 응답은 검토 요청ID, 항목ID, 차수, 결과, 이유 댓글ID(추가 수정 필요 시 필수), 작성 계정ID와 저장·수정 시각을 가진다.
  - 댓글은 항목·차수·작성자·본문·상위 댓글·대화 상태와 이력을 가진다.


### 2.3 반복 피드백 및 미해결 사항 확인
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 학생 | **기기**: 웹 브라우저

**기능의 근거**: 교수의 반복되는 피드백은 핵심 쟁점일 가능성이 크지만 주차별 기록이 나뉘어 있어 학생이 파악하기 어렵다.

학생이 여러 주차에 걸쳐 반복된 의견과 해결되지 않은 피드백을 관련 원문과 함께 모아 보는 P0 기능이다. 반복 피드백은 강조해 보여주며 각 주차의 원본 피드백으로 이동한다. 반복 여부의 최종 묶음은 학생이 확인하며 피드백의 반영 상태는 이 기능에서 바뀌지 않는다.

**성공 기준**: 사용성 검증에서 학생이 표현만 비슷한 피드백을 원본과 대조해 구분하고 잘못 묶인 관계를 해제할 수 있는지 확인한다.

**개발 준비 슬롯**
- **선행조건**: - 확정된 피드백 항목이 하나 이상 있어야 한다.
- **트리거**: - 학생이 피드백 화면에서 반복·미해결 보기를 선택하면 조회한다.
- **동작**:
  - 시스템은 미해결 피드백을 주차와 함께 모아 보여준다.
  - 시스템은 반복 피드백 묶음을 주차별 원문과 함께 보여준다.
  - 학생은 반복 묶음을 만들거나 해제한다.
- **결과**:
  - 학생이 확인한 반복 묶음이 저장되고 해당 피드백에 반복 표시가 붙는다.
  - 반영 상태와 교수 확인 결과는 바뀌지 않는다.
- **예외**:
  - 추가 작업이나 판단이 필요한 피드백이 0건이면 그 기준의 빈 상태를 표시하고 검토 대기 건수와 혼동하지 않는다.
  - 반복 묶음을 해제해도 구성 피드백의 원본과 각자의 반영 상태는 유지한다.
- **표시**:
  - 반복 피드백은 반복 횟수와 최초·최근 주차를 함께 강조 표시한다.
  - 미해결 피드백은 경과 주차 수를 함께 표시한다.
- **권한 & 접근**: - 학생만 반복 묶음을 만들거나 해제할 수 있다.
- **비즈니스 규칙**:
  - 남은 피드백은 학생 상태가 처리 전·진행 중·보류이거나 교수의 최신 차수 결과가 추가 수정 필요인 항목이다.
  - 학생이 반영 기록을 남겼지만 교수 응답만 기다리는 항목은 별도 검토 대기로 분류한다.
  - 표현이 비슷해도 대상이나 요구 수준이 다르면 같은 지적으로 자동 묶지 않는다.


### 2.4 작업 마무리·수정 결과·반영 근거 기록
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 학생 | **기기**: 웹 브라우저

**기능의 근거**: 학생이 피드백에 따라 실제로 무엇을 고쳤는지 매번 다시 설명해야 하고 작업 완료와 교수 확인을 혼동하기 쉽다.

학생이 실제로 수행한 작업의 수정 결과를 한 번 기록하고 여러 피드백·미팅과 교수 검토에서 재사용하는 초기 기능이다. 학생은 작업 완료와 피드백 반영 기록을 각각 선택하며 문서 수정일 때 보존 파일 버전과 위치를 연결한다. 개인 결과는 보존 파일 없이 저장할 수 있지만 문서 수정의 교수 검토 근거로는 사용할 수 없다.

**성공 기준**: 사용성 검증에서 학생이 한 수정본을 여러 피드백에 연결하고 작업 완료·피드백 반영·교수 확인을 구분할 수 있는지 확인한다.

**개발 준비 슬롯**
- **선행조건**: - 학생에게 실제 처리한 내용이 있어야 수정 결과를 저장할 수 있다.
- **트리거**: - 학생이 작업 또는 피드백에서 수정 결과 정리를 선택하면 시작한다.
- **동작**:
  - 학생은 결과 제목과 실제 처리 설명을 확인·수정하고 작업·피드백을 각각 선택한다.
  - 문서 수정이면 보존 파일을 추가하거나 기존 버전을 고르고 확인 위치를 연결한다.
  - 학생은 결과를 저장한 뒤 같은 설명과 근거를 교수 검토에 재사용한다.
- **결과**:
  - 저장된 결과는 선택한 작업·피드백에만 연결된다.
  - 검토로 보낸 결과의 당시 설명·파일은 이후 학생 편집으로 바뀌지 않는다.
- **예외**:
  - 공백 설명은 저장하지 않으며 저장 성공·연결 실패는 구분해 연결만 다시 시도한다.
  - 보존 파일 없는 개인 결과는 저장하되 문서 수정 검토에 필요한 근거가 부족함을 표시한다.
- **표시**: - 결과 설명과 보존 파일 버전·확인 위치를 함께 보여주며 문서 검토 근거의 부족을 구분한다.
- **권한 & 접근**:
  - 학생만 자기 수정 결과와 작업·피드백 반영 기록을 저장한다.
  - 결과 저장은 교수 공유가 아니다.
- **비즈니스 규칙**:
  - 작업 완료, 학생의 반영 기록과 교수의 수정 내용 확인은 서로 자동으로 바뀌지 않는다.
  - 문서 수정의 검토 근거에는 등록 당시 내용을 보존한 파일과 확인 위치가 필요하다.
- **데이터**: - 수정 결과는 결과ID, 제목, 처리 설명, 관련 작업·피드백ID 목록, 근거 자료 버전ID·위치, 저장본과 검토에 보낸 차수의 식별자를 가진다.


### 2.5 항목별 재확인 요청·이전 차수 조회
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 학생 | **기기**: 웹 브라우저

**기능의 근거**: 교수의 추가 수정 요청 이후 새 결과를 보내도 과거에 무엇을 검토받았는지 잃지 않아야 한다.

학생이 이미 교수에게 보낸 수정 결과의 특정 항목에 새 설명과 근거를 보내 재확인을 요청하는 초기 기능이다. 선택한 항목만 새 검토 차수로 만들고 이전 자료·설명·교수 응답은 유지하며, 변경하지 않은 다른 항목의 결과는 그대로 둔다. 같은 링크에서 최신·이전 차수를 구분해 조회하는 방식은 작성 기준안이다.

**성공 기준**: 사용성 검증에서 한 항목의 재확인 뒤 학생과 교수가 이전 차수의 자료·결과와 다른 항목의 결과를 혼동하지 않는지 확인한다.

**개발 준비 슬롯**
- **선행조건**: - 이전에 공유한 검토 항목과 학생이 다시 보낼 실제 수정 결과가 있어야 한다.
- **트리거**: - 학생이 검토 항목에서 재확인 요청을 선택하면 시작한다.
- **동작**:
  - 학생은 선택 항목의 새 설명·근거·위치를 확인하고 미리 본다.
  - 학생이 저장하면 해당 항목에만 새 차수를 열고 같은 링크에서 최신·이전 차수를 구분한다.
- **결과**: - 새 차수의 교수 결과는 응답 전으로 시작하고 이전 차수의 응답과 다른 항목의 결과는 유지된다.
- **예외**:
  - 저장 취소·실패 시 새 차수를 만들지 않는다.
  - 이전 차수에서 늦게 저장한 응답은 이전 차수에 연결하며 최신 차수를 덮어쓰지 않는다.
- **표시**: - 최신과 이전 검토 차수, 각각의 보존 파일·설명·응답을 구분해 보여준다.
- **권한 & 접근**: - 학생만 재확인을 요청하며 지정된 교수 계정만 공유 중인 차수를 검토한다.
- **비즈니스 규칙**:
  - 새 자료 등록이나 결과 편집만으로 교수의 기존 검토 내용은 바뀌지 않는다.
  - 재확인은 수정 전 방향 승인 용도로 사용하지 않는다.
- **데이터**: - 검토 차수는 요청ID, 항목ID, 차수, 당시 설명·보존 파일 버전·위치, 응답 상태와 저장 시각을 가진다.

## 3. 선택적 AI 활용 및 근거 관리
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중

학생은 필요한 기록 정리·피드백 대조·수정 방안 비교·할 일 후보·준비 문서 구성에 선택적으로 AI를 쓴다. 새 방법은 원문 발췌와 AI의 가정·추정을 구분하며 학생이 수정·채택하거나 직접 작성한다. AI 미사용·실패 중에도 기본 기록과 작업을 이어갈 수 있고 연구 방향·교수 응답·작업 완료를 AI가 자동 확정하지 않는다.

**수용 기준:**
```
1. ○ 학생이 AI 실행 전 대상 메모·자료 버전·구간을 확인하고 선택하지 않은 자료가 입력 범위에 포함되지 않는다.
2. ○ 수정 방안 후보의 방법·예상 결과·필요 자료와 가정이 원문 발췌와 구분되며 학생이 고쳐 저장하거나 직접 작성할 수 있다.
3. ○ AI 생성 중단·영역 닫기·채택 취소가 각각 구분되고 연결된 작업이 채택 취소만으로 삭제되지 않는다.
4. ○ AI 없이도 기록·할 일·미팅 준비가 가능하고 저장만으로 교수 공유·반영·완료가 바뀌지 않는다.
```


### 3.1 여러 기록의 비교·추가 AI 정리
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 학생 | **기기**: 웹 브라우저

**기능의 근거**: 기본 AI 단계가 정착된 뒤 학생이 반복 정리 작업을 더 줄이길 원할 때 승인된 범위 안에서만 도움을 넓히기 위함이다.

학생이 선택한 미팅·피드백·자료 버전을 함께 비교하고 필요한 경우 AI로 추가 정리하는 후속 기능이다. 관련 원문·버전으로 이동하고 결과를 고쳐 별도 정리본으로 저장한다. 원문 수정·연구 방향 결정·피드백 반영 판정은 자동 실행하지 않는다.

**개발 준비 슬롯**
- **선행조건**: 비교할 기록과 열람 권한이 있어야 한다. AI 추가 정리를 실행할 때만 처리 자료 범위를 선택·확인한다.
- **트리거**: 학생이 기록 비교 또는 추가 정리를 선택한다.
- **동작**:
  - 학생은 비교할 기록과 자료 버전을 선택해 나란히 읽는다.
  - 원하면 선택 범위에서 AI 추가 정리를 실행하고 근거·가정·추정을 구분해 읽는다.
  - 고쳐 저장한 정리본에서 원문·버전으로 이동한다.
- **결과**: 비교 조회는 원문을 바꾸지 않으며 학생이 저장한 정리본만 별도 기록으로 연결한다.
- **예외**: 원문·권한 없는 항목은 처리하지 않는다. AI 실패 시에도 직접 비교를 계속하고 선택 기록·기존 입력을 유지한다.
- **표시**: 원문·학생 작성·AI 제안을 구분하며 관련 버전과 불확실한 추정을 표시한다.
- **권한 & 접근**: - 학생만 추가 정리를 실행할 수 있다.
- **비즈니스 규칙**: 비교와 추가 정리는 학생이 선택한 기록에 한정하며 기본 과거 미팅 조회는 이 기능 없이 초기부터 제공한다.


### 3.2 AI 수정 방안 제안·비교·선택
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 학생 | **기기**: 웹 브라우저

**기능의 근거**: 학생이 지도 피드백을 읽어도 어디를 어떻게 수정할지 판단하기 어렵고 여러 방법에 필요한 작업을 비교해야 한다.

학생이 특정 피드백에 대해 선택한 원문·자료를 바탕으로 복수의 수정 방안 후보를 비교하고 수정하거나 직접 방안을 작성하는 초기 기능이다. AI는 수정 대상·방법·예상 결과·필요 자료·추가 작업과 근거·가정을 구분해 제시하고, 학생은 방안을 할 일 초안으로 연결할 수 있다. 제안 선택은 실제 반영이나 교수 확인이 아니며 근거 없는 교수 지시는 생성하지 않는다.

**성공 기준**: 사용성 검증에서 학생이 방안별 예상 결과와 추가 작업 차이를 설명하고 근거 없는 추정을 알아차려 수정하거나 직접 방안을 작성할 수 있는지 확인한다.

**개발 준비 슬롯**
- **선행조건**:
  - 학생이 대상 피드백과 열람 가능한 근거 원문을 선택해야 AI 제안을 요청할 수 있다.
  - AI 미사용 시에도 학생은 수정 방안을 직접 작성할 수 있다.
- **트리거**: - 학생이 피드백에서 수정 방안 보기와 제안받기를 선택하면 시작한다.
- **동작**:
  - AI는 학생이 선택한 피드백과 자료의 입력 당시 원문에서 실제 발췌·위치를 찾아 근거로 연결한다.
  - AI는 원문에서 확인한 내용과 새 방법·가정을 구분해 여러 방안을 제안한다.
  - 학생은 필요한 방안을 고쳐 저장하거나 직접 작성하고 선택적으로 할 일 초안에 연결한다.
- **결과**: - 학생이 선택·저장한 방안은 해당 피드백에 연결되지만 반영 상태와 교수 확인 결과는 바뀌지 않는다.
- **예외**:
  - 입력이나 접근 권한이 부족하면 AI 실행을 막고 부족한 자료를 안내한다.
  - AI 실패 시 직접 작성한 방안과 기존 할 일을 유지한다.
  - 채택을 취소할 때 연결된 작업은 자동 삭제하지 않고 관계 유지·해제를 학생이 고르게 한다.
- **표시**:
  - 원문 발췌와 AI의 새 방법·가정·확인 필요 사항을 나란히 구분한다.
  - 방법별 예상 결과·필요 자료·추가 작업을 비교한다.
- **권한 & 접근**:
  - 학생만 AI 제안을 요청하고 방안을 채택·수정·취소할 수 있다.
  - 제안은 저장만으로 교수에게 공유되지 않는다.
- **비즈니스 규칙**:
  - AI가 제안하는 새로운 방법은 원문 자체나 교수의 직접 지시로 취급하지 않는다.
  - AI가 근거 없는 추정을 제시하면 확인 필요로 남기고 학생이 수정하거나 선택하지 않을 수 있다.
  - 학생이 저장·채택한 방안도 이후 수정·채택 취소가 가능하며 관련 작업은 자동 삭제하지 않는다.
- **데이터**: - 방안은 방안ID, 피드백ID, 선택 자료·원문 구간, 수정 방법, 예상 결과, 근거, 가정, 필요 자료·작업과 상태(제안·학생 저장·취소)를 가진다.

## 4. 할 일 및 다음 미팅 준비 관리
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중

학생은 피드백과 선택한 수정 방안을 바탕으로 할 일을 한 번 저장하고 여러 미팅에 연결해 이번 준비의 범위를 직접 정한다. 작업 기한은 미팅과 별도로 관리하며 미완료 작업을 다음 준비에 다시 포함해도 원래 기록을 복제하지 않는다. 보여줄 결과·자료·막힌 이유·질문을 담은 준비 문서는 AI 없이도 만들며 장기 로드맵과 연구 내용 대필은 제외한다.

**수용 기준:**
```
1. ○ 학생이 직접 작성하거나 AI 방안에서 가져온 작업을 하나만 저장해 여러 피드백과 미팅에 연결할 수 있다.
2. ○ 준비 목록에서 작업을 제외하거나 일부 미완료 작업만 다시 선택해도 원본 작업과 이전 미팅 관계를 찾을 수 있다.
3. ○ 작업 상태·기한·준비 순서는 각각 변경할 수 있고 미팅 연기가 기한을 자동 변경하지 않는다.
4. ○ AI 미사용이나 실패에도 날짜 미정 미팅에 미완료 사유와 질문을 담은 준비 문서를 직접 저장할 수 있다.
```


### 4.1 할 일 생성·다음 미팅 포함
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 학생 | **기기**: 웹 브라우저

**기능의 근거**: 학생이 다음 미팅까지 무엇을 얼마나 가져갈지 기준 없이 혼자 정하고 있어 준비 범위 판단에 시간이 든다.

학생이 피드백이나 AI 방안에서 할 일을 직접 만들고 다음 미팅의 준비 목록에 넣거나 이미 저장된 작업을 다시 선택하는 초기 기능이다. 할 일은 한 번 저장하고 여러 미팅·피드백에 연결하며 준비 목록에서 제외해도 원래 작업과 과거 연결은 남는다. 준비 대상 미팅과 개별 작업 기한은 별개이며 이번에 선택하지 않은 후보는 거부가 아니다.

**성공 기준**: 사용성 검증에서 학생이 다음 미팅까지 수행할 작업을 선택하면서 미선택 후보와 명시적으로 거부한 후보를 구분하고 필요한 작업을 누락하지 않는지 확인한다.

**개발 준비 슬롯**
- **선행조건**: - 할 일 후보가 있거나 학생이 직접 할 일을 추가할 수 있어야 한다.
- **트리거**: - 학생이 할 일 추가, AI의 할 일로 만들기 또는 기존 작업의 이번 미팅에 포함을 선택하면 시작한다.
- **동작**:
  - 학생은 직접 작업을 입력하거나 AI가 제안한 내용을 같은 할 일 초안에서 고친다.
  - 피드백·결정에 이미 연결된 작업을 먼저 보여주고 학생이 새 작업이나 기존 작업을 고른다.
  - 학생은 작업을 한 번 저장하며 준비 미팅을 선택한 경우에만 해당 미팅에 연결한다.
- **결과**:
  - 저장한 작업은 전체 할 일 목록에 남고 선택한 경우 다음 미팅 준비 목록에도 표시된다.
  - 미팅에 포함하지 않은 작업도 진행·완료할 수 있다. 후보 미선택은 거부가 아니다.
  - 근거 피드백·결정이 있는 작업은 해당 관계를 유지하며 학생의 직접 추가에는 근거 연결을 강제하지 않는다.
- **예외**:
  - 작업 저장 뒤 미팅 연결만 실패하면 원래 작업을 유지하고 연결만 다시 시도한다.
  - 같은 피드백에 이미 작업이 있어도 추가 작업 가능성을 막지 않고 중복 여부를 학생이 확인한다.
- **표시**:
  - 전체 작업과 현재 준비 미팅에 포함된 작업을 구분한다. 준비 목록에는 순서를 표시한다.
  - 직접 만든 작업과 AI 후보에서 만든 작업의 출처를 구분한다.
- **권한 & 접근**: - 학생만 할 일을 선택·확정할 수 있다.
- **비즈니스 규칙**:
  - 하나의 작업은 여러 피드백·미팅에 연결할 수 있다. 준비 목록 제외는 해당 미팅 연결만 해제한다.
  - 작업 저장·미팅 포함·후보 채택을 구분하며 후보를 고르지 않았다는 이유로 거부 상태로 바꾸지 않는다.
- **데이터**:
  - 할 일은 할 일ID, 연구ID, 제목(필수), 설명, 진행 상태, 기한, 출처, 후보ID(해당 시), 근거 피드백·결정ID를 가진다.
  - 미팅 준비 연결은 미팅ID, 할 일ID, 준비 순서를 가진다. 주차를 작업의 유일한 소속 기준으로 사용하지 않는다.
  - 후보는 제안·채택·미선택·거부를 구분하며 미선택은 명시적 거부와 다르다.


### 4.2 작업 진행·기한·준비 우선순위
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 학생 | **기기**: 웹 브라우저

**기능의 근거**: 전체 연구 계획과 이번 주 작업이 분리되어 있어 학생이 진행 상황을 한곳에서 확인하기 어렵다.

학생이 작업의 진행 전·진행 중·완료 상태와 개별 기한을 관리하고 다음 미팅 준비 목록 안의 순서를 직접 바꾸는 초기 기능이다. 완료를 다시 진행으로 되돌릴 수 있고 지연은 별도의 확정 상태가 아닌 지난 기한의 미완료 표시다. 미팅 연기나 작업 완료가 피드백 처리·교수 결과를 자동으로 바꾸지 않는다.

**성공 기준**: 사용성 검증에서 학생이 작업 완료와 피드백 반영·미팅 준비를 혼동하지 않고 각각의 진행 상황을 설명할 수 있는지 확인한다.

**개발 준비 슬롯**
- **선행조건**: - 학생이 소유한 할 일이 있어야 한다. 특정 미팅에 포함돼 있어야 한다는 조건은 두지 않는다.
- **트리거**: - 학생이 전체 할 일 또는 다음 미팅 준비 목록에서 작업의 상태·기한·순서 수정을 선택한다.
- **동작**:
  - 학생은 작업을 진행 전·진행 중·완료로 바꾸고 필요하면 다시 진행을 선택한다.
  - 학생은 개별 기한을 지정·수정·해제하고 준비 목록 순서를 버튼이나 드래그로 바꾼다.
- **결과**:
  - 할 일 상태 변경은 연구 진행 현황에 반영되지만 미팅 준비 상태를 자동 확정하지 않는다.
  - 일부 또는 모든 연결 할 일이 완료되어도 피드백의 반영 상태는 자동으로 바뀌지 않는다.
- **예외**:
  - 마감일이 지난 미완료 할 일은 지연으로 표시한다.
  - 완료된 할 일을 다시 진행 중으로 되돌릴 수 있다.
- **표시**:
  - 상태·기한·준비 순서를 구분해 보여주며 시각이 없으면 시각 미정으로 표시한다.
  - 순서 변경은 드래그 외 위로·아래로 버튼도 제공한다.
- **권한 & 접근**:
  - 학생만 자기 작업의 내용·진행·기한·준비 순서를 수정한다. 영구 삭제 조건은 운영 정책에서 별도로 정한다.
  - 전체 할 일 목록은 교수에게 자동 공유하지 않는다.
- **비즈니스 규칙**:
  - 준비 목록에 저장한 순서가 준비 우선순위이고 별도 등급을 필수로 요구하지 않는다.
  - 지난 기한의 미완료 작업만 지연으로 표시한다.
  - 미팅 연기·목록 포함·작업 완료는 서로 다른 작업의 상태를 자동 변경하지 않는다.


### 4.3 다음 미팅 준비 목표·자료·문서 구성
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 학생 | **기기**: 웹 브라우저

**기능의 근거**: 학생이 매주 진행 내용과 수정사항을 다시 모아 미팅 자료로 정리하는 데 반복적인 시간이 든다.

학생이 다음 미팅을 기준으로 보여줄 결과·작업·자료·막힌 이유·질문을 모아 직접 준비 문서를 만들거나 선택적으로 AI의 도움을 받는 초기 기능이다. 날짜가 정해지지 않은 미팅도 준비할 수 있고, 작업의 개수나 완료 상태만으로 준비 완료를 판정하지 않는다. 문서 저장은 교수 공유와 구분하고 이전에 저장한 준비 문서 내용은 이력으로 남긴다.

**성공 기준**: 사용성 검증에서 학생이 AI 미사용과 사용 모두에서 초안을 만들고 정리·확인 시간을 포함한 준비 부담이 기존 방식보다 줄어드는지 확인한다.

**개발 준비 슬롯**
- **선행조건**:
  - 학생이 선택할 진행 내용, 수정사항, 할 일 또는 질문이 있으면 AI를 사용하지 않고도 초안을 만들 수 있다.
  - AI를 사용하기로 선택한 경우에만 해당 단계의 AI 사용과 자료 범위 승인이 필요하다.
- **트리거**: - 학생이 다음 미팅 준비에서 자료 초안 만들기를 선택하면 시작한다.
- **동작**:
  - 학생은 준비 대상 미팅을 고르고 보여줄 결과·완료 작업·미완료 사유·검토 질문을 선택한다.
  - 학생은 기존 보존 문서 버전 또는 외부 참조 자료를 구분해 미팅에 연결한다.
  - 학생은 포함 내용을 직접 구성하거나 선택적으로 AI 구성안을 고쳐 준비 문서를 저장한다.
- **결과**:
  - 학생이 미팅에 연결한 자료·작업·질문과 저장한 준비 문서가 다음 준비사항에서 조회된다.
  - 문서 저장은 교수 공유가 아니며 재저장한 현재본과 이전 저장본을 구분한다.
- **예외**:
  - AI 실패·취소 후에도 학생의 선택 목록과 직접 입력을 유지한다.
  - 미팅이 연기·취소되어도 연결된 자료·질문을 삭제하지 않는다.
  - 자료 연결만 실패하면 저장된 원본을 유지하고 연결을 다시 시도한다.
- **표시**: 초안의 각 문단에 출처 항목을 표시한다. AI 제안과 학생이 편집·저장한 내용을 구분하며 저장 중·저장됨·실패를 표시한다.
- **권한 & 접근**: 학생만 준비 문서를 작성·편집·저장한다.
- **비즈니스 규칙**:
  - P0 한 장 요약은 학생이 선택한 진행 내용과 수정사항을 미팅 자료 형식으로 구성하는 범위이다.
  - P1 추가 요약은 별도로 승인한 여러 기록의 내용을 추가 요약·정리하는 범위이다.
  - 초안에는 학생이 선택하지 않은 연구 내용이나 수행하지 않은 결과를 넣지 않는다.
  - 직접 작성과 AI 구성을 같은 편집 영역에서 저장한다. AI 적용·확정·저장을 별도 반복 단계로 만들지 않는다.
- **데이터**: 준비 문서는 문서ID, 미팅ID(필수), 본문(필수), 출처 항목ID, 작성 방식(직접·AI 보조), 저장 시각과 저장본 이력을 가진다. 현재 저장본과 이전 저장본을 구분한다. 날짜가 미정이어도 연결할 미팅 기록은 있어야 한다.


### 4.4 미완료 작업 재선택·다음 준비 연결

### 6.1 검토 허용 계정 변경·공유 중지
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 학생 | **기기**: 웹 브라우저

**기능의 근거**: 학생의 개인 메모와 교수에게 보여줄 기록이 섞이면 원치 않는 내용이 공유되고, 학생이 기록한 교수 발언과 교수의 직접 확인을 혼동할 수 있다.

학생이 교수 검토 요청의 허용 이메일을 변경하고 공유를 중지·다시 공유하는 초기 기능이다. 주소 변경 뒤에는 새로 허용된 확인 계정만 검토 자료와 파일에 접근하며 이전 교수 응답의 작성자·당시 자료는 그대로 남는다. 공유 중지는 이후 접근을 막는 행위로 연구·자료 보관이나 영구 삭제와 구분한다.

**개발 준비 슬롯**
- **선행조건**: - 학생이 만든 검토 요청이 있어야 허용 계정을 변경하거나 공유를 중지할 수 있다.
- **트리거**: - 학생이 검토 요청의 공유 설정에서 주소 변경·공유 중지·다시 공유를 선택하면 시작한다.
- **동작**:
  - 학생은 새 교수 이메일을 입력하고 변경 전후를 확인해 저장한다.
  - 학생은 공유를 중지하거나 허용 계정을 재확인해 다시 공유한다.
- **결과**:
  - 주소가 바뀌면 새 계정만 이후 접근할 수 있으며 기존 교수 응답 작성자는 유지된다.
  - 공유 중지는 검토 이력이나 학생이 볼 수 있는 기존 응답을 삭제하지 않는다.
- **예외**:
  - 변경 저장 실패 시 기존 접근 설정을 유지한다.
  - 이미 열린 화면에서도 파일 열기·다운로드·응답 저장 때 현재 권한을 다시 확인한다.
- **표시**:
  - 공유 중·공유 중지와 현재 허용 주소를 학생에게 구분해 표시한다.
  - 이전에 다운로드한 사본까지 회수할 수 있는 것으로 안내하지 않는다.
- **권한 & 접근**:
  - 학생만 자기 검토 요청의 허용 계정과 공유 상태를 변경한다.
  - 지정된 이메일 계정의 교수는 공유 중인 검토만 읽고 본인 응답을 남긴다.
- **비즈니스 규칙**:
  - 요청당 한 교수 이메일은 작성 기준안이며 최종 검증 전 수치 확정으로 취급하지 않는다.
  - 새 기록과 AI 결과·준비 문서 저장은 자동 공유가 아니다.
  - 공유 중지는 보관·연결 해제·영구 삭제와 구분한다.
- **데이터**: - 검토 공유는 검토 요청ID, 허용 교수 이메일, 상태(준비 중·공유 중·공유 중지), 변경자와 변경 시각을 가진다.


### 6.2 계정 로그인·이메일 확인·지정 계정 접근
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 학생, 교수 | **기기**: 웹 브라우저

**기능의 근거**: 교수에게 보내는 수정본과 개인 연구 기록이 링크만 아는 다른 사람에게 노출되지 않도록 해야 한다.

학생과 교수가 계정으로 로그인하고, 교수가 검토 링크를 열 때 학생이 지정한 이메일과 확인된 로그인 이메일을 대조하는 초기 기능이다. 일치하는 계정만 해당 검토 자료·파일·댓글에 접근하며 링크만 소지한 다른 계정에는 내용을 공개하지 않는다. 이메일·비밀번호와 이메일 확인 화면은 작성 기준안이며 실제 인증 수단과 보안 값은 운영 전 결정한다.

**성공 기준**: 사용성 검증에서 지정된 교수 계정은 검토로 복귀하고 다른 계정은 파일·댓글·응답에 접근하지 못하는지 확인한다.

**개발 준비 슬롯**
- **선행조건**: - 교수 검토에는 지정 교수 이메일과 검토 요청이 있어야 한다.
- **트리거**: - 사용자가 로그인 또는 검토 링크 열기를 선택하면 계정 확인을 시작한다.
- **동작**:
  - 사용자는 계정으로 로그인하고 필요하면 가입·이메일 확인을 마친다.
  - 검토 링크의 허용 이메일과 확인된 계정 이메일을 대조한 뒤 원래 검토 위치로 돌아간다.
- **결과**: - 지정된 계정은 현재 공유 중인 검토 자료에 접근하고 불일치 계정은 내용에 접근하지 못한다.
- **예외**:
  - 로그인·이메일 확인이 실패하면 검토 내용을 공개하지 않는다.
  - 계정의 이메일 변경은 새 주소를 확인한 뒤 적용한다.
- **표시**:
  - 접근 불가에는 자료 내용 대신 다른 계정으로 로그인 안내를 보여준다.
  - 이메일 확인 대기·접근 가능·불가를 구분한다.
- **권한 & 접근**:
  - 학생의 자기 연구 소유 권한과 교수의 개별 검토 접근 권한은 서로 다르다.
  - 계정 이메일 일치는 교수 신분 자체를 증명하지 않는다.
- **비즈니스 규칙**:
  - 검토 권한은 화면과 파일 열기·다운로드·댓글·응답 저장 시점마다 확인한다.
  - 이메일·비밀번호와 이메일 확인은 화면 기준안이며 실제 인증 제공자·보안 수치는 운영 전에 확정한다.
- **데이터**:
  - 계정은 계정ID, 확인된 이메일, 이메일 확인 상태와 표시 이름을 식별한다.
  - 검토 요청은 지정 교수 이메일과 공유 상태를 가진다.

## 7. 연구 통합 대시보드
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중

학생은 현재 연구의 다음 미팅에서 보여줄 결과·남은 작업·질문·새 교수 응답·가까운 마감을 요약해서 보고 원래 기록으로 이동한다. 기본 목록 찾기와 새 응답 표시는 초기 범위이며 통합 검색·전체 활동과 외부 자동 알림은 후속으로 둔다. 교수에게 연구 전체 대시보드를 제공하거나 여러 상태를 하나의 연구 완성도로 합치지 않는다.

**수용 기준:**
```
1. ○ 학생은 현재 연구의 다음 미팅·남은 작업·질문·교수 새 응답과 가까운 마감을 각각 원래 항목으로 이동해 확인한다.
2. ○ 기본 목록에서 이전 기록을 찾고 필터를 해제할 수 있으며 새 교수 응답은 해당 항목으로 이동한다.
3. ○ 교수 응답 대기와 추가 수정 필요, 학생의 남은 작업을 서로 구분하고 조회 실패한 영역은 정상 영역과 구분한다.
4. ○ 통합 검색·전체 활동·외부 알림은 후속 범위로 표시하고 권한 없는 제목·발췌·건수는 노출하지 않는다.
```


### 7.1 연구 현황·다음 행동 요약
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 학생 | **기기**: 웹 브라우저

**기능의 근거**: 학생은 이전 피드백, 수정본, 미완료 작업을 함께 찾기 어렵다. 서비스를 열었을 때 지금 무엇을 해야 하는지 빠르게 파악할 시작점이 필요하다.

다시 접속한 학생이 선택한 연구의 다음 미팅, 보여줄 결과, 남은 작업, 질문, 교수의 새 응답과 가까운 마감을 한곳에서 확인하는 초기 기능이다. 각 항목은 원본 기록으로 이동하고 현재 작업과 당시 미팅에서 보고한 내용을 구별한다. 교수에게 연구 전체 현황을 제공하거나 여러 상태를 하나의 연구 완성도로 자동 합치지 않는다.

**성공 기준**: 사용성 검증에서 학생이 추가 작업이 필요한 피드백과 교수 응답만 기다리는 피드백을 혼동 없이 찾아낼 수 있는지 확인한다.

**개발 준비 슬롯**
- **선행조건**:
  - 학생이 로그인한 상태이고 열람 권한이 있는 연구가 하나 이상 있어야 한다.
  - 표시 정보는 로드맵, 할 일, 피드백 기능에 등록된 데이터를 사용한다.
- **트리거**:
  - 학생이 서비스에 진입하면 대시보드를 연다.
  - 학생이 메뉴에서 대시보드를 선택하면 조회한다.
  - 학생이 다른 연구로 전환하면 해당 연구의 현황을 다시 조회한다.
- **동작**:
  - 현재 연구의 다음 미팅과 준비 내용·남은 작업·질문·새 교수 응답·가까운 마감을 각각 조회한다.
  - 학생은 요약에서 해당 원본 항목으로 이동한다.
- **결과**:
  - 대시보드 조회는 데이터를 변경하지 않는다.
  - 학생이 항목을 선택하면 해당 원본 화면으로 이동한다.
- **예외**:
  - 일부 조회 실패는 해당 영역만 재시도하고 정상 영역은 유지한다.
  - 접근할 수 없는 자료의 제목·발췌·건수는 보이지 않는다.
- **표시**:
  - 할 작업, 교수 응답만 기다리는 항목과 추가 수정이 필요한 새 교수 응답을 구분한다.
  - 빈 연구는 미팅 기록 남기기와 자료 추가를 안내한다.
- **권한 & 접근**:
  - 학생은 열람 권한이 있는 연구의 현황만 조회할 수 있다.
  - 교수에게는 대시보드를 제공하지 않는다.
- **비즈니스 규칙**:
  - 추가 작업이나 판단이 필요한 피드백은 학생 상태가 처리 전·진행 중·보류이거나 연결된 검토 항목의 최신 교수 결과가 추가 수정 필요인 항목으로 집계한다.

  - 진행 중 과제는 투두 리스트에서 진행 전 또는 진행 중인 과제이다.
  - 주요 일정은 오늘부터 향후 4주 이내 일정을 보여준다.


### 7.2 기본 목록 찾기·새 응답 표시
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 학생, 교수 | **기기**: 웹 브라우저

**기능의 근거**: 댓글, 자료, 일정 변경이 문서 편집기와 메신저에 흩어져 있어 학생이 교수 의견이나 변경 사항을 놓치기 쉽다.

학생이 기본 목록의 이름·날짜·상태로 지난 기록을 찾고 새 교수 응답을 확인하는 초기 기능이다. 허용된 교수는 자신의 검토 안에서 새 차수나 학생 답글을 읽으며, 각각 원래 항목이나 대화 위치로 이동한다. 본문 OCR·외부 URL 수집·전체 활동 피드와 외부 자동 알림은 후속 범위다.

**개발 준비 슬롯**
- **선행조건**: 학생은 자기 연구, 교수는 공유받은 검토 안에서만 조회한다.
- **트리거**: 기본 목록을 열거나 검색·필터를 선택한다. 새 교수 댓글·결과, 새 검토 차수·학생 답글이 저장되면 관련 계정에 새 표시를 만든다.
- **동작**: 목록 조건을 입력·해제하고 해당 항목·대화로 이동한다. 항목·대화를 열면 계정별 읽음으로 기록한다.
- **결과**: 학생은 새 교수 응답을, 교수는 허용 검토의 새 차수·학생 답글을 확인한다.
- **예외**: 0건에는 필터 해제를 안내하고 실패 시 조건을 유지한다. 권한 없는 제목·발췌·건수는 노출하지 않는다.
- **표시**: 현재 조건·결과·새 응답을 표시한다. 자료 등록·일정 변경 등을 모은 전체 활동 피드는 초기 화면에 넣지 않는다.
- **권한 & 접근**: 학생·허용 교수는 각자 허용된 기록만 조회한다.
- **비즈니스 규칙**: 읽음은 이해·반영·교수 확인을 뜻하지 않는다. 교수 결과는 수정 내용 확인·추가 수정 필요를 사용한다. 전체 활동·외부 자동 알림은 후속 범위다.

## 8. 논문 미팅 및 주차별 기록 관리
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중

학생은 날짜 미정인 미팅부터 자료·작업·질문을 연결하고, 실시한 미팅의 원문 메모를 피드백·결정·질문으로 정리한다. 날짜·기록 상태는 학생이 직접 바꾸고 연기·취소에도 기존 연결을 보존한다. 과거 미팅 목록과 원문 대조는 초기 범위이며 참여 의사 전달과 실시간 녹음은 제외하고 동의가 필요한 녹음·전사만 후속으로 둔다.

**수용 기준:**
```
1. ○ 날짜 미정 미팅에도 준비 자료·작업·질문을 연결하고 일시 변경·취소 이후에도 원래 관계를 찾을 수 있다.
2. ○ 미팅 기록의 메모 구간을 피드백·결정·질문으로 정리하면서 당시 발췌와 학생의 수정 내용을 구분할 수 있다.
3. ○ 과거 미팅 목록에서 취소·날짜 미정 기록과 당시 자료 버전·질문을 찾고 현재 작업 상태와 당시 보고를 구분할 수 있다.
4. ○ 녹음·전사는 참여자 동의와 보존·삭제 정책을 확정하기 전 활성화하지 않으며 메모 입력은 독립적으로 사용할 수 있다.
```


### 8.1 미팅 생성·날짜 미정 준비·일정 변경
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 학생 | **기기**: 웹 브라우저

**기능의 근거**: 미팅 일정과 참여 여부가 메신저 등에 흩어져 있어 주차별 기록과 준비 자료를 연결하기 어렵다.

학생이 미팅의 이름과 날짜 지정·미정을 선택해 준비를 시작하고, 기록 시작·마무리 및 일정 변경·취소를 관리하는 초기 기능이다. 일시가 바뀌어도 같은 미팅에 연결한 자료·작업·질문은 유지하고 미팅 연기로 작업 기한·공식 투고 마감을 바꾸지 않는다. 참여 의사 전달과 반복 일정 일괄 편집은 초기 범위 밖이다.

**개발 준비 슬롯**
- **선행조건**: 학생이 소유한 연구가 있어야 한다.
- **트리거**: 미팅 추가, 날짜 미정으로 준비 시작, 일시 변경, 미팅 기록 시작·마무리, 취소·취소 되돌리기를 선택한다.
- **동작**:
  - 이름과 날짜 미정·지정을 선택해 미팅을 만든다. 날짜 지정 시 날짜를 받고 시각은 선택으로 둔다. 시간대도 구분한다.
  - 기록 시작은 기록 중, 기록 마무리는 기록 완료로 변경한다.
  - 일시 변경·취소 후에도 같은 미팅과 자료·작업·질문을 유지한다.
- **결과**: 미팅과 기록 상태가 저장되고 다음 준비 대상에 반영된다. 취소된 미팅은 기본 준비 대상에서 제외한다.
- **예외**: 중복 일시는 안내하되 별개 미팅이면 허용한다. 실패 시 입력·기존 상태·연결을 유지한다.
- **표시**: 날짜·시각 미정과 준비 중·기록 중·기록 완료·취소를 문구로 구분한다.
- **권한 & 접근**: 학생만 자기 미팅의 일시·기록 상태를 변경한다.
- **비즈니스 규칙**:
  - 연기는 일시 변경 이력으로 남기며 작업 기한·공식 마감을 바꾸지 않는다.
  - 날짜 경과만으로 실시·기록 완료로 바꾸지 않는다.
  - 주차·회차는 보조 표기로 사용한다. 참여 의사 전달·참여 상태 기록·반복 일정 관리는 현재 초기 범위에 넣지 않는 기준안으로 둔다.
- **데이터**: 미팅ID, 연구ID, 이름, 날짜 미정·지정 여부, 날짜·선택 시각·시간대, 선택 회차·장소, 기록 상태(준비 중·기록 중·기록 완료·취소), 연결 기록과 변경 이력을 가진다.


### 8.2 미팅 메모·원문 대조·정리 항목 저장
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 학생 | **기기**: 웹 브라우저

**기능의 근거**: 교수 발언을 잘못 이해하거나 일부를 누락한 채 수정하는 문제가 있어 미팅 내용을 다음 작업에 쓸 수 있는 형태로 남겨야 한다.

학생이 미팅 뒤 남긴 메모를 원문으로 보존하고 선택 구간을 피드백·결정·질문으로 정리하는 초기 기능이다. 학생은 자동 입력된 내용을 고쳐 저장할 수 있고 AI 정리는 선택적으로만 이용한다. 당시 원문 발췌와 학생이 정리·수정한 항목을 구분하며 AI 후보를 채택하지 않아도 직접 기록과 후속 작업을 계속한다.

**성공 기준**: 사용성 검증에서 학생이 입력 메모의 원문과 정리 항목을 대조해 누락이나 근거 없는 이유·다음 행동을 찾아내고 고칠 수 있는지 확인한다.

**개발 준비 슬롯**
- **선행조건**:
  - 기록을 연결할 미팅이 등록되어 있어야 한다.
  - AI 분류를 쓰려면 학생이 해당 단계와 자료 범위를 승인해야 한다.
- **트리거**:
  - 학생이 미팅 상세에서 기록 작성을 선택하면 시작한다.
  - 학생이 기록 화면에서 AI 분류 실행을 선택하면 분류를 시작한다.
- **동작**:
  - 학생이 미팅 메모를 입력하거나 붙여 넣는다.
  - 학생이 AI를 선택하면 선택 원문에서 피드백·결정 사항·질문 후보를 제안한다. 무엇을·왜·다음에 무엇을은 보조 정리 내용으로 사용할 수 있지만 원문에 없는 이유를 필수로 채우지 않는다.
- **결과**:
  - 원문 메모와 정리 결과가 따로 저장된다.
  - 정리 항목은 원문 구간과 연결된다.
- **예외**:
  - AI 분류가 실패하면 원문을 유지하고 학생이 직접 정리할 수 있도록 안내한다.
  - 미팅 메모는 작성 중 자동 저장한다.
- **표시**:
  - 원문 메모와 정리 결과를 나란히 표시한다.
  - AI가 만든 정리 항목은 AI 초안으로 표시한다.
- **권한 & 접근**:
  - 학생만 미팅 기록을 작성·수정할 수 있다.
  - 새 기록의 공개 범위는 개인 기록과 교수 공유 권한 정책을 따른다.
- **비즈니스 규칙**:
  - AI가 쓰이지 않거나 중단돼도 메모와 피드백·결정·질문의 직접 저장을 계속한다.
  - AI가 근거를 표시할 때는 실제 입력된 당시 발췌·위치를 연결하고 없는 교수 발언이나 의도를 원문으로 만들어 내지 않는다.
  - 학생이 정리해 저장한 항목에 대조 완료·분류 확정·AI 채택 절차를 반복 요구하지 않는다.
- **데이터**:
  - 미팅 기록은 기록ID, 미팅ID, 원문 메모, 작성자, 작성 시각을 가진다.
  - 정리 항목은 항목ID, 기록ID, 유형(피드백·결정 사항·질문), 내용, 당시 원문 발췌·위치, 생성 주체, 저장 여부와 학생 수정 이력을 가진다.


### 8.3 결정 사항 및 미해결 질문 관리
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 학생 | **기기**: 웹 브라우저

**기능의 근거**: 미팅에서 정한 방향과 보류한 쟁점이 섞여 기록되면 학생이 다음 지도에서 무엇을 다시 논의해야 하는지 놓친다.

학생이 미팅에서 결정된 연구 방향과 보류된 쟁점을 구분해 기록하고 다음 논의로 연결하는 P0 기능이다. 미해결 질문은 다음 미팅의 질문 항목으로 가져갈 수 있고 해결되면 해결 처리한다. 결정과 보류의 구분은 학생이 하며 AI가 결정 사항을 확정하지 않는다.

**성공 기준**: 사용성 검증에서 학생이 결정된 내용과 미해결 질문을 원문 근거와 함께 구분하고 다음 지도에서 확인할 질문을 스스로 정할 수 있는지 살핀다.

**개발 준비 슬롯**
- **선행조건**: - 학생이 소유한 연구와 저장할 결정·질문 내용이 있어야 한다. 직접 추가할 때는 기존 미팅 메모를 요구하지 않는다.
- **트리거**:
  - 학생이 미팅 기록의 정리 항목을 결정 사항 또는 미해결 질문으로 지정하면 시작한다.
  - 학생이 미팅 상세에서 결정 사항·미해결 질문을 직접 추가할 수 있다.
- **동작**:
  - 기존 정리 항목에서 시작하면 원문 관계를 유지하고, 직접 추가하면 학생 작성으로 저장한다.
  - 같은 질문을 다음 미팅에 연결하거나 해결 처리하며 필요하면 다시 열 수 있다.
- **결과**:
  - 결정·질문 내용과 작성 주체를 저장하며 관련 원문이 있는 경우에만 원문 관계를 연결한다.
  - 결정 사항은 할 일 후보 생성의 원천으로 쓰인다.
  - 해결 처리한 질문은 미해결 목록에서 빠지고 이력은 유지된다.
- **예외**: - 이미 다음 미팅에 연결된 질문을 다시 연결하면 중복 연결하지 않는다.
- **표시**:
  - 결정 사항과 미해결 질문을 별도 목록으로 구분해 표시한다.
  - 출처 미팅·원문이 있으면 해당 정보를 표시한다. 직접 작성한 질문에는 존재하지 않는 원문 링크를 만들지 않는다.
- **권한 & 접근**: - 학생만 결정 사항과 미해결 질문을 분류·수정할 수 있다.
- **비즈니스 규칙**:
  - 결정 사항은 학생이 분류하며 AI가 확정하지 않는다.
  - 학생이 기록한 결정은 교수의 직접 확인과 구분한다.
  - 같은 발언의 기존 정리·피드백이 있으면 원문과 해당 항목에 관계를 연결하고 동일 피드백을 별도로 복제하지 않는다.
  - 학생이 선택한 미해결 질문만 다음 미팅에 연결한다.


### 8.4 과거 미팅 목록·기록 이동
> **중요도**: 🔴 높음 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 학생 | **기기**: 웹 브라우저

**기능의 근거**: 학생이 논문 지도 과정의 전체 피드백 흐름을 파악하려면 여러 주차 기록을 따로 찾아야 한다.

학생이 지난 미팅의 메모·피드백·질문·당시 준비 문서와 보존 자료 버전을 목록에서 찾아 여는 초기 기능이다. 날짜 미정·취소된 미팅도 찾고 당시 보고 내용은 현재 작업 상태와 구분한다. 여러 기록을 비교하거나 AI로 추가 정리하는 후속 기능은 포함하지 않는다.

**개발 준비 슬롯**
- **선행조건**: - 조회할 이전 미팅이 하나 이상 등록되어 있어야 한다.
- **트리거**: - 학생이 미팅 화면에서 히스토리를 선택하면 조회한다.
- **동작**:
  - 시스템은 미팅별로 일시·기록 상태·당시 자료 버전·피드백·결정·질문을 모아 시간순으로 보여준다.
  - 학생이 항목을 선택하면 원본 기록으로 이동한다.
- **결과**: - 히스토리 조회는 데이터를 변경하지 않는다.
- **예외**:
  - 권한이 없거나 삭제된 자료는 내용을 노출하지 않고 접근할 수 없음으로 표시한다.
  - 주차가 많으면 일정 단위로 나누어 불러온다.
- **표시**:
  - 과거 미팅 목록에는 날짜 미정·취소된 기록도 표시하고 필터 해제를 제공한다.
  - 당시 저장된 준비 문서와 현재 작업 상태를 구분한다.
- **권한 & 접근**: - 학생은 열람 권한이 있는 연구의 히스토리만 조회할 수 있다.
- **비즈니스 규칙**: - 히스토리는 미팅·문서 버전·피드백·결정 사항의 기존 관계를 그대로 사용한다.


### 8.5 미팅 녹음·전사와 원문 대조
> **중요도**: 🟡 중간 | **진행 상태**: ⚪ 기획 작성중 | **역할**: 학생 | **기기**: 웹 브라우저

**기능의 근거**: 학생이 미팅 중 메모만으로 교수 발언을 모두 남기기 어렵고 누락이 생길 수 있다.

참여자의 녹음 및 외부 처리 동의·보존·삭제 정책을 확정한 뒤 학생이 허용된 음성을 미팅과 연결하거나 전사하는 후속 기능이다. 학생은 음성 구간과 전사 문장을 대조해 정정하고 메모 정리에 이용하며, 화자 추정은 교수 발언 검증으로 취급하지 않는다. 녹음·전사가 없어도 기본 미팅 메모 작성은 이용할 수 있다.

**개발 준비 슬롯**
- **선행조건**:
  - 녹음과 외부 처리에 필요한 참여자 동의·보존·삭제 정책이 먼저 확정되어야 한다.
  - 학생은 녹음하거나 등록할 대상 미팅과 필요한 접근 권한을 확인해야 한다.
- **트리거**:
  - 학생이 허용된 미팅에서 녹음 시작 또는 음성 등록을 선택하면 시작한다.
  - 학생이 허용된 음성에서 전사·원문 대조를 선택하면 시작한다.
- **동작**:
  - 학생은 녹음·중지 또는 음성 파일 등록을 진행한다.
  - 학생은 음성 구간과 전사 문장을 대조하고 오류를 정정해 미팅 메모에 활용한다.
- **결과**:
  - 음성 시점·전사 문장·학생 정정과 작성 주체는 구분해 연결된다.
  - 전사 진행·부분 결과·확인 결과는 별도로 남는다.
- **예외**:
  - 녹음 권한 거부·파일 오류·전사 실패 시 학생은 직접 메모를 계속한다.
  - 부분 전사는 완료 전사와 구분하고 저장된 메모를 덮어쓰지 않는다.
  - 음성 삭제 뒤 전사와 발췌의 유지·제거 범위는 확정된 참여자 동의·보존 정책을 따른다.
- **표시**:
  - 녹음 시작·중지 및 전사 진행·실패·부분 결과를 구분한다.
  - 음성 구간과 정정 전후 텍스트, 교수 직접 확인 여부를 구분해 보여준다.
- **권한 & 접근**:
  - 학생만 녹음을 연결하고 전사를 실행할 수 있다.
  - 녹음의 교수 공유는 개인 기록과 교수 공유 권한 정책을 따른다.
- **비즈니스 규칙**:
  - 화자 추정이나 전사 결과만으로 교수의 발언·의도가 직접 검증되었다고 표현하지 않는다.
  - 실제 음성·전사 보존 기간, 삭제 범위와 처리 제공자는 후속 운영 정책에서 확정한다.
  - 전사 확인은 음성 삭제 동의나 교수 공유 동의를 뜻하지 않는다.
- **데이터**:
  - 음성 연결은 미팅ID, 음성 자료ID, 확인한 동의 범위, 녹음 시점과 전사 상태를 식별한다.
  - 전사 문장은 음성 구간, 텍스트, 학생 정정 내용, 확인 상태와 변경 이력을 구분한다.

## 프로덕트 정책

### 1. AI 처리 범위와 사람의 확정

사용 범위:
  - 초기 AI 보조는 학생이 선택한 미팅 기록 정리·피드백 대조·수정 방안 후보·할 일 후보·준비 문서 구성에만 적용한다.
  - 후속 일정 제안과 녹음 전사는 초기 AI 범위에 포함하지 않는다.
  - AI를 쓰지 않거나 실패해도 직접 기록·작업·준비를 계속할 수 있다.

판단 경계:
  - AI는 추출한 내용의 실제 발췌·위치와 새 방법의 근거·가정을 구분해 표시한다.
  - AI는 원문에 없는 수정 방법을 제안할 수 있지만 교수의 실제 지시라고 표현하지 않는다.
  - AI는 없는 발언·문헌·연구 결과·정확한 소요 시간을 만들거나 연구 방향·피드백 반영·작업 완료를 자동 확정하지 않는다.
  - AI 제안의 저장은 교수 공유와 구분하며 학생 메모는 교수 직접 작성·응답과 구분한다.

외부 처리·학습:
  - 학생이 선택한 자료·버전·구간만 AI 처리 대상으로 제안한다.
  - 시연 AI 제공자는 Google API로 정한다. 실제 API 접속 방식·모델·프로젝트 설정은 구현 시 기록한다.
  - 해당 접속 방식의 저장·학습 사용·삭제·사용 한도는 시연 전에 확인하며 확인하지 않은 조건을 보장하지 않는다.

근거 누락: - AI가 근거 부족인 항목은 확인 필요로 남기며 교수의 확정된 발언으로 표현하지 않는다.

생성 중단과 영역 닫기:
  - AI 영역을 닫으면 입력과 후보는 유지하고 생성 중단과는 별개로 처리한다.
  - AI 생성을 중단하면 가능한 이후 처리를 멈추되 이미 외부에서 처리된 내용까지 소급 취소했다고 표현하지 않는다.

항목 채택 취소:
  - 학생이 채택을 취소해도 연결된 작업과 수정 결과는 자동 삭제하지 않는다.
  - 채택 취소 시 학생에게 기존 관계를 보여주고 유지·해제를 선택하게 한다.

처리 전 안내:
  - AI 실행 전 학생에게 선택한 메모·자료 버전·구간을 보여준다.
  - AI 처리 동의는 교수 공유 동의와 구분하며 생성된 결과의 원문 열람 권한을 자동으로 넓히지 않는다.

### 2. 개인 기록과 교수 공유 권한

기록과 협업 상대:
  - 학생은 자신의 연구 기록을 작성·수정한다.
  - 교수는 학생이 지정한 이메일의 서비스 계정으로 공유된 수정 결과에 항목별로 응답한다.
  - 교수 전용 대시보드나 다수 학생 관리 화면은 제공하지 않는다.
  - 학생이 옮겨 쓴 교수 발언은 교수의 직접 댓글·응답과 구분한다.

공통 접근 제한:
  - 교수의 확인된 로그인 이메일이 검토 요청의 허용 주소와 같고 요청이 공유 중일 때에만 접근을 허용한다.
  - 자료 열기·다운로드·댓글·응답 저장 때마다 현재 권한을 다시 확인한다.
  - 접근 불가한 자료의 제목·발췌·건수는 공개하지 않는다.
  - 학생의 연구 소유 권한과 교수의 개별 검토 권한은 구분한다.

교수 확인 방식:
  - 학생은 링크를 직접 복사해 전달하며 링크 생성만으로 교수의 전달·열람을 확정하지 않는다.
  - 하나의 링크에 여러 수정 결과를 담고 항목·차수별로 교수 결과를 남긴다.
  - 요청당 교수 계정 하나와 같은 링크에서 재확인 차수를 여는 것은 검증 전 작성 기준안으로 둔다.

공유 허용 동작:
  - 허용 교수는 검토에 첨부된 파일 전체를 열람·다운로드하고 댓글·답글 및 본인 결과만 작성·수정한다.
  - 지정 위치만 볼 수 있게 하려면 학생이 해당 부분으로 만든 별도 파일을 선택한다.
  - 교수의 추가 수정 필요 결과에는 이유 댓글을 필수로 하고 수정 내용 확인의 댓글은 선택으로 둔다.

기록 기본 공개 범위:
  - 새 기록·AI 후보·준비 문서 저장은 교수 공유가 아니다.
  - 연구 전체와 개인 메모·미채택 후보·전체 작업 목록은 자동 공개하지 않는다.
  - 공유 결과에 연결된 개인 원문의 열람 권한은 자동으로 부여하지 않는다.

공유 회수:
  - 공유 중지는 이후 교수 접근을 차단하고 보관이나 영구 삭제와 구분한다.
  - 공유 중지 후에도 학생은 기존 교수 응답과 검토 이력을 읽을 수 있다.
  - 이전에 내려받은 사본까지 회수할 수 있다고 안내하지 않는다.

### 3. 연구 기록 관계와 변경 이력

버전과 검토 차수:
  - 보존 파일 버전은 등록 당시 내용을 유지하고 새 파일은 새 버전으로 추가한다.
  - 외부 참조 URL만으로 당시 본문이 보존된 버전이라고 취급하지 않는다.
  - 검토 차수는 교수에게 보낸 당시 항목 설명·자료·위치·응답의 묶음이다.

관계와 출처:
  - 자료·작업·질문·미팅 메모는 원본 하나를 저장하고 여러 미팅·피드백에 연결한다.
  - 같은 발언에서 파생된 정리·피드백·할 일은 원문 관계를 유지하고 학생이 수정한 내용은 당시 발췌와 구분한다.
  - 준비 목록에서 항목을 제외하면 해당 연결만 해제하고 원본은 유지한다.
  - 학생이 새 파일을 등록하거나 결과를 편집해도 이미 보낸 검토 차수의 내용은 바뀌지 않는다.

피드백과 할 일 관계:
  - 하나의 피드백은 여러 작업에 연결하고 하나의 작업도 여러 피드백과 미팅에 연결한다.
  - 이번 준비 목록에서 선택하지 않은 작업과 후보는 유지하며 명시적 거부와 구분한다.
  - 작업 완료와 학생의 피드백 처리 결과, 교수의 항목별 검토 결과는 서로 자동 변경하지 않는다.

처리·검토 상태:
  - 학생의 피드백 처리 상태는 처리 전·진행 중·반영 기록 있음·보류·미수정 결정을 구분한다.
  - 교수의 항목별 최신 차수 결과는 응답 전·수정 내용 확인·추가 수정 필요를 구분한다.
  - 남은 피드백에는 학생의 처리 전·진행 중·보류 및 교수의 추가 수정 필요를 포함하고 교수 응답만 기다리는 경우와 구분한다.
  - 교수의 추가 수정 필요는 과거 학생 반영 이력을 지우지 않는다.

버전 근거 범위:
  - 문서 수정의 교수 검토에는 보존 파일 버전과 확인 위치를 연결한다.
  - 외부 URL의 과거 내용·변경 감지·자동 동기화를 보장하지 않는다.
  - 허용된 교수에게 위치를 지정해도 첨부 파일 전체는 열람·다운로드할 수 있다.

변경 이력 범위:
  - 보낸 검토의 당시 설명·파일 버전·위치·교수 응답과 재확인 차수는 따로 남긴다.
  - 메모 원문을 수정해도 이미 저장된 파생 항목의 당시 발췌를 자동 변경하지 않는다.

보관과 삭제:
  - 연구와 자료 보관은 활성 목록에서 제외할 뿐 기존 연결과 공유 상태를 변경하지 않는다.
  - 연결 해제는 원본 삭제가 아니며 공유 중지는 이후 접근 권한만 차단한다.
  - 영구 삭제·탈퇴와 보존 기간은 운영 전 정책으로 남긴다.

### 4. 공통 입력·저장·실패 처리

- 필수 텍스트가 비었거나 공백뿐이면 저장하지 않는다. 선택 입력은 비어도 저장한다.
- 메모는 자동 저장하며 저장 중·저장됨·실패를 표시한다. 작업·결과·교수 응답·권한 변경은 명시적으로 저장한다.
- 실패 시 마지막 저장 값과 미저장 입력을 유지한다. 재시도·중복 선택으로 같은 기록을 여러 개 만들지 않는다.
- 원본 저장과 연결의 성공 여부를 구분한다. 연결만 실패하면 저장된 원본을 유지하고 연결만 재시도한다.
- 다른 창에서 바뀐 기록은 알리지 않고 덮어쓰지 않는다. 미저장 내용을 두고 이동할 때 계속 편집·버리고 이동을 선택하게 한다.
- 없음·검색 결과 없음·불러오기 실패·접근 불가를 구분한다.

### 5. 수업 시연의 실제 AI 실행과 제한 공개 배포

- AI 실행은 로그인한 학생의 현재 연구·선택 원문·자료 접근 권한을 앱 서버에서 확인한 뒤 Google API를 호출한다. API 인증 정보는 서버 비밀 설정으로 관리하고 브라우저·Git·응답에 노출하지 않는다.
- 메모 정리와 수정 방안 제안은 실제 API 응답을 사용한다. 저장된 예시를 대신 보여줄 때는 실시간 응답으로 표시하지 않는다. 선택한 텍스트만으로 기본 시연을 구성할 수 있으며 PDF 전체 분석·OCR·외부 URL 수집을 암묵적으로 추가하지 않는다.
- 구조화된 응답의 필드·유형·출처 관계를 확인한 뒤 후보를 표시한다. 형식 검증이 내용의 정확성을 뜻하지 않으며 없는 발췌·위치는 원문 사실로 저장하지 않는다.
- 생성 중·완료·실패를 구분하고 중복 실행을 막는다. 시간 초과·사용량 제한·권한 오류·차단·응답 형식 오류는 입력을 유지해 재시도 또는 직접 작성으로 복귀한다. 무한 재시도하지 않는다.
- 허용 계정·검토 공유 상태는 화면뿐 아니라 파일·댓글·응답·AI 실행에서도 확인한다. 시연용 가상 자료와 실제 계정 인증 정보를 구분한다.
- 대표 시나리오와 접근 거부·필수 이유·이전 차수 유지·실패 복귀를 배포 주소에서 확인해야 시연 준비 완료로 기록한다. 문서 검사 통과를 앱 기능·배포 통과로 취급하지 않는다.
