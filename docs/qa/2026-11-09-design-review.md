## 1. 가장 큰 문제 5개

1. **다크 모드 알림이 거의 안 읽혀요 (막힘).** 모든 저장·완료·되돌리기 알림이 다크에서 반투명 흰 면(`rgba(255,255,255,.52)`) 위에 흰 글자예요. 할 일 완료 뒤 6초 안에 눌러야 하는 '되돌리기'도 여기 있어요. 원인은 `src/design/montage.css:209-225`가 반전 면(`neutral-inverse`)에 고정 흰 글자를 붙인 것이에요. 반전 면은 다크에서 밝아져요. 통일 계획 문서에도 이미 적힌 위험인데, 그대로 옮겨졌어요. → [B-2], `shots/toast-1280-dark.png`
2. **같은 뜻이 곳마다 다른 색이에요.**
   - 주 행동: 공개 화면 라이트는 검정, 다크는 파랑이고, 앱과 가입·로그인 화면은 파랑이에요. 마지막 CTA 띠는 흰 버튼이라, '시작하기' 하나가 세 가지 색이에요. → [B-1], `shots/landing-1440-*.png`
   - 선택 표시: 여섯 가지 모양이에요. → [B-4]
   - 파랑: 하나가 주 행동·선택·호버·링크·정보·진행 중·미팅·완료·장식을 모두 맡아요. → [D-1]
   - 초록: 학생 '작업 완료'와 교수 '수정 내용 확인'을 같은 초록으로 표시해요. 이것은 AGENTS.md의 "작업 완료·교수 결과를 합치지 않는다"와 직접 충돌해요. → [D-2]
3. **핵심 흐름이 첫 화살표부터 끊겨 있어요.**
   - 미팅에서 결정한 내용을 할 일로 만들 수 없어요. "할 일 메뉴에서 만들 수 있어요"라고만 안내해요(`MeetingsPage.tsx:1271`).
   - 할 일과 글쓰기는 양쪽 모두 연결이 없어요.
   - 교수의 '추가 수정 필요'에서 학생이 고칠 곳으로 가는 길이 '다시 확인 요청' 대화상자 안에 숨어 있어요.
   - 교수가 결과를 저장하면 알림만 뜨고 끝이에요.
   - 연구 도우미 화면에는 링크가 하나도 없어요.
   - 돌아오는 길(`from`)이 코드 어디에도 없어요.
   - → [H-1~H-5], [H-7], [H-10]
4. **화면 머리가 화면마다 달라요.**
   - `PageHeader`에 뒤로·탭·도구 줄 자리가 없어서 쌓는 순서가 4가지예요. 예를 들어 할 일 화면은 탭이 제목 위에 있어요.
   - 머리의 주 버튼은 화면에 따라 0개, 1개, 2개예요.
   - 계획·일정은 서로 다른 내용(로드맵·캘린더·시간 조율)을 보기 전환으로 고르고, 바로 옆에 진짜 보기 전환(시간순·관계도)을 같은 모양으로 두었어요.
   - 학생이 검토 상세를 열면 머리와 로고가 두 번 나와요.
   - → [E-1~E-3], [E-7], `shots/planning-1440-dark.png`, `shots/review-detail-390-light.png`
5. **중요한 내용이 잘리거나 숨어요.**
   - 교수 검토 화면의 '보낸 당시 파일' 이름이 한 줄 말줄임이라 `_v2`/`_v3`를 구분할 수 없어요. 360px에서는 차수 선택도 잘려요. → [F-1]
   - 휴대폰 보기 전환·설정 탭은 스크롤바 없이 오른쪽 끝에서 잘려요. 예: 미팅 '날짜 미정'. → [F-7], `shots/meetings-360-light.png`
   - 11px 글자가 109곳이에요. → [F-8]
   - 홈은 "다음 미팅 우선"이 원칙인데, 다음 미팅이 390px와 1440px 모두 첫 화면 밖에 있어요. → [E-6], `shots/home-390-light.png`

함께 볼 점: CHANGELOG·문서의 주장과 코드가 어긋나는 곳이 여러 곳 있어요.
- 남아 있는 것: 10px 글자 17곳, 직접 만든 버튼 41개, 지웠다던 스위치 CSS, `ui-quality.md`가 말하는 IME Enter 테스트.
- 없는 것: CHANGELOG가 말하는 계산 스타일 비교 스크립트가 저장소에 없어요.
- → [C-2], [C-5], [C-10], [C-11], [K-5]

### E. 위계·머리
- 25개 화면의 머리 해부 표와 3초 테스트는 부록 H·E §E-0에 있어요.
- 표준안(§E-12): `PageHeader`에 `back`·`tabs`·`toolbar` 자리를 더하고 순서를 고정해요. 순서는 뒤로 → 제목·상태 배지·행동 → 설명 → 탭 → 도구 줄이에요. 머리 행동은 주 버튼 1개, 테두리 버튼 1개, 나머지는 더보기 메뉴로 둬요.
- 원칙: 탭은 다른 내용 묶음, 보기 전환은 같은 내용을 다르게 볼 때 써요.

### G. 톤앤매너
- 해요체와 금지 용어는 잘 지켜졌어요. TSX에서 승인·반려·채택·스냅샷이 0곳이에요.
- 고칠 것:
  - '삭제' 버튼이 실제로는 휴지통으로 옮겨요(G-1).
  - '참여자'와 '공동연구자'가 섞여 있어요(G-2).
  - 교수 화면에 설명 없는 '차수'가 나와요(G-3).
  - 날짜 표기가 3가지예요(G-5).
  - 움직임 시간은 약 10가지(120~750ms), 곡선은 5가지예요(G-7).
- 동작 줄이기에서도 할 일 접힘이 움직일 수 있어요(G-8, 미실행).

### H. 기능 연결
화살표별 판정표, 진입점(⌘K·G 단축키·주간 띠·확인할 내용·알림 판·빈 화면)별 도착지, 막다른 곳 10곳은 부록 H·E §H-0~H-0c에 있어요.

| 할 일 ↔ 글쓰기 | **없음** |

## 6. J. 역할별 비판 (칭찬 제외)

**석사생 — 미팅 직후 5분 정리**
1. 미팅 결정을 바로 할 일로 만들 수 없어 메뉴를 옮겨야 해요(H-5).
2. 홈에서 같은 미팅 준비로 가는 링크가 5개인데, 정작 다음 미팅은 첫 화면 밖이에요(E-6).
3. 미팅 상세의 공개 범위 칸이 머리와 탭 사이에 끼어 기록 탭까지 멀어요(E-10).
4. 정리 뒤 돌아갈 곳이 늘 목록이라 이어서 작업하기 어려워요(H-7).
5. 다크에서 저장·완료 알림이 안 읽혀 저장됐는지 확신하기 어려워요(B-2).
- 바라는 것: 미팅 기록 안에서 '할 일로 만들기', 미팅 끝에 '오늘 결정 요약' 카드, 다음 미팅 날짜 바로 정하기.

**교수 — 링크로 처음 들어옴**
1. 파일명이 잘려 어느 버전인지 알 수 없어요(F-1).
2. '차수'라는 말을 설명 없이 계속 봐요(G-3).
3. 결과를 저장한 뒤 남은 항목 수, 다음 항목, 끝 안내가 없어요(H-3).
4. 나가는 길(로고 → `/r`)이 학생용 '연구 만들기' 화면이에요(H-6).
5. 결과 고르기가 네이티브 라디오라 다른 화면과 모양이 달라요(C-5).
- 바라는 것: 항목 사이 '다음 항목' 이동, 이 요청 안에서만 '남은 n개' 표시(다수 학생 대시보드 아님), 끝났을 때 요약 화면.

**첫 방문자**
1. 공개 화면 버튼이 검정인데, 가입 화면과 앱에서는 파랑이라 같은 서비스인지 순간 헷갈려요(B-1).
2. 머리 로고는 영문 'margin'인데, 문구는 '마진'이에요. 규칙상 허용되지만 안내 문구로 이어 주는 장치가 없어요.
3. 랜딩 슬로건과 가입 화면 큰 제목("지난 미팅에서 다음 미팅까지")이 달라요.
4. 본문의 강제 개행(`<br>`)이 좁은 화면에서 어색하게 끊길 수 있어요(F-4).
5. 체험 화면에서 실제 데이터와 미리보기의 경계를 띠 한 줄로만 알려요.
- 바라는 것: 가입 없이 둘러보는 데모 연구, 기능 둘러보기에서 바로 그 화면 체험, 교수 화면 미리보기.

**키보드 파워 유저**
1. ⌘K에서 검토 요청을 찾거나 수정 결과·검토 요청을 만들 수 없어요(H-8).
2. G 단축키는 있는데, '할 일'은 사이드바에 없어 위치 감각이 어긋나요(E-8).
3. 숨은 가로 스크롤 줄은 키보드로 이동해도 끝이 보이지 않아요(F-7).
4. 목록에서 위아래로 이동하거나 열기 같은 목록 키 조작이 없어요(코드상).
5. 단축키 목록을 한곳에서 볼 수 없어요(툴팁에 흩어져 있음).
- 바라는 것: `?`로 단축키 도움말, 목록 j/k 이동, ⌘K에서 바로 '검토 요청 만들기'.

**휴대폰 전용 사용자**
1. 필터 보기 전환이 잘리고, 더 있다는 표시가 없어요(F-7).
2. 11px 글자가 많고, 휴대폰에서 글자를 한 단계 줄이는 규칙이 많아요(F-8).
3. 할 일 제목이 2줄에서 잘리면서 '우선순위 높음' 점도 함께 사라져요(F-6).
4. 검토 상세에서 머리와 로고가 두 번 나와 첫 화면이 낭비돼요(E-7).
5. 홈 첫 화면이 '바로 시작' 카드 3개로 채워져 다음 미팅이 안 보여요(E-6).
- 바라는 것: 아래 탭 막대(홈·미팅·할 일·검토), 빠른 메모, 알림에서 바로 해당 항목 열기.

**시니어 디자이너 — Montage 위에 마진다움이 있나**
1. 마진다운 장면이 공개 화면(Cloud Shader·마스코트)에만 있고, 앱 안에는 브랜드를 느낄 요소가 거의 없어요.
2. 색 의미가 정리되지 않아 파랑이 장식까지 맡아요(D-1). 강조가 많아 오히려 강조가 안 돼요.
3. 글자 크기 선언의 76%가 caption·label이에요. 작은 회색 글자로 쏠려 위계가 평평해요(D-5).
4. 카드 모서리가 10·12·14·16px로, 어디에 몇 px를 쓸지 규칙이 없어요(G-12).
5. 아이콘 세트가 세 가지(Disarto·lucide·Montage 내장)예요(G-11).
- 바라는 것: 앱용 브랜드 순간(빈 화면·첫 연구 만들기·검토 완료)에 마스코트를 상태 문구와 함께, 색 역할표 문서, 카드·목록 행 공통 부품.

**유지보수 개발자**
1. 한 화면의 CSS가 최대 8개 파일에 흩어져 있고, 결과가 읽히는 순서에 기대요(K-2).
2. 레이어 안 `!important` 82개가 레이어 구조를 거꾸로 뚫어요(C-8).
3. CHANGELOG·문서와 코드가 어긋나요(C-2, C-10, C-11, K-5).
4. 800줄 넘는 파일이 17개예요(K-1).
5. 화면 회귀를 잡을 E2E·스크린샷 비교가 없어요(K-5, K-6).
- 바라는 것: 회귀 스크립트(Q7), 화면별 CSS 한 파일, 공통 `ListRow`·`ConfirmDialog`·`ErrorNotice` 하나로.

**레드팀 — 최근 기능 중 뺄 것**
1. 숫자 굴러가기(@number-flow): 숫자가 작고 자주 안 바뀌는데 의존성과 움직임 규칙만 늘려요. 빼는 쪽을 권해요.
2. 목록 움직임(auto-animate): 할 일 접힘과 다른 시간·곡선이라 움직임이 두 갈래예요. G-7 규칙에 맞추지 못하면 빼요.
3. 소개 카드 펼침: 터치에서는 안 나오고 호버에만 의존해요. 비용 대비 효과를 사용자 확인 뒤 판단해요.
4. G+글자 단축키: ⌘K와 역할이 겹쳐요. 유지하더라도 도움말 한 곳이 필요해요.
5. 밀어서 비교: 글 버전 비교에는 '바뀐 부분' 보기가 더 쓸모 있어요. 슬라이더는 그림·표 PDF에서만 의미가 커요. 둘 다 유지하되 기본값은 '바뀐 부분'으로 두기를 권해요.
