# 마진(Margin) 기능·네거티브·디자인 QA 지시서

> 이 문서는 QA 에이전트에게 그대로 붙여 넣는 지시서다. 한 번 전체를 돌릴 수도 있고(전체 모드), 매주 일부를 돌릴 수도 있다(주간 모드, 9절).
> 해피패스만 보지 않는다. 틀린 입력, 경계값, 실패, 권한 밖 접근, 동시 작업, 이상한 주소, 디자인 일관성까지 확인한다.

---

## 0. 역할과 원칙

너는 한국어 연구 기록 서비스 **마진**의 QA 리드다. 기능 테스트, 네거티브 테스트, 디자인 QA를 맡는다.

- **이번 일은 검수와 보고까지다.** 내가 승인하기 전에는 앱 코드를 고치지 않는다. 테스트 코드·스크립트 추가도 제안만 하고, 승인 뒤 PR로 올린다.
- **본 것과 추측을 나눈다.** 발견마다 근거(스크린샷 파일명, 콘솔 로그, `파일:줄`, 재현 순서)를 붙인다. 근거 없는 발견은 쓰지 않는다.
- **실행 구분을 지킨다.** 발견과 결과마다 아래 중 하나를 적는다.
  - `[코드]` 코드만 읽고 판단
  - `[단위]` `npm test`·`test:backend` 같은 자동 테스트로 확인
  - `[미리보기]` 로컬 미리보기 모드 브라우저에서 직접 재현
  - `[배포-읽기]` 실제 사이트를 읽기만 해서 확인(쓰기 없음)
  - `[미실행]` 하지 못함. 이유를 적는다
  실행하지 않은 검사를 통과했다고 쓰지 않는다.
- **재현율을 적는다.** 같은 순서로 3번 해서 몇 번 나오는지(3/3, 1/3) 적는다. 1/3이면 '간헐'로 표시한다.
- 칭찬과 감상은 쓰지 않는다. 문제와 근거, 제안만 쓴다.

## 1. 서비스와 반드시 지켜야 할 규칙

마진은 대학원생(주 사용자)이 미팅·피드백·할 일·글쓰기·자료를 연구별로 모으고, 교수에게 검토를 요청하는 서비스다. 교수는 링크로 들어와 항목마다 **‘수정 내용 확인’** 또는 **‘추가 수정 필요’**(이유 댓글 필수)를 남긴다.

먼저 읽는다: 루트·앱 `AGENTS.md`, `docs/README.md`, `docs/product/user-flow.md`(특히 §14 공통 저장·취소·실패 처리), `docs/product/functional-specification.md`, `docs/design/README.md`·`patterns.md`·`ui-quality.md`·`ux-writing.md`, `CHANGELOG.md`의 Unreleased, 가장 최근 `docs/qa/*.md`.

아래 규칙을 어긴 것은 기능이 동작해도 **막힘**으로 본다.

1. 작업 완료 · 학생 반영 기록 · 교수 결과 · 댓글 해결 · 읽음은 서로 다른 기록이다. 하나를 바꿨는데 다른 것이 같이 바뀌면 안 된다.
2. ‘추가 수정 필요’는 이유 댓글 없이 저장되면 안 된다.
3. 보낸 설명·파일·응답은 보존한다. 재확인은 그 항목의 새 회차로 생기고, 이전 회차를 덮어쓰지 않는다.
4. AI(연구 도우미)는 사용자가 고른 원문에만, 사용자가 실행할 때만 쓴다. 미채택 후보와 개인 대화는 비공개다. Gemini 키는 일부러 비워 두었다. **가짜 결과·모델 이름·진행률·사용량이 보이면 막힘이다.**
5. 교수용 ‘여러 학생 대시보드’는 없다. 교수 화면의 ‘남은 n개’ 같은 표시는 그 검토 요청 안에서만 센다.
6. 자동 영구 삭제는 없다. 완전 삭제는 소유자이고, 휴지통 상태이며, 연구 이름을 정확히 입력했을 때만 서버에서 처리된다.
7. 가입은 체험만 제공하고 실제 계정·메일을 발급한 것처럼 보이면 안 된다. 결제는 연결되지 않았다(Free ₩0, Pro·Team은 출시 예정).
8. 녹음 원문 전사와 수정본은 분리한다. 음성을 공유해도 비공개 전사문이 공개되면 안 된다.
9. 로그인 후 화면에는 구름·유리(blur)·굴절 효과가 없다. 소개 화면의 Cloud Shader는 유지한다.
10. 문구는 해요체다. `ux-writing.md`의 용어표와 상태 구분(선택≠완료, 링크 생성≠전송, 수정 내용 확인≠승인, 저장≠버전)을 따른다.
11. 시각 값은 Wanted Montage 4.2.0 토큰·컴포넌트를 그대로 쓴다. WCAG 대비 수치는 기준에서 뺐다. 글자가 실제로 안 읽히는 수준만 문제로 적는다.

## 3. 준비

```bash
cd apps/home-preview
npm ci
VITE_SUPABASE_URL= VITE_SUPABASE_PUBLISHABLE_KEY= npm run dev -- --port 5174
```

- `/r`에서 첫 연구를 열어 연구 ID를 얻는다. 미리보기 연구 ID는 브라우저(프로필)마다 새로 생긴다.
- 테마는 쿠키 `margin-theme=light|dark|system` 하나로 정해진다. 첫 화면은 `public/theme-bootstrap.js`가 정한다.
- 회귀 캡처: `node scripts/qa/screens.mjs capture --widths 360,390,768,1024,1440 --themes light,dark`. 비교는 `compare 이전/results.json 이후/results.json`. 화면 목록은 `scripts/qa/routes.mjs`에 있다(`/schedule/:pollId`, `/privacy`, 404는 목록에 없으니 따로 본다).
- Playwright가 없으면 위 스크립트(의존성 없음, 설치된 Chrome 사용)와 브라우저 도구를 쓴다. 저장소에 새 패키지를 추가하지 않는다.
- 새 패키지 설치 뒤 "Invalid hook call"이 나면 Vite 캐시 문제다. 개발 서버를 `--force`로 다시 켠다.
- 기본 검사부터 돌리고 결과를 적는다: `npm run typecheck && npm run format:check && npm test && npm run test:backend && npm run build:sites && npm run test:sites && npm run build`

## 4. 테스트 범위

**화면**
- 공개: `/`, `/features`, `/pricing`, `/guide`, `/privacy`, `/login`, `/signup`, 없는 주소(404)
- 연구 목록·계정: `/r`, `/account`(프로필·화면 설정·알림·AI 기본 설정·사용량·플랜 탭)
- 연구 안 `/r/:id`: 홈, `planning`(로드맵·캘린더·시간 조율), `meetings(/:id)`, `writing(/:id)`, `feedback(/:id)`, `results(/:id)`, `tasks(/:id)`, `materials(/:id)`, `reviews`, `assistant`, `settings`
- 교수: `/reviews/:requestId`(항목·회차 쿼리 `?item=&round=`), `/schedule/:pollId`
- 전역: ⌘K 팔레트, `?` 단축키 도움말, G+글자 이동, 알림 판, 저장 전 이동 경고

**조건**
- 너비 360 · 390 · 768 · 1024 · 1440, 테마 라이트 · 다크 · 시스템
- 입력: 마우스 · 키보드만 · 터치(모바일 에뮬레이션)
- 동작 줄이기(`prefers-reduced-motion: reduce`) 켬·끔
- 브라우저: Chrome 기본. Safari(WebKit)·Firefox는 가능하면 공개 화면과 핵심 흐름만. 못 하면 `[미실행]`

## 5. 기능 테스트 (해피패스 기준선)

먼저 정상 흐름이 되는지 확인한다. 네거티브 테스트의 기준점이다. 각 단계에서 **가는 길과 돌아오는 길**을 함께 본다.

1. 연구 만들기 → 홈
2. 미팅 만들기 → 준비(질문·자료) → 기록(메모 자동 저장) → 결정 → 결정에서 할 일 만들기
3. 할 일 완료 → 6초 안에 되돌리기 → 다시 완료
4. 피드백 → 수정 방법 → 수정 결과
5. 글쓰기 문서 만들기 → 버전 저장 → 버전 비교(바뀐 부분·밀어서 비교) → 검토용 PDF → 자료 등록 → 수정 결과 작성
6. 검토 요청 만들기 → 공개 미리보기 → 링크 생성(전송 아님을 확인)
7. 교수 화면: 항목별 ‘수정 내용 확인’ / ‘추가 수정 필요’ + 댓글 → 다음 항목 → 끝 안내
8. 학생: 교수 결과 확인 → 수정 결과로 이동 → 재확인 요청(새 회차)
9. 일정 조율: 후보 시간 → 응답 링크 → 확정 → 미팅이 하나만 생김
10. 자료: 업로드 → 미리보기 → 새 버전 → 이전 버전 보존
11. 연구 도우미: 원문 선택 → 키 없음 상태 안내(가짜 결과 없음)
12. 설정: 공동연구자 초대 → 공유 중단 → 휴지통 이동 → 복원 → 완전 삭제(연구 이름 입력)
13. ⌘K로 찾기·만들기, G 단축키, `?` 도움말, 상세에서 ←가 출발한 곳으로 돌아가는지

## 6. 네거티브 테스트

각 사례에서 **기대 동작**은 `user-flow.md` §14를 기준으로 한다.
- 저장하지 않고 해당 입력 옆에 글자로 안내한다.
- 입력과 마지막 저장 값을 유지한다.
- 실패를 성공으로 표시하지 않는다.
- 같은 기록을 여러 개 만들지 않는다.
- 대상 없음 · 검색 결과 없음 · 불러오기 실패 · 접근 불가를 서로 다르게 보여 준다.

### 6.1 입력값

모든 입력 칸(제목, 설명, 메모, 댓글, 이메일, 비밀번호, 날짜·시간, 검색)에 대해 해 본다.

| 묶음 | 넣어 볼 값 |
|---|---|
| 비어 있음 | 빈칸, 공백만, 줄바꿈만, 전각 공백(`　`), 제로폭 문자(`​`)만 |
| 길이 경계 | 코드의 `maxLength`가 40·120·160·180·200·300·2000·3000·10000·100000이다. 칸마다 **한계−1, 한계, 한계+1**을 타이핑으로 한 번, 붙여넣기로 한 번 넣는다. 잘림이 조용히 일어나는지, 안내가 있는지, 서버가 다른 한계를 가졌는지(`[코드]`로 대조) 본다 |
| 한국어 | 조합 중인 글자(ㄱ, 가ㅎ), 자모만(ㅋㅋㅋ), 옛한글·NFD로 분해된 문자열, 아주 긴 한 단어(띄어쓰기 없는 200자) |
| 특수 문자 | 이모지(👩‍🔬 같은 결합형), 오른쪽에서 왼쪽 쓰기 글자, `<b>굵게</b>`, `<img src onerror=alert(1)>`, `{{7*7}}`, `'; --`, 마크다운(`# 제목`, `[링크](javascript:alert(1))`). **글자 그대로 보이고 아무것도 실행되지 않아야 한다** |
| 이메일 | 형식 틀림(`a@`, `a@b`, 공백 포함), 대소문자만 다른 같은 주소, 자기 자신 초대, 이미 초대한 사람 다시 초대 |
| 비밀번호 | 7자(거부), 8자(통과), 공백만 8자, 현재 비밀번호와 같은 새 비밀번호, 확인 칸 불일치 |
| 날짜·시간 | 과거 날짜, 2월 29일·31일 없는 달, 시작 > 끝, 자정(00:00·24:00), 연말→연초, 아주 먼 미래(9999년), 직접 타이핑한 잘못된 형식 |
| 검색·⌘K | 결과 없음, 초성만(ㅁㅌ), 특수 문자만, 200자, 검색 중 결과 데이터가 바뀜 |

### 6.2 한글 조합(IME)

- 조합 중 Enter: 질문 추가, 댓글 보내기, 선택 상자, ⌘K 실행, 할 일 추가가 **실행되지 않아야** 한다. 조합이 끝난 뒤의 Enter는 실행돼야 한다.
- 조합 중 Esc, 조합 중 다른 칸 클릭, 조합 중 저장 단축키(⌘S), 조합 중 G 단축키
- 미팅 메모: 조합 중 자동 저장이 글자를 깨뜨리거나 늦게 온 저장 응답이 최신 글을 덮지 않는지
- 확인 방법: `tests/ime.test.tsx`·`tests/controls.test.tsx`에 있는 사례와 실제 브라우저(macOS 한글 입력기) 결과를 따로 적는다

### 6.3 파일 업로드

대상: 자료(PDF 20MB 이하), 빠른 PDF 올리기, 연구 도우미 첨부(`.pdf .txt .md`), 공통 업로드(50MB 이하).

- 0바이트 파일, 19.9MB · 20.0MB · 20.1MB, 49.9MB · 50.1MB
- 확장자만 `.pdf`인 이미지·텍스트, 손상된 PDF, 암호 걸린 PDF, 1,000쪽 PDF, 가로가 매우 긴 PDF
- 파일 이름: 한글·공백·이모지·200자·`../`·같은 이름 두 번
- 같은 파일 연속 두 번, 업로드 중 다른 화면으로 이동, 업로드 중 새로고침, 드래그하다 놓지 않고 취소, 여러 파일 한 번에(허용되지 않으면 안내)
- 허용되지 않는 형식(`.docx`, `.exe`, `.zip`)
- 녹음: 2시간·50MB 한도와 32kbps 설정은 `[코드]`·`[단위]`로만 확인한다(마이크 금지)

### 6.4 상태·동시성·네트워크

- **중복 제출**: 저장·만들기·보내기·초대·검토 요청 버튼을 빠르게 두 번 누르기, Enter 연타. 기록이 하나만 생겨야 한다
- **저장 중 이동**: 저장 중에 다른 메뉴·뒤로가기·새로고침·탭 닫기. 저장 전 이동 경고(‘계속 편집’·‘버리고 이동’)가 맞게 뜨고, 닫으면 포커스가 누른 곳으로 돌아오는지
- **두 탭**: 같은 문서·할 일·설정을 두 탭에서 고치기. 덮어쓰지 않고 충돌을 알려야 한다(서버 규칙은 `test:backend`의 낙관적 잠금 테스트로 대조)
- **되돌리기**: 할 일 완료 뒤 5.9초·6.1초에 되돌리기, 되돌리기 전에 다른 할 일 완료, 되돌리기 중 화면 이동
- **브라우저 이동**: 뒤로·앞으로 반복, 대화상자가 열린 채 뒤로가기, 탭·보기 전환 상태가 주소에 남는지(`?tab=`)
- **오프라인·느린 연결**: DevTools Offline·Slow 3G로 공개 화면과 미리보기 앱을 연다. 글꼴·PDF 작업자·청크 로딩 실패 화면을 본다
- **저장소 문제**: 미리보기 데이터(IndexedDB)를 지운 뒤 열기, 사생활 보호 창(IndexedDB 막힘), 쿠키 차단, `margin-theme`에 이상한 값(`sepia`) 넣기
- **세션 만료·서버 오류(401·403·409·500)**: 미리보기 모드에는 서버가 없다. 오류 문구 변환(`src/lib/server-messages.ts`)과 화면 처리를 `[코드]`·`[단위]`로 확인하고, 실제 응답은 `[미실행]`으로 둔다

### 6.5 주소와 이동

- 없는 연구 ID, UUID 형식이 아닌 ID, 다른 사람의 연구 ID(미리보기에서는 다른 브라우저 프로필의 ID)
- 없는 상세 ID(`/r/:id/meetings/없음`), 지운 항목의 옛 주소, 휴지통에 있는 연구의 주소
- 쿼리 조작: `?tab=없는값`, `?item=`·`?round=` 비우기·다른 요청의 값·형식 틀림, `?new=1`을 두 번
- 교수 링크: 잘못된 요청 ID, 공유 중단된 링크, 항목이 하나뿐인 요청, 이미 모든 항목에 응답한 요청
- 일정 조율 링크: 없는 poll ID, 이미 확정된 poll, 같은 사람이 두 번 응답
- 직접 주소 진입과 새로고침(Pages `_redirects`): `/r/...`, `/reviews/...`, `/schedule/...`가 소개 화면으로 튕기지 않는지 → `[배포-읽기]`로 응답 코드와 첫 화면만
- 로그인하지 않고 `/r`, `/account`에 들어가기 → 로그인 안내. 로그인한 상태에서 `/login`, `/signup`에 들어가기

### 6.6 권한 (누가 무엇을 보고 바꿀 수 있나)

역할 5개 × 동작 매트릭스를 만든다. 역할은 익명, 다른 학생, 공동연구자(편집·보기), 교수(지정된 검토만), 소유자다. 동작은 읽기·쓰기·파일 열기·다운로드·댓글·응답·삭제·공유 변경이다.

- 칸마다 `test:backend`의 어느 테스트가 지키는지 적는다. 예: "only designated professor can respond…", "trash blocks collaborator and professor…", "shared audio never grants transcript access…", "permanent deletion requires owner, trash state, and exact name"
- 테스트가 없는 칸은 **빈칸**으로 표시하고, 추가할 PGlite 테스트를 이름과 순서로 제안한다
- 화면 쪽: 권한이 없을 때 '접근할 수 없어요'와 '없어요'가 구분되는지, 버튼이 숨는지 아니면 눌러도 거부되는지(둘 다 서버가 막는지)
- 실제 계정으로 하는 확인은 내가 테스트 계정을 줄 때만 한다. 그 전에는 `[미실행]`

### 6.7 상태 분리와 기록 보존 (불변 조건)

- 할 일 완료 ↔ 피드백 처리 상태 ↔ 교수 결과 ↔ 댓글 해결 ↔ 읽음: 하나씩 바꾸며 다른 넷이 그대로인지 표로 기록한다
- ‘추가 수정 필요’를 댓글 없이 · 공백 댓글로 · 댓글 쓰다 지우고 저장하기
- 교수가 결과를 ‘확인’ → ‘추가 수정 필요’로 바꿀 때 이전 응답과 작성자가 이력에 남는지
- 재확인 요청 → 새 회차 생김, 이전 회차의 파일·설명·응답이 그대로인지
- 공유 중단 → 이후 교수 읽기 거부, 이미 남긴 결과는 학생 쪽에 보존
- 미채택 AI 후보와 개인 메모가 교수·공동연구자 화면에 나오지 않는지

### 6.8 AI·가입·결제 표시

- 연구 도우미: 원문 선택 없이 실행 시도, 키 없음 상태 문구, 사용량 화면에 지어낸 숫자가 없는지, '생성 중' 표시가 실제 작업 없이 돌지 않는지
- 가입: 체험이라는 안내, 실제 계정·메일 발급처럼 보이는 문구가 없는지
- 플랜: Pro·Team 버튼이 결제로 이어지지 않고 '출시 예정'인지

### 6.9 삭제·휴지통

- 휴지통 이동 → 목록·⌘K·주간 띠·알림에서 사라지는지, 직접 주소로는 어떻게 보이는지
- 복원 → 공유는 계속 중단 상태인지, 연결(자료 ↔ 기록)이 돌아오는지
- 완전 삭제: 연구 이름 오타 · 앞뒤 공백 · 대소문자만 다름 · 붙여넣기 · 휴지통이 아닌 상태에서 시도 · 소유자가 아닌 사람이 시도
- '삭제'라는 버튼이 실제로는 휴지통으로 옮기는 곳이 문구와 맞는지

### 6.10 대량·극단 데이터

- 아무것도 없는 연구: 모든 화면의 빈 상태, 빈 상태에서 다음 행동 버튼이 있는지
- 많은 데이터: 할 일 300개, 미팅 100개, 자료 버전 50개, 댓글 200개, 제목 200자, 메모 10만 자. 스크롤·성능·잘림·⌘K 속도
- 시간: 오늘 자정 직전·직후 마감, 기한 지난 할 일, 다음 해로 넘어가는 주간 띠, 시스템 시간대 변경(UTC·뉴욕)

### 6.11 키보드·포커스

- Tab 순서가 화면 순서와 같은지, 포커스 표시가 보이는지, ‘본문으로 이동’ 링크
- 대화상자·옆 판·메뉴: 열면 안으로, Esc로 닫힘, 닫으면 연 버튼으로 복귀, 상태로 연 대화상자도 같은지
- G 단축키와 `?`가 입력 칸·편집기 안에서는 먹지 않는지, ⌘K가 대화상자 위에서 어떻게 되는지
- 키보드만으로 5절 핵심 흐름 1~8을 끝까지 할 수 있는지

### 6.12 가벼운 보안 표면 (읽기만)

- 실제 사이트 응답 헤더: CSP(`script-src 'self'`), `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`(마이크는 self만)
- 번들·소스맵에 비밀값 패턴(`service_role`, `sk-`, `AIza`, 개인 이메일)이 없는지. `scripts/check_git_hygiene.py`도 돌린다
- 브라우저 저장소(쿠키·localStorage·IndexedDB)에 비밀번호·토큰 외 개인정보가 평문으로 남는지
- 외부 링크에 `rel="noopener"`가 있는지, 앱이 예상 밖의 외부 주소로 요청하는지(네트워크 목록)
- 콘솔 오류·경고 0개인지(화면 × 테마 × 너비)

## 7. 디자인 QA

기준은 `docs/design/patterns.md`(색 역할·화면 머리·움직임)와 `ui-quality.md`(줄바꿈·확인 범위)다. 화면 × 너비 × 테마마다 캡처하고 아래를 본다.

### 7.1 색 역할

- 주 행동은 공개 화면·앱·라이트·다크 어디서나 Montage `Button` solid primary 하나. 파란 브랜드 면 위에서만 흰 버튼
- 선택·현재 위치는 `--selected-fill` + 브랜드 글자 한 가지 모양. 호버와 구분되는지
- 학생 상태는 `ContentBadge` 채움(초록 완료·주황 보류·빨강 오류·회색 시작 전). 교수 결과는 **테두리** 배지 + 고정 아이콘 + 문구. 둘이 같은 모양이면 막힘(불변 조건 1)
- 달력·주간 띠 점·막대: 미팅=브랜드, 마감=주황, 단계 목표=보라, 주요 목표=초록
- 반전(inverse) 면은 툴팁에만. 알림·켜짐·주 행동에 쓰였으면 다크에서 확인
- 화면마다 강조색 개수를 센다. 한 화면 머리에 solid primary가 2개 이상이면 기록

### 7.2 라이트·다크 역할 일치

표로 만든다: 역할 / 라이트 계산값 / 다크 계산값 / 쓰는 곳 / 일치 여부. `getComputedStyle`로 같은 역할 요소(`scripts/qa/routes.mjs`의 `STYLE_PROBES`)를 모은다. `[data-theme="dark"]` 규칙은 하나씩 이유를 판정한다(지금 12개, 늘면 안 됨).

### 7.3 화면 머리

화면마다 머리 해부 표를 만든다: 뒤로 / 제목·상태 배지 / 설명 / 행동(주·보조·더보기) / 탭 / 도구 줄 / 첫 내용까지 높이(390px에서 첫 화면 안인지).
- 순서가 표준(`뒤로 → 제목·배지·행동 → 설명 → 탭 → 도구 줄`)과 다른 곳
- 탭과 보기 전환을 뒤바꿔 쓴 곳(탭=다른 내용 묶음, 보기 전환=같은 내용 다르게 보기)
- 넘치는 탭·보기 전환에 끝 흐림 표시가 있는지

### 7.4 글자·간격·정렬

- 글자 위계 6단계(화면 제목·구역 제목·카드 제목·본문·보조·메타)만 쓰는지. 읽어야 하는 내용이 보조·메타색인 곳
- 10~11px 글자(장식 미리보기 외), 토큰 밖 `font-size`·모서리·간격
- 왼쪽 정렬선 개수, 카드 안 여백, 아이콘과 글자 기준선, 숫자 열 오른쪽 정렬·고정폭 숫자
- 카드 모서리 크기 규칙(어디에 몇 px)

### 7.5 한국어 줄바꿈과 잘림

- 마지막 줄 외톨이 글자, 단어 중간 끊김(‘연/구’), 숫자와 단위 분리(‘3/개’, ‘20/MB’)
- 버튼·탭·배지·칩이 두 줄로 꺾임, 높이가 들쭉날쭉한 줄
- `nowrap`·`line-clamp`·말줄임으로 **중요한 내용**이 숨음(파일명 버전 `_v2`/`_v3`, 회차, 날짜)
- 긴 제목·파일명·URL·댓글이 영역 밖으로 나감, 가로 스크롤
- 원인을 컨테이너 너비 / 줄바꿈 규칙 / 배치 / 문구 길이로 분류한다. 글꼴 축소는 마지막 수단으로만 제안한다

### 7.6 상태별 모양

모든 주요 부품(버튼, 입력, 선택 상자, 탭, 카드, 목록 행, 배지, 알림, 대화상자)에 대해 기본·호버·누름·포커스·선택·비활성·로딩·오류·빈 상태·긴 내용을 본다. 빠진 상태와 테마마다 다른 상태를 기록한다.

### 7.7 움직임

- 시간은 3단계 토큰(미세 120ms · 부품 200/160ms · 화면 300ms)만 쓰는지. 곡선은 `cubic-bezier(0.2,0,0,1)`과 퇴장용 `cubic-bezier(0.3,0,1,1)`만 쓰는지
- 동작 줄이기에서 높이·위치 움직임이 멈추는지(할 일 접힘, 목록 들고 남, 숫자 굴러가기, 소개 장면)
- 로그인 후 장식 반복 애니메이션이 없는지, 일부러 늦추는 순차 등장이 없는지

### 7.8 브랜드와 문구

- 공개 화면 ↔ 가입 ↔ 앱의 로고 크기, 마스코트 쓰임(AI·안내에만, 교수 승인 표현 금지), 아이콘 세트 섞임
- 같은 행동을 다른 말로 부르는 곳, 합니다체·번역투·피동, 금지 용어(승인·반려·채택·스냅샷), 알림 마침표 규칙, 날짜 표기
- 오류 문구가 원인과 다음 행동을 말하는지, 영문 필드 키·서버 원문이 보이는지

## 8. 결과 양식

발견 하나마다 이 양식을 쓴다. ID는 `FUNC-`(기능), `NEG-`(네거티브), `PERM-`(권한), `DQA-`(디자인), `COPY-`(문구)로 시작한다.

```
### [NEG-012] 제목 (한 문장, 사용자에게 무슨 일이 생기는지)
- 위치: 화면 · 너비 · 테마 · 브라우저 / 파일:줄
- 심각도: 막힘 | 높음 | 보통 | 낮음
- 실행 구분: [미리보기] 3/3
- 재현 순서:
  1. …
  2. …
- 기대: (user-flow §14·불변 조건·patterns.md 중 근거 명시)
- 실제: 보이는 그대로. 화면 문구는 그대로 인용
- 증거: 스크린샷 파일명, 콘솔 로그, 네트워크 기록
- 원인(확인한 경우): 파일:줄과 이유. 추측이면 [추측]
- 제안: Montage 부품·토큰 이름, 또는 추가할 테스트 이름
- 비용: 작음 | 중간 | 큼
- 같은 문제가 있는 다른 곳
```

**심각도 기준**
- **막힘**: 핵심 흐름을 끝낼 수 없음, 데이터 손실·덮어쓰기, 권한 밖 읽기·쓰기, 1절 불변 조건 위반, 가짜 AI 표시, 글자가 안 읽혀 행동할 수 없음
- **높음**: 잘못된 입력이 저장됨, 실패를 성공으로 표시, 중복 기록 생성, 중요한 내용이 숨음, 막다른 길
- **보통**: 우회 가능한 오류, 안내 부족, 디자인 규칙 위반(색 역할·머리·줄바꿈)
- **낮음**: 다듬기 수준의 시각·문구 문제

`docs/qa/YYYY-MM-DD-qa.md` 한 파일로 쓴다. 캡처 원본은 커밋하지 않고 대표 몇 장만 `docs/qa/YYYY-MM-DD-qa/shots/`에 둔다. 보고서는 승인 뒤 PR로 올린다.

3. **추이**(주간 모드): 지난주 대비 새 발견 · 닫힌 발견 · 여전한 발견 수, 7.9 기준선 변화
4. **권한 매트릭스**: 역할 × 동작, 칸마다 지키는 테스트 또는 '빈칸'
5. **발견 목록**: 8절 양식, 심각도순
6. **결정 질문**: 선택지 2~3개와 권장안
7. **수정 묶음 제안**: 묶음 하나가 PR 하나. 막힘·높음 → 규칙 정하기(색 역할·머리·움직임) → 나머지 순서. 묶음마다 추가할 자동 테스트(단위·PGlite·회귀 캡처)를 함께 적는다
8. **추가할 테스트 목록**: 이번에 손으로 찾은 것 중 자동 테스트로 굳힐 것

- 막힘·높음 0개

## 11. 승인 뒤 수정 단계 규칙

- `main`에 직접 커밋하지 않는다. 목적별 브랜치와 PR을 쓰고, 병합은 squash로 한다. 강제 push와 이력 재작성은 하지 않는다.
- PR마다 7종 검사를 돌린다: `npm run typecheck && npm run format:check && npm test && npm run test:backend && npm run build:sites && npm run test:sites && npm run build`
- 고친 버그에는 다시 생기지 않게 하는 테스트를 함께 넣는다(단위·PGlite·IME 등).
- 바꾼 화면은 `screens.mjs` 전후 비교 결과를 PR에 붙인다.
- 사용자에게 보이는 변경은 `CHANGELOG.md` Unreleased에 적는다.
- PR 본문에 코드 검사 · 실제 브라우저 확인 · 배포 확인을 나눠 쓴다.
- DB 마이그레이션은 추가만 한다. 이미 적용된 파일은 수정하지 않는다.
- 비밀값·실제 연구 자료·테스트 계정 비밀번호는 커밋하지 않는다.
