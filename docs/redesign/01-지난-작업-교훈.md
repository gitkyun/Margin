# 지난 작업에서 잘못된 것 (2026-11-24~27)

> 다음 AI가 같은 실수를 하지 않게 남깁니다. 근거 경로는 `re-evaluation/` 기준입니다. 각 항목은 지난 검수 문서가 적은 내용이며, 이번 정리에서 모두 다시 재현하지는 않았습니다.

## 1. 방향을 잘못 잡았다 — 가장 큰 실수

- 사용자는 "쓰기 쉬운 제품으로 크게 바꾸기"를 원했는데, 우리는 지금 화면을 전제로 결함을 찾고 판정표(142화면)·비교표(108항목)를 만들었다. 화면 구조 자체가 문제라는 가능성을 묻지 않았다.
- **교훈**: 시작할 때 "실제로 쓸 때 어디서 막히나요?"를 먼저 묻는다. 결과는 표가 아니라 실제 크기 화면(지금 / 바뀐 뒤)으로 보여 준다. 사용자는 긴 문서·표보다 화면을 보고 말로 정하는 것을 원한다.

## 2. 결정을 결함으로 분류했다

- 사용자가 이미 정한 7가지(토스증권 골조, 패널 기본 열림, 라이브러리 섞어 쓰기, 교수 편집자 겸임, 슬라이더 확인, 메일 의견, 스크롤바 자리)를 결함으로 올렸다 (`06-independent-review.md` 0절).
- **교훈**: 결정 원장(`v2-2026-11-25-corrected/07-decision-ledger.md`)과 AGENTS.md를 먼저 읽고, 결정과 어긋나는 것은 "결함"이 아니라 "다시 물어볼 결정"으로 적는다.

## 3. AI 제안을 확정처럼 썼다

- 개선 초안이 '검토'를 '확정'으로 올리고, AI가 낸 해법('6초', '호버 시 잔여량' 등)을 '절대 준수' 전제에 넣었다. 지시 없이 다음 단계를 시작했다 (`2026-11-26_Phase1-4_전수검사_v1/`).
- 'Google 모델만', '토스 홈 기준'이 출처 없이 결정처럼 적혔다(뒤에 사용자가 승인).
- 보강 단계에서 PUB-01 제안을 확정으로 표시했다 (`2026-11-26_Phase5_보강_v1/보고/검수_수정_보고.md`).
- **교훈**: 모든 항목에 `확정(누가 언제)` / `제안` / `확인 필요`를 붙인다. 확정은 사용자 말이 있을 때만.

## 4. 근거가 틀렸다

- 인용한 코드 경로 약 50개 중 22개가 없는 경로였다 (`06-independent-review.md` 1-4절).
- 캡처 이름·설명과 실제 내용이 다른 것 15건, 문서 설명이 사진과 다른 곳 26건, 같은 파일을 두 장면으로 쓴 것 2쌍 (`2026-11-26_Phase1-4_정리_v1/캡처_설명_정정표.md`).
- 증거 수량을 154개로 적었으나 실제 PNG 200장. 벤치마크 수도 문서마다 달랐다.
- 원인 진단이 거꾸로 된 항목(RC-3, RC-6 등)과, 눈으로 본 인상을 '확인된 사실'로 적은 문서(`08-micro-detail-audit.md`)가 있었다.
- **교훈**: 경로·줄 번호는 적기 전에 열어 본다. 캡처를 인용할 때는 사진을 직접 본다. 수는 세어서 적는다. 심각도에는 기준을 같이 적는다.

## 5. 참고 서비스를 잘못 읽었다

- 토스증권 활성 탭 모양, 라이너의 레일·모드 칩을 사실과 다르게 적었다 (`06-independent-review.md` 5-1절).
- **교훈**: 참고 서비스는 "무엇을 왜 가져오는지" 한 줄로 적고, 모양을 단정하기 전에 캡처를 다시 본다.

## 6. 보기 어려운 결과물

- 비교 페이지·판정표가 너무 촘촘해서 사용자가 "이해가 하나도 안 된다"고 했다(2026-11-26).
- 반대로 '쉬운보기'(지금 / 바뀐 뒤 버튼 + 실제 크기 화면 + 아래 설명 몇 줄)는 "보기 좋다"고 했다(2026-11-27).
- **교훈**: 사용자에게 보여 줄 결과물은 쉬운보기 형식을 기본으로 한다.

## 7. 개인정보

- 참고 서비스 캡처(라이너·매니패스트·모듈리파이·오픈서베이·토스증권 등)에 실명·소속·학교 이메일·접속 IP가 찍혀 있었다 (`캡처_설명_정정표.md` 3절). 저장소 주인이 이 저장소에는 그대로 올리기로 정했다(2026-11-27). 저장소 밖으로는 옮기지 않는다.
