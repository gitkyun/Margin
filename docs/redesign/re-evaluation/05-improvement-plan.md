## 2. 핵심 쟁점 대안 A vs 대안 B 트레이드오프 비교

### 쟁점 1. [RC-1 / D1 재검토] 겸임 교수(지정 교수 + 편집자)의 검토 화면 및 연구 권한 경계
| 항목 | 대안 A (권고): 수신자 우선 잠금 + 역할 단일 판정 함수 | 대안 B: 상단 역할 전환 스위치(‘교수 보기 / 편집자 보기’) |
|---|---|---|
| **동작 방식** | 검토 요청의 `professorEmail === me`이면 클라이언트·서버(`rms_set_sharing`, `rms_recheck`) 모두 **‘교수 수신 모드’만 허용**(발신 UI·이메일 변경·재확인 차단). 미담당 할 일(`!assigneeId`)은 소유자(학생)에게만 `내 할 일`로 노출. | 기본은 교수 수신 모드로 열되, 상단 토글로 편집자 모드 전환 허용. |
| **장점** | 자기에게 온 검토의 교수 이메일을 바꾸거나 학생 대신 재확인 차수를 만드는 권한 사고를 서버 단계에서 원천 차단. UI 단순. | 공동연구 겸임 교수가 정말 학생 대신 공유 설정을 고쳐야 할 예외 상황에 대응 가능. |
| **단점 / 위험** | 겸임 교수가 검토 공유 설정을 직접 수정해야 할 때는 학생 소유자에게 요청해야 함. | 토글 자체가 인지 부담이며, 서버 보안 경계가 느슨해짐. |
| **권고 이유** | 학술 지도에서 검토의 ‘보내는 사람’과 ‘받는 사람’이 섞이면 신뢰가 깨진다. **대안 A**가 제품 불변 조건과 가장 잘 맞는다. | — |

### 쟁점 2. [RC-2 / AGENTS.md:21 재검토] 완전 삭제 이름 입력 전환 방식
| 항목 | 대안 A (권고): 영향 요약 + 연구명 입력(NFC/NFD·trim 정규화) + 복사 버튼 | 대안 B: 영향 요약 + 연구명 직접 타이핑(복사 버튼 없음) |
|---|---|---|
| **동작 방식** | 삭제 모달에 **“미팅 n건 · 원고 n건 · PDF n개가 영구 삭제됩니다”** 요약 표시 → 연구명 입력(서버 실제 대조 + `trim` + 한글 NFC 정규화). 연구명 옆에 복사 버튼 제공. | 복사 버튼 없이 긴 연구명을 처음부터 끝까지 직접 타이핑. |
| **장점** | `AGENTS.md:21`을 ‘슬라이드’에서 ‘영향 요약 + 이름 확인’으로 갱신하면서, 40자 긴 연구명의 오타·한글 자소 분리(NFD) 스트레스를 해소. | 마찰이 최대치라 무의식적 삭제 가능성이 극소화됨. |
| **단점 / 위험** | 복사-붙여넣기가 너무 쉬워 습관적으로 통과할 우려가 소폭 있음. | 30~40자 한국어 논문 제목을 오타 없이 치는 피로가 매우 크고, 실수 방지보다 짜증이 커짐. |
| **권고 이유** | 위험 요약 숫자를 눈으로 확인시키고, 복사 버튼 + 서버 실제 검증을 결합한 **대안 A**가 안전과 사용성의 균형이 가장 좋다. | — |

### 쟁점 3. [RC-4 / RC-7 / D17 유지] 홈 화면 역할 & 사이드 패널 중복 해소
| 항목 | 대안 A (권고): 라우트별 패널 중복 방지 + 홈 ‘연구 시계’ & 첫 묶음 소제목 | 대안 B: 홈에서 하단 `할 일` 탭을 완전히 제거하고 로드맵 전용화 |
|---|---|---|
| **동작 방식** | D17(1440px 기본 열림)은 유지하되, **홈 진입 시 기본 패널을 `도우미`로 자동 전환**해 홈 `할 일`과 중복을 제거한다. 홈 할 일 첫 묶음에 **`다음 미팅에 가져갈 할 일`** 소제목을 붙여 정렬 이유를 드러낸다. `/reviews/:id` 진입 시에는 패널 자동 접힘. | 홈 하단 `할 일`을 없애고 `/flow` 로드맵을 홈으로 끌어올림. |
| **장점** | D17 결정을 지키면서도 홈↔패널 중복(P02-1)과 `/flow` 역할 중복을 동시에 방지. “오늘 할 일 + 다음 미팅 준비”가 한눈에 보임. | 홈이 거시적 로드맵 대시보드로 완전히 차별화됨. |
| **단점 / 위험** | 홈에서 `할 일`을 보면서 동시에 우측 `할 일` 패널을 열고 싶은 소수 패턴은 제한됨. | `/flow`와 기능이 겹치고, 홈에서 당장 할 일을 체크하는 학생의 최빈 동선이 +1클릭 늘어남. |
| **권고 이유** | **대안 A**가 D17 유지 전제와 학생의 미팅 준비 루프를 모두 살리면서 중복을 깔끔하게 제거한다. | — |

### 쟁점 4. [RC-5 / #12·#13] 연구 도우미 빈 상태 & `제안` 56건 적체 해소
| 항목 | 대안 A (권고): `제안`·`실행 내역` 탭 유지 + 56건 일괄 정리 + 맥락 우선 3카드 | 대안 B: `제안`·`실행 내역` 탭 삭제 후 대화 내 완전 통합 |
|---|---|---|
| **동작 방식** | `assistant-starters` 역전을 고쳐 **맥락 칩(최대 3) + 부족분 일반 예시 보충**으로 항상 3개 카드를 채우고 PDF/자료 분기를 추가한다. `제안` 탭은 유지하되 상단에 `선택 수락 / 오래된 제안 비우기` 일괄 트리아지 바를 추가하고, 대화 중 생성된 제안은 대화 안에도 인라인 카드로 표시. | `제안`·`실행 내역` 탭을 없애고 대화 스레드 안에서만 관리. |
| **장점** | 미팅 정리에서 생성된 연구 전체 AI 후보 승인함과 실행 취소·크레딧 추적 기능을 잃지 않으면서, 56건 적체와 홈 단일 칩 문제를 모두 해결. | 상단 탭 영역이 사라져 도우미 헤더가 극도로 단순해짐. |
| **단점 / 위험** | 상단 3탭 구조 자체는 남음. | 미팅 정리 제안·실행 취소·실행별 크레딧 추적 기능이 유실됨(독립 검수 #12 부작용 경고). |
| **권고 이유** | 기능 유실 없이 체감 문제를 정확히 푸는 **대안 A**를 권고한다. | — |

### 쟁점 5. [의견 수집 / #15 재검토] `mailto:` → 인앱 의견 수집
| 항목 | 대안 A (권고): 우측 레일 하단 `의견` → 우하단 플로팅 UT 팝오버 | 대안 B: 전체 화면 중앙 피드백 모달(매니패스트식) |
|---|---|---|
| **동작 방식** | 토스증권식 우하단 플로팅 팝오버(1~5점 만족도 + `불편해요 / 제안해요 / 오류예요` 칩 + 1줄 입력 + `[✓] 현재 화면 주소·창 크기 함께 보내기` 명시적 동의 체크박스). | 화면 중앙을 가리는 모달 + 제목/내용 장문 폼. |
| **장점** | 보고 있는 화면을 가리지 않고 10초 만에 의견을 남길 수 있으며, UT 메타 첨부 동의를 투명하게 받을 수 있음. | 상세한 버그 리포트 작성에 유리. |
| **권고 이유** | **대안 A**가 연구 작업 흐름을 끊지 않고 응답률을 최대화한다. | — |
