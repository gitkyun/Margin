## 라이브러리를 섞어도 한 제품처럼 보이게 할 기준

1. **같은 동작에는 같은 이름과 위계.** 저장, 링크 만들기, 전송, 공유 중지, 완전히 삭제는 결과가 각각 다르다. 버튼 순서·색·완료 문구와 복귀 위치를 그 결과에 맞춘다. 화면 모드도 같은 선택에는 같은 이름을 쓴다. 마진 문구 기준 (`../../../Margin-repo/docs/design/ux-writing.md`, 저장소에 없음) · [토스 공통 디자인 접근](https://toss.tech/article/toss-design-system)
2. **마진의 색과 글꼴을 공통으로.** 일반 폼·모달·시트·세그먼트는 Montage에 둔다. Kokonut 입력과 계정 메뉴는 도입 당시 정한 구조, 마진의 색·서체·문구, 실제 상태 연결을 차례로 비교한다. Coss 탭의 초점과 Montage 보기 전환의 선택도 각각 확인한다. 마진 디자인 기준 (`../../../Margin-repo/docs/design/README.md`, 저장소에 없음) · Kokonut 원본 매핑 (`../../../Margin-repo/docs/design/kokonut-map.md`, 저장소에 없음) · [설치판](캡처/installed-baseline-light.jpg)
3. **버튼을 누른 다음 장면까지 맞춘다.** AI 근거는 원본을 가리켜야 하고, 보관 뒤 되돌리기는 복원 범위를 알려야 한다. 확인창을 닫으면 원래 위치를 찾을 수 있어야 한다. 오류 뒤에는 입력과 선택을 확인하고 이어갈 수 있어야 한다. [권한과 복귀 재현](마진-재검증/checks.json)
4. **같은 가상 연구로 여러 화면을 비교한다.** 토스의 소개 흐름, 토스증권의 작업판, 라이너의 근거, 매니패스트의 선별 반영을 마진의 한 연구에 적용해 보면 버튼과 기록이 자연스럽게 이어지는지 확인할 수 있다. [이전 서비스 대조](../2026-11-25_5단계-전_화면수집_v2/README.md) · [라이브러리 대조](라이브러리-1대1.md)
