현재 저장한 결과는 조사·비교·재현이다. 아래 완료 기준은 후속 검토·설계·구현에 쓸 제안이다. 담당 작업이 정해지면 같은 기준 커밋에서 해당 장면을 먼저 연다.

## 앞에서 다룰 네 가지 작업

### 원고 저장·복원·충돌

- **재현** · v1을 남긴 뒤 제목과 본문 굵기만 바꿔 저장한다. v1을 복원하면 두 모드 모두 직전 상태가 이력에 빠진다. 체험에서 본문도 바꾸면 `v2·v2·v1`, 격리 연결에서는 `v3·v2·v1`이었다.
- **재현** · 서로 다른 본문의 원고 복원에서 마지막 버전 저장만 한 번 실패시킨다. 오류 화면에는 복원 직전 제목, 서버에는 과거 제목이 남았다. 새로고침 뒤 서버의 내용이 보였다. 이 시험에서 복원 직전 본문은 v2로 남았다.
- **재현** · 공유 원고의 본문 저장 응답을 늦추고 그 사이 `나만 보기`를 선택한다. 응답 직후 화면은 `나만 보기 · 저장됨`이었고 서버는 공유를 유지했다. 제목을 바꾸는 경우에도 응답 종료 조건을 함께 점검한다.
- **재현** · 학생과 공동연구자가 같은 공유 원고를 열고 학생이 먼저 저장한다. 다른 창에서 `내가 쓴 내용 유지`를 누른 직후에는 먼저 저장된 본문이 서버에 남는다. 로컬 편집창을 다시 저장하자 나중에 쓴 내용이 저장됐다.
- **조사 위치** · `WritingPage.tsx`의 `persist`, `restoreVersion`, 충돌 모달, `workspace.tsx`와 `CompareView.tsx`, `WordDiff.tsx`, `documentVersions` 저장 경로를 읽는다. 직전 이력 생략, 요청 응답의 변경 상태 정리, 번호 할당을 각각 확인한다. [증거와 소스 위치](03_증거와재현.md)
- **완료 기준** · 제목·구조·서식·본문을 포함한 직전 원고를 복원 이력에서 다시 열 수 있다. 같은 원고에서 번호가 겹치지 않는다. 복원 실패·응답 유실·재시도·두 창 작업의 결과가 새로고침 뒤 화면과 일치한다. 저장 중 새로 바꾼 값은 저장하거나 저장 대기임을 드러낸다. 충돌 시 현재 초안과 상대의 저장 상태, 다음 동작의 결과를 읽을 수 있다.

### 미팅 기록·할 일·피드백

- **재현** · 미팅 기록 탭의 `피드백·할 일`에서 새 할 일을 추가한다. 기록과 저장소에는 출처가 남는다. 전체 할 일 목록에서 `직접 추가`로 표시되고, 그 기록을 필터에서 고르면 빠진다.
- **재현** · 한 줄 목표만 저장한 다음 미팅이 홈에서 `아직 준비한 내용이 없어요`로 보인다. `다음` 배지와 `홈의 다음 미팅으로 지정`은 자동 선택과 수동 지정의 차이다.
- **코드 확인** · 홈·할 일·기록 패널에서 완료를 풀면 `진행 중`, 원고 여백과 항목 상세에서는 `시작 전`으로 가는 경로가 있다. 두 패널의 완료 되돌리기 시간이 겹쳤을 때 단축키 한 번이 두 항목을 바꾸는지는 별도 브라우저 재현이 필요하다.
- **조사 위치** · `RecordSide.tsx`의 직접 생성, `record-view.ts`의 기록 관계, `task-groups.ts`의 `taskSource`, `TasksHome.tsx`의 필터, `NextMeetingPreview.tsx`와 `HomePage.tsx`의 요약을 대조한다. 기록에서 생성한 일, 피드백에서 생성한 일, 기존 일을 다음 미팅에 가져가는 관계를 구별한다.
- **완료 기준** · 같은 할 일에서 보이는 출처, 필터 포함, 원문으로 가기와 돌아오기가 일치한다. 먼저 생성한 기록과 나중에 가져간 미팅을 사용자가 구분할 수 있다. 목표만 쓴 다음 미팅, 피드백이 있고 연결 할 일이 0건인 기록, 완료 직후 되돌리기와 새로고침을 각각 확인한다. 이미 저장된 연결값과 현재 열 수 있는 범위를 사용한다.

### 공통 화면과 버튼 상태

- **재현** · 피드백 행의 상태·연결 할 일 수는 목록 폭 1200px에서 숨고 672px에서 보였다. 320×680의 첫 할 일 행은 아래로 밀렸다. 홈 위에 모바일 도우미를 열면 같은 파란색 두 강조가 보였다.
- **기존 화면과 코드** · 기본 폭 상세 패널에서 현재 진행 단계명이 사라지고 161초 오디오 타임라인 눈금이 겹친다. 토스트는 오른쪽 레일에, 업로드 결과 트레이는 푸터에 겹친 사례가 있다.
- **완료 기준** · 320×680, 390×844, 820~960px 경계, 1440px과 1760px에서 같은 기능을 비교한다. 열린 레일과 실제 콘텐츠 폭을 별도로 기록한다. 기본·선택·비활성·저장 중·성공·실패·취소·되돌리기 및 라이트·다크를 확인한다. 탭, 열어 둔 보조 창, 모달에서의 초점·키보드 동선이 각각 드러난다.

### 교수 검토·연구 도우미

- **재현 기록** · 학생이 PDF가 연결된 두 항목을 공유하면 지정 교수가 응답하고 한 항목만 재확인할 수 있다. 새 차수는 다른 항목의 차수와 이전 교수 의견을 보존한다. 제3자, 일반 공동편집자, 겸임, 이전 교수, 새 지정 교수를 같은 링크로 비교했다.
- **남은 화면** · 편집자를 겸한 교수의 발신 가능 버튼과 이유, 공유 중지 뒤 링크의 재열기, 만료·다시 발급, 삭제 댓글의 답글과 모바일 PDF 핀 취소, 원고 새 버전의 문장 위치, 실제 외부 초대·알림 전달. 링크 생성과 실제 전송은 따로 시험한다.
- **AI** · 일반 질문, 첨부 PDF, 웹 검색, 기록 정리, 제안 선택·저장, 취소와 대기열을 나눠 본다. 실제 24시간 횟수 제한은 사라졌고, 월 크레딧과 분당 6회 제한을 사용하는 코드가 있다. 모델 4개의 공식 이름은 확인됐고 이 검수 묶음에서의 운영 호출 증거는 앞선 Flash 실험을 이용한다. 75 사용·36 예약은 특정 시각의 과거 화면이다.
- **완료 기준** · 누구에게 보낼지, 어떤 항목·파일·인용을 쓰는지 실행 전에 확인한다. 닫기, 재전송, 복구 뒤 보고 있던 항목이나 원문으로 돌아간다. 사용량·실행 내역에는 성공·실패·진행·취소의 포함 기준과 예약·확정 차감 차이가 보인다. 원문의 현재 접근·삭제·수정 상태를 확인하고 예전 대화·제안은 보존한다. [이전 실험과 1:1 대조](../2026-11-25_5단계-전_화면수집_v2/README.md) · [역할별 재검증](../2026-11-25_5단계-전_라이브러리-기본값_v3/README.md)

## 09의 24개 항목과 후속 확인

각 행은 09 원문 번호를 따른다. 원문 화면 링크와 근거는 [교차 검토 본문](../2026-11-26_09-교차검토_v1/README.md#09-원문-24개-항목)에서 연다.

| 번호 | 최신 판정 | 후속 확인 |
|---|---|---|
| 1 | 번호 중복은 체험에서 재현. 연결은 서버가 번호를 배정한다. | 번호 외에 복원 직전 이력·부분 실패·재시도 검사. |
| 2 | 넓은 피드백 행에서 상태와 할 일 수가 숨는다. | 같은 넓이에서 열형 할 일과 피드백 행을 모두 비교한다. |
| 3 | 기록에서 만든 할 일은 학생도 직접 추가로 보이며 같은 기록 필터에서 빠진다. | 직접 출처·피드백 연결·미팅으로 가져간 관계를 모두 시험한다. |
| 4 | 목표만 적으면 홈에 준비 없음. 자동·수동 지정은 서로 다른 상태다. | 목표만, 할 일만, 준비 없음, 수동 지정 해제를 각각 연다. |
| 5 | 혼합 제목 아래 숫자는 할 일만 센다. | 피드백 2·할 일 0처럼 각 숫자의 뜻을 드러낸다. |
| 6 | 음성 공유는 바로 저장하며 성공 시 행 상태를 바꾼다. 전사는 별도 비공개다. | 공유 전 대상 안내와 누른 뒤의 행·오류·중지·재열기. |
| 7 | 좁은 피드백 패널에서 진행 단계 이름이 숨는다. | 한 줄에서 현재 단계명과 상태를 읽을 수 있는지 확인한다. |
| 8 | 좁은 오디오 영역의 눈금이 겹친다. | 여러 길이와 패널 폭에서 끝 눈금·키보드 이동·실제 재생 범위. |
| 9 | 보관 화면에서 음성 공유 네 글자는 읽힌다. 버튼 끝 여백은 좁다. | 실제 잘림을 긴 문구와 더 작은 너비에서 확인한다. |
| 10 | 공동연구 서면 피드백 모달 첫 화면에서 공개 선택이 접힌다. 스크롤로 조작 가능하다. | 실제 폼 선택 후 값을 저장하고 다시 열 수 있는지 본다. |
| 11 | 320×680 첫 할 일 미노출. `모두`는 오른쪽 308px 안이었다. | 데이터량·글자 확대·390px·필터 접힘에서 첫 행이 읽히는지 확인한다. |
| 12 | 모바일 홈과 보조 도우미가 같은 색으로 강조된다. | 현재 페이지, 보조 창 열림, 화면 뒤로 가기를 구분한다. |
| 13 | 삭제 댓글 자리에 답글·해결·링크 복사·개수가 남는다. 모바일 핀 안내·취소 위치가 갈린다. | 답글 유무와 설명, 문서 탭에서 핀·취소·복귀, 접근 가능한 스레드. |
| 14 | 토스트 겹침은 기존 RC-4와 연결되며 업로드 트레이는 별도 사례다. | 중첩 폭, 오류와 되돌리기, 푸터와 설정 버튼 접근. |
