## 복사해 둔 브라우저 재현

앱이 설치된 `Margin-repo/apps/home-preview`에서 실행한다. 인계 검수 환경은 Node.js v24.15.0, 저장소 잠금 파일의 패키지, Playwright Chromium을 사용했다. 의존성이 없는 별도 작업본에서는 `npm ci`와 `npx playwright install chromium`로 준비한다. PDF 보조 자료 준비는 두 서버보다 먼저 한 번 실행한다.

```sh
cd '/Users/kyun/Downloads/스튜디오26-2/신정훈 교수님/Margin-repo/apps/home-preview'
node scripts/prepare-pdf-assets.mjs
```

터미널을 두 개 열어 각각 위 앱 폴더에서 실행한다. 5215는 체험 모드, 5203은 격리 연결 모드다. 54399의 요청은 브라우저 시험이 가로채고 인메모리 PostgreSQL(PGlite)에 현재 저장소 마이그레이션을 적용해 처리한다. 실제 계정 키나 별도 Supabase 서버가 필요하지 않다.

```sh
VITE_SUPABASE_URL='' VITE_SUPABASE_PUBLISHABLE_KEY='' npm exec vite -- --host 127.0.0.1 --port 5215 --strictPort
```

```sh
VITE_SUPABASE_URL='http://127.0.0.1:54399' VITE_SUPABASE_PUBLISHABLE_KEY='local-audit-only' npm exec vite -- --host 127.0.0.1 --port 5203 --strictPort
```

다른 터미널의 같은 앱 폴더에서 실행한다. 필요한 항목을 골라도 된다. 새 출력 폴더를 사용해 기존 캡처를 보존한다.

```sh
margin_handoff_replays='../../../문서_정리/margin-re-evaluation/2026-11-26_5단계-전_통합인계_v1/재현'
margin_handoff_output="$(mktemp -d /tmp/margin-handoff-audit.XXXXXX)"
node "$margin_handoff_replays/preview-defects.mjs" "$margin_handoff_output/preview"
node "$margin_handoff_replays/connected-review.mjs" "$margin_handoff_output/connected"
node "$margin_handoff_replays/professor-review.mjs" "$margin_handoff_output/professor"
node "$margin_handoff_replays/settings-sharing.mjs" "$margin_handoff_output/settings"
node "$margin_handoff_replays/home-list-scope.mjs" "$margin_handoff_output/home"
printf '%s\n' "$margin_handoff_output"
```

## 재현 중 겪은 일

- 두 개의 `npm run dev`를 같이 열면 `predev`가 같은 PDF 보조 파일을 정리하면서 파일 삭제가 경합했다. 위처럼 준비를 한 번 하고 Vite 두 개를 띄운다.
- Montage 버전 메뉴 행은 `menuitemradio`다. 텍스트만 가리키면 겹친 상호작용 요소가 클릭을 받는다. 스크립트는 행을 선택한다.
- 화면에 `할 일 추가`가 기록 패널과 전역 도우미에 같이 있다. 기록 출처 조작은 `요약·할 일` 안에서 눌러야 한다. 기록 필터는 보이는 `기록` 라벨과 접근성 이름이 달랐다. 현재 이름이 `모든 기록, 모든 기록`으로 중복되는 것도 확인했다.
- 격리 데이터에서 예정 미팅 상태는 `preparing`이다. `planned`로 입력했을 때 서버는 `미팅 상태를 확인해 주세요.`라고 반환했다.
- 공동연구 없는 서면 피드백에는 공개 범위가 숨는다. 공동연구자를 둔 데이터로 모달을 열면 스크롤 전후를 비교할 수 있다.
