# 마진(Margin) UI·UX·인터랙션 종합 개선 검토 및 작업 인계서

## 0. 작업 목적

마진(Margin)의 현재 GitHub 저장소, 실제 구현된 화면 및 기능, 기존 UI 라이브러리와 디자인 시스템을 파악하고, 기존에 검토했던 라이브러리와 새롭게 발견한 라이브러리를 종합적으로 비교해 제품의 UI·UX·인터랙션 완성도를 높이고자 한다.

단순히 새로운 컴포넌트를 추가하거나 화려한 애니메이션을 적용하려는 작업이 아니다. 기존 기능의 사용성을 높이고, 필요한 기능을 발견하며, 각 상황에서 시각적 완성도와 실제 사용성이 가장 좋은 컴포넌트를 선택하는 것이 목적이다.

이미 구현된 컴포넌트도 다시 검토 대상에 포함한다. 기존에 있다는 이유로 무조건 유지하거나 제외하지 말고, 다른 라이브러리의 원본 데모와 비교하여 가장 적합한 것을 추천한다.

이 문서의 60개 후보는 종합 검토 결과이며, 전부 도입하기로 확정한 사항은 아니다. 먼저 비교·검토하고 사용자와 선택한 뒤 구현한다.

# 2. 작업 및 디자인 원칙

## 2-1. 기본 디자인 방향

마진은 장시간 문서를 읽고, 연구를 정리하고, 교수의 피드백을 반영하는 생산성 서비스다.

따라서 다음을 중요하게 판단한다.

- 정보 구조와 시각적 위계
- 장시간 작업 시 피로도
- 문서 및 목록의 가독성
- 필요한 정보의 발견 가능성
- 조작 단계 최소화
- 상태 변화의 명확성
- 정교하고 자연스러운 모션
- 기능과 인터랙션의 일관성
- 모바일과 데스크톱의 적합한 사용 방식
- 기존 연구 흐름과의 연결
- 서비스 전체의 시각적 완성도

화려하거나 유행하는 컴포넌트라는 이유만으로 채택하지 않는다. 실제 기능과 디자인이 함께 좋아지는지를 기준으로 판단한다.

그렇다고 지나치게 보수적으로 판단하거나 기존 구현을 무조건 유지하지도 않는다. 더 좋은 원본 컴포넌트가 있다면 적극적으로 비교하고 제안한다.

## 2-2. 기존 디자인 시스템

일반적인 버튼, 입력창, 모달, 시트, 메뉴 등은 Wanted Montage 4.2.0을 기본으로 사용한다.

- 공식 Montage 토큰 사용
- 라이트·다크 테마 유지
- Pretendard 유지
- 브랜드 컬러 유지
- 별도의 전역 색상표 및 테마 시스템 추가 금지
- 불필요한 전역 덮어쓰기 CSS 생성 금지
- 기존 접근성, 키보드 조작, 포커스 복귀 유지
- Coss UI 및 Kokonut의 이미 확정된 도입 영역 존중

다만 공식 외부 컴포넌트를 사용자와 선택하여 도입할 때는 아래 원본 도입 원칙을 적용한다.

## 2-3. 외부 컴포넌트 도입 원칙

사용자가 특정 라이브러리 또는 데모를 골라 가져오라고 하면, 해당 데모의 모양과 동작을 실제로 사용하라는 의미다.

단순히 비슷하게 재구현하라는 의미가 아니다.

1. 공식 레지스트리 또는 공식 배포 소스에서 실제 원본 코드를 가져온다.
2. 원본 JSX/DOM 구조, 치수, 간격, 비례, 정렬, 모서리, 내부 구성, 모션 수치, 인터랙션을 최대한 유지한다.
3. 기본적으로 마진에 맞게 변경하는 것은 색상, Pretendard, 한국어 문구, 필요한 현행 다국어 처리, 실제 데이터 및 기능 연결이다.
4. 원본 내부 부품을 Montage로 전부 교체하거나 기존 CSS로 원본 외형을 흉내 내지 않는다.
5. 실제 제품 기능 때문에 변경이 필요하다면 최소한의 범위만 수정하고 그 차이를 기록한다.
6. 파일을 추가하거나 의존성을 설치한 것만으로 도입 완료라고 하지 않는다. 실제 화면에서 사용되어야 한다.
7. 원본의 가짜 데이터, 가짜 진행률, 존재하지 않는 기능, 가짜 AI 처리 과정, 가짜 결제 및 성공 상태를 실제 제품에 넣지 않는다.
8. 출처, 라이선스, 원본과 수정본의 차이, 실제 연결 위치를 기록한다.

Kokonut UI의 원본 도입 범위에서는 이미 이 원칙이 확정되어 있다.

## 2-4. 시각 및 기능 제약

- 로그인 이후 작업 화면에서는 구름 셰이더, 과도한 유리 효과, 광학 굴절 효과를 사용하지 않는다.
- 소개 사이트의 기존 Cloud Shader와 브랜드 마스코트는 유지할 수 있다.
- 모션은 `prefers-reduced-motion`을 지원해야 한다.
- 불필요한 가로 스크롤, 중첩 스크롤, 가짜 드래그 가능 영역을 만들지 않는다.
- 긴 한국어 제목과 본문, 실제 데이터 밀도를 고려한다.
- 사용자의 명시적 동작 없이 기록을 삭제하거나 수정하지 않는다.
- 기존 저장, 취소, Undo, 실패 복구, 권한, IME 입력, 원문 보존을 유지한다.

특히 다음 상태를 서로 합치지 않는다.

- 할 일 완료
- 학생의 수정 반영 기록
- 교수의 검토 결과
- 댓글 해결
- 읽음 여부

교수의 검토 결과는 기존 제품 정의를 따른다. 일반적인 승인 상태로 임의 변경하지 않는다.

연구 도우미는 실제로 접근 권한이 있는 연구 기록을 활용하며, 사용자 확인 없이 실행하거나 채택하지 않는다.

## 3-3. 이전 코드 조사에서 발견한 사항

- AutoAnimate와 Number Flow의 의존성 및 래퍼 파일이 남아 있지만, 이전 조사에서는 해당 래퍼가 현재 화면으로 연결된 경로를 발견하지 못했다.
- 실제 목록 애니메이션은 주로 Motion 기반 자체 구현을 사용한다.
- Coss 탭과 세그먼트 컨트롤은 실제 도입되어 있다.
- Kokonut 원본 18개가 도입됐다는 과거 기록은 현재 18개 모두 화면에서 사용된다는 의미가 아니다.
- 우클릭, 더보기, 길게 누르기, 모바일 스와이프의 공통 행 동작은 이미 구현되어 있다.
- 파일 업로드 전 제목·분류 등 정보 확인, 중복 후보 처리, 업로드 큐, 오류 시 재시도 역시 이미 구현되어 있다.
- 버전 비교 및 복원, 댓글 답글·편집·해결, 녹음과 전사문의 동기화도 기존 기능이다.
- 현재 코드에서 해당 기능을 다시 확인하고, 이미 있는 기능을 신규 기능이라고 보고하지 않는다.

현재 연구 도우미는 IA v2에 따라 오른쪽 사이드 패널에서 제공된다. 과거 전체 화면 연구 도우미를 무단 복원하지 않는다.

기존 사용자 결정에 따른 입력창 예외 사항도 확인한다.

- 추천 질문 묶음에 맞춘 가변 폭
- 최대 760px
- 입력창 왼쪽 음성 버튼
- 불필요한 폴더 버튼 제외
- 기존 모델·답변 깊이 두 칩 유지
- 입력창 위 추천 모델
- 입력창 아래 실제 크레딧 잔액 및 사용량

실제 최신 화면과 충돌하는 부분은 현행 설계 및 코드와 비교하여 확인한다.

## 4-1. 라이선스 주의 사항

마진은 이전 조사 시점에 공개 GitHub 저장소이며, 상업 서비스로 발전시킬 계획이 있다.

따라서 다음을 지킨다.

- EasyUI: 이전 검토에서는 공식 저장소 MIT 라이선스를 확인했다. 개별 컴포넌트 및 최신 라이선스 재확인.
- React Bits 무료판: MIT + Commons Clause로 확인되었으므로 순수 MIT라고 일괄 표기하지 않는다. 앱 사용과 컴포넌트 자체의 판매·재배포 조건을 구분한다.
- React Bits Pro: 공개 저장소에서의 원본·수정 소스 배포 제한 및 개발자 좌석 조건을 확인해야 한다. 공개 저장소와 양립하는 권한을 확인하기 전에는 원본 소스를 반영하지 않는다.
- Kobra: 이전 검토에서 Free의 개인 사용 조건이 확인됐다. 무료라고 무조건 상업 이용 가능한 것으로 판단하지 않는다.
- BoardUI: 무료 MIT 영역과 Pro 영역을 구분한다.
- Watermelon UI: 이전 조사상 MIT 기반 무료 라이브러리이나 현재 개별 소스 조건을 확인한다.
- Aceternity Cloud Shader: 별도 Aceternity License 조건을 따른다. MIT로 변경 표기하지 않는다.
- DesignBookmark, 21st.dev: 탐색 플랫폼 자체와 개별 컴포넌트 원본의 라이선스는 별개다.
- 유료 컴포넌트는 구매 또는 적법한 사용 권한 없이 복제하거나 공개 저장소에 추가하지 않는다.

이 문서에 적힌 라이선스는 이전 조사 결과다. 실제 채택 시 공식 현행 조건을 재확인한다.

- **신규:** 현재 기능 범위를 확장하는 후보
- **재활용:** 설치 또는 보유 중인 기존 부품의 재연결

- **★:** 우선적으로 비교하거나 시연할 가치가 높은 항목

## A. 공통 UI·탐색·마이크로 인터랙션

### 01. 기본 버튼·입력창·모달·시트

- 분류: 유지
- 우선 추천: 현재 Wanted Montage
- 적용 범위: 서비스 전체 일반 UI

기본 조작의 크기, 간격, 글자, 색상, 접근성은 현재 Montage 체계를 유지하는 것이 적합하다. 새로운 라이브러리의 기본 버튼을 불필요하게 혼용하지 않는다.

### 02. 탭·세그먼트 컨트롤

- 분류: 유지
- 우선 추천: 현재 Coss Tabs 및 Segmented Control
- 공식 사이트: https://coss.com/ui

이미 도입되어 사용 중이다. 이동하는 선택 인디케이터와 활성 상태를 살리되 화면마다 표현이 다르지 않은지 확인한다.

### 03. 더보기·우클릭 메뉴

- 분류: 개선
- 기존 구현: RowActions, Radix ContextMenu
- 비교 추천: beUI Animated Context Menu
- 링크: https://beui.dev/components/motion/context-menu

현재 더보기, 우클릭, 모바일 행 조작이 하나의 동작 모델을 공유한다. 이를 유지하면서 메뉴 출현 위치, 열림·닫힘 모션, 선택 반응, 메뉴 밀도를 비교한다.

동일한 기능을 하는 별도의 컨텍스트 메뉴 시스템을 중복 추가하지 않는다.

### 04. 모바일 목록 스와이프

- 분류: 개선
- 우선 추천: beUI Swipeable List
- 링크: https://beui.dev/components/blocks/swipeable-list
- 비교 대안: React Bits Swipe Row
- 링크: https://reactbits.dev/micro/swipe-row

현재 모바일 스와이프는 이미 구현되어 있다. 일정 거리 이상 밀면 바로 실행되는 현재 방식과, 밀었을 때 행동 버튼을 드러내는 beUI 방식을 비교한다.

할 일 미루기, 보관, 자료 관리 등에 적용할 수 있다. 스크롤과의 충돌, 우발적 실행, 되돌리기 여부를 확인한다.

### 05. 통합 검색 및 커맨드 팔레트

- 분류: 개선
- 기존 구현: cmdk, CommandPalette
- 비교 추천: Arc Command Palette
- 링크: https://uiarc.dev/components/blocks/command-palette

현재 검색 범위와 동작을 유지하면서 최근 방문 기록, 고정 항목, 검색 결과 미리보기 등을 검토한다.

현재 최근 항목이 수정 시각 기준으로 정렬된다면 실제 사용자가 열었던 방문 기록과 구분한다.

### 06. 사이드 패널 크기 조절

- 분류: 유지 우선
- 기존 구현: PanelResizer
- 비교 추천: affectUI Resizable
- 링크: https://www.affectui.com/components/resizable

현재 드래그, 방향키, 너비 초기화, 너비 저장 기능이 있다. 원본 교체 여부보다 손잡이 발견성, 경계선 반응, 조절 시 주변 콘텐츠와의 자연스러운 연동을 비교한다.

### 07. 날짜·시간·기간 입력

- 분류: 유지 및 부분 개선
- 기존 구현: Montage DatePicker / TimePicker
- 비교 추천: ReUI Date Selector
- 링크: https://reui.io/docs/components/base/date-selector

일반 날짜·시간 입력은 Montage를 유지한다. 자료 및 할 일 목록의 기간 필터처럼 복잡한 조건 선택에는 ReUI를 비교한다.

### 08. 토스트·알림·Undo

- 분류: 유지 및 개선
- 기존 구현: Sonner
- 비교 추천: EasyUI Undo Toast
- 링크: https://easyui.site/components/undo-toast

현재 알림과 Undo 체계를 유지하면서 남은 시간, 여러 알림 스택, 위치, 가시성, 알림 동작을 비교한다.

기존 알림과 별도의 중복 토스트 시스템을 만들지 않는다.

### 09. 요청 중인 버튼

버튼 폭 변화로 주변 레이아웃이 출렁이지 않도록 한다.

### 10. 작은 진행 및 완료 상태

- 분류: ★ 개선

- 링크: https://reactbits.dev/micro/status-mark

대기, 처리 중, 성공, 실패 등의 실제 상태를 작은 인터랙션으로 표현하는 후보.

문서 저장, 파일 업로드, 실행 상태에 적합하다. 같은 목적의 상태 표시가 여러 종류로 늘어나지 않도록 한다.

### 11. 숫자 변화 모션

- 분류: 재활용
- 기존 보유: Number Flow, RollingNumber
- 적용 후보: 할 일 개수, 연구 개수, 실제 크레딧 잔액, 실제 사용량

현재 설치되어 있지만 연결되지 않았을 가능성이 있는 컴포넌트다.

필요하면 출처를 문서 카드로 펼쳐 읽는 표현을 비교한다.

### 47. 실제 도구 실행 상태

- 분류: ★ 개선
- 추천: React Bits Call Chip
- 링크: https://reactbits.dev/micro/call-chip

자료 검색, 파일 읽기 등 실제 실행 중인 작업의 상태를 작은 칩 형태로 표현하는 후보다.

서버에서 실제로 제공되는 상태 정보만 사용한다.

존재하지 않는 도구 실행, 가짜 단계, 임의의 진행률을 표시하지 않는다.

### 48. 처리 내역 접기 및 펼치기

- 분류: 개선
- 추천: React Bits Thought Line
- 링크: https://reactbits.dev/micro/thought-line

실제 확인 가능한 처리 내역이나 실행 상태를 진행 중에 보여주고, 완료 후 한 줄로 접는 용도다.

AI의 비공개 내부 추론을 표시하는 기능으로 해석하지 않는다. 실제 서버 이벤트와 사용자에게 제공 가능한 작업 기록만 연결한다.

### 49. AI 답변의 표·수식·긴 Markdown

- 분류: ★ 확장
- 추천: Streamdown
- 링크: https://streamdown.ai/
- 비교 대안: 기존 react-markdown 렌더러 확장

이전 조사에서는 현재 일반 AI 답변 렌더러의 허용 요소에 표 및 수식 지원이 부족한 것으로 확인됐다.

연구 도우미라는 특성을 고려하면 다음 지원이 중요하다.

- Markdown 표
- 연구 결과 및 비교표
- 수학 및 통계 수식
- 긴 문단
- 제목과 계층 구조
- 코드 및 인용
- 기존 근거 연결

Streamdown 도입과 서버 응답의 실제 스트리밍 구현은 별개의 작업이다.

현재 인용 구조와 안전한 Markdown 렌더링을 보존해야 한다.

변경 전후의 차이, 실제 수정 범위, 적용 및 취소를 명확하게 보여준다.

일반적인 질문 답변마다 승인 모달을 띄우지 않는다.

# 6. 이번에 추가된 EasyUI 상세 검토

공식 사이트: https://easyui.site

우선 비교 순위는 다음과 같다.

| 순위 | 컴포넌트 | 적용 영역 |
|---|---|---|
| 1 | Recovery Ledger | 문서 버전 이력 및 복원 |
| 2 | Animated File Upload | 파일 업로드 진행 및 상태 |
| 3 | Peek Card | 연구 기록 링크 미리보기 |
| 4 | Product Tour | 첫 사용 안내 |
| 5 | Selection Basket | 자료 다중 선택 및 일괄 작업 |
| 6 | UnfoldAccordion | FAQ 및 접히는 설명 |
| 7 | Undo Toast | 알림 및 되돌리기 비교 |
| 8 | Prompt Input | AI 입력창 비교 |
| 9 | Gooey Menu | AI 입력창 주변 메뉴 비교 |

추가 검토 대상:

- Interactive Timeline
- Density Lens
- Dependency Trace
- Focus Mode

다음 판단을 참고한다.

### Interactive Timeline

연구 과정 및 단계 시각화에 활용할 수 있다.

다만 긴 연구 기록을 읽는 용도에는 Arc Timeline이 더 차분하고 적합할 가능성이 높다. 단계 진행을 적극적으로 시각화하는 화면이라면 EasyUI Interactive Timeline도 비교한다.

### Density Lens

표의 정보 밀도를 편안하게 또는 촘촘하게 바꾸는 기능이 아니다. 포인터 주변을 확대하는 효과다.

이름만 보고 자료 테이블의 밀도 전환 컴포넌트로 도입하지 않는다.

### Dependency Trace

현재 마진의 React Flow 관계도와 역할이 겹칠 수 있다.

실제 관계 탐색상의 장점이 있는지 확인한 뒤 판단한다.

### Focus Mode

이전에 제거했던 자동 집중 모드와 혼동하지 않는다.

다시 도입할 필요가 있다면 명확한 신규 사용 시나리오를 제시한다. 현 단계에서는 우선순위가 높지 않다.

- Sound
- Command Menu
- 기타 AI 및 모션 컴포넌트

디자인 후보로 유지한다.

Free의 상업 이용 조건을 확인하지 않고 원본을 도입하지 않는다.

## 8-12. Origin UI 및 Coss

현재 마진에 실제 들어와 있는 Coss UI는 단순 후보가 아니다.

이미 적용된 탭과 세그먼트 등을 우선 기준으로 삼는다.

Origin UI의 입력 및 일반 컴포넌트는 필요한 부분만 비교한다.

## 8-13. Magic UI 및 Aceternity

공개 소개 화면과 제한적인 시각 효과 참고에 적합하다.

전체 라이브러리가 실제 앱에 설치된 것과 일부 원본 또는 참고 구현만 존재하는 것을 구분한다.

Cloud Shader는 기존 공식 소스 도입 및 변형 기록을 유지한다.

MagicCard, AnimatedList, Dock, 도트 등의 과거 자체 구현을 모두 공식 원본 도입으로 잘못 분류하지 않는다.

## 8-14. Astryx

https://astryx.atmeta.com/

React·StyleX 기반 별도 디자인 시스템이다.

현재 Montage와 역할이 겹치므로 작은 모션 기능을 추가하기 위해 전체 디자인 시스템을 도입하지 않는다.

## 8-15. DesignBookmark 및 21st.dev

컴포넌트와 인터랙션을 발견하는 탐색 채널로 활용한다.

이전에 비교한 디자인북마크 후보에는 다음이 포함된다.

- Prompt Box
- Agent Steps
- Ghost Suggestion
- Command Palette
- File Drop
- Sidebar Collapse
- Read Along
- Undo Button
- Focus Mode
- Mention Picker

상당수는 이미 마진의 기존 기능과 겹친다.

Agent Steps는 이전 조사에서 구현 파일이 있으나 연구 도우미의 실제 화면에서는 미사용 상태로 확인된 기록이 있다.

Sidebar Collapse의 기존 전환과 모션 수치를 확인하고, 더 좋은 원본이 있다면 비교한다.

Focus Mode와 Mention Picker는 별도 후보로 판단한다.

## 8-16. AI Elements 및 prompt-kit

AI 답변, 실행 상태, 프롬프트 입력, 인용 및 대화 UI의 부품별 비교에 활용한다.

현재 Kokonut에 이미 있는 기능을 무조건 교체하지 않는다.

## 8-17. assistant-ui, CopilotKit, Ant Design X

단순한 UI 컴포넌트 교체보다는 AI 대화 실행 구조나 별도 디자인 체계까지 변경할 때 검토할 후보들이다.

이번 개별 UI 완성도 개선에서는 우선순위가 낮다.

# 10. 실제 신규 기능 후보 별도 정리

아래는 단순 외형 개선이 아니라 기능 또는 데이터 구조의 추가가 필요한 후보들이다.

| 기능 | 추천 기반 | 주요 고려 사항 |
|---|---|---|
| PDF 전체 페이지 탐색 | PDF.js, Preview Rail 참고 | 페이지 렌더링 및 성능 |
| PDF 본문 검색 | PDF.js | 실제 검색 및 결과 이동 |
| 자료 다중 선택·일괄 이동 | ReUI, EasyUI | 선택 상태, 권한 및 오류 복구 |
| 저장된 필터 및 보기 | ReUI Filters | 실제 저장 구조 |
| 연구 기록 링크 미리보기 | EasyUI Peek Card | 권한, 데이터 연결 |
| 참여자 및 기록 멘션 | Arc Mention Input | 선택 데이터 및 알림 구분 |
| 사진 및 스캔 자료 | 기존 업로드, OCR | 원문 보존, 비용 및 처리 실패 |
| 할 일 칸반 보기 | ReUI Kanban | 상태 의미 유지 |
| 본문 문장 단위 댓글 연결 | React Bits Pro Comments 2 참고 | 문서 버전 및 위치 앵커 |
| 미해결 댓글 통합 보기 | Comments 5 참고 | 접근 권한 및 해결 상태 |
| 피드백에서 검토까지 연결 이력 | Arc Timeline | 기존 데이터 관계 |
| 실제 방문 기록 기반 최근 검색 | cmdk | 수정 시각과 방문 시각 구분 |
| AI 답변 표·수식 지원 | Streamdown 또는 react-markdown 확장 | 인용 및 안전한 렌더링 |

각 기능은 UI 컴포넌트의 설치만으로 구현이 끝나지 않을 수 있다.

백엔드, 데이터 구조, 권한, 저장 및 실제 동작이 필요한지를 구분하여 보고한다.

# 11. 개선 우선순위

이전 검토에서 추천한 우선순위다. 사용자가 최종 승인한 작업 순서로 단정하지 않는다.

## 우선순위 1. 문서 버전 이력

- EasyUI Recovery Ledger
- 기존 버전 비교 및 복원 기능의 가시성 개선
- 시각적인 변화와 실용성이 모두 큰 후보

## 우선순위 2. 저장 상태

- Kokonut Save Status
- 문서 편집 중 저장 결과의 신뢰성 및 명확성 개선
- 비교적 작은 범위에서 완성도를 높일 수 있음

## 우선순위 3. PDF 전체 페이지 탐색 및 본문 검색

- 현재 PDF.js 기반 확장
- 긴 논문을 읽고 원하는 부분을 찾는 시간을 줄이는 실제 신규 기능

## 우선순위 4. 필터 통일 및 저장된 보기

- ReUI Filters
- 반복적으로 동일한 필터 조건을 설정하는 비용 감소
- 할 일 및 자료 관리의 효율 개선

## 우선순위 5. 자료 다중 선택 및 일괄 작업

- ReUI Data Grid
- EasyUI Selection Basket
- 자료가 쌓였을 때 관리하기 편리한 구조

## 우선순위 6. 본문과 댓글의 연결

- 기존 CommentThread
- affectUI Comment Thread
- React Bits Pro Comments 2
- 교수와 학생의 실제 논문 검토 작업 개선

## 우선순위 7. AI 답변 표현력

- Streamdown
- 기존 react-markdown 확장
- 표, 수식, 긴 연구 내용, 인용 개선

## 우선순위 8. 작은 상태 모션 정돈

- React Bits Status Mark
- React Bits Call Chip
- 기존 Number Flow 재연결
- 저장, 실행, 완료, 실제 사용량 등의 표현 개선

## 첫 시연 대상으로 특히 추천하는 4개

1. 문서 버전 이력
2. 문서 저장 상태
3. 자료 일괄 선택
4. 댓글 검토

실제 연구 데이터를 가정한 내용으로 기존 화면과 후보 화면을 비교했을 때 디자인 차이를 명확하게 확인할 수 있는 영역이다.

현재 Coss 탭, 할 일 완료 체크, Kokonut 인용, 전사문과 원음의 연결은 좋은 기존 자산이므로 이 비교 과정에서도 유지 후보로 포함한다.

# 12. AI가 추가로 수행해야 할 검토

이 인계서에 적힌 후보를 그대로 구현하기 시작하지 말고, 먼저 정확한 현황과 추가 가능성을 검토한다.

## Phase 1. 최신 저장소 및 실제 구현 조사

- 최신 main 및 작업 브랜치 확인
- 기존 작업자가 진행 중인 변경 확인
- 현재 `package.json` 및 실제 의존성 확인
- 모든 관련 화면 및 컴포넌트 확인
- import뿐 아니라 실제 렌더링 여부 확인
- 기존 디자인 시스템 및 토큰 확인
- 현재 IA v2 구조 확인
- 이미 구현되었지만 드러나지 않는 기능 확인
- 미사용 또는 중복 컴포넌트 확인
- 현재 상태의 실제 문제 발견

단순히 의존성 목록이나 파일명만 보고 도입 상태를 추측하지 않는다.

## Phase 2. 공식 라이브러리 조사

이 인계서의 모든 후보 라이브러리에서 실제 마진에 적용할 만한 것을 폭넓게 검토한다.

특히 다음을 확인한다.

- 공식 데모
- 실제 동작
- 원본 소스
- 무료 및 유료 구분
- 상업 이용 조건
- 공개 저장소 반영 가능 여부
- 기존 프로젝트와 기술 호환성
- React 및 Tailwind 버전 호환성
- 필수 의존성
- 모바일 및 다크 모드
- 접근성
- 실제 적용 시 유지해야 하는 기능

공개 데모만 보고 내부 구현까지 확인했다고 주장하지 않는다.

인계서에 없는 더 적합한 컴포넌트를 발견한다면 추가 제안한다.

## Phase 3. 컴포넌트별 비교

각 UI 및 기능에 대해 다음 관점에서 비교한다.

- 현재 마진 구현
- 가장 적합하다고 생각하는 후보
- 대안 후보
- 시각적 차이
- 조작 방식 차이
- 정보 전달력
- 실제 사용자의 이점
- 기존 구현을 유지해야 할 이유
- 교체 시 위험
- 기술적 난이도
- 라이선스 및 적용 조건

기존 구현이 가장 낫다면 기존 구현을 추천해도 된다.

반대로 이미 구현된 UI라도 더 완성도 높은 원본이 있다면 교체를 적극적으로 제안한다.

## Phase 4. 실제 화면 비교

가능하다면 공식 데모와 마진의 현재 화면을 실제로 열어서 확인한다.

다음을 포함한다.

- 긴 한국어 제목
- 실제 논문 및 연구 기록과 유사한 내용
- 데이터가 없는 상태
- 많은 자료가 존재하는 상태
- 처리 중 상태
- 저장 완료 및 실패
- 권한이 다른 사용자
- 선택 및 다중 선택
- 데스크톱 및 모바일
- 라이트 및 다크 모드

공식 데모의 짧은 영어 샘플과 마진의 긴 한국어 실제 화면을 비교하면서 잘림, 불필요한 여백, 과도한 스크롤, 컴포넌트 밀도를 확인한다.

시각적으로 확인하지 못한 부분은 미검증으로 표시한다.

## Phase 5. 사용자에게 검토 결과 제시

아래 형식으로 보고한다.

| 화면 | 기능·UI | 현재 구현 | 추천 컴포넌트 | 대안 | 판단 | 우선순위 | 공식 링크 | 적용 조건 |
|---|---|---|---|---|---|---|---|---|

판단은 다음 중 하나로 분류한다.

- 기존 유지
- 기존 개선
- 공식 원본으로 교체
- 기존 부품 재활용
- 신규 추가
- 비교 시연 필요
- 보류
- 제거 후보

추천 사항을 한꺼번에 확정하거나 실제 저장소에 반영하지 않는다.

사용자가 직접 비교해서 선택할 수 있도록 공식 데모 링크 및 가능한 시각 자료를 제공한다.

## Phase 6. 승인된 사항만 구현

사용자가 선택한 컴포넌트 및 기능에 한해 구현한다.

- 공식 원본 도입
- 기존 데이터 및 기능 연결
- 디자인 토큰 및 색상 적용
- 접근성 유지
- 기존 기능 회귀 방지
- 모바일 및 다크 모드 확인

# 15. 최종 요구사항

이 작업에서 내가 원하는 것은 단순한 라이브러리 추천 목록이 아니다.

마진의 실제 서비스 전체를 이해하고, 기존 구현과 새로운 공식 컴포넌트를 비교하여 각 UI의 완성도를 높일 수 있는 실질적인 개선안을 얻고 싶다.

이미 구현되어 있는 컴포넌트도 다시 추천할 수 있다. 기존 구현이 가장 아름답거나 적합하면 유지하고, 다른 원본이 더 좋다면 교체를 제안한다.

새로운 라이브러리를 많이 설치하는 것이 목적이 아니다. 그렇다고 기존 라이브러리만으로 모든 것을 해결하려 하지도 않는다.

각 화면과 기능에 가장 적합한 UI·인터랙션을 선별하고, 현재 존재하지 않지만 마진에 가치가 있을 기능도 함께 발굴한다.

특히 다음을 우선한다.

- 시각적인 완성도
- 정교한 인터랙션
- 실제 연구 작업의 편리함
- 기존 서비스의 정체성
- 직관적인 정보 구조
- 사용자에게 필요한 기능의 발견
- 불필요한 컴포넌트 및 인터랙션 제거
- 기존 좋은 구현의 보존
- 공식 원본 컴포넌트의 충실한 활용

우선 전체 저장소와 라이브러리를 검토하고, 실제 화면별로 비교 결과 및 추천 목록을 작성하라.

인계서의 60개 항목에만 갇히지 말고 다른 적합한 기능이나 컴포넌트를 발견하면 추가하라.

단, 현재 기능이나 이전에 승인된 결정을 정확히 이해하지 못한 상태에서 전체 디자인을 무단으로 변경하지 않는다.

최종적으로 사용자가 어떤 컴포넌트를 유지하고, 어떤 것을 교체하며, 어떤 신규 기능을 추가할지 직접 선택할 수 있도록 명확하고 충분한 근거를 제시하라.
