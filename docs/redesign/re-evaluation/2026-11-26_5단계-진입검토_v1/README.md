## 5. 사용자 결정이 필요한 질문

1. **[결정 2026-11-26] 넣는다(설계만).** Phase 5에서 설계하고 구현 순서는 Phase 6에서 정한다.
   계정·프로필(탈퇴, 데이터 내보내기, 연결된 로그인 관리, 테마 통일)을 Phase 5 범위에 넣을까?
   [제안] 넣는다. 테마 불일치는 작은 수정이다. 탈퇴·내보내기는 연구 데이터 서비스에서 개인정보 처리 측면으로 요구될 가능성이 높다[추론]. 다만 서버 작업이 커서 Phase 5에서는 설계만 하고 구현 순서는 Phase 6에서 뒤로 둔다.
2. **[결정 2026-11-26] 직전 상태로 돌아간다.** 완료 전 상태(`시작 전` 또는 `진행 중`)를 한 칸 저장해 두고, 모든 화면이 공통 함수로 그 값을 되살린다.
   완료한 할 일을 다시 풀면 어느 상태로 돌아가야 할까?
   - 직전 상태로 되돌리기 [추천]: 사용자가 기대하는 "되돌리기"와 같다. 상태 이력을 한 칸 저장해야 한다.
   - 항상 `진행 중`: 구현이 가장 단순하다. 한 번도 시작하지 않은 일도 진행 중이 된다.
   - 항상 `시작 전`: 현재 원고 여백·상세의 동작이다.
   어느 쪽을 고르든 두 화면이 공통 함수를 쓰게 고치는 것은 같다.
3. **목표 한 줄만 적은 다음 미팅을 "준비함"으로 볼까?**
   [제안] 요약에 목표를 첫 줄로 보여 주되 "준비 내용 0개"는 따로 셈한다. 준비 여부를 판정하지 않고 보여 주는 방식이라 결정 부담이 작다.
