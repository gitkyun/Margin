## 1. 쟁점과 대안 (다룰 순서대로)

### 쟁점 1. 원고 저장 단위 (RC-9) — 신규

**지금 [사실]**
- 복원 전 백업이 본문 글자만 비교해 제목·서식 변경을 놓친다.
- 복원은 최대 네 번의 독립 요청이라 중간에 실패하면 화면과 서버가 갈린다.
- 저장 중 바꾼 공개 범위가 서버에 반영되지 않는다.
- 충돌 창에서 `내가 쓴 내용 유지`를 누르면 화면만 바뀌고, 다음 저장 전까지 서버는 상대 내용이다.

| | 대안 A [권고] 서버에서 한 번에 | 대안 B 화면에서 순서대로 + 실패 시 되돌리기 |
|---|---|---|
| 복원 | 서버 함수 하나가 '현재본을 버전으로 남기기 → 문서 바꾸기 → 새 버전 기록'을 한 트랜잭션으로 처리한다. 성공 아니면 아무것도 안 바뀐다 | 지금 순서를 유지한다. 중간 실패 시 이미 바뀐 문서를 원래대로 되돌리는 요청을 보낸다 |
| 변경 판단 | 두 대안 공통: '제목·공개 범위·본문 구조(`content`)'를 하나의 기준으로 비교한다 | 같음 |
| 공개 범위 | 두 대안 공통: 공개 범위는 자동 저장과 떼어 바로 저장하는 별도 동작으로 둔다. 바꾸면 즉시 저장되고 결과 토스트가 뜬다 | 같음 |
| 충돌 | 두 대안 공통: `내가 쓴 내용 유지`를 누르면 그 자리에서 내 내용을 저장한다. 상대 내용은 버전 기록에 '다른 사람이 저장한 내용'으로 남는다. 아무것도 사라지지 않는다 | 같음 |
| 좋은 점 | 네트워크가 끊겨도 반쯤 바뀐 상태가 생기지 않는다. 체험 모드 번호 중복도 같은 함수 규칙으로 맞출 수 있다 | 서버 변경과 배포가 없다 |
| 대가 | 서버 함수 1개와 마이그레이션, 권한 검사가 필요하다 | 되돌리기 요청마저 실패하면 여전히 갈린다. 코드가 길어진다 |

**권고 이유**: 원고는 마진에서 잃으면 안 되는 첫째 데이터다. 실패 창을 남기는 B보다 A가 맞다.

### 쟁점 2. 할 일과 기록의 관계 (RC-10) — 신규

**지금 [사실]**
- 기록에서 만든 할 일은 `sourceRecordId`에 출처가 저장된다. 그런데 할 일 목록의 출처 이름과 기록 필터는 이 값을 읽지 않는다.
- 다음 미팅 요약은 `goal`을 세지 않는다.
- 완료를 풀 때 화면마다 다른 상태로 돌아간다.

| | 대안 A [권고] 읽는 함수 하나 | 대안 B 저장 필드 하나로 정리(데이터 이관) |
|---|---|---|
| 방법 | 관계를 읽는 함수 하나(할 일의 '나온 곳'과 '가져간 미팅')를 만든다. 목록 이름·필터·기록 상세·항목 상세가 모두 이 함수를 쓴다. 우선순위는 `sourceRecordId` → 피드백의 기록 → 가져간 미팅 | 기존 데이터의 관계를 `sourceRecordId` 하나로 옮기고 다른 경로를 없앤다 |
| 화면 | 할 일 행에 `제5차 논문 지도에서` 한 칩만 둔다. 다른 미팅에 가져갔으면 `→ 제6차` 칩을 하나 더 붙인다. 기록 필터는 '나온 곳 또는 가져간 미팅'으로 찾는다 | 칩은 `나온 곳` 하나 |
| 볼 수 없는 기록 | 편집자가 볼 수 없는 비공개 기록에서 나왔으면 `직접 추가` 대신 `비공개 기록에서`로 보인다 | 같음 |
| 좋은 점 | 데이터 변경이 없다. 바로 고칠 수 있다 | 장기적으로 규칙이 하나다 |
| 대가 | 필드 두세 개를 계속 같이 읽는다 | 이관 스크립트, 운영 데이터 변경, 되돌리기 계획이 필요하다 |

**다음 미팅 요약** [권고]
- 목표를 첫 줄에 그대로 보인다.
- 준비 수는 따로 센다. 예: `목표: 2장 비교 기준 확정 · 가져갈 할 일 0 · 질문 0`
- '준비 없음'이라고 판정하는 문구는 없앤다.
- 자동으로 정해진 다음 미팅에는 `홈의 다음 미팅으로 지정` 버튼을 숨긴다.

**완료 취소 = 직전 상태 [결정]**

| | 대안 A [권고] 할 일에 '완료 전 상태'를 저장 | 대안 B 되돌리기 토스트 안에서만 기억 |
|---|---|---|
| 방법 | 완료할 때 `시작 전`/`진행 중`을 함께 저장한다. 어느 화면에서 언제 풀어도 그 값으로 돌아간다 | 6초 안에 `되돌리기`를 누르면 직전 상태로 간다. 그 뒤 체크를 풀면 `진행 중` |
| 대가 | 필드 1개 추가 | 결정(직전 상태)을 6초 안에서만 지킨다 |

어느 대안이든 항목 상세와 원고 여백도 공통 함수를 쓰게 고친다.

## 4. 사용자 선택 결과

**[결정] 2026-11-26: 쟁점 1~8 모두 대안 A로 확정.** 쟁점 2의 두 세부 선택(관계 읽기, 완료 전 상태 저장)도 모두 A다. 아래는 당시 질문 목록이다.

| 쟁점 | 확정안 |
|---|---|
| 1 원고 저장 | 서버 함수 하나로 복원을 한 번에 처리. 변경 비교 기준은 제목·공개 범위·본문 구조. 공개 범위는 따로 즉시 저장. 충돌 시 고른 쪽을 바로 저장하고 다른 쪽은 버전으로 보존 |
| 2 관계 읽기 | 관계를 읽는 함수 하나. `비공개 기록에서` 표기. 다음 미팅은 목표 첫 줄 + 준비 수 따로. 할 일에 완료 전 상태 필드 저장 |
| 3 홈 | 라우트별 탭 중복 방지, 첫 묶음 제목, 정렬 규칙은 유지 |
| 4 겸임 교수 | 지정 교수 본인은 보내는 쪽 동작 금지(화면·서버 `rms_set_sharing`·`rms_recheck`), 연구 정보는 소유자만 |
