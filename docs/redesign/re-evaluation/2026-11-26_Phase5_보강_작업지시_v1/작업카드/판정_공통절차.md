# 판정 카드(T02~T06) 공통 절차

T02~T06은 맡은 **구역**만 다르고 절차는 같다. 카드 파일과 이 파일을 함께 읽는다.

## 입력
1. `2026-11-26_Phase5_보강_v1/판정표/A1_화면목록.tsv` — 내 구역의 줄만 쓴다
2. `2026-11-26_Phase5_개선설계_v1/README.md` — 0절(전제), 1절(쟁점 1~8), 2절(매트릭스), 4절(확정안)
3. `2026-11-26_Phase1-4_정리_v1/통합_결함목록.md` — 결함 ID와 내용
4. `v2-2026-11-25-corrected/02-product-evaluation.md` — P-ID 평가 카드
5. `08-micro-detail-audit.md` — 미세 결함(번호 `#1`~`#17`). 정정 사항은 통합 결함목록 5절
6. `2026-11-26_Phase1-4_전수검사_v1/부록/A_데스크톱캡처89장.md`, `B_모바일교수기타캡처.md` — 캡처별로 실제 보이는 것(새 발견 표 1). 결함목록에 없는 낮음 등급도 여기 있다
7. `2026-11-26_Phase1-4_정리_v1/캡처_설명_정정표.md` — 쓰면 안 되는 캡처
8. `v2-2026-11-25-corrected/02-visual-archive-index.md` — 캡처 파일을 찾을 때(설명은 정정표가 우선)

## 출력
`2026-11-26_Phase5_보강_v1/판정표/판정_Txx.tsv` (Txx = 내 카드 번호)

첫 줄(열 이름)은 정확히 아래와 같다.
```
화면ID	화면 이름	판정	문제 ID	쟁점	지금(전)	바뀐 뒤(후)	지금 캡처	근거 등급	메모
```

| 열 | 쓰는 법 | 예 |
|---|---|---|
| 화면ID | A1 목록의 ID 그대로. 내 구역의 **모든 줄**을 빠짐없이 옮긴다 | `HOM-02` |
| 화면 이름 | A1 목록 그대로 | `다음 미팅 카드` |
| 판정 | 6기준 하나 또는 둘(`보완 + 제거`). 공통지침 6절 | `재설계` |
| 문제 ID | 근거 ID를 ` · `로 잇는다. 없으면 `기록된 문제 없음` | `09-4 · E-5 · RC-10` |
| 쟁점 | 관련 Phase 5 쟁점 번호(1~8). 여러 개면 ` · `. 없으면 `—` | `2 · 3` |
| 지금(전) | 지금 화면·동작을 한 문장으로. 문서에 적힌 사실만 | `목표만 적은 다음 미팅이 "아직 준비한 내용이 없어요"로 보여요` |
| 바뀐 뒤(후) | 확정안이면 그 내용을 한 문장으로. 확정안이 없고 매트릭스 '방향'만 있으면 앞에 `제안: `을 붙인다. 판정이 `유지`면 `그대로` | `목표를 첫 줄에 보이고 준비 수는 따로 세요` |
| 지금 캡처 | 이 화면이 가장 잘 보이는 캡처 **하나**의 경로(자료 루트 기준). 없으면 `없음` | `assets/live-desktop/17_meetings_list_1440.png` |
| 근거 등급 | `재현`·`코드`·`사진`·`불확실`·`기록 없음` 중 하나. 문제 ID 쪽 문서에 적힌 등급을 따른다 | `재현` |
| 메모 | 필요할 때만. 없으면 `—` | `편집자 화면은 B-19 참고` |

### 문제 ID 형식 (이 형식만 쓴다)
- 통합 결함목록: `09-4`, `A-N10`, `B-23`, `E-7`
- Phase 3 평가 카드: `P02-1`, `P04-S1` (02-product-evaluation의 ID 그대로)
- 08 미세 결함: `08-#5`
- 원인: `RC-1`~`RC-10`
- 사용자 결정: `D17`, `결정:휴지통`, `결정:공유중지`, `결정:크레딧%`, `결정:연구정보`, `결정:완료취소`, `결정:계정`

## 절차 (한 줄씩 반복)
1. A1 목록에서 내 구역의 줄을 하나 고른다.
2. 이 화면 이름과 비슷한 말로 입력 3~6을 검색한다(예: `다음 미팅`, `NextMeeting`, `준비한 내용`). **카드에 적힌 '이 구역에서 찾을 ID'를 먼저 본다.**
3. 문제가 있으면 그 ID를 모두 적는다. Phase 5 README 2절 매트릭스에 같은 대상이 있으면 **그 판정과 방향을 그대로** 쓴다.
4. 문제가 없으면 판정 `유지`, 문제 ID `기록된 문제 없음`, 바뀐 뒤 `그대로`, 근거 등급 `기록 없음`으로 적는다.
5. 캡처를 고른다.
   - 순서: `assets/live-desktop/` → `assets/live-desktop-deep/` → `assets/live-mobile/` → `assets/live-professor-editor/` → `assets/dark-mode/` → `2026-11-26_09-교차검토_v1/캡처/`
   - 공통지침 4절 6번의 **금지 캡처**와 `assets/benchmarks/`는 쓰지 않는다.
   - 파일이 실제로 있는지 `ls`로 확인한다.
6. 다음 줄로 간다. 내 구역 줄을 다 할 때까지 반복한다.
7. 카드에 적힌 '이 구역에서 찾을 ID'가 모두 어느 한 줄에는 들어갔는지 확인한다. 어느 화면에도 안 맞으면 가장 가까운 화면 줄에 넣고 메모에 이유를 적는다.
8. 검사를 돌린다: `python3 -I 2026-11-26_Phase5_보강_작업지시_v1/도구/검사.py 판정 Txx`

## 하지 말 것
- 문서에 없는 문제를 만들지 않는다. 캡처를 보다가 새로 발견한 것은 `메모`에 `새 관찰:`로 시작해 적고, 판정에는 반영하지 않는다.
- 확정안(공통지침 2절)과 다른 '바뀐 뒤'를 쓰지 않는다.
- A1 목록에 없는 화면 줄을 새로 만들지 않는다. 필요하면 보고서 질문에 적는다.
- 다른 카드의 구역 줄을 쓰지 않는다.

## 완료 기준
- [ ] 내 구역의 A1 줄이 모두 있다(줄 수가 같다)
- [ ] 모든 칸이 채워졌다
- [ ] '이 구역에서 찾을 ID'가 모두 어느 줄에 들어갔다
- [ ] 금지 캡처를 쓰지 않았다
- [ ] `검사.py 판정 Txx` 마지막 줄 `통과`
- [ ] 보고서에 판정별 줄 수를 적었다(예: `유지 7 · 보완 5 · 재설계 2`)
