# 처음 시작하는 사람을 위한 안내

코드를 몰라도 AI에게 시켜 Margin을 고칠 수 있게 정리한 문서입니다. 용어는 짧게만 풀었습니다.

## 먼저 알아둘 세 가지

- **main**: 완성본이 있는 줄기입니다. 여기에 직접 고치지 않습니다. 이 줄기에 합쳐지면 사이트에 반영됩니다.
- **브랜치(branch)**: 작업용 복사본입니다. 작업 하나에 브랜치 하나를 만듭니다.
- **PR(Pull Request)**: "이 브랜치를 main에 합쳐 주세요"라는 요청서입니다. 검사 결과와 변경 내용이 한 화면에 모입니다.

원칙은 하나입니다. **작업 하나 = 브랜치 하나 = PR 하나.** 합쳐진 브랜치는 지워서 main만 남깁니다.

## 시작하는 법

1. 이 폴더(`Margin-repo`)를 AI 도구(Claude Code, Codex, Antigravity 등)로 엽니다.
2. AI는 `AGENTS.md`(작업 규칙)를 먼저 읽습니다. 따로 시키지 않아도 됩니다.
3. 아래 [AI에게 보내는 말](#ai에게-보내는-말)을 붙여 넣고 `<…>` 부분만 바꿉니다.

실행 방법은 [README](../README.md)의 "실행"을, 화면 확인용 계정은 AGENTS.md의 "체험 계정"을 봅니다. 비밀번호는 채팅·PR·커밋에 다시 적지 않습니다.

## AI에게 보내는 말

**작업 시작**

```text
Margin 저장소에서 작업할게. 먼저 AGENTS.md와 docs/start-here.md를 읽고,
git status로 지금 상태를 알려줘. main에서 새 브랜치를 만들어서 아래 작업을 해줘.
작업: <하고 싶은 일을 한두 문장으로>
끝나면 검사 결과를 알려주고, 내가 말하기 전에는 commit·push·PR을 하지 마.
```

**끝내기(PR 만들기)**

```text
작업이 끝났어. CHANGELOG.md의 Unreleased에 한 줄 적고, 검사를 돌려줘.
통과하면 commit하고 push한 다음 PR을 열어줘.
PR 설명에는 무엇을 왜 바꿨는지, 어떤 검사를 했는지, 못 한 검사는 못 했다고 적어줘.
```

**지금 상태 확인(헷갈릴 때)**

```text
git 브랜치, 열린 PR, 아직 합치지 않은 변경을 표로 정리해줘.
무엇이 끝났고 무엇이 남았는지 한 줄씩 알려줘. 아무것도 고치지 마.
```

**합친 뒤 정리**

```text
내 PR이 main에 합쳐졌어. main을 최신으로 받고,
합쳐진 내 브랜치(로컬·GitHub)를 지워줘. 지우기 전에 목록을 먼저 보여줘.
```

**미완성 작업을 남겨 둘 때**

```text
이 작업은 지금 합치지 않을 거야. 브랜치를 지우지 말고 archive/<이름>-<날짜> 태그로 남기고
GitHub에 올린 뒤 브랜치는 정리해줘. docs/development.md의 "브랜치·PR 정리"를 따라줘.
```

## AI가 하면 안 되는 것

- main에 직접 고치기, 강제 push(`--force`), 기록 지우기
- 비밀번호·API 키·실제 연구 자료를 파일이나 PR에 적기
- DB 변경 파일(`supabase/migrations`)의 기존 내용 수정
- 검사를 안 돌리고 "통과했다"고 말하기

## 헷갈릴 때

| 상황 | 하는 일 |
| --- | --- |
| 무슨 상태인지 모르겠다 | "지금 상태 확인" 문구를 보낸다 |
| AI가 큰 변경을 하려 한다 | 멈추게 하고 작업을 쪼개 달라고 한다. 작업 하나는 10분 안팎이 좋다 |
| 실수로 지웠다 | 바로 AI에게 알린다. 합쳐진 기록은 GitHub에 남아 있다 |
| 화면이 이상하다 | 스크린샷과 주소를 함께 AI에게 준다 |

더 자세한 규칙은 [작업 규칙](../CONTRIBUTING.md), [개발 안내](development.md), [AI 작업 기준](../AGENTS.md)에 있습니다.
